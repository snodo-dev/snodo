# Delivered plans leave their records untracked, which blocks `make release`

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
When a plan is delivered to the base branch, its own records (`.snodo/plans/<plan>/`: plan.yml, status.json, wave specs, superseded specs) are committed with the delivery. Main then tracks every delivered plan's record, and the working tree stays clean.

## THE CHAIN
- Evidence: after each overnight delivery on 2026-10-10 and 2026-10-11, `make release` refused to run because of a dirty tree, with untracked `.snodo/plans/<name>/` directories. The maintainer committed them by hand every time: "chore: add plan records for …" in commits 37c8cc7 and 7135d99, among others.
- The maintainer's position is that plan records belong in the repository.
- Delivery to the base branch happens in `snodo/cli/commands/plan_delivery.py` (`deliver_healthy_plan_wave`) and `_deliver_plan_integration` in `snodo/cli/commands/run_merge.py`.
- Plan records live in the project's main working tree, not in task worktrees, so coders never see or touch them.

## CONSTRAINTS
- Commit only that plan's `.snodo/plans/<plan>/` directory, and only when it has changes. Never stage anything else; other untracked or modified files must stay as they are. Never touch other `.snodo/` content (audit log, jobs, sessions, protocol).
- Do it for each delivery mode that writes to the base branch locally (`local_merge`). For modes that only push a branch or raise a change request, include the record in what is delivered if that fits naturally; otherwise state in the issue why it is left out.
- Use a plain, recognisable commit message such as "chore: record plan <name>", with no "Fixes" line.
- If the commit fails, delivery itself must not fail. Report it and carry on.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in this repo. Tests use temporary git repositories with their own `.snodo/plans/` fixtures.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the targeted delivery tests.

## ACCEPTANCE
- In a temporary repo with a delivered plan, the plan's record directory is committed on the base branch after delivery.
- An unrelated untracked file is left untracked.
- A second delivery with no record changes makes no extra commit.
- There is a CHANGELOG entry under ## [Unreleased].
