## Intent
A provider that signs in with OAuth has no API key by design, so places that read "no API key" as "this provider is not set up" must recognise it as a normal, configured provider and, where it matters, say whether it is signed in.

## Evidence
- Provider listing in `snodo models` only counts a provider as configured when it has a literal key or a populated key environment variable (the helper that lists configured provider names in the models providers module under snodo/cli/commands), so an OAuth provider would never be listed.
- Model discovery in the foundation package's model discovery module resolves an API key first, logs that no key was found and returns an empty list; a provider that signs in with OAuth and has no models endpoint should not produce a misleading warning about a missing key.
- Run preflight in the run command module rejects a missing credential when a provider declares an api key environment variable; an OAuth provider declares none, so it passes unchecked even when the operator has not signed in.
- The `auth` provider setting and its helper `provider_uses_oauth` on the config manager already exist in the core config module.
- The token module already exists in this checkout as the Python module `snodo.infrastructure.chatgpt_oauth` in the foundation package, and it is read-only for this task: do not modify or recreate it. Its function `chatgpt_sign_in_state()` reads the token file only, makes no network call, and returns a small mapping with the expiry when signed in or None when not signed in. Use this function as the sign-in state; do not use the snodo-cloud OAuth store or cloud credential modules, and do not create another token module.

## Outcome
- An OAuth provider is listed as configured by `snodo models`, and its sign-in state (signed in, or not signed in with the `--authenticate` command to run) is shown beside it.
- Discovery for an OAuth provider that has no models endpoint returns an empty list quietly, without saying that an API key is missing, and does not call out to a key.
- Run preflight refuses to start a plan whose configured model belongs to an OAuth provider that is not signed in, naming the provider and the command `snodo models --provider <name> --authenticate`; a signed-in OAuth provider passes preflight.
- Providers without the `auth` setting behave exactly as before.
- Tests cover each of the three places for a signed-in provider, a not-signed-in provider, and a provider with an API key unchanged. Use a fake state function and no network.
- `make gate` passes, including ruff (no unused imports), the import-linter contract, and the file-length and docs-coverage checks.
