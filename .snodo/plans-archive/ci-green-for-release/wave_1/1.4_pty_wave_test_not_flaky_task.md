## INTENT

## THE CHAIN

Three other tasks were being gated on the same shared host at the time (GATE_JOBS=24, two concurrent slots), and the run took 130s. The same test has passed in earlier gates.
- The test drives a real pty around the delayed wave indicator. The likely cause is that its timing assumptions don't hold under load (fixed waits, read deadlines or thresholds on how quickly output appears). Confirm the cause from the test and the spinner code before changing anything.

## CONSTRAINTS

- Don't change product behaviour in snodo/cli/spinner.py unless the test exposes a real bug. If it does, say so in the issue.
