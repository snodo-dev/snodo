# The retired `resolve` capability name is gone from the repository

First open a GitHub issue for this work, or reuse the open one about retiring the `resolve` capability name if it exists. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Older shipped templates (greenfield, intent, bugfix-surgeon, feature-warden) granted a mode capability called `resolve`. It was never in the capability map, so it granted nothing. The templates were fixed to grant `decide` instead (#509), but projects created before then still carry `resolve` and see "grants unknown capability 'resolve'" warnings. The name still appears in the repository as though it were real:
- the property-test strategy that generates valid, non-exclusive mode tools lists `resolve` next to real capabilities;
- negative tests use `resolve` as their example of an unknown grant, which reads like a typo of a real capability rather than a made-up one.

Remove the name everywhere:
- the valid-tool strategy lists only real capabilities;
- negative tests use an obviously fictional name;
- a test guards that every shipped protocol template grants only capabilities in the capability map, so a stale name cannot ship again. If such a guard already exists, extend it to cover every template file.

## THE CHAIN
- `tests/strategies.py`: the non-exclusive tool strategy.
- `tests/mcp/test_server.py`, `tests/cli/test_ready_cmd.py` and `tests/cli/test_protocol_schema.py` use `resolve` as the unknown example.
- The capability map is `packages/snodo-foundation/src/snodo/protocols/capabilities.py`, and the templates live in `packages/snodo-foundation/src/snodo/protocols/templates/`.
- The published schema `schemas/protocol-v1.json` should not list `resolve` either.

## CONSTRAINTS
- Do not change the capability map, the templates' real grants, or the unknown-capability warning text.
- Words like "resolved" or "resolves" in comments and prose are fine. This is about the capability name only.
- No new audit event, status, severity or halt type.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run the touched tests plus the protocol template tests.

## ACCEPTANCE
- No test, template, schema or doc uses `resolve` as a capability name.
- The template guard test fails if a template grants a capability that is not in the map.
- There is a CHANGELOG entry under ## [Unreleased].
