INTENT
The serve registry's tests state clearly what the registry guarantees, and the guarantees hold: recording the same project and mode replaces the earlier entry, a removal leaves a replacement entry alone, and dead or reused process ids are dropped. This ticket only touches the registry's tests, and its module only if a test exposes a real defect.

GitHub issue #1002 already exists for this work. Do not open another; put "Fixes #1002" in the commit message. No CHANGELOG entry (the plan's entry already covers it).

EVIDENCE
The first test in the registry test file mixes several behaviors, replaces the record function with a stub halfway through, hand-writes the file contents and then asserts that three entries are listed (including two for the same project and mode), which contradicts the replacement behavior it claims to cover. The file also builds fixtures with inline imports. As written it would pass whether or not replacement works.

CONTRACT
- Replacement: recording the same project and mode twice leaves one entry, the newer; a different project or mode is kept alongside.
- Removal removes exactly the entry that was recorded, and leaves a newer replacement for the same project and mode in place.
- Entries whose process is gone, or whose process id belongs to a different process than the recorded one, are dropped when listing, and the file on disk is pruned.
- A corrupt file reads as empty and recording over it works.

CONSTRAINTS
- Tests use only public functions and an isolated temporary home; no stubbing of the registry's own functions.
- Do not touch serve, the relay, the CLI or any other module. No new dependency.
- No new status, severity, halt type or audit event.
- Targeted tests only (the registry tests and the serve tests that record into it). Do not run the snodo CLI, make gate or make release. Do not touch .snodo/.

ACCEPTANCE
- Separate small tests for each behavior above, each of which fails if its behavior is broken.
- Existing tests pass and lint is clean. Run the targeted tests and report their output.
