INTENT
A lease minted for the runner audience never disturbs the ingest lease that audit ingest and liveness rely on. Today the shared exchange stores every successful lease as the process-wide current lease, so minting a runner lease would replace the ingest lease and the next ingest send would present a runner token. The same exchange also shares its quiet window and failure counter between audiences. The ingest behavior stays exactly as it is.

GitHub issue #1004 already exists for this work. Do not open another; put "Fixes #1004" in the commit message. No CHANGELOG entry (the plan's entry already covers it).

EVIDENCE
The runner lease mint was added to the cloud lease module in the previous wave. On success the exchange sets the module-level current lease and its session id regardless of audience; on a refusal it clears them. get_current_lease, which the ingest and liveness senders call, would then return the runner lease. The relay will mint a fresh runner lease on every connect and reconnect, so this would happen repeatedly once the relay is wired in. Nothing in the tests covers it.

CONTRACT
- Minting a runner lease does not read, replace, clear or extend the cached ingest lease, and an ingest lease minted before or after is unaffected by runner mints in both directions.
- A runner mint that fails does not start or lengthen the quiet window that ingest uses, does not bump the ingest failure counter and does not record a permanent refusal against the ingest session. A runner mint is a one-shot request: the caller (the relay) owns its retry and backoff.
- The ingest request is made exactly as before, with the same call shape; existing stand-ins for the post call keep working without edits.
- The helper that mints a lease for a purpose honours its force argument rather than always forcing, and returns nothing when no credential is configured.

CONSTRAINTS
- No new status, severity, halt type or audit event. No new third-party dependency.
- Never log or print a lease token or credential.
- Do not touch the relay module, serve, the CLI or the MCP transport.
- Targeted tests only: every test file exercising the lease exchange, cloud credentials and cloud sync, plus the whole tests/infrastructure directory once. Do not run the snodo CLI, make gate or make release. Do not touch .snodo/.

ACCEPTANCE
- Tests show: an ingest lease survives a runner mint; a failing runner mint leaves the ingest quiet window, counter and refusal state untouched; a runner mint after an ingest refusal still performs its request; the runner request carries the audience and machine id and the ingest request carries neither.
- Existing lease and credential tests pass without edits to their expectations; lint is clean.
