INTENT
The frames the machine-level relay exchanges with the cloud are encoded and decoded in one self-contained module with its own tests, before any socket code exists. Bodies of any size are split into ordered chunks and reassembled; unknown or malformed frames are rejected without crashing the caller.

CONTRACT (agreed with snodo-cloud, v1.1; exactly these frames, nothing else)
JSON text frames, each with a "t" field.
- Client to cloud: hello {v, machine_id, snodo_version, endpoints:[{hostname, auth}]}; res {id, status, headers}; chunk {id, seq, last, data_b64}; err {id, code, message}; keep {id}.
- Cloud to client: req {id, hostname, method, path, headers}; chunk {id, seq, last, data_b64}; cancel {id}.
- Body chunks carry at most 192 KiB of raw body each (so the encoded field is larger). A body is split in order with seq starting at 0 and the last chunk marked last; an empty body is a single empty last chunk. The cloud chooses request ids; the relay echoes them.
- The headers a request may carry are authorization, mcp-session-id, content-type, accept and mcp-protocol-version; the codec passes headers through as given and does not interpret them.

THE CHAIN
Encoding takes plain values and returns a JSON string; decoding takes a string and returns a typed value, or raises one clear error type for: not JSON, not an object, unknown "t", missing or wrongly typed field, oversize chunk, bad base64, negative or non-integer seq. A reassembler takes chunks for one request id and yields the full body once the last chunk arrives, rejecting chunks that arrive out of order, repeat, or follow the last one, and refusing a body that grows past a configurable ceiling (default generous, for example 64 MiB) so a hostile peer cannot exhaust memory. A splitter turns a body of any size, given as bytes or as an iterable of byte pieces, into the ordered chunk frames without holding more than one chunk's worth beyond the input.

Place the module with the other user-level cloud infrastructure in the foundation layer, with no dependency on the engine, mcp or app layers.

CONSTRAINTS
- Pure code: no sockets, no clock, no I/O.
- Large payloads in tests are built inside the test body, never passed as parametrize values, so test ids stay short.
- The shared autouse fixture named above must always yield, whether or not it finds the repository root; a minimal fix to that fixture is in scope if the error shows up again.
- Never put request headers, bodies or credentials into error messages or log lines.
- No new status, severity, halt type or audit event. No new third-party dependency.
- Do not touch serve, the CLI, the MCP transport or the cloud client code.
- Targeted tests only, plus the whole tests/infrastructure directory once to confirm the fixture error is gone. Do not run the snodo CLI, make gate or make release. Do not touch .snodo/.

ACCEPTANCE
