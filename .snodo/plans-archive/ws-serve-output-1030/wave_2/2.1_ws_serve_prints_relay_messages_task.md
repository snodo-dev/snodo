# 2.1 — ws serve shows the relay's messages in the terminal

GitHub issue #1030 already exists for this work. Do not open another; put "Fixes #1030" in the commit message. Do not edit the CHANGELOG.

## INTENT

Two earlier tasks in this plan gave `RelayParticipant` and `CloudRelay` an optional `notify` callable that receives one plain-text message (waiting for the machine-wide relay lock; connected to snodo cloud; login needed; rejected; replaced; connection lost). Nothing passes one yet, so the user still sees nothing. `run_ws_tunnel` in `snodo/cli/commands/serve_tunnel_ws.py` builds the participant and the relay when none is injected.

## Outcome

- When `run_ws_tunnel` builds the participant and relay itself, both get a `notify` that prints the message on its own line to the terminal as it arrives, flushed, with no change to how stop, rollback and the "MCP server exited" error behave.
- An injected `participant` is used exactly as before.
- Messages that arrive before the existing active/connect output has printed are not lost.

## Acceptance

- Tests in tests/cli/test_serve_ws_provisioning.py or the existing ws serve tests (find them with grep for run_ws_tunnel) show that a message sent by the participant's `notify` reaches stdout, with the injected-participant path unchanged.
- The linter is clean.

## Constraints

- Do not change cloud_relay.py or relay_participant.py in this task, and do not change the connect block text.
