# The local gate passes tests that fail in CI

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Tests that behave differently under CI are exercised by the local gate the same way GitHub Actions exercises them. A green gate then means a green CI test job.

## THE CHAIN
- Evidence: CI's test job on main was red from at least 8 Oct until #824 and #825, and the release workflow failed its test step for v0.21.0, v0.22.0 and v0.23.0, so none of them reached PyPI. Every local gate in that period passed.
- One cause was code that changes behaviour when `CI` is set: `snodo/cli/spinner.py` stays silent under `CI`. GitHub Actions always sets `CI=true`. The gate (`make gate` / `make gate-ci`, run by `scripts/gate_remote.sh` on the gate host) does not.
- `.github/workflows/ci.yml` and `.github/workflows/release.yml` show how CI invokes pytest.

## CONSTRAINTS
- Make the gate's test run set `CI=true`, matching CI's environment, in `scripts/gate_remote.sh` (or wherever the gate composes its pytest invocation).
- Do not change what the gate checks or the order of its checks. Do not change the CI workflows.
- If any test then fails under `CI=true`, fix the test's environment handling, as #824 did for the spinner. Do not weaken production behaviour.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run the test suite once locally with `CI=true` set (`CI=true uv run pytest tests/ -q -n auto --timeout=60`) to confirm nothing else depends on its absence. Report the result in the issue.

## ACCEPTANCE
- The gate's pytest invocation runs with `CI=true`. A test or a static check of `scripts/gate_remote.sh` pins this.
- The full suite passes locally with `CI=true`.
- There is a CHANGELOG entry under ## [Unreleased].
