# 1.1 — the real-PTY wave test gives each phase its own time budget

GitHub issue #1019 already exists for this work. Do not open another; put "Fixes #1019" in the commit message. Do not edit the CHANGELOG; this is a test-only change.

## INTENT

`tests/cli/test_spinner.py::test_wave_output_completes_under_a_real_pty` fails intermittently when several gates run at once, with `CLI remained blocked under a PTY`. It passes on the base commit every time, and the failure lands on whichever task is being gated. Evidence from 2026-10-23: three tasks gated in parallel, two of them failed on exactly this test (1 failed, 5833 passed), and both passed once re-run alone with no code change. #802 already replaced the short fixed sleeps with output-synchronised waits and a 55 s deadline, so what remains is not a short timeout.

The test shares a single deadline across interpreter start-up, the wait for the first drawn frame and the wait for the child to exit. The child imports `snodo.cli.spinner`, which loads the CLI package; under heavy load that alone can take a large part of the budget, leaving the exit phase almost nothing, and the result reads as a deadlock although the child is only slow. The test also stops reading the PTY between the first drawn frame and the drain loop, so a stalled test process lets the animation fill the PTY buffer, and a failure carries no timings or output, so a slow child and a true hang look the same.

Make the test robust to load without weakening what it proves: the wave is drawn only on a real terminal, stops when output arrives, and the child exits cleanly without deadlocking. Give each phase its own budget so load in one phase cannot starve the next, keep draining the PTY for the whole run, and make a failure say which phase ran out, how long each phase took, and what output was captured. If the combined budgets can exceed the gate's per-test timeout, raise the timeout for this one test with the timeout marker the repository already registers rather than shrinking the budgets. Keep the genuine-hang case failing: a child that really never exits must still fail, just with a clear message.

## Acceptance

- The test has separate budgets for the draw wait and the exit wait, and the exit budget starts when the child is released, not at test start.
- The PTY is read continuously from start to finish, with no stretch where the test does not read while the child may be writing.
- An assertion failure names the phase that ran out, the elapsed time of each phase and the captured output so far.
- The test still uses a real PTY and still asserts the wave drew, the child exited with code 0 and the output ends with the task table text.
- Run the file's tests, a few repeats of this test under load (for example alongside a CPU-busy command), and the linter. Do not run the whole suite yourself: the engine runs it right after you finish, and a multi-minute silent command has been dropping the coder connection.
