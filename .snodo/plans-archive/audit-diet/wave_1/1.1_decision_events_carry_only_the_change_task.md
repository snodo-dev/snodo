# A session decision update audits only what changed

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Project audit logs have reached 0.6 to 2.6 GB, and opening one now takes tens of seconds. In this repository's log, 99% of the bytes are `session_decision_updated` events:
- 438 events for the "halt" key alone make up 515 MB, at about 430 KB each and up to 2.7 MB;
- "task_failure" and "classification" behave the same way.

These decisions are maps keyed by task. Each time one task's entry changes, the whole accumulated map is written into the hash-chained log again, including every task's spec text. That makes the log grow quadratically with the number of tasks in a session. The same events are shipped to cloud sync, which is how a single 6.3 MB event was refused upstream.

The audit event for a decision update should record what changed: for a per-task map, only the entry or entries that were added or changed. Task spec text should not be copied into these events, because it already lives in the task's own state. The session checkpoint file keeps the full map, as today. Only the audit event gets smaller.

## THE CHAIN
- The session manager in `packages/snodo-foundation/src/snodo/infrastructure/session.py` writes the decision into the session checkpoint and then audits it with the key and the full value.
- The engine's write-back node in `packages/snodo-engine/src/snodo/engine/nodes/writeback.py` builds the halt, failure and classification maps and passes the whole map on every update. It already strips coder output from the halt payload before it goes on the wire.
- Cloud sync's ingest contract in `packages/snodo-foundation/src/snodo/infrastructure/cloud_sync.py` lists this event's fields as key and value. Keep the event type and those field names. A consumer that merges the value into what it already has should arrive at the same map as before.
- Tests under `tests/mcp/` (decision handlers, resolution) and `tests/coders/` exercise decision updates. Check whether any assert the full map inside the audit event, and update them to the new behaviour.

## CONSTRAINTS
- The session checkpoint file and everything that reads decisions from it behave exactly as today.
- Same event type, same field names, no new audit event, status, severity or halt type.
- Scalar or non-map decision values are audited as today.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run the session, write-back, cloud sync and decision-handler tests.

## ACCEPTANCE
- Tests show:
  - after many tasks in one session each record a halt, the size of each new decision event stays flat instead of growing with the number of tasks;
  - a decision event holds only the changed task's entry and no task spec text;
  - the session checkpoint still holds the full map;
  - merging the audited values in order reproduces the checkpoint's map.
