INTENT
In recon rec_9f00e8 (2026-10-08 06:19Z, 2 agents), the deepseek agent's `result` was 57,831 characters of raw tool output:
- a repository directory listing;
- grep hits across docs and tests;
- a verbatim copy of provider_errors.py;
- a file list from snodo-foundation's infrastructure package.

It ended with "Output was truncated (finish_reason=tool_calls)". Its trace shows `turns_used: 10`, `ended: "truncated:tool_calls"`. The other agent (qwen) gave a clean, cited answer.

The cause is in `_retry_forced_answer` (packages/snodo-mcp/src/snodo/recon/__init__.py, around lines 590–606). When the forced final-answer retry still comes back as tool calls, it sets `retry_answer = "\n\n".join(gathered_findings or earlier_prose)`. `gathered_findings` holds raw tool results, so the orchestrator receives a dump that looks like an answer. The plan recon-failed-agents-keep-work (2.1, 2026-10-08) introduced this from its own spec ("a truncated answer built from what was gathered"). That spec was wrong: an answer must be model-authored.

When this is done:
- If the model wrote substantive prose earlier in the run, that prose may be returned as a truncated answer, as before.
- If the model wrote nothing usable, `result` is empty. `error` says the model returned tool calls instead of an answer after N turns.
- The trace still records what it called and read, so the orchestrator can see how far it got.
- No tool output is ever placed in `result`.

THE CHAIN
1. Change the refused-answer fallback so `result` is only ever model-written text: earlier prose, if any. Otherwise it's empty, with a clear error.
2. Keep the trace as it is: turns used, tools called, and how it ended. If a short list of the files the agent read would help the orchestrator, add it inside the existing trace dict, not as a new result field.
3. Tests, with a fake provider:
   - a model that keeps returning tool calls after the forced retry, having written no prose, yields an empty `result`, a clear error and a populated trace;
   - a model that wrote prose earlier yields that prose as a truncated answer;
   - no test fixture's tool output ever appears in `result`.

CONSTRAINTS
- Snodo's state machine is closed: add no status, severity, halt type or audit event, and no new top-level result field.
- No file may exceed its file-length limit or baseline.

ACCEPTANCE
- The tests in link 3 exist and pass.
