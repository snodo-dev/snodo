# Release the pin and retire the workarounds

GitHub issue #922 already exists for this work. Do not open another; put "Fixes #922" in the commit message.

## Why this task exists

The port only counts as finished once the things that were holding mcp at 1.x
are removed. Until then the repository says two contradictory things: the code
supports 2.x, and the metadata insists it does not. Issue #922.

## What "done" means

The project depends on mcp 2.x openly, the suppression added while the port was
pending is gone, and the documentation describes the current module path.

## Acceptance criteria

1. The MCP package manifest no longer caps mcp below 2 and the lock file
   resolves a 2.x version consistently with the manifest.
2. The suppression for this dependency in `.github/dependabot.yml` is removed —
   it exists only while the port is pending, and leaving it in place would hide
   future majors.
3. Any documentation or docstring that names the removed v1 module path now
   names the 2.x one, including the producer guide topic that describes the MCP
   transport.
4. A CHANGELOG entry under Unreleased records the upgrade and carries
   `(Fixes #922)`.
5. The full test gate passes.

## Constraints

- Do not re-open the transport port; if something is broken there, report it in
  the commit message rather than papering over it here.
- No new halt types or severities.
- Either the gate passes and you submit, or it does not and you fix it. Do not
  leave notes about validation anywhere in the tree.

## Running tests

Run the targeted MCP tests and the linter, and do not run the whole suite yourself: the engine runs it right after you finish, and a multi-minute silent command has been dropping the coder connection. Confine the diff to what this task asks for and drop every hunk the outcome does not require.
