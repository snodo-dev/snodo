# get_plan's run summary shows zeros for tasks that completed and were delivered

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
The run summary that MCP `get_plan` returns (added in #813) tells the orchestrator what the latest run actually did: each task's outcome, attempts, duration and whether it was delivered, plus correct totals.

## THE CHAIN
- Evidence: plan ci-test-green, run job j_c374787f367d. Both tasks completed, were merged into integration, and the integration branch was delivered to main ("Plan progress: 2/2 completed"). `get_plan("ci-test-green")` nevertheless returns `run_summary.tasks[*]` with `outcome: null`, `attempts: 0`, `duration_seconds: null` and `delivered: false`, and totals of `attempts 0`, `duration_seconds 0`, `delivered 0`.
- The same holds for persona-templates and other recent plans.
- The summary is built around `run_summary` in `packages/snodo-mcp/src/snodo/mcp/plan_handlers.py` and `snodo/cli/commands/plan_cmd.py`. Find where it reads per-task results and why it finds none for these runs. For example: it may look up the wrong job or task identity, or a record that plan runs don't write.
