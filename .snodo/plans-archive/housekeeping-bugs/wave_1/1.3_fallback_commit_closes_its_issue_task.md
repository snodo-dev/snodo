# Fallback coder commits leave their GitHub issue open

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
When the coder leaves changes uncommitted and snodo commits them on its behalf, that commit carries the same issue reference the coder would have used. A task tied to an issue then closes it on merge, the same way a coder-made commit does.

## THE CHAIN
- Evidence: commit e40efa3 on main, "coder: Rust fixture smoke test fails on runners where cargo exists but has no toolchain", has no "Fixes #825", although the coder opened issue #825 for that work. The issue stayed open after the merge and had to be closed by hand. Several other `coder: ...` commits on main have the same gap.
- The release-mode changelog check also relies on "Fixes #N" commits.
- The fallback message is composed in `_commit_message` in `packages/snodo-engine/src/snodo/coders/base.py`, from the spec's first line and the coder's findings only.
- The issue number is usually available. It may appear in the spec, for example as `Fixes #818` or "Issue #818 already exists". It may also appear in the coder's output or report, for example "Issue #825 is open" or a GitHub issue URL.

## CONSTRAINTS
- Add `Fixes #N` only when one issue number can be identified with confidence. If none is found, or several conflicting ones, keep today's message.
- Prefer an explicit reference in the spec over one found in the coder's output.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the targeted coder tests.

## ACCEPTANCE
- Tests show that the fallback message gains a `Fixes #N` trailer:
  - when the spec says "Issue #818 already exists" or "Fixes #818";
  - when only the coder output names the issue it opened.
- With no number, or with conflicting numbers, the message is unchanged.
- There is a CHANGELOG entry under ## [Unreleased].
