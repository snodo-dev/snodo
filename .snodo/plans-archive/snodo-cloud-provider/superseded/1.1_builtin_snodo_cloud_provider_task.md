# snodo cloud's model gateway is not a provider snodo knows

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
"snodo-cloud" is a built-in model provider. A model named `snodo-cloud/<id>` routes to the snodo cloud gateway's OpenAI-compatible API (default https://models.snodo.dev/v1). The provider authenticates with the user's snodo cloud login: the OAuth access token when logged in with OAuth (refreshed when needed), otherwise the configured `cloud.api_key`. With no cloud login, the provider has no key and behaves like any other unconfigured provider.

Gateway model ids look like "gpt-6-luna", "@cf/qwen/qwen3.8-27b" and "anthropic/claude-sonnet-5.5". The snodo names are "snodo-cloud/gpt-6-luna", "snodo-cloud/@cf/qwen/qwen3.8-27b" and "snodo-cloud/anthropic/claude-sonnet-5.5". The part after `snodo-cloud/` goes to the gateway as the model.

## THE CHAIN
- Recon rec_d1fad8, confirmed in the code. Built-in providers are data in `DEFAULT_PROVIDER_CATALOG` (`packages/snodo-core/src/snodo/config.py`, around line 44). `ProviderConfig` already carries `base_url`, `litellm_provider` and `models_endpoint`.
- Routing goes through `ConfigManager._provider_for_model`, `resolve_litellm_model`, `resolve_api_base` and `get_key_for_model` (config.py, around lines 346–463). Every completion site (validators via `build_completion_fn`, the classifier, recon, the litellm coder, models check and benchmark) uses those helpers.
- Pitfall: `PROVIDER_MODEL_PREFIXES` (config.py, around lines 223–229) maps `gpt-` to openai and "@cf/" to cloudflare. "snodo-cloud/gpt-6-luna" and "snodo-cloud/@cf/..." must resolve to snodo-cloud, never openai or cloudflare.
- Credentials: `resolve_cloud_credential` and `safe_cloud_sync_credential` live in `packages/snodo-foundation/src/snodo/infrastructure/cloud_credentials.py`. snodo-foundation depends on snodo-core, so core must not import foundation at module level. Find a hook that respects this layering; the key is resolved per call, so a refreshed token is picked up.
- The other cloud URLs are configurable under `cloud.*` with defaults (config.py, around lines 86–89, and `_cloud_url`). The gateway URL follows that pattern, e.g. `cloud.models_url`.
