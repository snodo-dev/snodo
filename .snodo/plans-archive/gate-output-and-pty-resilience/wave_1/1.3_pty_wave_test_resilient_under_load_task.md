INTENT
tests/cli/test_spinner.py::test_wave_output_completes_under_a_real_pty fails intermittently in a loaded gate - on 2026-10-10 it was the only failure out of 5309 tests while three tasks shared the gate host. The product behaviour is correct; the test's timing assumptions are not, so the failure teaches the operator nothing except to re-run the gate.

OUTCOME
The real-PTY wave test passes reliably under CPU contention while still proving the same three things: the wave is drawn only on a TTY, it stops and clears once output arrives, and the child exits without deadlocking.

CONSTRAINTS
- Replace fixed short timing assumptions - a four-second deadline used to observe process exit and a roughly 350 ms sleep used to let the animation thread draw before output - with synchronisation on observed PTY output plus generous bounds that still fit the per-test timeout.
- Do not weaken what the test asserts, do not skip or mark it expected-failure under load, and do not change spinner product code to make it pass.
- Do not run make gate in your session; run this test file repeatedly instead.

ACCEPTANCE
- The test passes at least 20 consecutive runs of the file.
- It still passes while the machine is loaded, for example running alongside a parallel pytest burst.
- The rest of tests/cli/test_spinner.py still passes.
