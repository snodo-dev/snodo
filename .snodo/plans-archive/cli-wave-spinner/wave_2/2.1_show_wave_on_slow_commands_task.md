INTENT
Wave 1 added a reusable "wave" loading indicator to the CLI. It draws on stderr only, appears after a short delay, and is off in CI, pipes and the MCP server. Today nothing uses it, so `snodo ready --json` still sits silent for several seconds before printing.

When this is done, any snodo command that does slow work before printing shows the wave with a short, accurate label. Examples are "checking readiness…", "validating changes…" and "testing providers…". Cover at least:
- `snodo ready` (with and without `--json`);
- `snodo validate`, including the `--base`, `--head` and `--pr` options;
- `snodo config test` and `snodo config validate`;
- any other command you find that commonly takes more than about a second with no output.

Prefer one central mechanism over sprinkling the indicator through every command, if the CLI structure allows it. One option is a wrapper applied at the command or app level, where commands only supply their label. Choose what is robust and explain it in a comment. Commands that already stream their own progress, such as `snodo run` and plan runs that print turns, must not get a second indicator layered over their output.

The indicator must stop and clear before the first real output line. That includes interactive prompts (for example `snodo init` asking questions), so it never draws over a prompt.

THE CHAIN
1. Find the slow, silent commands. Timing them locally is fine.
2. Wire in the wave component with accurate labels.
3. Tests:
   - `snodo ready --json` stdout is byte-identical with and without a TTY stderr;
   - the indicator is never drawn when stderr is not a TTY;
   - a command that prompts or streams its own output never has the indicator over it.
