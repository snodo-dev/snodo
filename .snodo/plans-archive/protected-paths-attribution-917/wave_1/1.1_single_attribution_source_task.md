# 1.1 — the protected-path list is injected into the coder one way

GitHub issue #917 already exists for this work. Do not open another; put "Fixes #917" in the commit message. Do not edit the CHANGELOG; this is an internal consistency fix.

## INTENT

The review of the protected-path attribution work (PR #915) left one finding standing. The `protected_paths` attribute a coder carries is declared as a tuple, and the engine sets it in two places that disagree:

- `packages/snodo-engine/src/snodo/engine/loop.py` (the graph builder's constructor, where the coder is attached) assigns `list(getattr(protocol, "protected_paths", []) or [])`.
- `packages/snodo-engine/src/snodo/engine/nodes/executor.py` (`_prepare_coder`, run for every dispatch, which also injects the protocol the adapters need for the notice) assigns `tuple(getattr(protocol, "protected_paths", None) or ())`.

Whichever ran last wins, and the first contradicts the declared type. The other two findings from the same review (the silent swallow in the base-branch resolver, and the redundant sources in the notice) are already closed; leave them alone.

Decide, from the code, whether the constructor assignment covers any path that `_prepare_coder` does not run (for example a coder used outside task dispatch). If it does not, remove the duplicate and let the executor be the single injection site. If it does, keep it but make it the same tuple conversion, with a one-line comment saying which path it covers. State which of the two you found, and why, in the commit message.
