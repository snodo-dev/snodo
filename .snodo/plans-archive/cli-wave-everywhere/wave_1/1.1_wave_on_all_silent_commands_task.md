INTENT
#780 and #781 added the wave loading indicator. `wave_while_silent` (snodo/cli/spinner.py) draws on stderr only, after a short delay, and stops and clears at the first real output or prompt. It is wired in through an allow-list, `_LABELS` in snodo/cli/slow_commands.py, which covers ready, validate, config test, config validate, protocol validate, recon and `models --check`. The operator loved it, and asked for the same on every other command that leaves them waiting.

An allow-list only covers the commands someone remembered and will drift as commands are added. Because the indicator only appears after a quiet delay and stops at the first output, it is safe to apply to nearly every command:
- a fast command never shows it;
- a command that streams progress only shows it until its first line.

When this is done, every CLI command gets the wave by default whenever it is silent for longer than the delay. That includes subcommands of groups such as task, plan, queue, job, logs, audit, cloud, worktree, survey, intake, models, status and runs. Commands where it would be wrong are explicitly excluded, each with a short reason. Examples:
- long-running servers and watchers (serve, serve watch, tunnel);
- full-screen TUIs (dashboard);
- anything that takes over the terminal or hands it to a child process.
Known commands keep or get a meaningful label (for example "loading tasks…", "reading the audit log…", "checking cloud status…"). Any command without a specific label gets a sensible default derived from its name, rather than a bare "working".

Verify the assumption that the indicator is harmless before a command's first output for run and plan run, which stream progress. If it causes any glitch there, exclude them.

THE CHAIN

2. Time or inspect the commands to choose good labels for those that commonly wait. Exclude the ones listed above and any others you find unsuitable.
3. Tests:
   - every registered command is either wrapped or in the exclusion set, so a newly added command is covered automatically (a test that walks the Typer app works well);
   - excluded commands are never wrapped;
   - `--json` stdout is unchanged for a sample of wrapped commands;
   - an interactive prompt (`snodo init`) never has the wave drawn over it.
4. Update the docs section that documents the indicator (search docs/ for SNODO_NO_SPINNER) to say it applies to all commands except the listed exclusions.
