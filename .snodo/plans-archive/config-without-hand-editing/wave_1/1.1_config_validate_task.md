Before starting, open a GitHub issue on snodo-dev/snodo titled "snodo config validate: check ~/.snodo/config.yml against the strict models". If an earlier attempt already opened it (#757), reuse it. Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased].

INTENT
Most of `~/.snodo/config.yml` can only be edited by hand. According to `docs/runbook.md`, provider endpoint settings, cloud settings and notification targets answer "Unknown config key" to `config set`. A hand-editing typo has no feedback loop until something fails at run time, even though strict config models exist (ADR 046: an unknown llm key fails loud).

`snodo protocol validate` already gives this experience for protocols. Config deserves the same.

When this is done, `snodo config validate`, a subcommand of the existing `snodo config`, works as follows:
- It loads the user config through the same strict models snodo uses at run time.
- It reports every problem with its key path and section, plus a hint.
- It exits 0 when the config is valid and non-zero when it is not.
- It supports `--json` per `docs/machine-interface.md`.
- It never prints secret values.

A previous attempt (commit 70c07dc) implemented this, and its 146 config tests passed. But `make gate` failed on lint: ruff F841 flagged an unused exception variable (`except ... as exc`) in the invalid-YAML branch. The coder had noted that ruff wasn't available in its shell. The gate's lint step is part of `make gate`, so run the full `make gate` and fix whatever it reports before finishing.

THE CHAIN
1. A `validate` subcommand under `snodo config` reuses the runtime config loading and models.
2. Error reporting gives the key path and section, and redacts secrets the way `config show` does.
3. `--json` output follows the machine-interface conventions.
4. Tests:
   - a valid config passes;
   - an unknown key and a wrongly typed value are each reported with their path;
   - secrets never appear in the output.

CONSTRAINTS
- No new top-level command.
- Snodo's state machine is closed.
- Do not change how `config set` and `config get` resolve keys; another task owns that.
- No file may exceed its file-length limit or baseline.

ACCEPTANCE
- The tests in link 4 exist and pass.
- The CHANGELOG entry is present.
- `make gate` passes, including lint.
