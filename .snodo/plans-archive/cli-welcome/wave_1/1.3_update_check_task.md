# Nothing tells a user a newer snodo is out

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
snodo can tell whether a newer release exists on PyPI, cheaply and politely. A later task uses this to add one line under `snodo --version`, such as "0.24.1 is available. Update with: curl -fsSL https://snodo.dev/install | bash". This task builds only the check.

## THE CHAIN
- `snodo --version` prints only the installed version (`snodo/cli/main.py`, `_app_callback`).
- No code in the repo looks up the latest published version today.
- PyPI exposes it at https://pypi.org/pypi/snodo/json (`info.version`).
- The installed version is `snodo.version.__version__`.

## CONSTRAINTS
- New small module, for example `update_check.py` in the `snodo.cli` package, with one function that returns the newer version string or None.
- It must never slow the CLI down or fail loudly:
  - short timeout, about 1.5 seconds;
  - any error returns None;
  - the result is cached for a day in the user-level snodo directory the CLI already uses for user config. Find the existing location; don't invent a new one. Never write under the project's `.snodo/`.
- It returns None without a network call when:
  - `SNODO_NO_UPDATE_CHECK` is set;
  - `CI` is set;
  - the caller says the output isn't a TTY.
- Compare versions properly (packaging's Version or equivalent); never compare strings. Pre-releases don't count as newer.
- Don't wire it into any command yet.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the new update-check tests. Tests must not touch the network; mock the HTTP call.

## ACCEPTANCE
- Tests show:
  - a newer release returns its version;
  - an equal or older release, or a pre-release, returns None;
  - a timeout or HTTP error returns None;
  - a fresh cache is used without a network call, and a day-old cache triggers a new one;
  - `SNODO_NO_UPDATE_CHECK`, `CI` and non-TTY each skip the network.
- There is a CHANGELOG entry under ## [Unreleased].
