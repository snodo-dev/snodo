# The wordmark, readiness view and update check aren't reachable yet

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Wire the three pieces built in wave 1 into the CLI entry point:
- **Bare `snodo`:** prints the wordmark (TTY only), then the readiness view. This replaces the fixed "Start here" list.
- **Top-level `snodo --help`:** starts with the wordmark on a TTY, then the existing grouped help, unchanged.
- **`snodo --version`:** still prints `snodo <version>`. On a TTY, when a newer release exists, it adds one line: "<new> is available. Update with: curl -fsSL https://snodo.dev/install | bash".

## THE CHAIN
- Entry point: `snodo/cli/main.py`.
  - `_app_callback` handles `--version` and the no-subcommand case.
  - `HELP_PANELS` groups the help.
- Wave 1 added three modules; find the actual names in the code:
  - a wordmark module under `snodo/cli/` (plain and coloured renderers, plus a TTY show-helper);
  - an update-check module under `snodo/cli/` (returns the newer version or None);
  - a home-view module under `snodo/cli/` (readiness view text).
- `tests/cli/test_main.py` and `tests/cli/test_top_level_help.py` cover today's behaviour and may pin the old "Start here" text.

## CONSTRAINTS
- Non-TTY output must stay exactly as plain as today, with no wordmark and no update line. That covers pipes, `--json` paths, tests and MCP stdio. Subcommand help (`snodo plan --help`) is unchanged.
- The update line goes on stderr, so scripts parsing `--version` stdout keep working.
- Keep the help panels and command inventory as they are. The CLI contract test must still pass.
- Bare `snodo` exits 0, even when the readiness view shows "!" lines.
- Update the existing tests where they pin the old text. Don't delete coverage.
- Note the new bare-`snodo` behaviour, the update hint and its opt-out (`SNODO_NO_UPDATE_CHECK`) in `docs/command-reference.md`.
- No new top-level command. No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only `tests/cli/test_main.py`, `tests/cli/test_top_level_help.py` and the wave-1 banner, update-check and home-view tests.
