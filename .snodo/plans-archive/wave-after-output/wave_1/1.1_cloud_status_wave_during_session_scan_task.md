# `snodo cloud status` goes silent after its header

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
On a terminal, `snodo cloud status` prints its connection header and then pauses for a noticeable while before the "Sync status per session and project" section. During that pause the user sees nothing. The snodo wave should show there as it does at the start of slow commands ("working on …"), and clear the moment the next line prints. Commands that call the helper can reuse it for any later silent phase.

## THE CHAIN
- Every command is wrapped by `add_slow_command_indicators` (`snodo/cli/slow_commands.py`). Its wave (`wave_while_silent` in `snodo/cli/spinner.py`) stops permanently at the first output, by design, so it never covers a slow step that comes after the first line.
- In `cloud_status_command` (`snodo/cli/commands/cloud_cmd.py`, around lines 317–370), the header is printed first. Then `CloudSyncState().get_summary()` and `local_unsent_counts(...)` (`snodo/cli/commands/cloud_status.py`) run before the per-session section. That is the observed pause.
- `WaveSpinner` already knows when to stay hidden: not a TTY, `NO_COLOR` and the like.

## CONSTRAINTS
- Reuse the existing spinner and its TTY rules. Piped, JSON and MCP output must stay byte-identical to today.
- The wave must never be left on screen, or interleave with a printed line. It clears before the next write, including when an exception is raised.
- Keep the generic wrapper's behaviour unchanged for other commands. This adds an opt-in way to show the wave for a later silent phase, and uses it in cloud status.
- Keep the label short and soft, e.g. "reading sync state".
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run the spinner and cloud command tests.

## ACCEPTANCE
- Tests show:
  - on a TTY stub, the wave appears during the per-session scan after the header, and is cleared before the section prints;
  - without a TTY, output is unchanged and has no escape codes;
  - an exception during the scan leaves no wave on screen.
