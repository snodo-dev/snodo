Before starting, open a GitHub issue on snodo-dev/snodo titled "Recon has only whole-file read and one-level list; reuse the validator/coder read tools and repeat-read tracking". Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased].

INTENT
Recon's tool surface is two local functions in `packages/snodo-mcp/src/snodo/recon/__init__.py`:
- `read_file` returns the whole file, with no range and no line numbers.
- `list_files` lists a single directory level.

So agents spend their turns walking directories and re-reading whole files, and they can't cite line numbers. Evidence from rec_480b88: "I cannot give a verified line number — the read tool output did not include line numbers." In rec_00a4f8, two agents consumed about 135k cumulative input tokens.

The coder and validators already have better read-only tools through the workspace tools and the shared read tracker:
- ranged reads (`read_file_lines`);
- `search_string` and `search_symbol`;
- batched reads with a size cap;
- a repeat read that returns a pointer to the earlier turn instead of the content again.

Recon should reuse those existing tools rather than keep its own. It should not invent new ones.

When this is done:
- Recon agents get the existing read-only search and ranged-read tools, confined to the project root as today.
- Read results that recon agents see carry line numbers, so answers can cite file:line. Do not change what coders see.
- Repeat reads are deduplicated with the existing read tracker, and turns that only repeat reads do not use up the budget. This mirrors the validator's progress-aware accounting.

THE CHAIN
1. The recon agent's tool definitions and dispatch use the shared read-only workspace tools.
2. Recon's read output includes line numbers.
3. Repeat-read deduplication and progress-aware turn accounting work as in the validator.
4. Tests:
   - a recon agent can search and read a line range;
   - output carries line numbers;
   - a repeated read returns the pointer and does not consume a turn;
   - path traversal outside the project root is still rejected.

CONSTRAINTS
- Read-only. Recon must never get a write, run or shell tool.
- Don't change the coder's or validators' tool output.
- Snodo's state machine is closed: add no status, halt type, severity, audit event or result field.
- The recon budget config already exists from the previous wave (`llm.recon.max_tool_turns`). Keep using it.
- Do not change the final-answer extraction. The next task owns it.
