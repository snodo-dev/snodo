Before starting, open a GitHub issue on snodo-dev/snodo titled "Recon loses the answer when the final message has no content". Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased].

INTENT
When a recon agent's reading budget runs out, recon makes one more request without tools. It takes only `response.choices[0].message.content` as the answer. If that content is empty (a tool-call-only response, reasoning-only output, or a truncated response), the whole lane fails with "Agent returned empty result" and everything the agent learned is lost.

Evidence: rec_00a4f8. deepseek-v4-pro and qwen3.6-plus each failed this way after about 133k and 137k cumulative input tokens. Recon also never checks `finish_reason`, and it saves no trace, so it can't tell which case happened.

Validators already solve this. On the final turn they force a structured `submit_verdict` tool call with `tool_choice`, and tell the agent that a verdict on partial reading is still a real verdict. Recon should follow the same pattern.

When this is done:
- A recon agent delivers its answer through a structured submit-answer tool call, which is forced on the final turn.
- If the agent still returns nothing usable, recon falls back to the substantive prose the agent produced earlier in the run, and says plainly that it is a partial answer. It does not return an empty result.
- Truncation, meaning a `finish_reason` that shows the output was cut off, is detected and reported in the result's existing error or result text.
- Each recon result records a short trace in its existing result payload: the turns used, the tools called, and how the run ended. This makes failures diagnosable without guessing. Use existing fields where possible; if a new key in the stored recon result JSON is truly needed, say so in the commit message.

THE CHAIN
1. Recon's agent loop offers a submit-answer tool and forces it on the final turn, mirroring the validator's `submit_verdict` handling.
2. Empty-final-answer handling falls back to earlier substantive content, clearly marked as partial.
3. Truncation is detected through `finish_reason`.
4. The per-agent trace is stored with the recon results.
5. Tests:
   - a forced final turn returns the submitted answer;
   - a tool-call-only or empty final response falls back and does not fail;
   - a truncated final response is reported;
   - a normal prose answer still works.

CONSTRAINTS
- Snodo's state machine is closed: add no status, halt type, severity or audit event.
- Read-only. Keep the recon budget config and the shared read tools from the previous waves as they are.

ACCEPTANCE
- The tests in link 5 exist and pass.
- The CHANGELOG entry is present.
- `make gate` passes.
