# 1.3 — serve registry entries record their transport and the relay advertises only ws ones

GitHub issue #1015 already exists for this work. Do not open another; put "Fixes #1015" in the commit message. Do not edit the CHANGELOG (a later task in this plan owns the entry).

## INTENT

The serve registry (`packages/snodo-foundation/src/snodo/infrastructure/serve_registry.py`) records the `snodo serve` processes running on a machine: project, mode, port, tunnel hostname, process identity. The machine relay (`packages/snodo-foundation/src/snodo/infrastructure/cloud_relay.py`) reads it and announces to the cloud every entry that has a hostname and a port, always as an oauth endpoint. Entries carry no transport, so once ws serves and Cloudflare-tunnelled serves can coexist on one machine the relay would announce Cloudflare tunnels as relay endpoints and would forward requests to servers that the cloud reaches by another route.

## Outcome

- A registry entry can carry a transport (`cloudflare` or `ws`); entries written without one are read as `cloudflare`, and every existing field and the existing replace/prune/remove behaviour are unchanged.
- The record call takes the transport as an optional input defaulting to `cloudflare`, so the existing caller keeps working untouched.
- The relay announces and forwards only entries whose transport is `ws`. Cloudflare entries are ignored by it. The auth announced for a ws endpoint stays oauth for now.
- The relay's decision to stop on replacement (code 4001) and on terminal rejections, and everything else it does, is unchanged.

## Acceptance

- Tests: a ws entry round trips and an old entry reads as `cloudflare`; the relay announces a ws entry and does not announce a Cloudflare one; a mixed registry announces only the ws ones; forwarding to a Cloudflare-only hostname is not attempted.
- The existing registry and relay tests (`tests/infrastructure/test_serve_registry.py`, `the cloud relay tests under packages/snodo-foundation/tests`) stay green; the linter is clean; run the targeted tests and the linter, and do not run the whole suite yourself: the engine runs it right after you finish, and a multi-minute silent command has been dropping the coder connection.
