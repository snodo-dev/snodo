# Rust fixture smoke test fails on runners where cargo exists but has no toolchain

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
The compiled-language fixture smoke tests in `tests/coders/test_coders.py` run when a language toolchain is actually usable, and skip with a clear reason when it is not. A rustup shim with no default toolchain counts as not usable.

## THE CHAIN
- Evidence: CI run 38089625587 and release run 38089625681, on v0.23.0. Both fail `test_mock_adapter_compiled_language_fixture_smoke[rust-cargo]`. Running `cargo test` exits 1 with: "rustup could not choose a version of cargo to run, because one wasn't specified explicitly, and no default is configured."
- The test (around line 298) only checks `shutil.which(command)` before running the fixture. On GitHub's ubuntu-24.04 image, `cargo` is on PATH as a rustup proxy without a default toolchain.
- This failure, together with the spinner tests, has kept the release workflow from publishing v0.21.0 to v0.23.0 to PyPI.

## CONSTRAINTS
- Test-only change: before running the fixture, check that the toolchain actually works (for example, that the command's `--version` exits 0) and skip otherwise. Apply the check to every compiled language in that parametrisation, so Go or others can't hit the same trap. Do not install toolchains in CI.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` on touched files. Run only the targeted test: `uv run pytest tests/coders/test_coders.py -k compiled_language`.

## ACCEPTANCE
- With a working toolchain, the rust fixture still runs and passes.
- When the toolchain probe fails, the test is skipped with a reason that names the command, and the run does not fail.
- There is a CHANGELOG entry under ## [Unreleased].
