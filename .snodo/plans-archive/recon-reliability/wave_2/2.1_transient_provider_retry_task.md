Before starting, open a GitHub issue on snodo-dev/snodo titled "Recon: retry transient provider errors once before failing an agent". Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased].

INTENT
Two recon agents failed tonight on errors that were transient:
- gemini returned a 429 RESOURCE_EXHAUSTED (input tokens per minute) with an explicit RetryInfo of "retryDelay": "52s" (rec_882740). The agent failed at once.
- deepseek (ollama-cloud) returned `litellm.BadRequestError: OpenAIException - failed to read request body` after 17 seconds (rec_6d6228). This is a transport-level hiccup on the provider side, not a malformed request from us.

Each recon result already lists `attempts` and a `failover` map, so retry and failover vocabulary exists. In both cases the agent was reported failed after a single attempt.

When this is done, a transient provider error is retried once before the agent is marked failed. Transient means a rate limit or quota-per-minute 429, a 5xx, a dropped connection, or a request-body read failure. The retry honours the provider's suggested delay when one is given (capped at a sensible maximum), and backs off briefly otherwise. Each attempt shows in `attempts`. Permanent errors fail immediately as today: bad credentials, an unknown model, a context-length error.

THE CHAIN
1. Classify provider errors as transient or permanent in one place, reusing any classification the coder or validator paths already have.
2. Recon agents retry a transient error once, using the suggested delay when present.
3. Tests:
   - a 429 carrying a retry delay is retried once after that delay, scaled down in tests;
   - "failed to read request body" is retried once;
   - an authentication error is not retried;
   - each attempt is recorded in `attempts`.

CONSTRAINTS
- Snodo's state machine is closed: add no status, severity, halt type or audit event, and no new result field. `attempts` already exists.
- Never log API keys or request headers.
- No file may exceed its file-length limit or baseline.

ACCEPTANCE
- The tests in link 3 exist and pass.
- The CHANGELOG entry is present.
- `make gate` passes, including lint and the file-length check.
