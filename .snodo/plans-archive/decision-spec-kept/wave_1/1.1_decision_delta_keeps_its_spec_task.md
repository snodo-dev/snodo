# A session decision event keeps the changed task's spec text

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
A recent change stopped `session_decision_updated` audit events from re-sending a session's whole per-task map (halt, task failure, classification) on every update. That change keeps the audit log from growing quadratically. It also removed task spec text from the changed entry. Cloud sync ships these events, and the cloud needs the spec text for halted and failed tasks: those never reach `task_merged`, which is the other event that carries a spec.

The changed task's entry should carry its spec text again, exactly as the full map used to carry it for that task. Only the delta is sent, so an event holds one task's spec, never every task's. The change stops at that: the event stays a delta, and coder output stays out of it, as before.

## THE CHAIN
- `packages/snodo-foundation/src/snodo/infrastructure/session.py` audits decision updates. It now records only the changed entries, and runs them through a helper that strips spec-text keys before auditing. Spec text should come back; the delta behaviour stays.
- `packages/snodo-engine/src/snodo/engine/nodes/writeback.py` builds the halt and failure entries, including the task spec. It already strips coder output from the halt payload.
- Tests added by that change assert that no spec text is present. Update them to assert the spec is present for the changed entry only, and that other tasks' specs are absent.
- Cloud sync's ingest contract in `packages/snodo-foundation/src/snodo/infrastructure/cloud_sync.py` lists key and value for this event. It is unchanged.

## CONSTRAINTS
- The event stays a delta. The session checkpoint file is unchanged.
- Coder output stays out, as today.
- No new audit event, status, severity or halt type.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run the session, write-back and decision-handler tests.

## ACCEPTANCE
- Tests show:
  - a halt decision event carries the changed task's spec text;
  - it carries no other task's entry or spec;
  - event size stays flat as the number of tasks in a session grows;
  - merging the audited values in order reproduces the checkpoint's map, specs included.
