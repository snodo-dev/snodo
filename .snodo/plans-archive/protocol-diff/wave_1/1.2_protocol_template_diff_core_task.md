# Nothing can say how a project protocol differs from its template

Before any change, open a GitHub issue in snodo-dev/snodo describing the gap. Write the issue body to a file under /tmp and pass it with `--body-file`; never pass text containing backticks or `$(` in an inline shell string. Put "Fixes #<issue number>" in the commit message, and add a CHANGELOG entry under ## [Unreleased].

## INTENT
A pure, tested function takes two loaded protocols (the project's and a template) and returns a structured difference that a CLI or report can render:
- validators present only in the template, and only in the project;
- validators in both but changed: type, evaluation phase, criteria, tools, severity cap, scope;
- modes added or removed, and per mode, changed tools, validators, transitions and delivery;
- changed protocol-level settings: execution and delivery, initial mode, disagreement policy, protected paths, write-allowed prefixes, global constraints.

## THE CHAIN
Facts from recons rec_c33098 and rec_1c9eb8:
- The model fields are Protocol (packages/snodo-foundation/src/snodo/compiler/models.py:417-475), Mode (350-399) and Validator (157-223).
- The only existing comparison is `missing_template_validators()` (packages/snodo-foundation/src/snodo/protocols/__init__.py:147-174). It covers template-only validators, matched by `protocol_id`.
- Shipped templates are listed by `list_templates()` in the same package.

## CONSTRAINTS
- Compare loaded models, not raw text, so formatting and comments don't count as differences. Order-insensitive lists, such as tools, compare as sets.
- `tooling.test_command` differences, which init injects, are reported in a separate "project-local" group, so they don't read as drift.
- Pure function in a new module of its own. No CLI, no file IO beyond what the callers pass in, and no changes to init. Another task, in the same wave, adds template provenance to init.
- No new status, severity, halt type or audit event.
- Do not run the `snodo` CLI or `python -m snodo` in the worktree, and do not create, change or delete anything under `.snodo/`.
- Run only the new tests, not `make gate`.

## ACCEPTANCE
- Unit tests cover:
  - identical protocols giving an empty diff;
  - each difference category, using small synthetic protocols;
  - every shipped template diffed against itself giving empty;
  - a test-command-only change landing in the project-local group.
- There is a CHANGELOG entry under ## [Unreleased].
