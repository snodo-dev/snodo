# No command shows a project's drift from its template

Before any change, open a GitHub issue in snodo-dev/snodo describing the gap. Write the issue body to a file under /tmp and pass it with `--body-file`; never pass text containing backticks or `$(` in an inline shell string. Put "Fixes #<issue number>" in the commit message, and add a CHANGELOG entry under ## [Unreleased].

## INTENT
A user runs one command under the existing `snodo protocol` group and sees how their protocol differs from the shipped template it came from:
- what the template has that they don't;
- what they've changed or added;
- the project-local settings, shown separately.

It has human-readable and JSON output, and a clear message for bespoke protocols that match no template. An option lets the user compare against a named template instead.

## THE CHAIN
- This repo has a helper that resolves a protocol's template (from its metadata, then from `protocol_id`), and a pure function that diffs two loaded protocols. Find them and use them; don't reimplement.
- The `snodo protocol` group already exists (`protocol validate`). Find its command module and add a subcommand there.
- docs/evolving-the-protocol.md explains how templates and project protocols relate.

## CONSTRAINTS
- A subcommand of `snodo protocol`, not a new top-level command.
- Read-only. It never writes protocol.yml, and the output must say how to adopt a change, e.g. by editing the file or with `snodo init --force`, without doing it.
- Exit code 0 when there's no drift. Use a documented non-zero code when there is drift, so CI can use it, consistent with how other snodo check commands signal.
- Document it in docs/evolving-the-protocol.md and in the `protocol` section of docs/command-reference.md.
- Don't touch ready_cmd.py or run_cmd.py; another task owns them.
- Do not run the `snodo` CLI or `python -m snodo` in the worktree. Use CliRunner and tmp_path projects. Do not create, change or delete anything under `.snodo/`.
- Run only the protocol command tests and the docs build, not `make gate`.

## ACCEPTANCE
- CLI tests cover: no drift, drift in each group, a bespoke protocol, a named-template override, the JSON shape and exit codes.
- The strict docs build passes.
- There is a CHANGELOG entry under ## [Unreleased].
