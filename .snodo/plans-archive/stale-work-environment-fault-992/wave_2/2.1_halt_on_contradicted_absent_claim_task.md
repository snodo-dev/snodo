# Halt as an environment fault when the coder's "absent" claim is contradicted (Fixes #992)

GitHub issue #992 already tracks this work. Put "Fixes #992" in the commit message.

## INTENT
When a coder returns with no changes, the engine checks the task branch for an earlier attempt's commits and, finding them, prints "Work already present on the task branch … Validating the existing work" and validates that older work. That is right when the coder looked and chose to change nothing. It is wrong when the coder's report says the subject files are absent, because the work is on the branch the coder was dispatched to. The two cannot both be true, and validating stale work turns a dispatch fault into a confusing test failure.

## THE CHAIN
1. Wave 1 added a detector that reports which explicitly named paths the coder called absent but that exist at the dispatched workspace's HEAD, and made sure an environment halt does not consume an attempt.
2. In the post-execution path, where the engine decides what to do about a run with no diff, consult that detector before falling back to the "work already present" validation.
3. When it reports a contradiction, halt with the existing environment-fault halt type. The halt names the workspace, the branch and HEAD, the contradicted paths, and the fact that they are present at that HEAD. It follows the way the existing environment faults report their next action (retry after fixing the environment, not after rewriting the spec) and stays adjudicable like other halts: it carries the artifacts and the reason.
4. Validators do not run against the stale work in that case, and the attempt is not spent.
5. When the detector reports nothing, the existing fallback is unchanged.

## CONSTRAINTS
- Do not add a status, severity, halt type or audit event; reuse the existing environment-fault halt type.
- Do not change the retry-budget rules for genuine coder failures or the spec-replacement reset.
- No new third-party dependency.
- Add one entry under [Unreleased] in CHANGELOG.md in the repo's existing style, referencing "Fixes #992". Soft wording. This is the only ticket in the plan that edits it.
- Targeted tests only.

## ACCEPTANCE
- Coder reports a named subject file as absent while the workspace HEAD contains it: the run halts with the environment-fault type, the payload names the path and the HEAD, and no validators run on the stale work.
- Coder reports nothing to change with no contradiction: the existing "validate the prior attempt's work" path still runs unchanged.
- The environment halt leaves the attempt count unchanged.
- Targeted tests pass and lint is clean for the whole tree.
