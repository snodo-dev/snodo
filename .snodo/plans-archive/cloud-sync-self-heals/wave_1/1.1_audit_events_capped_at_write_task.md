# Audit events can grow too large for the cloud to store

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Every audit event snodo writes fits comfortably within what the cloud ingest accepts, so a single event can never be refused for size. Oversized content is trimmed when the event is written, before its hash is computed, so the local hash chain stays valid and the trimmed event is exactly what gets synced.

## THE CHAIN
- Evidence: one session's cloud sync stalled with about 1456 unsent events after the server refused a single event as too large (HTTP 413). Recon rec_45af18 traced this.
- Sync batches are capped at 50 events and about 4.75 MB (`_DEFAULT_PAYLOAD_LIMIT` minus `_PAYLOAD_MARGIN` in `packages/snodo-foundation/src/snodo/infrastructure/cloud_sync.py`, around lines 63–66). A single event over the server's limit becomes a terminal refusal (around lines 915–931).
- Events that carry large free text include `spec_replaced` (full `previous_spec` and `new_spec`, in `packages/snodo-mcp/src/snodo/mcp/server.py` around lines 946–951) and `verification_executed` (`command` plus `output_tail`, in `packages/snodo-engine/src/snodo/validators/quality.py` around lines 286–296).
- Audit events are appended in `packages/snodo-foundation/src/snodo/infrastructure/audit.py`.

## CONSTRAINTS
- Apply the cap centrally, where events are appended, so every event type benefits. Trim long string fields, deepest or largest first, until the serialised event is under a fixed budget well below the sync byte limit (for example 256 KB). Each trimmed field gets a visible marker saying how many bytes were removed.
- The hash and sequence are computed on the trimmed event, so chain verification keeps passing.
- Small events are byte-identical to today.
- No new status, severity, halt type or audit event type.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo. Tests use temporary audit logs.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the targeted audit and cloud-sync tests.

## ACCEPTANCE
- Tests show:
  - an event with a multi-megabyte field is stored under the budget with a truncation marker;
  - the chain verifies after it;
  - a small event is unchanged;
  - a batch built from capped events never hits the single-event limit.
- There is a CHANGELOG entry under ## [Unreleased].
