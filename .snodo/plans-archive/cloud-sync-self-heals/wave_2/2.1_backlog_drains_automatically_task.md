# Old sessions' unsent events never drain without a manual command

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
When cloud sync is enabled, unsent events in any of the project's sessions catch up on their own. The current session doesn't have to be the one with the backlog, and the user doesn't have to run `snodo cloud sync --all`. This happens in the background, in bounded batches, without slowing tasks or server startup.

## THE CHAIN
- Recon rec_45af18: the only automatic sync is `sync_if_enabled` (`packages/snodo-foundation/src/snodo/infrastructure/cloud_sync.py`, around lines 1254–1314). It is called from the running task's `finally` (`snodo/cli/commands/run_cmd.py`, around lines 1077–1083) and syncs only that session.
- An older, inactive session's backlog therefore never drains. One session of the maintainer's had about 1456 unsent events, drained only by a manual forced sync.
- Wave 1 of this plan capped event size at write time, made a single-event size gap non-blocking for automatic sync, and surfaced stuck sessions in `ready` and at serve startup.

## CONSTRAINTS
- After the per-task sync, and at `snodo serve` startup, also sync other sessions of this project that have unsent events, using the normal non-forced path. Sessions with a real terminal refusal are skipped.
- Keep it bounded: a cap per call (for example a few batches, or a few seconds), oldest backlog first, in the background or within the existing bounded wait. Never delay task completion or server readiness noticeably.
- Respect the locking added for sync state (#hardening task 1.5): concurrent drains must never move a cursor backwards.
- No new status, severity, halt type or audit event, and no change to what is sent.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo. Tests use temporary state and a mocked server.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the targeted cloud-sync, run and serve tests.

## ACCEPTANCE
- With a mocked server, tests show:
  - after a task in session B finishes, unsent events of an older session A are delivered in bounded batches;
  - serve startup triggers the same drain;
  - a session with a terminal refusal is skipped;
  - the drain's time bound is respected.
