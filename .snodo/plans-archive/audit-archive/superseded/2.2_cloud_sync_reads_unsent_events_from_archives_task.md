# Cloud sync still delivers unsent events that were archived

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Cloud sync delivers audit events after a per-session cursor, which is a sequence number. Today it selects them from the events the audit log loaded into memory. Once the log is archived weekly or by size, opening it loads only the current file. Unsent events with sequence numbers past the cursor may then sit in an archive, for example a machine that was offline for a week, and today they would never be sent. Sync, and the unsent counts shown by `snodo cloud status`, should read events past the cursor across the archives plus the current file. They should use the archive-aware history walk added earlier in this plan and stream it, reading archives only when the cursor is older than the current file's first event.

## THE CHAIN
- `packages/snodo-foundation/src/snodo/infrastructure/cloud_sync.py`: the dispatcher selects events with a sequence above the stored cursor, and the cursor is persisted per session in the sync state.
- `snodo/cli/commands/cloud_status.py` computes unsent counts from the loaded events. `snodo/cli/commands/cloud_cmd.py` runs `snodo cloud sync`.
- The history walk in `packages/snodo-foundation/src/snodo/infrastructure/audit.py`, from task 1.1. This task may build on task 1.1's branch.
- Cloud sync tests and cloud CLI tests live under `tests/infrastructure/` and `tests/cli/`.

## CONSTRAINTS
- The cursor stays a sequence number, and its semantics are unchanged. With no archives, the delivered events and the counts are identical to today.
- Do not read archives when the cursor already covers them.
- No new audit event, status, severity or halt type, and no change to the cloud ingest contract.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run the cloud sync and cloud command tests.

## ACCEPTANCE
- Tests show:
  - with a cursor that points into an archive, sync sends the archived unsent events and then the current ones, in order;
  - with a cursor inside the current file, no archive is opened;
  - unsent counts include archived unsent events;
  - nothing changes when there are no archives.
