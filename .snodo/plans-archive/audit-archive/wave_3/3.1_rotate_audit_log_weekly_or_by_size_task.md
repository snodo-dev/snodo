# The audit log is archived weekly or when it gets large

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Project audit logs have reached 0.6–2.6 GB, and every process that opens one pays for its whole size. Earlier tasks in this plan made the chain, `snodo audit verify`, cloud sync, job notifications and the history readers archive-aware. This task switches archiving on.

When the current `audit.log`'s oldest event is more than 7 days old, or the file is larger than 256 MB, it is moved to a sibling archive named by the ISO year and week of its oldest event, for example `audit.log.2026-w41`. A further rotation in the same week gets a numeric suffix (`.2`, `.3`). The next event starts a fresh `audit.log` that continues the chain, as the earlier task defined.

The check is cheap: the file size plus the first line's timestamp. It happens under the same exclusive lock that appends use, so concurrent writers never interleave a rotation with an append. An existing oversized log is archived on its first open after upgrade, so the projects with GB-sized logs get relief straight away.

## THE CHAIN
- `packages/snodo-foundation/src/snodo/infrastructure/audit.py` already takes an exclusive file lock to append, and after task 1.1 it understands archives when loading, appending and verifying.
- Other processes may hold the log open. After a rotation their next append must chain from the archive tail, which the earlier task covers. They must not write into the moved file.
- The audit tests live under `tests/infrastructure/`.

## CONSTRAINTS
- Rotation never drops, rewrites or reorders an event. The archive is the same bytes, moved.
- The thresholds are 7 days and 256 MB, kept as named module-level defaults. No new config key.
- If rotation fails (for example, the move is not permitted), log a warning and keep appending to the current file, as today.
- No new audit event, status, severity or halt type.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run the audit tests.

## ACCEPTANCE
- Tests show:
  - a log whose oldest event is 8 days old is archived on the next append, with the week-based name, and the chain verifies across the boundary;
  - a log over the size limit is archived;
  - a second rotation in the same week gets a suffix;
  - two concurrent appenders across a rotation produce one unbroken chain;
  - a failed move leaves logging working.
