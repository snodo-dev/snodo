## INTENT
Cloud sync delivers audit events after a per-session cursor, which is a sequence number. Today it selects them from the events the audit log loaded into memory. Once the log is archived weekly or by size, opening it loads only the current file. Unsent events with sequence numbers past the cursor may then sit in an archive, for example a machine that was offline for a week, and would never be sent. Sync, and the unsent counts shown by `snodo cloud status`, should read events past the cursor across the archives plus the current file. They should stream them through the archive-aware history walk added earlier in this plan, reading archives only when the cursor is older than the current file's first event.

An earlier attempt at this (task 2.2 of this plan; this task may build on its branch) did the work, but pushed `cloud_sync.py` to 1002 lines. The repository's file-length check allows 1000, and a file that crosses it must be split rather than baselined. Put the "which events are unsent, across archives" logic in its own small module next to `cloud_sync.py`, so the sync module stays under the limit. Ideally it ends up shorter than it was.

## THE CHAIN
- `packages/snodo-foundation/src/snodo/infrastructure/cloud_sync.py` is at about 1000 lines of code. Its dispatcher selects events with a sequence above the stored cursor, and the cursor is persisted per session in the sync state.
- `snodo/cli/commands/cloud_status.py` computes unsent counts from the loaded events. `snodo/cli/commands/cloud_cmd.py` runs `snodo cloud sync`.
- The history walk in `packages/snodo-foundation/src/snodo/infrastructure/audit.py`, from task 1.1 of this plan.
- The file-length check is `scripts/enforce_file_length.py`, with its baseline. Do not add files to the baseline.
- Cloud sync and cloud CLI tests live under `tests/infrastructure/` and `tests/cli/`. The import-linter contracts in `pyproject.toml` apply to the new module.

## CONSTRAINTS
- The cursor stays a sequence number, and its semantics are unchanged. With no archives, the delivered events and the counts are identical to today.
- Do not read archives when the cursor already covers them.
- `cloud_sync.py` ends at or below its current length, and the new module is well under the limit.
- No new audit event, status, severity or halt type, and no change to the cloud ingest contract.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, `uv run python scripts/enforce_file_length.py`, `uv run lint-imports`, and the cloud sync and cloud command tests.

## ACCEPTANCE
- Tests show:
  - with a cursor that points into an archive, sync sends the archived unsent events and then the current ones, in order;
  - with a cursor inside the current file, no archive is opened;
  - unsent counts include archived unsent events;
  - nothing changes when there are no archives.
- The file-length check passes with no baseline change.
