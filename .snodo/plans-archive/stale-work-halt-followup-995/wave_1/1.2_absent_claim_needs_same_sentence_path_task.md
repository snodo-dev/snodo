# Absent-claim detector: the path and the absence wording must share a sentence (Fixes #995)

GitHub issue #995 already tracks this work. Put "Fixes #995" in the commit message.

## INTENT
The detector that spots a coder claiming a file is absent looks for absence wording ("missing", "does not exist", "absent" and similar) and collects any file path within a fixed number of characters around it. That is looser than intended: a report such as "the function is missing a docstring in `x.py`" names a file that exists, and the detector would read it as a claim that `x.py` is absent. A false positive halts a legitimate attempt as an environment fault, which is worse than a miss.

## THE CHAIN
1. The absence wording and the path must belong to the same sentence (or the same short clause). A path in a neighbouring sentence is not a claim about that path.
2. Within that sentence the path should read as the subject of the absence: "`x.py` is missing", "`x.py` does not exist", "cannot find `x.py`", "missing file `x.py`". Wording where the absence concerns something else in the sentence ("missing a docstring in `x.py`", "`x.py` has a missing import") does not count.
3. Everything the detector already does stays: paths are checked against the workspace HEAD, not the project root; absolute or parent-escaping paths are ignored; failures to read the repository return nothing.

## CONSTRAINTS
- Conservative on purpose: when in doubt, return nothing.
- Keep the change inside the detector and its tests.
- Do not add a status, severity, halt type or audit event.
- No new third-party dependency.
- Do not touch CHANGELOG.md.
- Targeted tests only.

## ACCEPTANCE
- "`subject.py` is missing" and "I cannot find `subject.py`" still yield the path when it exists at HEAD.
- "the function is missing a docstring in `subject.py`" and a path mentioned only in the sentence before or after the absence wording yield nothing.
- Existing detector tests pass unchanged.
- Lint is clean for the whole tree.
