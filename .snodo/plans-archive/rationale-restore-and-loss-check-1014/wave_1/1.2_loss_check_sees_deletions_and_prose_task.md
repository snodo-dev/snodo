# 1.2 — the coverage-loss check must see deleted files and docstring prose

GitHub issue #1014 already exists for this work. Do not open another; put "Fixes #1014" in the commit message.

## INTENT

The check delivered for #959 (`packages/snodo-engine/src/snodo/validators/coverage_accountability.py`)
is meant to make the operator aware when a task removes existing test cases or strips explanatory
text. Reviewing it against the two incidents that motivated #959 found two gaps that let the same
failure through.

## Evidence

```text
1. Only files that still exist after the change are examined. A task that deletes a whole test
   file, or renames one, loses every case in it and produces no finding.
2. The explanation count only recognises lines that start with a comment marker or that open a
   docstring. Docstring prose (the lines between the quotes) is not counted, yet one of the
   incidents was a deletion of roughly 350 lines of docstring prose; that case would not fire.
```

## Outcome

- A test case that disappears because its whole file was deleted, or because the file was renamed
  and the case did not come along under the new name, is surfaced like any other disappeared case:
  a finding naming the file and the case, unless the task's specification asked for it.
- The explanation measure counts comment lines and docstring prose lines, so stripping docstring
  bodies from a file the task had no reason to shorten produces the finding, and a task that only
  rewrites code while keeping its comments and docstrings produces none.
- Findings stay visibility, not a veto: no halt type, no new status or severity, same place the
  other post-execute findings appear. It must also be visible on a delivery that otherwise passes,
  so the operator sees it without reading logs; confirm where a passing delivery's findings are
  shown and make sure these appear there.

## Acceptance

- Tests: a deleted test file with cases produces a finding naming file and case; the same deletion
  asked for in the specification produces none; a renamed file that keeps its cases produces none;
  a file with docstring prose stripped (code unchanged) produces a finding; a file whose comments
  and docstrings are kept produces none.
- The new tests open repositories only through the project's sanctioned repository opener and leave
  no child processes behind: run `tests/validators` together with
  `tests/engine/test_post_validate_recovery.py` in one pytest invocation, and the linter.
- Add one CHANGELOG entry under [Unreleased] (soft wording, "(Fixes #1014)").

## Constraints

- No new dependency and no running tests at the base revision.
- Do not change what the length ratchet counts.
- Keep the change block bounded as it is today.
