# Retire the stale payload field and document the attempt-summary contract

GitHub issue #968 already exists for this work. Do not open another; put "Fixes #968" in the commit message. The CHANGELOG entry is written once, by the last task in this plan (2.1); other tasks do not edit it.

## Why this task exists

Two loose ends from the work that landed #931, both raised by the fix-forward
review in issue #968.

1. **A field the governance already removed.** ADR 043 was superseded by ADR 045,
   which states that the `non_verdicts` count was removed along with the
   abstention state. The closure driver's fallback payload still writes it, so the
   machine-readable halt account still carries a key whose meaning no longer
   exists. Readers of halt payloads — the CLI, the orchestrator, snodo cloud —
   see a count that can never be anything but zero.
2. **A contract nobody wrote down.** The attempt summary now excludes pre-execute
   refusals: a refusal before a dispatch must not append a fictional code state or
   shift the attempt numbering that recovery history relies on. That behaviour is
   the ADR 045 contract, and it is not stated anywhere a reader of the payload
   would find it.

## What "done" means

The fallback payload stops advertising a removed concept, and the attempt-summary
rule is written where the payload contract lives, with a test that fails if the
rule is broken.

## Acceptance criteria

1. No halt or fallback payload emits `non_verdicts`; the removal is confined to
   that stale key and does not disturb any other field in the payload.
2. A test asserts the fallback payload's keys, so a reintroduced field fails the
   gate.
3. The decision record that defines the attempt summary explains that a pre-execute
   refusal is not counted as an attempt and does not append a code state, and says
   why recovery numbering depends on it.
4. A test covers both shapes: an attempt that was refused before dispatch, and an
   attempt that dispatched and then failed — the first must not appear in the
   history the recovery spec is built from, the second must.
5. The full gate passes.

## Constraints

- Do not change what the halt payload means for any other field, and do not add a
  replacement count.
- No new halt types, severities, validator kinds, or statuses.
- Amend the existing decision record rather than writing a new one, and keep its
  status and supersession lines intact.
- Do not edit the CHANGELOG; the last task in this plan owns the entry.
- Either the gate passes and you submit, or it does not and you fix it. Do not
  leave notes about validation anywhere in the tree.
