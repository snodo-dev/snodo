## INTENT
Users configure gateway providers as custom blocks in `~/.snodo/config.yml`, with a base URL, a credential and one `litellm_provider` (usually `openai`). Some gateways serve different model families over different API formats behind one key and one host. OpenCode Go (configured by users as "ocgo") puts DeepSeek, GLM, Kimi and MiMo on its OpenAI-compatible chat-completions endpoint, and Claude models (and, per its docs, MiniMax and Qwen) on its Anthropic-compatible messages endpoint. Today every model in a block goes through the block's single route, so a Claude model on "ocgo" is sent in OpenAI format and the gateway refuses it: "Model does not support this protocol".

A provider block should be able to say "models whose id matches this go over that LiteLLM route", for example claude-* over anthropic. Those models then reach the gateway in the right format, with the same credential and the matching base URL. Everything else in the block keeps the block's default route.

The earlier attempt at this (task 1.1 of this plan; this task may build on its branch) implemented the feature, but broke an existing test. The recon model-routing test resolves models with a stand-in provider object that has no field for the new setting, and failed with "'Provider' object has no attribute 'model_routes'". Resolution has to treat the new setting as optional wherever a provider object comes from: config, defaults, or test doubles. Any provider without it must resolve exactly as before.

## THE CHAIN
- The user-config provider model is in `packages/snodo-core/src/snodo/config.py`, with the strict schema in `packages/snodo-core/src/snodo/config_validation.py`. ConfigManager resolves the LiteLLM route, model string and base URL. Validators, the litellm coder, the classifier, recon, `snodo models --check` and `snodo models --benchmark` resolve through it.
- `tests/recon/test_recon.py` is the routing test that failed with the earlier attempt. Other tests build provider objects too; search for them.
- An Anthropic-format client builds its own request path, so a base URL ending in the OpenAI-style `/v1` may need adjusting for the Anthropic route. Make it work for `https://opencode.ai/zen/go/v1`, with or without the suffix.
- Configuration docs: `docs/configuration.md`. The project keeps two strict user-config schemas in step; check `snodo/` for the second one.
