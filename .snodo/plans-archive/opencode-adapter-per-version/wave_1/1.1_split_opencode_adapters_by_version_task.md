# Split the opencode-cli adapter by CLI major version (Fixes #982)

## INTENT
OpenCode 1.x and 2.x take different `run` flags. Today one adapter carries both launch shapes behind a version branch, and a change aimed at one major has already leaked into the other (the 2.x launch regained a directory flag that 2.x does not accept, which broke every 2.x run). The adapter used for a run should be chosen from the installed CLI's major version, with one small adapter per major that owns that major's launch shape and nothing else's. A reader of either adapter should be able to see its full contract in one place.

## THE CHAIN
1. The user's model id keeps its `opencode-cli/` prefix and the registered coder name stays `opencode-cli`. Nothing the user configures changes.
2. When the coder is resolved for a run, the installed OpenCode binary's version is read the way the existing adapter already reads it, and the major selects which per-version adapter handles launch.
3. The 1.x adapter launches exactly as the current 1.x branch does today (directory flag, skip-permissions flag, the same environment and permission config).
4. The 2.x adapter launches exactly as the current 2.x branch on main does today: no directory flag, the process working directory is the pin, auto-approve flag instead of skip-permissions. Shared behaviour that is genuinely version-independent (output parsing, model argument, environment construction, result handling) lives once in a common base rather than being copied.
5. If the installed major is not one the adapters describe, the run is refused up front with a clear, soft message that names the detected version and the majors snodo supports. It must not silently fall back to the nearest shape.
6. If the version cannot be read at all, behaviour stays as it is today for that case (assume the oldest supported major), so existing environments do not regress.

## CONSTRAINTS
- Do not change what any existing launch sends on either major. This is a structural split; argv for 1.x and 2.x must come out identical to main before this change.
- Do not add a status, severity, halt type or audit event. Refusal for an unsupported major uses the existing coder-unavailable / launch-failure path.
- No new third-party dependency.
- Keep the registry key `opencode-cli` and the model-prefix mapping untouched.
- Add one entry under [Unreleased] in CHANGELOG.md in the repo's existing style, referencing "Fixes #982". Soft wording.
- Update the existing opencode adapter tests so they exercise each major's adapter; do not weaken or delete assertions about argv, environment or permissions.

## ACCEPTANCE
- With a faked 1.x version, the launch argv and environment equal the pre-change 1.x launch.
- With a faked 2.x version, the launch argv and environment equal the pre-change 2.x launch, and the argv contains no directory flag and no skip-permissions flag.
- With a faked 3.x (or any undescribed major) the run is refused with a message naming the version and the supported majors; no process is spawned.
- With an unreadable version the 1.x adapter is used.
- The registered name and model-prefix resolution still map to the same coder.
- Targeted coder tests pass.
