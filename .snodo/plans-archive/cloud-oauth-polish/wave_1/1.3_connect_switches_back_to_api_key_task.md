INTENT
After `snodo cloud login`, the CLI says "OAuth now takes priority. Run `snodo cloud connect <api_key>` to switch back." That is not true today: cloud_connect_command in snodo/cli/commands/cloud_cmd.py only stores the API key and leaves the OAuth login in place, so OAuth keeps winning. Connecting with an API key should really switch the machine to the API key.

Indications: when `snodo cloud connect` succeeds, clear any OAuth login from the store and revoke its refresh token when the server metadata lists a revocation endpoint, reusing whatever `snodo cloud logout` already does rather than duplicating it; a failed or missing revocation never blocks the switch, and the output says so plainly. Also re-read the success message printed by `snodo cloud login` ("Signed in to snodo cloud; audit sync enabled." and the switch-back hint) against the merged behaviour and correct anything that is not accurate. Keep `connect` behaviour for machines with no OAuth login unchanged. Update the command reference if the wording of connect changes.

Acceptance: tests cover connect clearing an existing OAuth login (with revocation attempted and with revocation failing), connect on a machine without an OAuth login unchanged, and `snodo cloud status` reporting the API key as the method in use after connect. CHANGELOG.md updated.
