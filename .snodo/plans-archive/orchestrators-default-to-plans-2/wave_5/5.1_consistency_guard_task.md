INTENT
Earlier tasks reworded the orchestrator-facing guidance so plans are the default unit of work. That guidance covers the MCP connect-time instructions, the guide tool's default answer and topics, the README and the MCP self-description spec. The canonical rule is:

"Group work into plans. A plan is one clear intention. Waves group its tasks: tasks in a wave run in parallel, and waves run in series. Queues group and schedule plans. Dispatch a single task only for a true one-off with no related work. A plan with one task in one wave adds nothing."

These surfaces drifted apart before, and agents kept defaulting to single tasks. Add a regression guard so they stay consistent.

Evidence from a first attempt: a guard that searched for the rule as a literal substring on every surface failed on five of them. Two causes:
- The markdown docs hard-wrap lines, so sentences span line breaks.
- Some surfaces (the guide default answer and the `mistakes` and `planning` topics) only point at the rule. They don't restate it in full, and that is intended.

How the guard checks this is your call. It should catch real drift, such as the old "smallest structure" wording coming back or a surface dropping the rule. It should not fail on formatting or on surfaces that only reference the rule.

THE CHAIN
1. A new regression test under `tests/mcp/` guards that the orchestrator-facing surfaces agree that plans are the default, and that the old smallest-structure wording is gone.
2. `README.md` and `docs/specs/mcp-self-description.md` state the rule in full. Their earlier task required this. If either still doesn't, fix it.
3. `CHANGELOG.md`, under `## [Unreleased]`: an entry for #726.

CONSTRAINTS

- Do not reword the connect-time instructions or guide topics. If one of them still carries the old smallest-structure wording, an earlier task did not land, so stop and report it.
