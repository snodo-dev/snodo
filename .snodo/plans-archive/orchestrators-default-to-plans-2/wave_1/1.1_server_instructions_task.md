INTENT
Orchestrating agents read the MCP server's connect-time instructions and the `guide` tool's default (no-topic) answer first. Today both steer them to single tasks:
- The instructions say "Choose the smallest structure that fits: dispatch one task directly; … use a plan only for multiple waves…".
- The guide default points at "the `waves` topic for the smallest-structure rule".

The owner's model is that plans are the default unit of work. When this task is done, both surfaces teach that model with this canonical rule, verbatim:

"Group work into plans. A plan is one clear intention. Waves group its tasks: tasks in a wave run in parallel, and waves run in series. Queues group and schedule plans. Dispatch a single task only for a true one-off with no related work. A plan with one task in one wave adds nothing."

The existing true statements stay: a plan adds plan→wave→task history for cloud reporting, does not add a human authorization gate, and does not change the validator loop or auto-merge policy.
