## INTENT
A team that runs `snodo init` and picks the `docs` template gets a protocol for technical writer work. The coder produces guides, reference pages and runbooks as Markdown files in the project's existing docs tree. Role-specific validators judge each diff, and verified work is delivered as a change request, so a person signs off before it merges.

## THE CHAIN
- Every `*.yml` in `packages/snodo-foundation/src/snodo/protocols/templates/` is auto-discovered as a template. The product and design templates are already there, added by an earlier wave; use them as the closest reference.
- The default delivery is read from the template: `_configure_delivery` in `snodo/cli/commands/init_cmd.py` looks at the producer mode's `delivery`, the top-level `delivery`, or `execution.delivery`.
- `schemas/protocol-v1.json` lists every template name under `x-snodo-choices` → `templates`, and `tests/scripts/test_protocol_schema_publication.py` pins it. A new template fails the gate until the schema is regenerated.
