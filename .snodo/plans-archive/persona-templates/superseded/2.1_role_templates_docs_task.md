# Document the product, design, docs and research templates

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Someone who isn't an engineer, such as a PM, a designer, a technical writer or an analyst, can find out from the docs that snodo has a template for their work. The docs explain what that template produces, how its work is judged, and how they sign it off. Every place that lists templates now includes the four new ones.

## THE CHAIN
- Wave 1 added four role templates, `product`, `design`, `docs` and `research`, in `packages/snodo-foundation/src/snodo/protocols/templates/`. Read them for the facts.
- Each one produces Markdown deliverables in the repo and is judged by role-specific LLM validators plus `acceptance` and `protocol`. Its `quality` step is a docs check, and its default delivery is `change_request`.
- The template lists are in `docs/runbook.md` (the template table near the `feature-warden` row), `docs/protocol.md` (the same table), `docs/command-reference.md` (the `snodo init` template list) and `packages/snodo-foundation/src/snodo/protocols/templates/README.md`.
