INTENT
Recon rec_831df0 started at 04:50Z on 2026-10-08 with 3 agents:
- deepseek and qwen both finished by 04:51 with good answers, written to `.snodo/recons/rec_831df0/results.json`;
- the gemini agent's account has run out of credits. More than 7 minutes later it had still not returned, and the recon stayed `running` with `completed_at: null`.

An exhausted-credits or quota error should fail fast. Instead the agent either hangs in provider-side retries or blocks on a call with no deadline. Meanwhile the whole recon looks unfinished.

When this is done, each recon agent runs under a wall-clock deadline, which is configurable next to the existing `llm.recon.max_tool_turns` and `max_tokens`. A sensible default is a few minutes. An agent that hits the deadline ends with a clear error naming the deadline. It keeps the trace and any partial answer it has, as other failures already do. The recon then completes with the remaining agents' results. A provider error saying credits or billing are exhausted counts as permanent, so it is not retried.

THE CHAIN
1. Find why the gemini agent did not return: the provider client's own retries or timeout, the absence of a per-call timeout, or the agent loop. Fix the cause, and add a per-agent deadline as the backstop.
2. Make sure credit or billing exhaustion is classified as permanent in the shared provider-error classifier, so the recon-reliability retry does not retry it.
3. Tests, with a fake provider:
   - one agent that never returns, while two others answer, leaves the recon `complete` within the deadline, with two answers and one deadline error that carries its trace;
   - a "credit balance exhausted / billing" error is not retried;
   - the deadline is read from config.
