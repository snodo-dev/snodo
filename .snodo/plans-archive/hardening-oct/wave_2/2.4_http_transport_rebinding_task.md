## INTENT
`snodo serve` only ever listens on loopback (the MCP library's default host is 127.0.0.1, and snodo exposes no host option), and its only public route is the Cloudflare tunnel over HTTPS. Even so, a malicious web page in the user's browser must not be able to reach the localhost HTTP endpoint through DNS rebinding.

## THE CHAIN
- In `snodo/cli/commands/serve_cmd.py` (around lines 350–353), every non-stdio transport sets `FORWARDED_ALLOW_IPS="*"` and `transport_security.enable_dns_rebinding_protection = False`. That disables the protection the MCP library turns on by default for loopback hosts.
- Without a tunnel there is also no auth on the localhost endpoint, which exposes write_file, commit, merge_branch and similar tools.

## CONSTRAINTS
- Enable rebinding protection with an explicit allowed-hosts and allowed-origins list: loopback names with the port, plus the configured tunnel hostname when a tunnel is used. The existing tunnel flow, where cloudflared forwards to localhost with the tunnel's Host header, must keep working. Narrow `FORWARDED_ALLOW_IPS` to what the tunnel needs (loopback).
- Keep the bind on loopback. Add no option that binds a non-loopback address.
- Existing auth paths (oauth through the tunnel, service tokens at the edge) keep working.
