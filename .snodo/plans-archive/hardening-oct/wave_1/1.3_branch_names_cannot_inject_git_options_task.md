# Branch names from MCP tool calls are passed to git unchecked

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
A branch name arriving from a tool call can only ever be a branch name. Anything git could read as an option, or an invalid ref, is refused before git runs.

## THE CHAIN
- Recon rec_f8c7a8: in `packages/snodo-tools/src/snodo/tools/git.py`, `create_branch` calls `repo.git.checkout("-b", name)` (around lines 294–306), `merge_branch` calls `repo.git.merge(branch)` and `checkout(base)` (around lines 364–472), and `delete_branch` calls `repo.git.branch("-d", branch)` (around lines 460–472).
- These use the names straight from MCP arguments. A name starting with `-` would be read as a git option.

## CONSTRAINTS
- Validate every branch or ref name from tool input before use, with git's own rules (for example `git check-ref-format --branch`) plus refusing a leading `-`. Where git accepts it, also pass `--` before positional refs.
- Valid names that work today keep working, including slashes as in `task/<plan>/<id>/…`.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo. Tests use temporary repos.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the targeted git-tool tests.

## ACCEPTANCE
- Tests show that names such as `--upload-pack=x`, `-d` and `a..b` are refused for create, merge and delete without running git, while existing valid names (including nested `task/…` names) still work.
- There is a CHANGELOG entry under ## [Unreleased].
