# Workspace tools can read the tunnel token and may write into .snodo

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
The protocol and plan records under `.snodo/` stay readable to judges and orchestrators (ADR 026), but credential files there can never be read through the workspace tools. Prefix-scoped writes can never land inside `.snodo/`, even through a broad prefix or a symlink.

## THE CHAIN
Recon rec_f8c7a8 found the following, and the orchestrator checked it against the code:
- `packages/snodo-tools/src/snodo/tools/workspace.py` makes all of `.snodo` readable (`_READABLE_IGNORED_DIRS = {".snodo"}`, around line 26; exemption around lines 214–220).
- `_save_tunnel_config` in `snodo/cli/commands/serve_tunnel_config.py` writes `.snodo/tunnel.json` with the live `tunnel_token`, `client_id` and any `credentials`. An MCP `read_file` of that path returns the token in a tool result.
- `write_file_with_prefixes` (around lines 435–483) checks prefix membership after `resolve()`, but unlike `validate_path(..., for_mutation=True)` (around lines 181–184) it has no `.snodo/` exclusion.

## CONSTRAINTS
- Narrow the readable part of `.snodo/` to what ADR 026 intends (protocol, plans and similar context). Deny credential and secret-bearing files: at least `tunnel.json`, and any other `.snodo` file holding tokens or keys. Grep for writers of credentials under `.snodo` to find them. Prefer an allow-list over a deny-list if it fits the ADR.
- Writes through prefixes refuse any resolved path inside `.snodo/`, including via symlinks.
- Search and symbol tools follow the same read rule.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo. Tests use temporary workspaces.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the targeted workspace-tool tests.

## ACCEPTANCE
- In a temporary workspace:
  - reading `.snodo/protocol.yml` and a plan file works;
  - reading `.snodo/tunnel.json` is refused with a clear message;
  - a prefix-scoped write to a path inside `.snodo/`, directly or through a symlink in an allowed prefix, is refused.
- There is a CHANGELOG entry under ## [Unreleased].
