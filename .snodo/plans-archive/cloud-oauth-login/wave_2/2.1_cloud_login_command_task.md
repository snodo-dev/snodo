INTENT
`snodo cloud login` signs a person in through their browser and leaves snodo connected to the cloud with an OAuth token.

Builds on the three modules merged in the previous wave (modules cloud_oauth_client, cloud_oauth_store and cloud_oauth_loopback in the infrastructure package of snodo-foundation). Read them first and use them as they are. The existing commands `snodo cloud connect <api_key>`, `disconnect`, `status` and `sync` live in snodo/cli/commands/cloud_cmd.py.

Indications: add `login` to the cloud command group. It discovers the OAuth server, registers once and reuses the stored client_id on later logins, starts the loopback listener, opens the browser at the authorize URL, exchanges the code, saves the tokens through the store, turns cloud sync on in the user's cloud config the same way `connect` does (without requiring or storing an API key), and prints a short success line that names the account or organisation if the token carries it, never the token. Failure paths print one actionable line (timeout, denied, unreachable) and exit non-zero. Support `--no-browser` to print the URL only. If an API key is already configured, say that OAuth now takes priority and how to go back. Keep this ticket to the command and its tests; changing how sync authenticates is a separate ticket in this wave, and logout and status changes come in the next wave.

Acceptance: tests with the OAuth modules stubbed cover the happy path, reuse of a stored client_id, denial, timeout, `--no-browser`, and that sync is enabled without an API key being written. CHANGELOG.md updated.

First open a GitHub issue in snodo-dev/snodo for this ticket and put "Fixes #<n>" in your commit message; mention the issue number in the CHANGELOG.md entry. Secrets (access tokens, refresh tokens, authorization codes, PKCE verifiers) are never printed, logged, put in audit events, or sent anywhere except the cloud endpoints named here. The state machine is closed: add no new status, halt type, severity, audit event type or audit field. Do not touch snodo-cloud. Tests use temporary directories and a stubbed HTTP transport (no real network, no real browser) and never write the repository's own .snodo/ directory. `make gate` must pass.
