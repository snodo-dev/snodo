INTENT
A command can open the person's browser at the cloud sign-in page and receive the answer on a temporary local address, then hand back the authorization code. This ticket is that listener and browser step, as a small self-contained module.

Agreed with the cloud side: the redirect URI must use the hostname `localhost` (http://localhost:<port>/callback), though the listener may bind to 127.0.0.1 (and ::1 if easy). The port is chosen at random per login.

Indications: a new module in the infrastructure package of snodo-foundation, named cloud_oauth_loopback: bind a one-shot HTTP listener on a free local port, expose the redirect URI to build the authorize URL from, open the system browser at a URL the caller supplies (webbrowser, injectable for tests; print the URL as a fallback when no browser can be opened, including on headless machines), wait with a timeout for the single callback request, check the `state` value matches, reject anything else (wrong path, wrong state, error parameter such as access_denied, a second request) with a short plain page, show the person a friendly "you can close this tab" page on success, shut the listener down, and return the code or a clear error. The listener must serve only that one callback and must not accept connections from other hosts. Do not put the authorization code or any token in logs. Do not edit the OAuth client or token store modules; they are written in parallel.

Acceptance: tests with a fake browser that performs the redirect cover success, state mismatch, provider error, timeout, wrong path, the fallback URL print, and that the listener is closed afterwards. CHANGELOG.md updated.

First open a GitHub issue in snodo-dev/snodo for this ticket and put "Fixes #<n>" in your commit message; mention the issue number in the CHANGELOG.md entry. Secrets (access tokens, refresh tokens, authorization codes, PKCE verifiers) are never printed, logged, put in audit events, or sent anywhere except the cloud endpoints named here. The state machine is closed: add no new status, halt type, severity, audit event type or audit field. Do not touch snodo-cloud. Tests use temporary directories and a stubbed HTTP transport (no real network, no real browser) and never write the repository's own .snodo/ directory. `make gate` must pass.
