INTENT
OAuth credentials live in one place on the user's machine, readable only by them, and survive restarts. This ticket is that store, as a small self-contained module.

Indications: a new module in the infrastructure package of snodo-foundation, named cloud_oauth_store that keeps, under the user config directory (resolve_home() in packages/snodo-core/src/snodo/paths.py, so SNODO_HOME is honoured), a single file for the cloud OAuth state: the registered client_id, the access token, the refresh token, the access token's absolute expiry time, and the scope. Operations: load (missing or corrupt file means "not logged in", never an exception that leaks contents), save (atomic write, file mode 0600, directory created if needed; the existing atomic_write_json helper may fit), clear (logout), and helpers that say whether the access token is expired or near expiry (reuse the margin idea in the lease code) and whether a refresh token is present. Refresh tokens rotate, so saving after a refresh replaces both tokens in one atomic step. The client_id can be kept when tokens are cleared, so a later login does not register again. Writes must be safe when two snodo processes refresh at once (a simple lock, as the other state files do).

This is user-level state, never project state: it must not be written under a project's .snodo/ directory. Do not edit the OAuth client or the loopback modules; they are written in parallel.

Acceptance: tests cover round trip, file mode 0600, atomic replacement, corrupt file treated as logged out, clear keeping or dropping the client_id as designed, expiry helpers with a controllable clock, and that nothing is written outside the temporary SNODO_HOME. CHANGELOG.md updated.

First open a GitHub issue in snodo-dev/snodo for this ticket and put "Fixes #<n>" in your commit message; mention the issue number in the CHANGELOG.md entry. Secrets (access tokens, refresh tokens, authorization codes, PKCE verifiers) are never printed, logged, put in audit events, or sent anywhere except the cloud endpoints named here. The state machine is closed: add no new status, halt type, severity, audit event type or audit field. Do not touch snodo-cloud. Tests use temporary directories and a stubbed HTTP transport (no real network, no real browser) and never write the repository's own .snodo/ directory. `make gate` must pass.
