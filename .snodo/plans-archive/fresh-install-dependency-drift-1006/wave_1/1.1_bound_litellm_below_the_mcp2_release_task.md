# Fresh installs stop resolving a litellm that needs mcp 2

## Intent

Someone running a fresh install of snodo should get a combination of dependencies that works. Today they do not: the newest litellm releases need a newer mcp than snodo allows, so snodo fails at import on a clean machine, while the locked development environment still works and hides it. Until the mcp 2.x port lands, the allowed litellm range must stop short of the releases that need it.

## Tracking

Open a GitHub issue first, or reuse https://github.com/snodo-dev/snodo/issues/1006, and put "Fixes #1006" in the commit message. Add one entry under [Unreleased] in the CHANGELOG, tagged (Fixes #1006).

## Symptom and evidence

- Issue #1006: litellm 1.106.x imports a type that exists only in mcp 2.x, and snodo caps mcp below 2 (in the snodo-mcp package). A fresh `pip install snodo` resolves litellm 1.106.x and mcp 1.30.x and fails on import; the PR review workflow, which installs the released snodo unpinned, broke the same way.
- The root project declares litellm as `>=1.80,<2` and the engine package declares `>=1.80.0`. The lockfile pins litellm 1.105.1 with mcp 1.30.0, which works, which is why nothing in the working tree noticed.
- The mcp 2.x port is planned separately; this ticket only holds the line until then.

## Contract

- Both places that declare litellm share the same upper bound, which excludes the 1.106 line and later, with a comment that names the reason and says to lift the bound when the mcp 2.x port lands.
- No other dependency range changes, and no behaviour change.
- The lockfile is regenerated by the maintainer after this lands; do not hand-edit it. Say in the task result that the lock needs a refresh.

## Acceptance

- A fresh resolution of the project's declared dependencies, without the lockfile, yields a litellm below 1.106 and an mcp below 2, and importing litellm and snodo succeeds in that environment. Show it in the task result.
- Existing dependency and packaging tests still pass; lint passes; no baseline is edited.

## Constraints

- Do not touch .snodo/ or the lockfile.
- Do not leave notes about validation anywhere in the tree.
