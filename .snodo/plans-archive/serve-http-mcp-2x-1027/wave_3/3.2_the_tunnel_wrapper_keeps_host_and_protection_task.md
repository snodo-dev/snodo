## CONTINUATION

An earlier attempt on this task wrote a new module `tests/mcp/test_serve_tunnel_factory_host_protection.py` that is close but has two design errors, found by running it (2 failed, the rest of the suite green). If a preserved worktree exists, continue from it and keep what is right.

1. The streamable-http case fails with `RuntimeError: Task group is not initialized. Make sure to use run().` The streamable app needs its session manager's task group; `tests/mcp/test_auth.py` shows the way this repo's tests install it (`mcp.session_manager._task_group = tg` inside an anyio task group). Use the same approach.
2. The sse case fails with `assert 404 == 421` because the test rewrites the tunnel path to `/mcp`, and `sse_app` serves `/sse` and `/messages`, not `/mcp`. Each transport must be exercised on its own routes; read them from the app rather than assuming one path for both.

One weakness besides: the allowed-Host assertion is only `!= 401`, which a 421 also satisfies, so a wrapper that dropped `transport_security` would fall back to the SDK default protection and still pass. Make the test discriminate: allow a Host that the SDK default would refuse (the tunnel hostname handed to `build_transport_security_settings`) and assert it is not refused with 421, while a foreign Host is refused with 421. A wrapper that dropped `transport_security` must make the allowed-Host assertion fail.

## INTENT

For a service-token tunnel, `_run_server` replaces the server's `streamable_http_app` and `sse_app` factories with wrappers that put the tunnel path router (`TunnelMCPPaths` in `snodo/cli/commands/serve_tunnel_asgi.py`) in front of the real app. On mcp 2.x the factories take `host` and `transport_security`; if the wrapper dropped or mis-forwarded either, the router would serve an app without host protection and nothing would say so.

The module builds a real mcp 2.x server through the project's server builder, installs the same wrapper the way `_run_server` does (reuse the code path; do not re-implement the wrapper inside the test), calls the wrapped factory the way `run` does, and exercises the resulting ASGI app in process with no sockets: an allowed Host reaches the app, a foreign Host is refused with 421, and both factories behave the same on their own routes.
