# Task worktrees can run ruff out of the box

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Before a task commits, the coder lints its own changes. The task worktree's environment is built with a plain `uv sync`, which installs the default `dev` dependency group. ruff is listed only in the `dev` optional extra in the root `pyproject.toml`, not in the `[dependency-groups] dev` list. So `uv run ruff` fails with "Failed to spawn: ruff" in a fresh worktree, and lint errors are found later by the gate (15 gate failures were ruff findings). A plain `uv sync` should give a worktree everything the gate's lint step needs.

## THE CHAIN
- Root `pyproject.toml`:
  - `[project.optional-dependencies] dev` pins `ruff==0.15.16`;
  - `[dependency-groups] dev` (around line 113) does not list ruff.
- `uv.lock` must be regenerated to match. Use `uv lock`, and change no other pins.
- The remote gate (`scripts/gate_remote.sh`) runs `uv run ruff check .`.

## CONSTRAINTS
- Add only ruff, at the same pinned version, to the default dev group. Do not change any other dependency or pin. If `uv lock` wants to move other packages, use the option that keeps the existing resolution.
- No new status, severity, halt type or audit event.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Verify with `uv sync` then `uv run ruff --version` in the worktree.

## ACCEPTANCE
- After a plain `uv sync`, `uv run ruff --version` reports 0.15.16.
- The `uv.lock` diff is limited to adding ruff to the dev group.
- There is a CHANGELOG entry under ## [Unreleased].
