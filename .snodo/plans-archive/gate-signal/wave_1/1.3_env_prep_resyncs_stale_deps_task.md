# Environment prep re-installs when the lockfile is newer than the installed deps

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Before a task runs, snodo prepares the task's worktree environment. It auto-detects the install command from lockfile markers, and skips the install if the install directory already exists (`node_modules`, `.venv`, ...). An install directory left from an earlier run is reused even after the lockfile changed, so the task runs against missing or outdated dependencies and fails for reasons that have nothing to do with its work. The skip should only happen when the existing install is at least as new as the lockfile that triggered it.

## THE CHAIN
- `packages/snodo-foundation/src/snodo/infrastructure/environment.py`:
  - `ECOSYSTEM_RULES` lists (markers, guard dir, command);
  - `detect_prepare_command` picks the first matching rule;
  - `prepare_environment` skips with "already installed (<guard> exists)".
- An explicit command and a protocol `execution.prepare_command` do not use the guard. Leave that path as it is.
- Tests: `tests/infrastructure/test_environment.py`. `test_already_installed_skips_auto_prep` asserts the skip when `node_modules` exists. Keep its intent: it still skips when the guard dir is newer than the marker.

## CONSTRAINTS
- Compare modification times of the matched marker file and the guard directory. Run the install when the marker is newer; otherwise skip as today. If the stat fails, keep today's skip.
- The skip reason stays readable, and a run triggered by a stale guard says why in the existing PrepResult reason.
- No new status, severity, halt type or audit event.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run `tests/infrastructure/test_environment.py`.

## ACCEPTANCE
- Tests show:
  - a guard dir older than the lockfile runs the install;
  - a guard dir newer than the lockfile skips;
  - a missing guard dir runs the install as before;
  - protocol and explicit commands behave as before.
