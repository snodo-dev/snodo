# A failed gate's output keeps the lines that say what failed

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
When the quality validator's test command fails, its verdict carries an output tail. Recovery hands that tail to the coder, so it is the only evidence of what broke. Today it is the last 400 characters of stdout and stderr combined. In this repo's own history, 45 of 102 failed gate runs kept no line saying what failed:
- ruff's rule code and file were cut off, leaving only "Found 1 error.";
- the file-length check's FAIL line was pushed out by its summary lines;
- stderr noise after a test summary pushes out the FAILED test ids.

The tail should always keep the lines that name the failure (failing test ids, `FAIL:` lines, lint rule codes with their file and line, `error:` lines), and then the end of the output for context.

## THE CHAIN
- `packages/snodo-engine/src/snodo/validators/quality.py`:
  - `_OUTPUT_TAIL_CHARS = 400` and `_output_tail(stdout, stderr)` (around line 590);
  - it is used by `_classify_failure` (the "Tests failed (exit N). Output:" justification), the timeout path and the base-commit rerun log.
- `_audit_verification` (around line 296) separately caps the audit event's `output_tail` at 400 chars. That cap protects the cloud event size and must stay. The audit should carry the failure lines first, so the 400 chars it keeps are the useful ones.
- Tests: `tests/validators/test_quality.py`. Check whether any existing test asserts the exact old tail shape or length, and update it to the new behaviour rather than keeping both.

## CONSTRAINTS
- The justification stays bounded. Pick a budget a little larger than today's 400 chars, but bounded, for example around 1500 chars. Failure lines come first, then a short end-of-output tail, with no duplicated lines.
- Failure-line detection is a small, readable set of patterns. If no pattern matches, fall back to today's plain tail.
- The audit `output_tail` stays at most 400 chars.
- Keep the verdict severity, error routing and wording prefix ("Tests failed (exit N). Output:") as they are.
- No new status, severity, halt type or audit event.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run `tests/validators/test_quality.py`.

## ACCEPTANCE
- Tests show that, from realistic long outputs:
  - the tail keeps the ruff rule code and file:line when 2 KB of source excerpt follows;
  - it keeps a `FAIL:` line that is followed by many summary lines;
  - it keeps pytest `FAILED tests/x.py::test_y` lines that are followed by stderr warnings;
  - a short output is returned unchanged;
  - the audit tail is at most 400 chars and starts with the failure lines.
