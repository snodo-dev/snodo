# `snodo cloud status` says a broken login will refresh itself

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
When the OAuth access token has expired and refreshing it fails, `snodo cloud status` says so plainly. It names the command that fixes it (`snodo cloud login`) and mentions it when sync is quietly falling back to the API key. While the login works, it reads as it does today.

## THE CHAIN
- On a real machine the access token showed "expired; next sync will refresh it" for 8 hours. Audit sync kept succeeding only because `safe_cloud_sync_credential` (`packages/snodo-foundation/src/snodo/infrastructure/cloud_credentials.py`, around lines 80–97) fell back to the configured API key after each failed refresh.
- Recon rec_267c88: `_format_oauth_expiry` in `snodo/cli/commands/cloud_cmd.py` (around lines 249–260) decides the message from the clock alone. It never knows whether a refresh was attempted or failed.

## CONSTRAINTS
- Base the message on evidence. Preferably, `cloud status` attempts the refresh itself, through the same resolver sync uses, when the token is expired. If that is unsuitable, a recorded last-refresh outcome works too. Choose whichever fits the code with the least new state.
- Never print token values. Keep the output plain and soft. Avoid "not X but Y" contrast phrasing.
- `--json` output (if `cloud status` has one) gains the same fact as a field. Its existing fields stay unchanged.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the cloud command tests.

## ACCEPTANCE
- Tests show three cases:
  - an expired token whose refresh fails prints a line telling the user to run `snodo cloud login`, and notes the API-key fallback when a key is configured;
  - an expired token whose refresh succeeds shows the new expiry;
  - a valid token prints as before.
