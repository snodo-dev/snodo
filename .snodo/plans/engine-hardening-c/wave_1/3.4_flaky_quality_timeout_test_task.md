## Intent
The quality validator's timeout test should pass reliably under load, and a command that times out should leave no child processes behind.

## Evidence
- tests/validators/test_quality.py, `test_timeout_preserves_output_and_kills_process_group`, spawns a grandchild process and polls for its disappearance; it failed once in a gate run on a task that did not touch this area (it passed on rerun). The test assumes the killed grandchild vanishes from the process table promptly, which does not hold when it lingers as a zombie or the machine is busy.
- `QualityValidator._run_command` in packages/snodo-engine/src/snodo/validators/quality.py runs the command and kills its process group on timeout. Another task in this plan changes the evidence quality passes to acceptance in the same file; read it as it stands on your branch and keep your change confined to timeout handling.

## Outcome
- The timeout test tolerates a zombie or a slow exit within a bounded deadline, and fails with a clear message only if the grandchild is genuinely still running afterwards.
- If reading the code shows a real gap in how the process group is killed or reaped on timeout, close it and test it; otherwise leave production code unchanged.
- The test passes in fifty consecutive runs alone and ten consecutive runs of its module under parallel load; say in the commit what was run.
- `make gate` passes.
