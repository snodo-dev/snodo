INTENT
When a plan finishes, delivering its integration branch through push_branch or change_request should go through the same verification gate as any other delivery, and should pass when the work genuinely verified. Today it is likely to be refused even for a clean plan, because the gate looks for verification of a commit that was never itself verified.

This is fix-forward work for issue #661 (the automated review of PR #660). Do not open a new issue; use #661. Put "Fixes #661" in the commit subject and mention #661 in the CHANGELOG.md entry.

Symptom and evidence: the review reported that plan integration delivery can be refused by the task verification gate because the integration branch head has no matching verification_executed event. In snodo/cli/commands/run_merge.py, `_merge_on_success` resolves the head commit of the branch being delivered and, for push_branch, change_request and audited local_merge, requires a passing `verification_executed` event whose commit matches it. `_deliver_plan_integration` passes the plan integration branch through `branch_override`. The integration head is a merge commit produced by merging each passing task into the branch, so none of the recorded verification events names it. Verify this against the current code before you change anything; if the gate already accepts a clean plan, say so in the issue and limit the work to a test that proves it.

Indications (your own path is welcome): the strongest evidence is to run the project's configured test command on the integration head before delivery and record the existing `verification_executed` event for that commit, so the gate has something real to match. Where no test command is configured the existing `no_tests` outcome applies. A failing run must refuse delivery with the existing refusal path and leave the branch and worktree for a human.

Constraints: the state machine is closed. Add no new status, halt type, severity, audit event type or audit field; reuse `verification_executed` and `unverified_merge_blocked`. Do not weaken the gate for ordinary task delivery.

Acceptance: a test shows a plan whose tasks each verified is delivered under change_request and push_branch without a refusal, and a test shows a failing test command on the integration head refuses delivery. Update CHANGELOG.md. `make gate` must pass.
