INTENT
After a local_merge delivery of a plan, snodo should remove the integration worktree and branch that were actually created for that plan, whatever the plan's name field says.

This is fix-forward work for issue #661. Do not open a new issue; use #661. Put "Fixes #661" in the commit subject and mention #661 in the CHANGELOG.md entry.

Evidence: `_run_plan` in snodo/cli/commands/plan_run.py creates the integration branch and worktree from the plan argument (`plan/<name>/integration` and a worktree under the plan's directory, named from `args.plan`). `_deliver_plan_integration` in run_merge.py is called with `plan_data.get("name", args.plan)` and derives the worktree path from that name for cleanup. When the name inside plan.yml differs from the plan directory name, the cleanup targets a different path, so the real worktree and branch can be left behind or the wrong one touched. Verify against the current code.

Indications: pass the identity that created the branch (the branch name, and the worktree path or the plan argument) into delivery and clean up from that, rather than recomputing it from a differently sourced name. Keep the intent and title text for the change request on the authored plan name. Check whether the queue-level integration branch from #665 has the same issue.

Acceptance: a test with a plan whose plan.yml name differs from its directory name shows the correct worktree and branch are removed after local_merge delivery and nothing else is. Update CHANGELOG.md. `make gate` must pass.
