## Intent
The in-process LiteLLM coder must never put an unbounded tool result into the model conversation. The shared bound in packages/snodo-engine/src/snodo/coders/tool_result_text.py (100,000 characters, commit 952aaf7f) already covers the coder loop in packages/snodo-engine/src/snodo/coders/litellm.py. What remains is that the bound must hold on the exact text the model receives, framing included, and that this is proven by a test that exercises the composition the loop uses.

## Evidence
- Issue #956: a coder's test run produced a single tool result of 93,550,113 characters and the provider refused it (limit 10,485,760).
- Earlier attempts produced a change on this task's branch: the bound is applied last, around the provider framing, through a helper in tool_result_text.py, and litellm.py ends at 1017 lines of code (baseline 1019). tests/coders/test_adr040_coder_tools.py drives the loop's own append site for a multi-megabyte stdout plus stderr and for a result exactly at the cap. The quality gate (full test suite, file-length ratchet) passed on the last two attempts.
- Those attempts ended without a merge only because the acceptance reviewer could not see the test run itself, and then because a validator hit a transient provider capacity error. If the work is already present on the branch, validate it as it stands; change code only where a criterion below is not met.

## Outcome
- The text delivered to the model for any coder tool call never exceeds the shared bound, whatever framing is added around it; results within the bound are unchanged, exit-code line included.
- litellm.py does not grow: it ends at or below 1019 lines of code (scripts/file_length_baseline.txt). The baseline must not be edited upward.
- A test under tests/coders proves the bound holds for the text the loop actually appends for a tool call (not only for the truncation helper alone), for a multi-megabyte stdout plus stderr and for a result exactly at the cap, keeping the exit-code line, the failure tail and the truncation notice. The coder runs that test and the file-length check and reports their result in its summary.

No new states, statuses, severities or halt types.
