New files this task will create: tests/cli/test_logs_json_job.py.

INTENT
`snodo logs <job id> --json` should print one JSON object for a job, with usage grouped by role, so the model time of validators and coder can be compared. It follows the machine interface contract (ADR 022 and docs/machine-interface.md) and uses the same schema as the recon payload from the previous ticket.

Evidence: a job's state file keeps a usage list, one record per model call, with the model, the model that served it, input tokens, output tokens, duration in milliseconds, the role (for example validator:architecture or coder) and the task id. One job (j_10d31d237248) made 130 validator calls for 6.1M input tokens and about 26.7 minutes of model time against a single 58 second coder call, and today that is only visible by reading the state file by hand. The previous ticket in this plan added --json for recon ids; this one covers job ids, including plan jobs.

What it should do: for a job id, --json writes one JSON object to standard output and nothing else. It carries the same schema field (snodo.logs.v1) and ok field as the recon payload, the id, a kind field with the value "job", the status, the elapsed seconds, the raw usage records, a by-role list (role, calls, input tokens, output tokens, model time in seconds, output tokens per second), and totals across all records: input tokens, output tokens, total model call time in seconds and calls. A job with no usage records prints empty lists and zero totals. The error behaviour is the same as in the previous ticket: the uniform error object on standard output with a non-zero exit code, never raw text. The text output without --json does not change.

Extend the logs section of docs/machine-interface.md so it covers the job payload and states which kinds of id --json supports.
