New files this task will create: none.

INTENT
The user-facing documentation should tell a reader that snodo logs can print machine-readable JSON for a recon id or a job id, and point to the contract page for the exact fields.

Evidence: the two earlier tickets in this plan add a --json option to the logs command for recon ids and job ids and document the payload in docs/machine-interface.md. The command reference lists the logs options, and the page about following a run explains how to read results, but neither mentions --json.

What it should do: add --json to the logs entry in the command reference, with a short description and a link to the machine interface page. Add a short section to the page about following a run that shows how to get throughput numbers from a recon or a job: one example command per kind, written with a real-looking id, a sentence on what the object contains (schema, status, elapsed seconds, per-agent or per-role breakdown, totals with input tokens, output tokens, model time and output tokens per second), and a note that it cannot be combined with --watch. Keep the wording plain and short.

CONSTRAINTS
Files that may change: docs/command-reference.md, docs/following-a-run.md. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Documentation only: no code or test changes. Do not add any state, status, severity or halt type.

ACCEPTANCE
Both pages mention --json for the logs command; the example commands use ids of the form rec_ and j_ followed by hex digits; links to the machine interface page point at an existing page. `make gate-task` is green. (The gate does not run the strict docs build, so it is not a criterion here.)

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
