## Intent
An operator should be able to benchmark one model of an OAuth provider by naming it, even though that provider cannot list its models. Today the benchmark finds its model through discovery, and an OAuth provider with no models endpoint discovers nothing, so naming the model gets "no models discovered".

## Evidence
- `snodo models --benchmark` takes a provider-and-model name (the short form added earlier) or `--provider` with `--id`; both are resolved by the models benchmark name module under snodo/cli/commands, whose model selection function asks discovery for the provider's models, applies the filters and requires exactly one match.
- Discovery for a provider that signs in with OAuth and has no models endpoint returns an empty list (an earlier task in this plan made that quiet).
- Earlier tasks in this plan added the `auth` provider setting with a helper that says whether a provider signs in with OAuth.

## Outcome
- When the provider signs in with OAuth and discovery returns no models, an exact model id given with `--id` or in the short form is used as named, with the provider's route in front as usual, and the benchmark proceeds. A signed-out provider gets the message asking to run `snodo models --provider <name> --authenticate` instead of a model call.
- When no exact id is given for such a provider, the message says that this provider cannot list its models and that the exact id is needed, instead of "no models discovered".
- Providers that can list models behave exactly as before, including the message for an id that matches nothing or several models.
- Tests cover: an exact id on an OAuth provider with empty discovery; the short form on the same; no id on such a provider; signed out; a normal provider unchanged. Use fakes and no network.
- `make gate` passes, including ruff (no unused imports), the import-linter contract, and the file-length and docs-coverage checks.
