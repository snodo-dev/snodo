INTENT
The side panel on the Now page opens for a clicked task but its body only says the spec is loading. The pieces to fill it now exist: the route GET /api/now/spec (project, plan and task as query values; answers {"project","plan","task","markdown"} or 404) and the renderer window.snodoMarkdown.render(text) that returns a DocumentFragment. This task connects them so the panel shows the task's ticket spec as rendered Markdown, as the snodo-cloud task panel does.

Evidence: snodo/web/static/now.js opens the panel (from the previous task) with a placeholder body; nothing in the view calls /api/now/spec or window.snodoMarkdown.

What the person should see: when the panel opens for a task that belongs to a plan, the body shows the spec rendered with headings, paragraphs, lists, code blocks, emphasis and links, scrollable inside the panel, styled with the dashboard's colour tokens in light and dark (code in the monospace token, headings quieter than the page's). While the spec loads the body says so; if the dashboard has no spec for that task the body says "No spec on this machine for this task."; for a task outside a plan it says the task ran outside a plan and has no spec; if the request fails it says the spec could not be loaded and offers a retry button. The spec is fetched once per opened task and kept while the panel stays on it, so the 10-second refresh does not refetch or reset the scroll position; switching tasks fetches the new one, and a late answer for a task the person has already left is ignored. If window.snodoMarkdown is missing the spec text is shown as preformatted plain text.
