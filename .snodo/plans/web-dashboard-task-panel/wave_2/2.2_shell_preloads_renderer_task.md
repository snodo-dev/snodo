New files this task will create: none.

INTENT
The page shell loads each view's script and stylesheet only when that view is opened. The task panel on the Now page needs the shared Markdown renderer (snodo/web/static/markdown.js, from an earlier task) to be present before any view draws, so this task makes the shell bring it in once at start-up.

Evidence: snodo/web/static/index.html loads /static/<view>.js and /static/<view>.css lazily per view and has no shared script; snodo/web/static/markdown.js exists but nothing loads it.

What it should do: the shell loads markdown.js from the static folder once, before the first view renders, so that window.snodoMarkdown is available to every view; a failure to load it must not stop the page from working (views check for it and carry on without). Nothing else about the shell changes: the polling, the view switching, the theme and the layout stay as they are.

CONSTRAINTS
Files that may change: snodo/web/static/index.html, tests/web/test_static_shell.py and CHANGELOG.md. No libraries, no external URLs, no inline event handlers, DOM through createElement and textContent only. Do not touch the views, the other static files or any Python module.

ACCEPTANCE
Tests that exist and pass: index.html references markdown.js and loads it before the first view render; a load failure path exists and does not throw; the existing shell tests still pass and no innerHTML or external host appears in the shell.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message. Add one CHANGELOG.md entry under [Unreleased] ending "(Fixes #<n>)". Before finishing, run `ruff check` on any Python files you wrote and fix every finding, such as unused imports.
