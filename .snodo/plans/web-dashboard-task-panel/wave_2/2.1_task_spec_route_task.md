New files this task will create: `snodo/web/routes_spec.py`, `tests/web/test_routes_spec.py`.

INTENT
The browser needs a way to ask the dashboard for one task's spec. The reader that finds the spec file (snodo/web/task_spec.py, from an earlier task) exists; this task serves it as a read-only JSON route in the same style as the other /api routes, so the Now page can show the spec in its side panel.

Evidence: snodo/web/app.py lists /api/projects, /api/now, /api/plans, /api/delivery and /api/gates; none returns a task spec.

What it should do: GET /api/now/spec with the query values project (the project name as /api/projects lists it), plan and task. It answers {"project", "plan", "task", "markdown"} when the spec exists. It answers a clear 404 JSON body when the project is unknown, the plan or task is not found or the values are not plain names, and a 400 when a value is missing. The project is chosen by name from the dashboard's own project list; the browser never supplies a path.

CONSTRAINTS
Files that may change: the two new files, snodo/web/app.py (only to register the route), tests/web/test_app.py (only if its route-list expectations need the new entry) and CHANGELOG.md. GET and HEAD only, loopback guard as for the other routes, read-only. Keep the import-linter layering: if this module needs the dashboard project list it reads it from the request's app state, as the other route modules do. Do not edit the other route modules or snodo/web/task_spec.py.

ACCEPTANCE
Tests that exist and pass, through Starlette's test client with a temporary project: a known task answers 200 with its spec text and the four keys; an unknown project, plan or task answers 404; a missing query value answers 400; a plan or task value containing ".." or a slash answers 404 and nothing outside the plan folders is read; a non-GET method is refused as on the other routes; the route is registered in the app. All other tests in tests/web still pass and `make gate-task` is green including the import-linter step.
