New files this task will create: `snodo/web/task_spec.py`, `tests/web/test_task_spec.py`.

INTENT
The local Now page is about to show a task's ticket spec in a side panel, and the spec exists only as a Markdown file inside the project: .snodo/plans/<plan>/wave_<N>/<task_id>_task.md (a plan that has been archived may sit under .snodo/plans-archive instead). Nothing in snodo/web reads those files yet. This task supplies the read: given one project directory, a plan name and a task id, return the spec text, or say there is none. The route that serves it to the browser is a later task.

Evidence: snodo/web/now_tree.py describes tasks by id, status and job only; no module under snodo/web opens a task spec.

What it should do: find the spec for that task under the project's plan folders and return its text; return nothing when the plan, the task or the file is not there, when the file cannot be read, or when it is not valid text. The plan name and task id come from the browser, so they are untrusted: anything that is not a plain name (path separators, dots that climb out, empty, absurdly long) finds nothing and never touches the disk outside the project's plan folders. A very large file is cut at a sensible size with a clear marker instead of being sent whole.

CONSTRAINTS
Files that may change: the two new files and CHANGELOG.md. Read-only: no writes, no subprocess, no network. Standard library only. Keep the import-linter layering; do not import snodo.dashboard from this module. Do not edit any existing module.

ACCEPTANCE
Tests that exist and pass, using a temporary project directory: a spec in wave_2 of a plan is found by plan and task id; a missing task, a missing plan and an unreadable file each give nothing; ids and plan names containing "..", "/" or a backslash, or empty, give nothing even when such a file exists outside the plan folders; an oversized spec is truncated with the marker; a spec in the archive folder is found when the plan is not in the live plans folder.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message. Add one CHANGELOG.md entry under [Unreleased] ending "(Fixes #<n>)". Before finishing, run `ruff check` on the files you wrote and fix every finding, such as unused imports.
