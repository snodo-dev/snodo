New files this task will create: `snodo/web/static/markdown.js`, `tests/web/test_static_markdown.py`.

INTENT
The task panel on the Now page has to show a task spec as rendered Markdown, the way the snodo-cloud task panel does, but the dashboard allows no libraries and no external hosts, and builds all DOM with createElement and textContent. This task adds the small Markdown renderer the panel will use: it turns Markdown text into DOM nodes and nothing else. The snodo-cloud app does the same job with a deliberately small subset (a few block types and a few inline marks, nothing more).

Evidence: snodo/web/static holds no Markdown support; task specs are Markdown with headings, paragraphs, bullet and numbered lists, fenced code, inline code, bold, italics and links.

What it should do: expose one function on the page, window.snodoMarkdown.render(text), returning a DocumentFragment that holds the rendered blocks. Support headings, paragraphs, bullet and numbered lists, fenced code blocks, inline code, bold, italic, and links; anything it does not understand is shown as plain text, never dropped and never executed. Links are only live for http and https addresses or relative ones and open with rel="noopener noreferrer"; any other scheme, such as javascript:, is shown as plain text. Specs are long, so rendering must stay linear in the input size.

CONSTRAINTS
Files that may change: the two new files and CHANGELOG.md. DOM only through createElement, createTextNode and textContent; never innerHTML, outerHTML, insertAdjacentHTML or document.write. No libraries, no external URLs, no eval. Add no class names that need styling in this task; use plain semantic elements so a later task can style them from the panel. Do not touch index.html, the views, or any Python module.

ACCEPTANCE
Tests that exist and pass (tests read the script as text, as the other static tests do, and where node is available also run it): the script defines window.snodoMarkdown.render; it contains no innerHTML, outerHTML, insertAdjacentHTML, document.write or eval, and no external host; it contains handling for each of headings, lists, fenced code, inline code, bold, italic and links; it refuses links whose scheme is not http or https (or relative) and sets rel to noopener noreferrer on links it makes. If node is available, rendering a sample spec yields a heading, a list, a code block and a link element, and a "javascript:" link yields no anchor element.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message. Add one CHANGELOG.md entry under [Unreleased] ending "(Fixes #<n>)". Before finishing, run `ruff check` on any Python files you wrote and fix every finding, such as unused imports.
