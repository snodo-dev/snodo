## Intent
Cover the OAuth-aware behaviour of `snodo config show` and `snodo config test` that issue 1059 added, which currently has no tests.

## Evidence
- tests/cli/test_config.py has only the pre-existing show and test cases (for example the case where no keys are configured); nothing exercises a provider with `auth: chatgpt-oauth`.
- The commands read sign-in state through `chatgpt_sign_in_state()` (token file only), so tests can fake it with no network.

## Outcome
- Tests for an OAuth-only setup: show lists the provider as signed in and as not signed in (with the authenticate command) and does not print "No API keys configured"; test exits 0 and reports the sign-in state.
- A test for a mixed setup (one key provider, one OAuth provider): both appear in show and in test.
- A test that an API-key-only setup behaves unchanged.
- Fakes only (monkeypatched sign-in state, isolated config home), no network.
- `make gate` passes, including ruff, import-linter and the file-length and docs-coverage checks.
