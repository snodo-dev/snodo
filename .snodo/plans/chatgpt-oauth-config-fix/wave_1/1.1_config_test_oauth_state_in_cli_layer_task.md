## Intent
Fix the layering break from the first attempt at issue 1059 so `make gate` passes: the core config module must not know about ChatGPT sign-in, while `snodo config test` and `snodo config show` keep reporting an OAuth provider's sign-in state.

## Evidence
- `make gate` fails in import-linter: "snodo.config is not allowed to import snodo.infrastructure", from the new import inside `ConfigManager.test_keys` in packages/snodo-core/src/snodo/config.py (contract "snodo-core depends on nothing above it").
- The same sign-in lookup already works in the CLI layer: `_config_show` in snodo/cli/commands/config_cmd.py imports `chatgpt_sign_in_state` itself. Only the test path put it in core.
- `_config_test` in config_cmd.py already prints "signed in" and "not signed in" statuses, but they are produced by the core method.

## Outcome
- `ConfigManager.test_keys` is back to its behaviour before the first attempt (no OAuth branch, no infrastructure import); the core config module change is reverted.
- `snodo config test` reports each OAuth provider's sign-in state from the command module (token file only, no network, no interactive sign-in), alongside key provider results, and still does not exit early when only OAuth providers exist.
- Output text for the sign-in states stays as the first attempt printed it.
- Providers without the `auth` setting, and provider objects without an `auth` attribute, behave exactly as before.
- `make gate` passes, including ruff, import-linter and the file-length and docs-coverage checks.
