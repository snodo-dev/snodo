## Intent
Document the new `--model` and `--models` options of `snodo recon` wherever recon usage is described, so the docs match the behaviour once the code task lands.

## Evidence
- docs/command-reference.md, docs/decompose-and-recon.md and docs/specs/recon-agents-cli.md describe `snodo recon` and its `--agents` / `-n` count; none mentions choosing models.

## Outcome
- The command reference and the decompose-and-recon guide show `--model` (repeatable, one model per agent) and `--models` (comma-separated list) with an example of two models, state that the number of models listed is the number of agents, that the same model may be repeated, that the models listed always override the recon configuration, and that they cannot be combined with `--agents` / `-n`. Failover chains are not available from the command line.
- The recon-agents spec records the options consistently with the above, without contradicting existing statements about the configured default path.
- Existing wording about the count and the configured models stays correct for the case without `--model`.
- `make gate` passes, including the docs-coverage and docs link checks.
