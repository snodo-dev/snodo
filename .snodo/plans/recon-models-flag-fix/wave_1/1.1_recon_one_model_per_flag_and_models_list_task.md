## Intent
Bring `snodo recon` model selection to the agreed design: each `--model` use names exactly one model (one agent), and a new `--models` option takes a comma-separated list of models, equivalent to repeating `--model` for each.

## Evidence
- In snodo/cli/commands/recon_cmd.py, the `--model` option splits each value on commas into a failover chain (lane with several models) and its help text advertises that; there is no `--models` option. The operator wants failover chains kept out of the command line.
- The refusal of `--agents` / `-n` together with `--model`, the override of the recon configuration, and the checks for an unknown model or an unconfigured provider already work and must keep working for both new forms.
- tests/cli/test_recon_model_option.py covers a failover chain in one `--model` value, which no longer matches the design.

## Outcome
- `--model <name>` can be repeated; each value is one agent running that one model, and a value that contains a comma is refused with a short message that points at `--models`.
- `--models <a,b,c>` runs one agent per listed model, the same as repeating `--model` for each; both forms may be used together and the models run in the order given. An empty entry in the list is ignored or refused with a clear message, not a crash.
- The same model may be listed more than once.
- `--agents` / `-n` together with `--model` or `--models` is refused as it is now, with the message naming both options.
- Unknown models and unconfigured providers are refused before dispatch for either form, as now.
- Without either option the command behaves exactly as before.
- Help text for both options says that the models listed override the recon configuration and that the number of models listed is the number of agents.
- Tests are updated to match: repeated `--model`, `--models` list, both forms together, repeated model, comma inside `--model` refused, `-n` refused with each form, unknown model refused, no-option path unchanged (no network, no real model calls).
- `make gate` passes, including ruff, import-linter and the file-length and docs-coverage checks.
