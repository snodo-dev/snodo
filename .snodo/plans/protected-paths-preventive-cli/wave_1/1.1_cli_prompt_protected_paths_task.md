INTENT: A CLI coder that edits a protected path currently finds out only after the whole run is spent, when the engine diffs the branch and rejects the task. Nothing in the prompt it is given mentions the boundary, so the run is wasted on work that was always going to be refused. Make that knowledge available before the coder starts.

OUTCOME: A coder that is asked to do work in a repository whose protocol declares paths off-limits is told which paths those are, and is also told about the engine's own state directory, which is off-limits whatever the protocol declares. A coder working in a repository that declares nothing is still told about the engine's own state directory. The paths a coder is shown are the paths the engine will enforce for that run, taken from the protocol the engine already loaded, so there is no second list that can drift from the enforced one. Both families of locally-running CLI coder behave the same way, so neither is left uninformed. The wording reads as a warning about what will be refused, not as a claim that the files are inaccessible.

CONSTRAINTS: Advisory only. The post-execution diff check and the existing state-directory guard keep enforcing exactly as they do now; nothing about them is relaxed, relocated, or removed, and this task does not add a rejection type or change a severity. The in-process coder already has its boundary enforced where it writes and is not part of this work. Shipped protocol templates keep the declarations they already have: this task changes what a coder is told, not what a project declares. The guidance must not imply a sandbox, hidden files, or a read-only boundary, for the reasons recorded in the existing decisions record about why a real write barrier is unavailable for these locally-running coders. Existing prompt content keeps its meaning; this adds information to it rather than rewriting it.

ACCEPTANCE: For a protocol that declares protected paths, the prompt a CLI coder receives contains those paths; for a protocol that declares none, it does not invent any. The engine's own state directory appears in the prompt even when the protocol declares nothing. The behaviour is observable in a test rather than only by reading code, and it holds for both coder families. The suites covering protected paths and coder prompts still pass with their existing expectations about enforcement intact.
