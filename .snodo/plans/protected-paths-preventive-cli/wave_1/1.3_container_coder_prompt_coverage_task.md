INTENT: The advance notice about which paths the engine will refuse now reaches the coder backends that build their prompt through the engine's shared subprocess prompt builder. The backend that runs the same CLI inside a container assembles its prompt on a separate path and is still told nothing. A boundary announced to some coders and not others leaves the operator guessing which runs are informed, and the uninformed one wastes a full run on work that will be refused afterwards.

OUTCOME: Every coder backend the engine can dispatch is shown, before it runs, the same warning naming the paths the engine will refuse: the declarations taken from the protocol the engine already loaded, plus the engine's own state directory, which is refused whatever the protocol declares. The warning is stated once rather than rewritten per backend, so the families cannot drift apart in wording or in what they promise. A backend whose protocol declares nothing is still told about the engine's own state directory and is not shown invented paths.

CONSTRAINTS: Advisory only. The post-execution diff check, the state-directory mutation guard that in-place coders already run, and the in-process coder's rejection where it writes all keep enforcing exactly as they do now; nothing is relaxed, relocated, or removed, and no new rejection type or severity is introduced. Shipped protocol templates keep the declarations they already have: this changes what a coder is told, not what a project declares. The wording must not imply a sandbox, hidden files, or a read-only boundary, for the reasons recorded in the existing decisions record about locally-running coders. Existing prompt content keeps its meaning; this adds information to it.

ACCEPTANCE: The prompt a containerised coder receives contains the declared paths and the engine's own state directory, observable in a test rather than only by reading code. The prompt tests for the other coder families still pass. A protocol that declares no paths does not cause any to be shown. The suites covering protected paths and coder prompts stay green with their existing expectations about enforcement intact.
