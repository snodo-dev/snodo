# Example plugin install steps miss uv-tool snodo installs

Before any change, open a GitHub issue in snodo-dev/snodo describing the gap below. Put "Fixes #<issue number>" in the commit message, and add a CHANGELOG entry under ## [Unreleased].

## INTENT
Someone following the "Try it in a minute" path should end up with the plugin loaded into the Python that runs their `snodo` command. Many users install snodo with `uv tool install`. For them, a plain `uv pip install -e` installs the plugin into whatever environment is active, not into snodo's own tool environment, so the plugin never shows up.

## THE CHAIN
- examples/snodo-hello-validator/README.md says `uv pip install -e /path/to/snodo/examples/snodo-hello-validator`, and docs/extending.md points to that README.
- What worked on a real uv-tool install was `uv pip install --python ~/.local/share/uv/tools/snodo/bin/python -e <example dir>`.
- Uninstall has the same problem: `uv pip uninstall --python ~/.local/share/uv/tools/snodo/bin/python snodo-hello-validator`.
- `uv tool install snodo --with <path>` may be the more idiomatic route. Check it and prefer it if it works.

## CONSTRAINTS
- Docs only: the example README, docs/extending.md and the CHANGELOG. No code changes.
- Cover the uv-tool case and a plain virtualenv or pip case. Keep it short, and keep each command on its own line so it can be copy-pasted.
- Include a one-line check that tells the user which Python their `snodo` runs on, so they can target it.

## ACCEPTANCE
- The README and docs/extending.md show working install and uninstall commands for a uv-tool snodo and for a pip or venv snodo.
- If the repo has a docs link checker or markdown test, it passes; run only that targeted check.
- There is a CHANGELOG entry under ## [Unreleased].
