# 3.2 — the tunnel paths wrap a real mcp 2.x app without losing host protection

GitHub issue #1027 already exists for this work. Do not open another; put "Fixes #1027" in the commit message. Do not edit the CHANGELOG; the other task of this wave owns the single entry.

## INTENT

For a service-token tunnel, `_run_server` replaces the server's `streamable_http_app` and `sse_app` factories with wrappers that put the tunnel path router (`TunnelMCPPaths` in `snodo/cli/commands/serve_tunnel_asgi.py`) in front of the real app. On mcp 2.x the factories take `host` and `transport_security`; if the wrapper dropped or mis-forwarded either, the router would serve an app without host protection and nothing would say so.

In a new test module under `tests/mcp` (a different file from the other task of this wave), build a real mcp 2.x server through the project's server builder, install the same wrapper the way `_run_server` does for a service-token tunnel (extract or reuse the code path; do not re-implement the wrapper inside the test), call the wrapped factory the way `run` does, and exercise the resulting ASGI app in process (no sockets needed): a good Host reaches the app, a foreign Host is refused, the access path and `/mcp` are routed as the tunnel router specifies, and both factories (`streamable_http_app` and `sse_app`) behave the same.

## Acceptance

- The tests use the real server object and the real router, with at most a stubbed Access verifier.
- A wrapper that dropped `transport_security` or `host` would fail them.
- Existing tests stay green; the linter is clean.

## Constraints

- No new halt types, severities or statuses. No new dependency; do not raise any length baseline. Tests only unless the wrapper turns out to lose an argument, in which case fix that in the smallest way and say so in the commit message.
