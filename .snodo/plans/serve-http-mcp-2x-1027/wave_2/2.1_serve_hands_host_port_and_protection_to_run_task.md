# 2.1 — `snodo serve` hands host, port and protection to the server the mcp 2.x way

GitHub issue #1027 already exists for this work. Do not open another; put "Fixes #1027" in the commit message. Do not edit the CHANGELOG; a later task in this plan owns the single entry.

## SYMPTOM AND EVIDENCE

On main with mcp 2.3.0, `snodo serve --tunnel --tunnel-transport ws --verbose` provisions a tunnel and then dies:

```
snodo/cli/commands/serve_cmd.py:335 in _run_server
    mcp.settings.port = port
ValueError: "Settings" object has no field "port"
Error: MCP server exited with code 1.
Rolled back tunnel: ...
```

The same happens for any non-stdio serve (`--transport streamable-http` or `sse`, with or without a tunnel). Stdio serve starts, which is why MCP clients never noticed.

## INTENT

`_run_server` in `snodo/cli/commands/serve_cmd.py` assigns `mcp.settings.port` and `mcp.settings.host` (two places: the non-stdio branch and the stdio branch with an explicit `--port`) and then calls `configure_http_transport`, which mutates a settings field that no longer exists, before `mcp.run(transport=transport)`. On mcp 2.x those values are arguments: the installed `MCPServer.run` forwards keyword arguments to `run_streamable_http_async` / `run_sse_async`, which take `host`, `port` and `transport_security`, and the `streamable_http_app` / `sse_app` factories take `host` and `transport_security`. Confirm the exact forwarding against the installed mcp package.

Make the HTTP path work on mcp 2.x: the chosen loopback host, the chosen port and the transport security built by the helper added in the previous wave reach the server through `run`. Preserve everything else the function does today: the port choice and bind-failure messages, `FORWARDED_ALLOW_IPS` handling, the printed URLs, and the tunnel ASGI wrapper that replaces `streamable_http_app` / `sse_app` (it already forwards `*args, **kwargs`; make sure the host and transport security reach the real factory through it).

Decide, from the code, what the stdio branch with an explicit `--port` should do now that stdio takes no port; keep the observable behaviour (the port is still recorded and reported) without touching a settings field. Once nothing uses it, remove `configure_http_transport` and its import, keeping the environment handling it did.
