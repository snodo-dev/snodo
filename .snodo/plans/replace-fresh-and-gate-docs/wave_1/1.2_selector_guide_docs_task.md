## Intent
A change to a docs file that the MCP guide serves at runtime selects the tests that consume it, so a docs-only task can no longer pass the per-task gate while breaking the guide tests. Docs changes that the guide does not serve keep selecting nothing, so ordinary docs edits stay cheap.

## Evidence
- A task that changed only docs/authoring-a-plan.md selected no tests. The guide reads that file at runtime, and tests/mcp/test_server.py asserts the default guide output stays under 1000 characters. The change pushed it over; the gate passed; the failure surfaced one wave later in other tasks.
- The selector maps changed Python files to tests by import and returns the whole suite for a short list of shared files. Any other path is dropped. The existing test test_docs_only_change_selects_nothing pins that behaviour.
- The guide serves top-level markdown files in docs/ that carry snodo-guide markers. Tests that consume them: tests/mcp/test_server.py (guide tests), tests/mcp/test_structure_guidance.py and tests/mcp/test_blocked_plan_guidance.py. Confirm the list against the repo and include any further consumer you find.

## Outcome
- A diff that touches a top-level docs file carrying guide markers selects the guide's consuming test files, and nothing more than those for that file.
- A deleted or renamed guide doc still selects them: the markers are read from the base version when the file no longer exists at HEAD.
- Docs files without guide markers still select nothing.
- The rule is expressed as data that maps changed paths to the tests that consume them, so that later tasks can add further runtime-read inputs without a new branch of logic. It sits beside the existing shared-file handling and does not use the whole-suite result.
- The docs-only test is updated to say what is now true (a non-guide docs change selects nothing), and new tests cover a guide doc change, a deleted guide doc, and a docs file without markers.
