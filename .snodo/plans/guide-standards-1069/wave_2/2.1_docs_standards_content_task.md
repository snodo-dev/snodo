## Intent
docs/authoring-a-plan.md carries a Standards & Conventions section, served by the `standards` guide topic, that tells a plan author everything the validators will refuse, and the two statements in the document that are wrong are corrected. The default `guide()` output, which every consumer reads first, stays within its size budget.

## Symptom and evidence
Recon rec_32a560 compared what the code enforces with what the guide teaches. Not taught anywhere in the guide today:
- `generate_spec` refusals: `task_exists` (resolved with `replace=true`), `parent_not_found`, `max_subtask_depth_exceeded` (default depth 3) and `cycle_detected` (a spec identical to an ancestor's).
- Wave `depends_on` entries must be integers, and wave ids are integers contiguous from 1.
- Malformed plan.yml, malformed status.json and a missing plan directory are reported as `Failed to parse plan.yml`, `Failed to parse status.json`, `Plan directory does not exist`.
- `intent_ref` form `int_<6 hex>` and the 10,000 character limit on recorded intent text.
- Branch names, commit subjects and issue references are produced by the engine; they are not plan acceptance rules and a plan should not try to satisfy them.
- Same-wave file overlap is a warning, and a path created only by a later task is an error.

Two statements in the document are wrong:
- The status.json section lists five task statuses; there are six, `unmerged` is missing (the vocabulary is in packages/snodo-mcp/src/snodo/mcp/status.py).
- The planning guidance says a newly created path must be declared with an exact phrase on the same line; the implementation in packages/snodo-foundation/src/snodo/infrastructure/worktree.py accepts several creation phrasings on the same or an adjacent line. Read the code and write what it does.

A size problem already exists on the base this task starts from. The first wave registered the `standards` topic with a one-line summary, and the default `guide()` output is now 1031 characters. The test `test_guide_default_is_source_backed_and_mode_honest` in tests/mcp/test_server.py requires it to stay under 1000, and it fails. That test blocked every task of the last run, so this task has to put the default output back under the budget.

## What done looks like

- The two wrong statements are corrected from the code.
- The default `guide()` output is under 1000 characters again, reached by tightening topic summaries (starting with the one for `standards`), not by raising the limit in the test. The tests in tests/mcp/test_server.py pass.
- Existing sections keep their meaning; this task adds and corrects, it does not restructure.
