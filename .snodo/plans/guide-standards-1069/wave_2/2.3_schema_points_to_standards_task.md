## Intent
The `generate_spec` and `propose_plan` schema text points a consumer to the `standards` guide topic, which exists once the first wave of this plan has landed.

## Evidence
In the first wave, the schema text task ran in parallel with the task that registers the `standards` topic. At that time the topic was not registered, so the schema text in packages/snodo-mcp/src/snodo/mcp/tools.py points to the `mistakes` topic instead. With `standards` now served, the pointer should name the topic that actually carries the layout and task-id rules.

## What done looks like
- Wherever the schema descriptions in packages/snodo-mcp/src/snodo/mcp/tools.py refer a consumer to a guide topic for task ids, layout and plan standards, they name `standards` (keeping `mistakes` for the refusal and authoring checklist if that is what the text means there).
- Confirm in the code that `standards` is a registered guide topic before pointing to it.
- If a test pins the exact schema text, update it deliberately.

## Constraints
- Text changes in the schema descriptions only; behaviour of the tools does not change.
- Do not add states, statuses, severities or halt types.
