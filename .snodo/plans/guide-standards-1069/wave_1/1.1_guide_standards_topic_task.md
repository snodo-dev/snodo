## Intent
The MCP `guide` tool gains a `standards` topic that serves the plan-authoring standards a consumer must respect, starting with the part of docs/authoring-a-plan.md that is written but never served today.

## Symptom and evidence
An MCP consumer (snodo-cloud's dispatcher) had plans rejected because it never learned the task-id form `<wave>.<seq>_<name>`. The rule, its regex and the worked examples exist in docs/authoring-a-plan.md under "Task ids", inside the "## 2. Layout" section. That section has no guide marker, and the guide builds each topic from a marked heading up to the next heading of the same or higher level (see packages/snodo-mcp/src/snodo/mcp/guide.py), so the layout, plan.yml, status.json and task-id text is reachable through no topic. Recon rec_32a560 confirmed this independently across three agents.

## What done looks like
- `guide(topic="standards")` returns the Layout material, including the task-id rule with its regex and examples, the requirement that the leading number equals the wave listing the task, and where each spec file lives.
- The topic appears wherever the guide lists its topics (the tool description and any index output), described in one line.
- It works through the existing marker mechanism in docs/authoring-a-plan.md and guide.py; follow how the other topics are registered rather than adding a new way of serving sections.

## Constraints
- Keep the change small and in the guide's existing style. Do not rewrite other topics.
- Do not add states, statuses, severities or halt types.
- Later tasks in this plan add more content to the same document and write the tests, so this task only needs the topic to exist and serve the Layout material.
