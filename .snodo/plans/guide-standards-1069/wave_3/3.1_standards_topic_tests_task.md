## Intent
Tests keep the `standards` guide topic from silently losing the rules that an MCP consumer needs.

## Evidence
The task-id rule was written in docs/authoring-a-plan.md for a long time without being served, because nothing checked that the guide reached it. The earlier waves of this plan add a `standards` topic, extend the schema text for `generate_spec` and `propose_plan`, and correct the status list in the document.

## What done looks like
- A test asserts that `guide(topic="standards")` is served and contains the task-id form `<wave>.<seq>_<name>`, the requirement that the leading number equals the listing wave, and the `replace=true` rule.
- A test asserts that the topic is listed wherever the guide lists its topics.
- A test asserts that the status vocabulary in the document names all six statuses defined in packages/snodo-mcp/src/snodo/mcp/status.py, so the document and the code cannot drift apart again.
- A test asserts that the `generate_spec` task_id schema text states the wave-equals-listing rule.
- Put the tests beside the existing tests for the guide tool and follow their style.

## Constraints
- Test behaviour a consumer relies on, not exact prose; match on the key rule words so wording can be improved later.
- Do not add states, statuses, severities or halt types.
