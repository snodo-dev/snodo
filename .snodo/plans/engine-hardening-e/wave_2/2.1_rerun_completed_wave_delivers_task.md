## Intent
When every task in a wave is completed (some recorded by hand), running the wave again finishes it by merging the integration work to main, instead of exiting as if nothing needed doing.

## Evidence
- In a recent plan, wave 2 had its last task hand-merged and recorded completed. `run_plan` with that wave returned a job that completed in about one second with exit 0 and no merge; the integration branch, still holding two completed tasks, stayed unmerged until the orchestrator merged it by hand. Wave 3 later merged normally, so the behaviour depends on how the wave was reached.
- The wave runner is in snodo/cli/commands/plan_run.py (it builds the list of pending tasks and only delivers after dispatching), and delivery of a healthy wave is `deliver_healthy_plan_wave` in snodo/cli/commands/plan_delivery.py.

## Outcome
- A rerun of a wave with no pending tasks merges any unmerged integration work to main and reports that it did, or says clearly why it did not (for example nothing to merge, or a wave task that is not completed).
- Tests: a wave that ends with all tasks completed, one of them via `record_task_status`, delivers on rerun; a rerun with nothing left to merge reports that and changes nothing.
- `make gate` passes.
