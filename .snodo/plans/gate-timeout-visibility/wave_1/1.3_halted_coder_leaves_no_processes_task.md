Don't run the full `make gate` inside your session; run only targeted tests. The post-execute gate runs the full suite, and a full run in-session hits the 600s silence limit.

INTENT
On 2026-10-08 several coders ran `make gate` themselves inside their sessions, even though their specs asked for targeted tests only. They went quiet past the 600s silence limit, and snodo logged "Coder halted after 600s of silence; judging the N artifact(s) it produced." In every case the quality gate that ran right afterwards timed out at 600s, while the same main passes `make gate` by hand in 76s.

The silence halt kills only the coder's own process group (`os.killpg` in SubprocessCoderAdapter._run_subprocess, packages/snodo-engine/src/snodo/coders/subprocess_adapter.py). An earlier code survey (recon rec_91a7b8) noted that a detached grandchild is not reaped. Coder CLIs often run each shell command in a new session or process group, so a `make gate` started by the coder, with its ssh connection and the remote test run, can outlive the halt. It can then compete with, or hold gate slots needed by, the real quality gate that runs next in the same worktree.

When this is done, a coder halted for silence or wall-clock timeout leaves no descendant processes running. Every descendant gets TERM, then KILL after a short grace period, including those that called setsid or started a new process group. scripts/gate_remote.sh already does the equivalent with a descendant-tree walk (gate_reap); a Python equivalent (psutil if it's already a dependency, otherwise a /proc or ps walk) is an indication, not a prescription. Cleanup failures are logged and never mask the halt. The halt still proceeds to judge the artifacts, as it does today.

THE CHAIN
1. Confirm how descendants escape today with a fake coder that spawns a setsid child which sleeps.
2. Reap the whole descendant tree on silence or timeout halts, and on normal exit if stragglers remain.
3. Tests:
   - after a silence halt, a setsid grandchild and a plain grandchild are both gone;
   - a coder that exits normally isn't slowed by the reaping.
