# The HTTP MCP transport disables DNS-rebinding protection and runs unauthenticated without a tunnel

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
`snodo serve` over HTTP never exposes write-capable tools to a web page or network peer that the user didn't intend to trust:
- on loopback, DNS-rebinding protection is on, and only the hosts snodo actually serves are allowed (localhost names, plus the configured tunnel hostname when a tunnel is used);
- binding a non-loopback address without any auth is refused, or clearly warned against.

## THE CHAIN
Recon rec_f8c7a8 found the following, and the orchestrator checked it against the code:
- In `snodo/cli/commands/serve_cmd.py`, an auth verifier is only wired when there is a tunnel hostname and `oauth` is in the auth methods (around line 271).
- For every non-stdio transport the code sets `FORWARDED_ALLOW_IPS="*"` and `transport_security.enable_dns_rebinding_protection = False` (around lines 350–353).
- So `snodo serve --transport streamable-http` without a tunnel serves write_file, commit, merge_branch and similar tools with no auth and no rebinding protection. A malicious page in the user's browser could reach it through DNS rebinding.

## CONSTRAINTS
- Turn rebinding protection on with an explicit allowed-hosts list (loopback names with the port, plus the tunnel hostname when configured). Make sure the existing tunnel flow, where cloudflared forwards to localhost with the tunnel Host header, keeps working. Restrict `FORWARDED_ALLOW_IPS` to what the tunnel needs instead of `*`.
- Binding a non-loopback host with no auth configured must be refused unless the user passes an explicit opt-in. Follow the CLI's existing option style; no new top-level command.
- Existing auth paths (oauth through the tunnel, service tokens) keep working.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the targeted serve tests (`tests/mcp/test_server.py`, `tests/mcp/test_serve_lifecycle.py`, `tests/cli/test_serve_auth.py`, plus new ones) with `-n auto`.

  - binding a non-loopback host without auth is refused unless the user opts in explicitly;
