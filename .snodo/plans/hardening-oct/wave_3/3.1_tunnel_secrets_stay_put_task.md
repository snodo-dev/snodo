# Tunnel secrets leak onto the terminal and the process list

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Tunnel credentials (the tunnel token, client secrets and service-token secrets) never appear on stdout or stderr, and never in another process's command line. The user is told where a secret is stored and how to get it on purpose.

## THE CHAIN
- `snodo/cli/commands/serve_cmd.py` starts cloudflared as `cloudflared tunnel run --token <tunnel_token>` (around line 1351). Any local user can see the token with `ps`. cloudflared also reads the token from the `TUNNEL_TOKEN` environment variable.
- The same file prints `Client secret: {new_secret}` on rotation (around line 1176) and `CF-Access-Client-Secret: …` (around line 1465).
- An earlier wave of this plan hardened the HTTP transport in the same file; build on its result.

## CONSTRAINTS
- Pass the tunnel token to cloudflared through the child's environment (`TUNNEL_TOKEN`) instead of argv.
- Replace each printed secret with a short message naming where it is stored. If a user genuinely needs a secret once (first-run client setup), print it only behind an explicit flag, following the CLI's existing option style. No new top-level command.
- Copy reads plain and soft. Avoid "not X but Y" contrast phrasing.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run the serve and tunnel tests with `-n auto`.

## ACCEPTANCE
- Tests show:
  - the cloudflared argv has no token and its env carries `TUNNEL_TOKEN`;
  - captured output of the rotation and first-run paths contains no secret value unless the explicit flag is given;
  - existing serve and tunnel tests pass.
