Before starting, open a GitHub issue on snodo-dev/snodo titled "Recon final answer: truncation fails the lane and the fallback returns narration". Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased].

INTENT
Recon now forces a `submit_answer` tool call on the final turn. When that doesn't yield an answer, two behaviours make recon useless on big questions.

Evidence from recon rec_8d4640:
1. deepseek's final response hit `finish_reason=length`, and the whole lane failed: "Output was truncated (finish_reason=length)". Whatever answer text it had produced was thrown away.
2. qwen's result was "Partial answer (final response was unusable):" followed only by narration between reads: "I'll systematically trace…", "Let me now read the key files…". That is not an answer. The fallback concatenates turn-to-turn narration, which an earlier design deliberately excluded because narration is never the answer.
3. gemini returned an empty result. The trace stored with the result shows how its run ended. Read the result-trace code to see which path produces an empty result despite the forced submit.

When this is done:
- **Truncated final answer:** if it carries text (in the `submit_answer` arguments or in content), that text is kept as the answer. The result clearly says it was truncated. It never fails the lane outright.
- **No usable answer from the forced submit:** if the final turn returns nothing usable (empty, unparseable arguments, or no tool call), recon retries the forced submit once. The retry includes a short reminder that a partial answer is still an answer.
- **Retry also fails:** the lane fails with an honest error that names how the run ended, using the existing trace. The narration-only "partial answer" is not returned.
- **Providers without named tool_choice:** for models that don't honour a named `tool_choice`, the final turn still works. Accept an answer delivered as plain content on that turn.

THE CHAIN
1. Final-answer extraction keeps truncated text and marks it as truncated.
2. The empty-final path retries once, then fails honestly. The narration fallback is removed.
3. Tests cover four cases: a truncated `submit_answer` is kept and marked; an empty final answer is retried, then succeeds; an empty final after the retry fails with a trace-based error and no narration; a content-only final answer is accepted.

CONSTRAINTS
- Snodo's state machine is closed: add no status, halt type, severity or audit event.
- Keep the shared read tools, the trace, and the budget defaults from the previous task.

ACCEPTANCE
- The tests in link 3 exist and pass.
- The CHANGELOG entry is present.
- `make gate` passes.
