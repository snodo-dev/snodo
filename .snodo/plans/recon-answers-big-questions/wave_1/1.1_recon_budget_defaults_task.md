Before starting, open a GitHub issue on snodo-dev/snodo titled "Recon default reading budget dropped to 6 turns; big questions fail". Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased].

INTENT
The recent recon fix made the reading budget configurable (`llm.recon.max_tool_turns`, `llm.recon.max_tokens`). But when unset, the default is now 6 turns: see the `max_tool_turns` defaults in the recon MCP handler and the recon manager and agent functions. That is lower than the old hard-coded 10. The owner has not set the keys, so every recon now gets 6 turns.

Evidence: recon rec_8d4640 asked to trace a flow end to end across dashboard, API and workers. All three agents failed:
- gemini returned an empty result;
- deepseek failed with "finish_reason=length";
- qwen returned only narration ("Let me read the key files…").

A small single-file question, rec_914510, worked within 6–8 turns. So the budget is too small for real questions.

Intended defaults: recon should get a reading budget comparable to the validator's configured budget (the owner runs validators at 40 turns and 8,000 output tokens). Its output allowance must also be large enough for a multi-section answer with citations. The value 6 comes from the typed engine default for validators, which is not a sensible recon default.

When this is done:
- With no `llm.recon` budget set, recon gets at least 40 reading turns.
- With no `llm.recon` budget set, recon's output-token allowance fits a long, structured answer: at least 16,000 tokens, unless the model's own limit is lower.
- Configured values still override both defaults.
- The handler, the manager and the agent functions share one source for these defaults, so they can't drift apart again.

THE CHAIN
1. One place defines recon's default turn and token budget. The MCP handler, the recon manager and the agent call path all use it.
2. `docs/configuration.md` states the defaults.
3. Tests: with no config, the agent run receives the new defaults; configured values override them.

CONSTRAINTS
- Snodo's state machine is closed: add no status, halt type, severity or audit event.
- Don't change the final-answer handling. The next task owns that.

ACCEPTANCE
- The tests in link 3 exist and pass.
- The CHANGELOG entry is present.
- `make gate` passes.
