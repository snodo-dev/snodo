# Spinner tests fail on GitHub runners because `CI` is set

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
`tests/cli/test_spinner.py` gives the same result on a developer machine and on a CI runner. The spinner's own behaviour, including switching itself off under CI, stays as it is.

## THE CHAIN
- Evidence: CI run 38089625587 and release run 38089625681, on v0.23.0. The `test (3.12)` job and the release "Test suite" step both fail on:
  - `test_spinner_preserves_stdout_and_clears_after_success`: assert '\x1b[2K' in '';
  - `test_line_cleared_after_exception`;
  - `test_non_utf8_terminal_uses_ascii_frame`: assert '[-]' in ''.
- In each case the fake Terminal captured nothing.
- `snodo/cli/spinner.py` (around lines 66–76) stays silent when `CI`, `NO_COLOR`, `TERM=dumb`, `SNODO_NO_SPINNER=1`, `SNODO_MCP_SERVER` or `SNODO_JOB_ID` is set. GitHub Actions always sets `CI=true`.
- The tests that expect drawing don't control these variables. They pass locally and fail on runners, and this has kept the release workflow from publishing v0.21.0 to v0.23.0 to PyPI.

## CONSTRAINTS
- Test-only change: control those environment variables in the spinner tests, for example with an autouse fixture using monkeypatch. Do not change `snodo/cli/spinner.py`.
- If no existing test proves that CI suppresses the spinner, add one that sets `CI` and asserts nothing is drawn.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` on touched files. Run only the targeted tests: `tests/cli/test_spinner.py`, once normally and once with `CI=true` set in the environment.

## ACCEPTANCE
- `tests/cli/test_spinner.py` passes both with and without `CI=true` in the environment.
- There is a CHANGELOG entry under ## [Unreleased].
