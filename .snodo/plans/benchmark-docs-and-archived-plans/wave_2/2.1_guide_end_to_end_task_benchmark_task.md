# 2.1_guide_end_to_end_task_benchmark

## INTENT
The user guide `docs/choosing-models.md` describes the task benchmark as three separate paragraphs. A reader who wants to try a different coder model on a task they already completed has no single path to follow. This task adds a short end-to-end walkthrough: pick a completed task, set its baseline, run a candidate, read the comparison, and understand what is scored.

## STARTING STATE
Wave 1 of this plan has been merged: archived plans work with `--set-baseline` and `--benchmark-run`, `docs/command-reference.md` states the prerequisites and what `--model` selects, and `docs/machine-interface.md` documents the comparison JSON. Link to them; do not repeat them in full.

## THE CHAIN
1. Open a GitHub issue first ("User guide has no end-to-end walkthrough for the task benchmark") and put "Fixes #<n>" in the commit message.
2. Read the "Compare a task benchmark" section of `docs/choosing-models.md` and the code in `snodo/cli/commands/models_cmd.py`, `models_baseline.py`, `models_benchmark.py`, `models_benchmark_notice.py` and `plan_compare.py`. The walkthrough shows commands to copy and the lines the commands really print (take the wording from the code and its tests); do not invent sample numbers or paste output that was not produced by the code. Use a placeholder-free example: plan `coder-tool-surface-guardrails-956`, task `1.1_bounded_tool_results`, and a candidate model written in the `opencode-cli/<provider>/<model>` form, with one sentence saying that a bare provider string makes direct paid API calls.
3. Add the walkthrough to that section as numbered steps (a numbered list is right here because the steps are a sequence): choose a task with a completed recorded run; `--set-baseline`; `--benchmark-run`; read the comparison (score, direction, the three scored signals, the unscored metrics, the harness-difference notice); optionally repeat with another model and `--compare --job`. End with a short paragraph on reading the result: a different coder harness makes token counts not comparable, and a candidate that does not complete is still shown.
4. `CHANGELOG.md` gets one new line under `[Unreleased]` in the same commit, in the style of the neighbouring entries, ending with "(Fixes #<n>)".
5. Run the docs checks the gate runs for `docs/`; fix what they report in your own change only.
