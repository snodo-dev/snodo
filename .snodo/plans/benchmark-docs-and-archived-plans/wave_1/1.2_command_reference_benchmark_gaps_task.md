# 1.2_command_reference_benchmark_gaps

## INTENT
The `snodo models` section of `docs/command-reference.md` lists `--benchmark-runs` among the flags and describes baseline, candidate run and comparison, but it does not say what a reader needs to use them: what must be true before a baseline can be set, what `--benchmark-runs` does, and above all what `--model` selects in `--benchmark-run`. A reader can easily take `--model` to cover the validators too; the code in `snodo/cli/commands/models_benchmark.py` passes it as the task's model, so it selects the coder, and the validators follow the protocol's own configuration. Evidence of the gap: a first end-to-end attempt on 2026-11-09 had to read the source to learn all of this.

## THE CHAIN
1. Open a GitHub issue first ("Command reference lacks prerequisites and meaning of --benchmark-runs and --model for task benchmarks") and put "Fixes #<n>" in the commit message.
2. Read `snodo/cli/commands/models_cmd.py`, `models_baseline.py`, `models_benchmark.py` and `models_benchmark_notice.py`, and the current text around the `snodo models` table in `docs/command-reference.md`. Every statement you write must be checked against that code; write nothing you have not seen it do.
3. Extend that section, in the prose style already used there, with: (a) the prerequisites for `--set-baseline` (the task has a completed recorded run with its change range and model provenance; the plan is found in the live or archive plan folders only if task 1.1 of the plan benchmark-docs-and-archived-plans has been merged, so describe the live folder and say nothing about the archive); (b) what `--benchmark-runs` does and its allowed range, read from the code; (c) that `--model` in `--benchmark-run` selects the coder model while validators use the protocol's configured models; (d) where the candidate runs (a disposable `benchmark/<plan>/<task>/<id>` branch, never merged) and where the baseline is stored.
