# 1.1_baseline_and_run_find_archived_plans

## INTENT
`snodo models --set-baseline` and `snodo models --benchmark-run` only look for a plan in `.snodo/plans/`. Completed plans are moved to `.snodo/plans-archive/`, so the commands cannot be used on the tasks most worth benchmarking: they are finished and their recorded runs exist. Symptom and evidence: `snodo models --set-baseline --plan coder-tool-surface-guardrails-956 --task 1.1_bounded_tool_results` fails at once with "Plan 'coder-tool-surface-guardrails-956' not found." although `.snodo/plans-archive/coder-tool-surface-guardrails-956/` holds its plan.yml, status.json and wave folders. The task's recorded run is complete and attributable, so only the plan lookup stands in the way.

The wanted behaviour: a plan is found in `.snodo/plans/` first and in `.snodo/plans-archive/` otherwise, by both commands (`--set-baseline` in `snodo/cli/commands/models_baseline.py`, and the task-spec lookup of `--benchmark-run` in `snodo/cli/commands/models_benchmark.py`). The error for a plan present in neither place stays as it is.

## THE CHAIN
1. Open a GitHub issue first ("Baseline and benchmark-run cannot use an archived plan") and put "Fixes #<n>" in the commit message.
2. Read how the two commands locate the plan directory and the task spec today, and how other code in the repository already resolves a plan across the live and archive folders (use that helper if one exists rather than writing a second one).
3. Make both commands accept an archived plan. Do not move, copy or modify anything in the archive.
4. Add tests in a new file `tests/cli/test_models_archived_plan.py` with exactly these names: `test_set_baseline_finds_plan_in_archive`, `test_benchmark_run_reads_spec_from_archived_plan`, `test_set_baseline_still_reports_unknown_plan`. Use the fixtures and helpers the neighbouring models/baseline tests use.
5. `CHANGELOG.md` gets one new line under `[Unreleased]` in the same commit, in the style of the neighbouring entries, ending with "(Fixes #<n>)".
6. The project supports Python 3.12. Do not run `ruff format` over whole files. Run `python -m pytest tests/cli/test_models_archived_plan.py` and `ruff check packages tests snodo`.

## CONSTRAINTS
- Files that may change: `snodo/cli/commands/models_baseline.py`, `snodo/cli/commands/models_benchmark.py`, a shared helper module only if one is clearly needed, the new test file, `CHANGELOG.md`.
- No new states, statuses, severities, halt types or event names.

## ACCEPTANCE
- Both lookups consult `.snodo/plans-archive/` when the plan is not in `.snodo/plans/`, and `.snodo/plans/` still wins when a plan exists in both.
- `tests/cli/test_models_archived_plan.py` exists and contains the three named tests.
- The diff adds one line under `[Unreleased]` in CHANGELOG.md that mentions the issue.
- No file outside the list under CONSTRAINTS differs.
