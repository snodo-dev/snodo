INTENT
The config layer now has a typed dotted-key resolver for provider (any name), cloud and notification fields. It validates through the strict runtime models and marks secret fields. `snodo config validate` also exists. But `snodo config set` and `config get` still accept only `model`, `engine.*` and `llm.*`, so users still hand-edit YAML to point snodo at a local model.

When this is done:
- `snodo config set` and `config get` work for those key paths through the resolver. For example, `snodo config set providers.ollama.base_url http://localhost:11434/v1`.
- Secret values are redacted on `get`.
- Errors name the key.
- The "Unknown config key … edit by hand" guidance in the docs is replaced with the CLI way.
