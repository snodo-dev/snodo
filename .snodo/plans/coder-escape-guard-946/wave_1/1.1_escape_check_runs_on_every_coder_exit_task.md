## Intent
The engine's workspace-escape check should run on every way a coder run can end, so a coder that escapes its workspace is reported whether or not it also produced artifacts, timed out, ran out of turns or failed.

## Evidence
- packages/snodo-engine/src/snodo/engine/nodes/executor.py: `_repo_ref_snapshot` is taken once before `coder.implement(...)` and `_escaped_repo_commit` compares it afterwards. In `_default_executor` the comparison runs only on the empty-artifact path, in the `TurnBudgetExhausted` handler and in the `CoderTimeoutError` handler. The path that commits non-empty artifacts, the findings-only path and the `SnodoMutationError`, `AdapterError` and generic exception handlers never run it.
- Subprocess coders can return non-empty artifacts after a timeout or a nonzero exit instead of raising (packages/snodo-engine/src/snodo/coders/subprocess_adapter.py), so those runs also take the unchecked path.
- Live case recorded in issue #946: an `opencode-cli` coder ran `git checkout`, `git commit` and `git clean` in the operator's checkout while its task worktree stayed empty of commits.
- An escape is reported today by raising the existing `ExecutionError`, which the loop already routes to a halt. That route stays as it is.

## Outcome
- The escape comparison happens once on each way `_default_executor` can finish after the coder was started, before artifacts are committed or accepted and before a coder failure propagates. When an escape is found the run ends with the existing `ExecutionError` carrying the escape description; when the run was already failing for another reason, that original reason stays visible in the message.
- A run with no escape behaves exactly as today on every path, including the messages of the existing errors.
- Tests cover: escape plus non-empty artifacts, escape plus findings-only result, escape during a timeout, a turn-budget exhaustion and an adapter failure, and a clean run on each of those paths that is not reported. Follow the existing executor test style in tests/engine/.
- Only the executor and its tests change. No new states, statuses, severities or halt types.
