Order of work: write the tests first, then the script, and commit both together before running `make gate` (the gate refuses to run on an uncommitted tree). A change without its tests is not complete.

## Intent
A small script that answers "which tests does this diff touch?", so a per-task check can run those instead of the whole suite (about 6,190 tests). The script only selects; it does not run anything.

## Evidence
- Every task currently runs the entire fast suite twice (coder, then the quality validator), while CI and the release dry run already run everything on each push.
- `scripts/` holds standalone enforce_* scripts with tests under tests/scripts/; follow that shape (stdlib only, runnable with `uv run python scripts/<name>.py`).
- Source lives in `snodo/` and `packages/<package>/src/snodo/`; tests mirror the areas under `tests/` (cli, engine, mcp, infrastructure, validators and so on).

## Outcome
- New `scripts/select_affected_tests.py --base <commit>` compares the base with HEAD and prints the tests to run, one path per line, then exits 0.
- A changed test file under `tests/` is selected. A changed Python source file selects the test files that name its module (for example `snodo/cli/commands/plan_run.py` and `packages/snodo-engine/src/snodo/engine/loop.py` map to `snodo.cli.commands.plan_run` and `snodo.engine.loop`, matched on a dotted import or a `from ... import` of it), so a test that exercises the module is found even when it lives in another directory.
- A change that can affect everything selects the whole suite by printing the single line `tests/`: `pyproject.toml`, `uv.lock`, `tests/conftest.py`, `tests/strategies.py`, `Makefile`, `scripts/gate_remote.sh`, and `.snodo/protocol.yml`. A diff with no Python or shared-file change (for example only docs) prints nothing.
- It never selects an e2e-marked file differently from today: it prints paths and leaves marker filtering to pytest's existing `addopts`.
- Tests build a throwaway git repository and cover each rule above, including a module mapped from a package path, a shared file forcing `tests/`, a docs-only diff printing nothing, and an unknown or missing base failing with a clear message and a non-zero exit.
- `make gate` passes.
