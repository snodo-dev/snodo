Order of work: write the tests first, then the change, and commit both together before running `make gate` (the gate refuses to run on an uncommitted tree). A change without its tests is not complete.

## Intent
`make gate-task` is the fast per-task check: everything `make gate` checks except the test run, which covers only the tests the diff touches.

## Evidence
- scripts/gate_remote.sh `gate_run` has a `case` on the target (`gate`, `gate-ci`) that differs only in the pytest arguments; the ruff, lint-imports and enforce_* steps after it are identical. The Makefile has `gate` and `gate-ci` targets that run it over ssh with `CHANGELOG_BASE=$(GATE_BASE)`.
- `scripts/select_affected_tests.py --base <commit>` (added earlier in this plan) prints the tests to run, the single line `tests/` for "run everything", or nothing when no test applies.
- tests/scripts/test_gate_remote.py already exercises gate_remote.sh functions and targets.
- Per-task runs currently spend most of their time in the full suite (issue 1068).

## Outcome
- A new target `gate-task` in `scripts/gate_remote.sh` and the Makefile (next to `gate` and `gate-ci`, same dependencies and ssh wrapper) runs the same steps as `gate` in the same order, with pytest limited to the selector's output for the merge base the Makefile already passes as `CHANGELOG_BASE`.
- The selector printing `tests/` runs the same pytest arguments as `gate`; printing nothing skips pytest and says so on the gate's own output line; a selector failure fails the gate rather than running nothing.
- Like the other reduced gate it announces, on the same screen, that it ran a reduced set and which tests, and that it does not decide.
- The usage text and error message in `gate_main` name all three targets.
- Tests cover the three selector outcomes (a list of files, `tests/`, nothing) and the failure case, in the style of the existing gate_remote tests, without needing a remote host.
- `make gate` passes.
