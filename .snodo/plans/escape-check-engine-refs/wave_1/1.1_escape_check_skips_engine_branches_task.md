INTENT
While a coder runs, the engine checks that no branch moved that the coder should not have touched. Branches the engine itself creates and moves, the plan integration branches and the task branches, should never count, whichever plan they belong to.

Evidence: job j_37de6ed4dee1, plan protocol-editor, task 1.3: the coder finished and post-validation was skipped with "Workspace escape detected: ref 'plan/protocol-editor/integration' changed in external checkout(s)". A sibling task of the same plan, running in the same wave, merged into that integration branch while 1.3 was working. Job j_b57b30ef7fa0, plan logs-json-output, task 1.1: the same message for 'plan/protocol-editor/integration', a different plan's branch, even though an earlier fix (Fixes #1259, which ignores other plans' branches when the task knows its plan) was already on main. Healthy tasks keep being stopped and have to be rerun. The earlier fix depends on knowing the plan name; the engine-managed namespaces are known without it.

What it should do: when deciding which moved branches count as an escape, leave out every branch that lives in the engine's own namespaces: plan integration branches (plan/<name>/integration) and task branches (under the configured task-branch prefix), for any plan including the task's own. Everything else is still reported exactly as today, notably main, any other operator branch and any unrelated branch, with the same message. The checkout-content comparison for host runs is unchanged. Keep the earlier plan-name logic only if it is still needed after this; remove it if this makes it dead code.

Tests, and what went wrong last time: an earlier attempt at this ticket passed on the operator's machine, then failed on the gate host in the cases that must still report an escape: one assertion compared the full message and the message differed in how the checkout location was worded, and another case built its moved branch with a real git commit whose output was passed to update-ref and failed there. Write those cases so they do not depend on the host: drive the check with a small stand-in for the repository (its heads and worktree listing) or set up git in a temporary repository with the plain commands, and assert on the ref name and the "Workspace escape detected" prefix, not on the wording of the location. Do not rename or delete the existing test that covers the filtering of other plans' branches; adjust it in place so its coverage stays (a renamed test is reported as a disappeared one). Add new tests under new names.

CONSTRAINTS
Files that may change: packages/snodo-engine/src/snodo/engine/nodes/executor.py and the tests that cover its escape check under tests/engine/. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change message wording for real escapes. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: a moved integration branch or task branch of the task's own plan during a run gives no escape; the same for another plan's branches, with and without a plan name known on the task; a moved main and a moved unrelated operator branch are still an escape with the "Workspace escape detected" message naming the ref. The tests pass when run on a different machine than the one that wrote them. `make gate-task` is green.
