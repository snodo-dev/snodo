Before any change, open a GitHub issue in snodo-dev/snodo describing the gap. Put "Fixes #<issue number>" in the commit message, and add a CHANGELOG entry under ## [Unreleased].

## INTENT
`snodo ready`, where readiness is judged, tells the user when their protocol has drifted from its template and points to the `snodo protocol` subcommand that shows the full diff. `snodo run` keeps a short notice, worded consistently.

## THE CHAIN
- Today `missing_template_validators()` (packages/snodo-foundation/src/snodo/protocols/__init__.py:147-174) is called only from `_print_missing_template_validators` in snodo/cli/commands/run_cmd.py:264-285, from `run_command` at line 386. It prints "Validator set is out of date… Regenerate (snodo init --force) or add them manually", swallows errors, and doesn't change execution.
- `ready` builds findings in snodo/cli/commands/ready_cmd.py.
- This repo has a template-resolution helper and a pure protocol diff function. Use them; find the subcommand name from the `snodo protocol` group.

## CONSTRAINTS
- Express the ready finding with the existing finding shape and severities. No new severity, status or audit event. Drift is advisory and never fails readiness on its own.
- The finding summarises counts per group and names the diff command. It doesn't dump the whole diff.
- Bespoke protocols produce no finding.
- The `run` notice stays non-blocking and keeps swallowing errors.
- Don't touch the `snodo protocol` command module or docs/command-reference.md; another task owns them.
- Do not run the `snodo` CLI or `python -m snodo` in the worktree. Use CliRunner and tmp_path projects. Do not create, change or delete anything under `.snodo/`.
- Run only the ready and run notice tests, not `make gate`.
