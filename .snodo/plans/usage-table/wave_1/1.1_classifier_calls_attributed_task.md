New files this task will create: none.

INTENT
The work-type classifier's model calls show up in the usage records under their own role and with the task they belong to, and the line written when the classifier switches model carries no provider error text.

Evidence: the usage records kept in a job's state.json attribute each call to a role. In a recent plan run the validators appear as validator:security, validator:adr and so on, but the classifier's calls (a small fast model, about 1.8k input tokens each) are recorded with role "unknown" and task_id "unknown", so a per-role table would show an "unknown" row nobody can interpret. The validators set their role and task in the metadata they pass with each completion; the classifier call in packages/snodo-engine/src/snodo/engine/nodes/governance.py does not. The same module writes the classifier's model-switch progress line with the first line of the provider's error message (up to 160 characters); ADR 063 and the security review of the validator fallback decided that such a line names the two models and the exception type only, because provider error text can carry request details.

What it should do: classifier completions carry metadata naming the role "classifier", the job and the task they serve, the way the validators' calls do, so the usage tracker records them under that role. The switch line names the failed model, the next model and the exception type, and nothing from the error message. No change to which model is called, to classification results or to the fallback order.

CONSTRAINTS
Files that may change: packages/snodo-engine/src/snodo/engine/nodes/governance.py (and the classifier module it calls if that is where the metadata belongs) and tests under tests/engine/. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change the usage tracker, the validators or the fallback helper. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: the classifier's completion request carries role "classifier" plus the job and task ids; a usage record produced for it is attributed to that role; the switch progress line contains both model names and the exception type but not the error text. `make gate-task` is green.
