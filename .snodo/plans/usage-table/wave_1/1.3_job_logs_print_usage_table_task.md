New files this task will create: none.

INTENT
`snodo logs <job_id>` ends with the per-role usage table, so anyone looking at a finished or running job sees where its model time and tokens went without asking for JSON.

Evidence: a job's state.json holds one usage record per model call (role such as validator:adr or coder, model, input and output tokens, duration_ms, outcome, with failed attempts included). `snodo logs <job_id> --json` already reports these as `by_role` and totals through summarize_usage (snodo/cli/commands/logs_cmd.py, _emit_job_json), and recon output ends with a table built by render_usage_summary in snodo/usage_summary.py (columns: role, input tokens, output tokens, model time, output tok/s). The ordinary text view of a job (`snodo logs <job_id>`, both the streamed stdout view and the plan-job view) prints no usage at all.

What it should do: when the job's state has at least one usage record, finish the text output of `snodo logs <job_id>` with the same table recon prints, one row per role followed by a total row, built from the job's records with the existing helpers. A job with no usage records prints nothing extra. The JSON output, the exit codes and the existing text are unchanged, and when the logs are followed live the table appears once at the end, not on every refresh.

CONSTRAINTS
Files that may change: snodo/cli/commands/logs_cmd.py and tests/cli/test_logs_cmd.py (plus tests/cli/test_logs_json_job.py only if an existing assertion must be kept in step). Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change snodo/usage_summary.py, the JSON schema or any other command. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: a job whose state has usage records ends its text output with the table (roles in order of first appearance, then total), failed-attempt records are counted, a job without usage prints no table, and the JSON output is byte-for-byte what it was. `make gate-task` is green.
