New files this task will create: none.

INTENT
The coder's usage records say which task they belong to, so a per-task and per-role table can include the coder.

Evidence: in the usage list of a plan job's state.json, the coder records (role "coder", the opencode-cli model, input/output tokens and a duration of minutes) have task_id None, while the validators' records carry their task ids (or "wave:N"). Anything that groups or filters usage by task therefore drops the coder, the most expensive role. The in-place coder path records its run through record_inplace_coder_run in packages/snodo-foundation/src/snodo/infrastructure/usage_tracker.py, called from packages/snodo-engine/src/snodo/coders/base.py with task_id taken from the spec's project_context, and the subprocess adapter (packages/snodo-engine/src/snodo/coders/subprocess_adapter.py) records usage on its own path; one or both of these evidently run without a task id in that context.

What it should do: find why the coder's usage record has no task id and make it carry the id of the task being executed, on every coder path that records usage (the in-place path, the subprocess adapter, and the failed or timed-out run path). Records that already have a task id keep it. Nothing else about what is recorded changes.

CONSTRAINTS
Files that may change: the coder modules under packages/snodo-engine/src/snodo/coders/, the place where the coder's project_context is built if that is where the id is lost, packages/snodo-foundation/src/snodo/infrastructure/usage_tracker.py, and tests under tests/coders/, tests/infrastructure/ and tests/engine/. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change what a record contains beyond the task id, cost handling, or any validator or classifier code. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: a successful coder run, a failed one and a timed-out one each record usage with the executing task's id on the paths that record usage; a record that already has a task id is unchanged. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
