New files this task will create: none.

INTENT
A plan run ends with the per-role usage table of the whole run, so the cost of a plan in model time and tokens is visible right under its progress line.

Evidence: snodo/cli/commands/plan_run.py ends a plan run with "Plan progress: N/M completed" (and the unfinished-task note) and prints no usage. The plan job's state.json holds one usage record per model call, with role (validator:<id>, coder, classifier) and failed attempts included, and snodo/usage_summary.py already builds and renders the table (summarize_usage, render_usage_summary) for recon and for task runs.

What it should do: after the progress lines, print the same table for the records of this run's job, one row per role followed by a total row, with the plan's elapsed time as the total time. When the plan job has no usage records nothing is printed. The records come from the running job's state (the job id is known to the plan run); a plan run that is started without a job state prints nothing and does not fail. Output and exit codes are otherwise unchanged.

CONSTRAINTS
Files that may change: snodo/cli/commands/plan_run.py and tests under tests/cli/ for the plan runner. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change snodo/usage_summary.py, the logs command, the task run summary or the JSON schema. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: a plan run whose job state has usage records ends with the table (roles in order of first appearance, then total, failed attempts counted), a plan run without records prints no table, and the existing progress text and exit codes are unchanged. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
