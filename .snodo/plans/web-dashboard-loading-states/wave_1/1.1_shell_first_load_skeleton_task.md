INTENT
A view that has not drawn yet should show a calm loading skeleton instead of a blank page, so a slow first answer does not look like a broken dashboard.

Evidence: snodo/web/static/index.html refresh() waits for the Markdown renderer and the view script, then awaits the view's render; until that finishes the view's container is empty, so the area under the top bar is blank for several seconds on a slow first request (seen in a screenshot of the Now page right after start-up).

What it should do: when a view is about to render and its container has never held content, the shell puts a skeleton in the container: a few soft placeholder blocks in the cloud style (a short heading bar, a row of card-shaped blocks and a taller list-shaped block) with a slow shimmer that stops for visitors who prefer reduced motion. The container is marked as busy for assistive technology and carries a short visually hidden "Loading" status text. The skeleton is replaced the moment the view renders, or by the existing error messages if it fails. Later refreshes (the ten-second polling) never bring the skeleton back, and switching to a view that already rendered once shows its content, not a skeleton. The skeleton is generic so it serves every view, and it is built only from tokens and color-mix.

CONSTRAINTS
Files that may change: snodo/web/static/index.html, tests/web/test_static_shell.py, tests/web/test_static_shell_style.py and CHANGELOG.md. Hex and rgba colours stay inside the token block only. No libraries, no external URLs, no inline event handlers, DOM through createElement and textContent only, no innerHTML. The polling, view switching, theme switch, lazy loading and the existing error messages keep working unchanged. Do not touch any view script or stylesheet. Existing tests stay; add new ones.

ACCEPTANCE
Tests that exist and pass: the shell defines the skeleton styles with a reduced-motion rule; refresh() puts the skeleton in a container that has not rendered yet and not in one that has; the busy marker and the hidden Loading text are present while loading and removed after render; a failed render shows the existing message and no skeleton; no innerHTML, external host or hex colour outside the token block appears; the existing shell tests still pass. `make gate-task` is green.
