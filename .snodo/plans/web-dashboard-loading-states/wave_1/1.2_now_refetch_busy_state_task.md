INTENT
Pressing Refetch on the Now page should visibly do something while it waits, and a failed or slow request should say so, instead of the page staying silent.

Evidence: snodo/web/static/now.js fetches the Now data and the Refetch button gives no feedback during the request; when the answer takes several seconds a visitor cannot tell whether the click registered.

What it should do: while a Now request started by the Refetch button is in flight, the button is disabled, reads "Refetching" and carries a small spinner (stopped for visitors who prefer reduced motion), the as-of text in the page head says the data is being refreshed, and the counters and tree stay on screen with their last data, slightly dimmed, so nothing jumps. When the request finishes the button returns to normal and the as-of age resets as today. If the request fails, the previous data stays visible and a short message next to the button says the refresh failed and the data shown is from the earlier answer. Pressing the button twice does not start two requests. The ten-second background refresh keeps working and does not flash the busy state.

No libraries, no external URLs, no hex colours (tokens and color-mix only), DOM through createElement and textContent only, no innerHTML. The side panel, selection and expanded rows survive a refetch as they do today. Existing tests stay; add new ones.

ACCEPTANCE
Tests that exist and pass: the Refetch button is disabled and shows the busy label while a request is pending and returns to normal afterwards; a second click while pending sends no second request; the previous data remains rendered while pending and after a failure; a failure shows the short message; the background refresh does not set the busy state; the reduced-motion rule for the spinner exists; no innerHTML, external host or hex colour appears; the existing now tests still pass. `make gate-task` is green.
