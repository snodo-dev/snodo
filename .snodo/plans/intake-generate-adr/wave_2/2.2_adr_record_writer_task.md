New files this task will create: one new module that writes an accepted proposal as a decision record, beside the proposal module from ticket 1.2, and one new test file for it.

INTENT
An accepted ADR proposal becomes a decision record file in the repository's decision records folder, numbered after the existing ones, with Status "Proposed".

Background: decision records live in docs/decisions or docs/adr (survey's _detect_decision_paths in packages/snodo-engine/src/snodo/survey/analyzer.py finds them) and are named like 063-validator-fallback-on-operational-failure.md. Their format is the Nygard one used in docs/decisions: a "# ADR NNN — Title" heading, then Status, Context, Decision, Consequences and Alternatives considered sections. A proposal from ticket 1.2 has a title, context, decision, consequences and evidence references.

What it should do: given a proposal and the decisions folder, work out the next number from the existing file names (three digits, no gaps assumed), make a file name from the title, render the record with Status "Proposed", put the evidence file references in a short "Evidence" section at the end, and write it. It never overwrites an existing file; if the name is taken it uses the next number. It writes nothing outside the decisions folder and returns the path written.

CONSTRAINTS
Files that may change: the new module, its test file and CHANGELOG.md (one entry under [Unreleased] ending "(Fixes #<n>)"). Do not touch intake_cmd.py, the existing records or docs/decisions/README.md. Do not add any state, status, severity or halt type to snodo.

ACCEPTANCE
Tests show: the next number follows the highest existing one; the file has the heading, Status "Proposed" and the five sections plus Evidence; an existing file is never overwritten; an empty decisions folder starts at 001; a title with punctuation gives a safe file name. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
