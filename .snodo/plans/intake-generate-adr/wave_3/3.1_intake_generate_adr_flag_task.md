INTENT
`snodo intake --generate-adr` works end to end: it asks the analysis step for proposals, lets the operator accept or reject each one, writes the accepted ones as decision records, and tells the operator how to start a decision records folder when the repository has none.

Background: intake_cmd.py (snodo/cli/commands/intake_cmd.py) already has the interactive gate for criteria: it lists proposals with their source, asks "Accept? [y/N]" for each, and honours --json (print proposals, write nothing), --accept-all, --reject-all and --no-input (never prompt; needs an explicit accept or reject). ADR 064 (ticket 1.1) records that intake now has this second direction. Tickets 1.2, 2.1 and 2.2 added the proposal checks, the model call and the record writer.

What it should do: with `--generate-adr` the command takes the generate path instead of the criteria path and reuses the same flags with the same meaning: --json prints the proposals and writes nothing, --accept-all and --reject-all and --no-input behave as they do for criteria, interactive mode asks per proposal and shows its title, decision and the evidence files. Only accepted proposals are written, one record each, through the writer; a run that accepts nothing writes nothing. When the repository has no decision records folder (survey's detection finds none), print one clear message that none was found and how to start one (create docs/decisions, with the README table and a first record in the Nygard format, naming the existing snodo folder as an example), write nothing and exit without error; --json reports the same fact. If the model call fails, print the error, write nothing and exit with a non-zero status. Without the flag, behaviour is unchanged. Do not add the flag to the MCP intake tool, which stays read-only. Add the flag's row to the intake line in docs/command-reference.md in this same ticket.

CONSTRAINTS
Files that may change: snodo/cli/commands/intake_cmd.py, docs/command-reference.md, tests under tests/cli/ and CHANGELOG.md (one entry under [Unreleased] ending "(Fixes #<n>)"). Tests must not make real model calls; inject a fake analysis result. Do not change the criteria path, the MCP tool or the analysis and writer modules beyond what they already expose. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: with the flag, a fake proposal accepted interactively writes one record with Status "Proposed" and a rejected one writes nothing; --json prints proposals and writes nothing; --accept-all and --reject-all and --no-input behave as for criteria; a repository with no decision records folder prints the how-to-start message, writes nothing and exits cleanly; a failing analysis exits non-zero with nothing written; without the flag the existing intake tests still pass. `make gate-task` is green.
