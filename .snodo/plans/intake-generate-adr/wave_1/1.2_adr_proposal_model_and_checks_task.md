New files this task will create: one new module for the ADR proposal model and its checks, placed beside the existing intake and survey code (snodo/survey/ is where criteria proposals live), and one new test file for it.

INTENT
A well-defined shape for a proposed decision record, and checks that reject a proposal unless it is grounded in the repository, so later tickets can feed model output through it.

Background: `snodo intake --generate-adr` will have a model read the code and propose decision records. Model output is untrusted. Today's intake keeps its gate by never building a proposal without its source record (ADR 044); the same discipline applies here: a proposal without evidence in the repository is never built.

What it should do: define a proposal (title, context, decision, consequences, and a list of evidence references, each a repository file path with an optional line range) and a function that takes the model's raw answer, which is JSON text possibly wrapped in prose or a code fence, and returns the accepted proposals plus a short reason for each dropped one. A proposal is kept only when: all fields are present and non-empty; it has evidence in at least three different files; every evidence path exists in the repository and a given line range lies inside the file; and its title does not match an existing decision record's title (compare normalised, ignoring the number prefix), the existing titles being passed in. Malformed JSON gives no proposals and one reason, never an exception. Proposals are returned in the model's order, capped at a limit passed by the caller.

CONSTRAINTS
Files that may change: the new module, its test file and CHANGELOG.md (one entry under [Unreleased] ending "(Fixes #<n>)"). Do not touch intake_cmd.py or any command. Make no model call and no network call in this module. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: a good proposal is kept; fewer than three evidence files, a missing evidence file, an out-of-range line range, an empty field and a duplicate title are each dropped with a reason; JSON in a code fence and JSON inside prose are both read; malformed output gives no proposals and a reason; the cap is applied. `make gate-task` is green.
