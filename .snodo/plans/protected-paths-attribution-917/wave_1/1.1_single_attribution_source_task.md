# Finish the #915 rework: one source of truth for protected-path attribution

## Goal

`https://github.com/snodo-dev/snodo/issues/917` carries the review findings that
survived the merge of PR #915. Three of them are still true on `main`; this task
closes them without changing the advisory-versus-enforcement split the PR
established.

## The three findings, with their current shape

1. **Two injection sites, two types.** `packages/snodo-engine/src/snodo/engine/loop.py:522`
   assigns `self.coder.protected_paths = list(getattr(protocol, "protected_paths", []) or [])`
   while `packages/snodo-engine/src/snodo/engine/nodes/executor.py:50` assigns
   `coder.protected_paths = tuple(getattr(protocol, "protected_paths", None) or ())`.
   The attribute is declared as a tuple, so the list assignment contradicts the
   declared type, and whichever runs last wins. Make the executor the single
   injection site (it also injects `protocol`, which the adapters need for the
   notice) and remove the duplicate from the loop. If the loop assignment exists
   to cover a path the executor does not run, say so in a comment and make it the
   same tuple conversion instead of a list.
2. **A silent swallow.** `packages/snodo-engine/src/snodo/engine/nodes/validation.py:18-29`,
   `_resolved_base_branch()`, catches every exception and returns `""` with no
   record. The docstring's reasoning is sound — an unresolvable base branch is not
   an error — but the operator loses the only clue when the guard's fork point
   looks wrong. Log it at debug or warning level, following the logging pattern
   already used in that module, and keep returning `""`.
3. **A redundant dual source.** `packages/snodo-engine/src/snodo/coders/base.py:39-55`,
   `protected_paths_notice()`, merges `protocol.protected_paths` with the
   `declared_paths` argument and deduplicates. Since the executor assigns
   `coder.protected_paths` *from* `protocol.protected_paths`, the two arguments
   carry the same data, and the merge only hides which one a coder is being told
   about. Use one source: read the protocol's declared paths, and treat the
   `declared_paths` argument as the override it effectively is (used when a caller
   has a more specific list) rather than a second list to union with. Keep the
   two-group wording the PR added — engine state versus protocol declarations —
   and keep the rule that a protocol declaring nothing must not read as though it
   had (#908).

## Constraints

- The notice stays advisory. Enforcement remains the post-execution diff guard and
  the state-directory mutation guard (ADR 049, ADR 058). Do not add a new
  enforcement path and do not weaken the existing ones.
- `docs/protocol.md` and ADR 058 describe attribution as the live base branch with
  a captured fallback, and the notice as advisory. If the wording no longer matches
  what the code does after these changes, update the documentation rather than the
  behaviour.
- Both adapters (`subprocess_adapter.py`, `opencode_adapter.py`) call
  `protected_paths_notice(self.protocol, self._workspace, self.protected_paths)`;
  keep them consistent with whatever signature you settle on.

## Acceptance criteria

- One place assigns `coder.protected_paths` per dispatch, and the value is a tuple
  matching the declared type; a test asserts the type, since a list would pass a
  content-only comparison.
- `_resolved_base_branch()` records why it returned `""` and still returns `""`
  (the guard must not fail the run over it).
- `protected_paths_notice()` draws its declared paths from one source; a test
  covers "protocol declares nothing" (the notice must not imply otherwise) and a
  test covering the override path.
- The real-git rebase-semantics tests added by PR #915 still pass — they are the
  reason the attribution change is safe, so do not replace them with doubles.
- CHANGELOG gets an entry under **Unreleased** naming #917.
- `make gate` green and `lint-imports` green (the engine keeps its import-linter
  contracts).
