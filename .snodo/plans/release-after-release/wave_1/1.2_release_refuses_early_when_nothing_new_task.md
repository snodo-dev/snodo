# make release with nothing new runs the full gate, bumps, then fails

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
If `make release PART=<part>` has nothing to release, it should stop in the first seconds. That means the CHANGELOG `[Unreleased]` section is missing or has no entries, for example straight after a release. The message should say there is nothing to release since the last tag. The gate does not run, the version is not bumped, and the tree stays clean.

## THE CHAIN
- Evidence: `make release PART=minor` was run a second time, right after v0.22.0 had shipped.
- The early check in the Makefile `release` target, `scripts/enforce_changelog.py --mode release --base <last tag>`, passed because there were no commits since the tag.
- The full gate and the strict docs build then ran for several minutes, and `make bump` moved every package from 0.22.0 to 0.23.0.
- Only then did `scripts/prepare_release_documents.py` fail with "CHANGELOG.md has no [Unreleased] section".
- That left nine modified files (the pyproject.toml files and uv.lock) to discard by hand.
- The same late failure happens when [Unreleased] exists but is empty. prepare_release_documents.py does refuse that case, but only after the bump.

## CONSTRAINTS
- The refusal happens before `$(MAKE) $(RELEASE_GATE)`. The natural home is the existing release-mode changelog check, or a small step next to it in the Makefile; follow whatever fits the existing pattern.
- No new top-level CLI command.
- Gate mode keeps its current behaviour. An empty [Unreleased] heading is the normal state of main right after a release and must not fail or warn there.
- Do not weaken any existing check. The release still refuses a dirty tree.
- Do not edit `scripts/prepare_release_documents.py`, because a sibling task is changing it.
- Message copy reads plainly, for example: "Nothing to release since v0.22.0: CHANGELOG.md [Unreleased] has no entries."
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/`.
- Run only the targeted tests.

## ACCEPTANCE
- Tests cover, in release mode:
  - a missing [Unreleased] section fails;
  - an empty [Unreleased] section fails, and the message names the last tag;
  - an [Unreleased] section with entries passes.
- A test also covers gate mode with an empty [Unreleased], which stays quiet.
- There is a CHANGELOG entry under ## [Unreleased].
