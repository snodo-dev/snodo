# Only reuse a workspace that belongs to this repository

## Why this task exists

Issue #970. When a task is retried, the engine must not throw away the work a
halted attempt left behind, so the workspace builder deliberately returns the
existing directory when one is already present at the task's identity path. That
reuse rule is correct and stays.

The bug is that it trusts the path. The identity path is built from the task id
inside a container directory that sits *beside* the project root, so two different
repositories that happen to share a parent directory and use the same task id
resolve the same path. The builder finds a directory there, takes the early return,
and hands back a workspace that belongs to the other repository — or a leftover
from a run that is long gone. No branch is created for this repository, the caller
goes on assuming it got one, and the failure surfaces much later as an unrelated
error about a missing branch.

This is not only a test-shape problem. Any operator who runs two projects from a
common parent, with the same task id, gets a silently wrong workspace.

## What "done" means

Reuse is conditional on proof. A directory at the identity path is reused only when
it is verifiably a worktree of the repository being worked on; anything else is
treated as not-a-workspace and the attempt gets a correct one.

## Acceptance criteria

1. Before reusing an existing directory at a task's workspace path, the builder
   establishes that the directory is a worktree of the repository it was asked to
   work in. Proof from the repository's own worktree list is preferred over
   inspecting the directory's contents.
2. A directory that fails that check is not used and not silently deleted: the
   builder either recovers the path to a valid workspace for this repository or
   refuses with an error that names the path and says the directory there belongs
   to another repository.
3. Work left by a previous attempt *of the same repository* is still preserved
   exactly as it is today — the retry-inheritance behaviour must not change, and a
   test that pins it must still pass unmodified.
4. A new test covers the collision: two distinct repositories under one shared
   parent, same task id, each retried; each gets a workspace that is a worktree of
   its own repository, with its own branch, and neither sees the other's files.
5. The full gate passes.

## Constraints

- Do not change the container's location relative to the project root; other
  behaviour, including the retention of halted attempts' work, depends on it.
- Do not delete a directory that belongs to another repository. Refusing is
  acceptable; destroying is not.
- Keep the error path a normal task failure with the existing vocabulary — no new
  halt types, severities, validator kinds, or statuses.
- Add one bullet under the `## [Unreleased]` section of CHANGELOG.md describing the
  fix. Touch only that section — other in-flight branches edit the same block, so do
  not reflow or reorder anything else in the file.
- Keep every file under the project's file-length gate; split rather than grow.
- Either the gate passes and you submit, or it does not and you fix it. Do not leave
  notes about validation anywhere in the tree.
