1. **Replacement detection must key on recorded spec identity, not on text.** A reviewer found: "Key spec_was_replaced reset to planner's recorded spec hash or exclude hand-edits to honor #832 contract" and "text-keyed reset resets on hand-edits, contradicting #832 guidance and PR's own hash-keyed claim". Issue #832 records the contract that *editing the spec file by hand does not reset the counter*; the delivered behaviour must honour that: a deliberate replacement through the supported path resets the lineage, an incidental hand edit of the file on disk does not. 2. **Unify the spec-normalization schemes.** A reviewer found: "Divergent spec-normalization schemes may cause false reset — spec_text, same_spec, _normalize_spec inconsistency".
