INTENT
The queues page should say plainly that plans in different queues can run at the same time without affecting each other's branches, and what the engine still guards.

Evidence: ADR 053 lets one queue_run start one runner per queue in parallel. Until now a plan advancing its branch could block another plan's task through the workspace-escape check, which is why this note is needed alongside the fix in the same plan.

What it should do: add a short paragraph to docs/queues.md under the part that describes running several queues: concurrent plans do not trip each other's workspace-escape check because branches of other plans are ignored; moving the task's own plan branches or an operator branch is still treated as an escape. Plain and short.

CONSTRAINTS
Files that may change: docs/queues.md. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Documentation only. Do not add any state, status, severity or halt type.

ACCEPTANCE
