# 2.1_adr_050_final_verdict_turn_note

## INTENT
`docs/decisions/050-repeat-reads-are-free-but-bounded.md` records how the validator tool loop spends its reading budget and when it forces the verdict-only turn. Task 1.1 of this plan changed what happens on that turn: when the judge returns no valid `submit_verdict`, it now gets one bounded extra attempt before failing closed, and the failure records what the provider returned on that turn (finish reason, completion tokens, whether there was text). The decision record should say so, because the next maintainer who reads "fail closed" in the code or in a `validator_error` halt will look here to learn how many chances the judge gets and why the number is not larger.

1. Open a GitHub issue first ("ADR 050: the verdict-only turn gets one bounded retry") and put "Fixes #<n>" in the commit message.
2. Read `docs/decisions/050-repeat-reads-are-free-but-bounded.md` and the merged change of task 1.1 in `packages/snodo-engine/src/snodo/validators/llm_validator.py` so that you describe exactly what the code does (how many attempts, what is recorded, what stays fail-closed).
3. Add a short dated section at the end of the ADR (one section, no other new headings): the verdict-only turn gets one bounded extra attempt; two misses still fail closed as an error blocker (`validator_error`), a judge that did not decide is never turned into a finding; the failure carries the finish reason and token counts so a recurring no-verdict case can be diagnosed; why the number of attempts is not larger (every attempt is a provider round trip of up to a minute on a judge that already spent its reading budget, and a judge that ignores the forced tool choice twice is a provider or model problem to surface, not to loop on). Keep the ADR's existing statements about free repeat reads and the stall bound unchanged.
