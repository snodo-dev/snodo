## Intent
A task whose gate passed and whose criteria are met in the tree should be accepted. The acceptance validator should not turn "I cannot run the gate myself" into a warn that triggers recovery.

## Evidence
- Many tasks across recent plans: `make gate` passed, acceptance wrote that every criterion was met in the tree, then warned that "make gate passes" (and sometimes a criterion such as docs checks or a repeated-run claim) had no independent execution evidence, because the only gate result it is given is the last line of the gate output (for example "Audit event contract check OK"). Recovery attempts change nothing (the work is already present), rerun the gate, get the same warn, and the task ends blocked after four attempts. A task costs 15 to 55 minutes this way, and docs tasks hit it regularly; two tasks in one plan did tonight.
- `QualityValidator._run_command` in packages/snodo-engine/src/snodo/validators/quality.py records a passing result with a one-line summary from `_extract_summary`; `AcceptanceValidator._build_tool_loop_prompt` in packages/snodo-engine/src/snodo/validators/acceptance.py presents that summary as the independent execution evidence.

## Outcome
- Acceptance is given the gate verdict as evidence: the command that ran, its exit code, and which steps ran or passed (a bounded excerpt, not the full output), so a green gate does not produce a warn.
- A criterion that only the gate can establish is not reported as unmet when the gate passed; a failing or missing gate result is still reported as before.
- Tests: a task whose gate passed and whose other criteria are met passes acceptance; a failing gate is still reported; the evidence given to acceptance includes the command and exit code.
- Quality validator tests that assert the old one-line summary keep passing, or are updated with a clear reason.
- `make gate` passes.
