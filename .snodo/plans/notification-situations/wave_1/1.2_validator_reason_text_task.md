## Intent
A warn or block notification can carry a short, readable reason taken from the validator output, so the operator sees why without opening the logs.

## Evidence
- The halt payload already holds `reason` and `validator_results`, each with an id, severity and justification, but no notification shows any of it.
- Notifications go to Slack, Discord, Teams, ntfy and a generic webhook; the Slack sink converts `**bold**` to `*bold*`, so reason text must not introduce markup that renders badly in those sinks.

## Outcome
- One small pure function turns a halt payload into a few plain-text lines: the halt reason first, then up to a small number of validators as "<validator id> (<severity>): <justification>", most severe first, with an "and N more" tail when cut.
- Each justification and the whole result are length-capped so a message stays readable on a phone; cut text ends visibly. Newlines inside a justification are collapsed, and characters that would break Slack, Discord or Teams formatting are neutralised.
- Missing, empty or malformed payloads return an empty result and never raise.
- Tests cover ordering, truncation, the "and N more" tail, odd characters and malformed input.
