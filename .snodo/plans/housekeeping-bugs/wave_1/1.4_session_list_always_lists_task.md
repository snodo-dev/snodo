# `snodo session list` hides the session table whenever the audit log cites missing sessions

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
`snodo session list` always prints the sessions it found. The note about audit-cited sessions with no file is extra information below the table, and it never replaces the table.

## THE CHAIN
- Evidence: right after `snodo session new` created sess_20261011_prod_6eb59c, `snodo session list` printed only "Audited but not in this store…" with 28 ids, and no "Sessions:" table.
- In `_session_list` in `snodo/cli/commands/session_cmd.py`, the `if missing:` branch prints the missing ids and then `return 0`. The table code after it never runs when any audited id is missing.

## CONSTRAINTS
- Print the table first, then the missing-ids section. If the missing list is long, it may be summarised (count plus a few ids, with a way to see all) instead of 28 lines.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo. Tests use temporary session stores.
- Run `uv run ruff check` on touched files. Run only the targeted session tests.

## ACCEPTANCE
- A test with both stored sessions and audit-cited missing ids shows that the output contains the "Sessions:" table with the stored sessions and the missing-ids section.
- There is a CHANGELOG entry under ## [Unreleased].
