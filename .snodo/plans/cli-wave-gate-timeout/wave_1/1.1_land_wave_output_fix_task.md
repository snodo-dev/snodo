INTENT
Issue #784: the wave loading indicator kept animating after `snodo task list` had printed its table. The rich Console in `render_task_table()` writes through a stream reference that `wave_while_silent` (snodo/cli/spinner.py) does not see. The branch above adds rich-level output notification plus stream interception, and makes the wave one-shot. The coder reported that the targeted spinner tests pass and ruff is clean.

The task was blocked anyway. The quality gate reported "Test command timed out after 600.0s: 'make gate'". The coder's own `make gate` run inside its session also never finished, and it was halted after 600s of silence. Before this change, the full gate finished well inside 600s; recent plans took 5–8 minutes per task including the gate. So the change most likely makes part of the test suite hang or slow down badly. Plausible causes:
- interception of sys.stdout and sys.stderr or rich consoles leaking across tests (for example a patch that is never undone);
- a spinner thread that never stops under pytest capture;
- a pty-based test that waits forever.
Confirm the real cause; don't assume it.

When this is done, the #784 behaviour is in place:
- any output stops and clears the wave;
- the wave never restarts after output;
- stdout stays byte-identical.
And `make gate` completes comfortably within the 600s budget, at about its pre-change duration.
