# Fallback coder commits still miss the issue the coder opened

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
When snodo commits a coder's uncommitted work for it, the commit carries "Fixes #N" whenever the coder's own output names exactly one issue it opened or worked on. The issue then closes on merge, as it would with a coder-made commit.

## THE CHAIN
- #828 added issue detection to the fallback message (`_commit_message` in `packages/snodo-engine/src/snodo/coders/base.py`, helper `_issue_numbers`). It looks at the spec text and at `last_report` (its findings and `str(report)`).
- Evidence that this is not enough: the first two fallback commits after #828 landed, f7552e1 ("coder: File-length ratchet failures are cut off…") and b40966c ("coder: Blocked-task guidance doesn't say…"), have no trailer. Yet the coder's output for those tasks, as shown in the plan job's stdout (job j_83ded579b55c), said "Issue #831 is open." and "Issue #832 is open." with links to the issues. Issues #831 and #832 stayed open after merge.
- So for the coder adapters in use (opencode-cli at least), the coder's actual output text does not reach `last_report`, or is not what `_commit_message` reads. Find where the adapter keeps the coder's final output (for example its output tail) and include it as an output source.

## CONSTRAINTS
- Keep #828's rules: an explicit spec reference wins; use a number only when the chosen source names exactly one distinct issue; otherwise leave the message unchanged.
- Placeholder text such as "Fixes #<that issue number>" in a spec must not count as a reference. It already doesn't, because no digits follow; keep it that way.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the targeted coder tests.

## ACCEPTANCE
- A test drives the fallback commit through an adapter whose final output says "Issue #831 is open." and whose spec contains only the placeholder. The resulting message ends with "Fixes #831".
- The existing #828 tests still pass.
- There is a CHANGELOG entry under ## [Unreleased].
