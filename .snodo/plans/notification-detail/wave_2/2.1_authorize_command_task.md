# 2.1_authorize_command

## INTENT
Whenever a notification says a task is waiting for a human, it also says what to run: `snodo authorize <task id>`. A person can copy it straight from Slack.

## THE CHAIN
1. Open a GitHub issue first ("Notifications: suggest snodo authorize on every waiting-for-a-human message") and put "Fixes #<n>" in the commit message.
2. Symptom (seen in Slack): "Waiting for a human — Inspect: snodo logs <job>" with no command to act.
3. Evidence: in `packages/snodo-mcp/src/snodo/jobs/notifications.py`, only the `disagreement_escalated` branch of `monitor()` sets `details["command"]` to `snodo authorize <task id>` and appends " — Authorize: ..." to the message. The halt-event branch and the job-finished branch can also classify the situation as `human_decision` (via `classify_outcome` in `packages/snodo-mcp/src/snodo/jobs/outcome.py`) and send no command.
4. Make every notification whose situation is `human_decision` carry the same command in `details` and in the message text, from one shared place so the three branches cannot drift apart. A notification for another situation (blocked, engine fault, success, warn recovered) gets no authorize command. Keep the existing "Inspect: snodo logs <job>" line.
5. Add tests in the existing `tests/jobs/test_notifications.py`: a halt-event and a job-finished notification with situation `human_decision` both contain the command with the right task id; a blocked notification does not; the escalation-branch message is unchanged.

## CONSTRAINTS
- Reuse the existing situation names, event types and details key. No new state, status, severity, halt type, event name or notification field.
- Notification delivery and deduplication are unchanged: a task still produces the same number of messages as today.
- Add one line under `[Unreleased]` in `CHANGELOG.md`.

## ACCEPTANCE
- Every `human_decision` notification shows `snodo authorize <task id>`; no other situation does.
- The same event does not produce an additional message.
- The notification tests pass under `python -m pytest tests/jobs/test_notifications.py`.
