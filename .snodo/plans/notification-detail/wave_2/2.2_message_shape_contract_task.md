# 2.2_message_shape_contract

## INTENT
The shape of a notification message for each operator situation is pinned by one table-driven test, so a later change cannot silently lose the reason or the command.

## THE CHAIN
1. Open a GitHub issue first ("Test: notification message shape per situation") and put "Fixes #<n>" in the commit message.
2. The situations come from `classify_outcome` in `packages/snodo-mcp/src/snodo/jobs/outcome.py` (success, warn recovered, human decision, blocked, engine fault), and messages are built in `packages/snodo-mcp/src/snodo/jobs/notifications.py` with the bounded formatter in `packages/snodo-mcp/src/snodo/jobs/halt_summary.py`.
3. Create a new test file named test_notification_message_shape.py under `tests/jobs/`. For each situation it builds a task state and halt payload (with validator results where the situation has them), runs the same message-building path the monitor uses, and asserts: Blocked and Waiting for a human messages contain the most severe validator id and its justification; only Waiting for a human contains `snodo authorize <task id>`; Success contains neither; every message contains the `snodo logs <job id>` inspect line; markup characters and mentions in a justification are neutralised; the message stays within the existing length bound.
4. Where the monitor path cannot be called without a running job, use the smallest existing seam (the message builder or the notify function with a stubbed sender) rather than changing production code. If a seam is missing, say so in the final report instead of editing production code.

## CONSTRAINTS
- Test file only; do not modify production code, docs or other tests.
- No network, no real Slack or sender. Stub the sender.
- Add one line under `[Unreleased]` in `CHANGELOG.md`.
- No new states, statuses, severities, halt types or event names.

## ACCEPTANCE
- The new test passes after waves 1 and 2 of this plan have landed, and covers every situation row above.
- It fails if the justification or the authorize command is removed from a message.
