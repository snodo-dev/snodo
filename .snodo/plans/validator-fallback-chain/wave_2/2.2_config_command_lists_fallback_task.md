New files this task will create: none.

INTENT
`snodo config` should let an operator read and set the validator fallback list the same way it already handles the recon model list, so nobody has to edit the file by hand.

Evidence: the config command knows which keys hold a list (recon.models is one) and parses a list value for them. llm.validator.fallback is a new list-typed key under the same section; without a mention in the command, setting it from the command line either fails as an unknown key or stores a plain string, which the loader then rejects.

What it should do: register llm.validator.fallback as a list-typed key beside the existing list key, so `snodo config set` accepts the same list notation recon.models accepts, `snodo config get` prints it the same way, and `snodo config list` (or its equivalent) shows it with the others. An empty list is valid and clears the setting. Invalid values give the same kind of error the existing list key gives.

CONSTRAINTS
Files that may change: snodo/cli/commands/config_cmd.py, tests/cli/test_config.py. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change any other key or how existing keys are parsed. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show set, get and clearing of llm.validator.fallback through the command, the same notation accepted as for recon.models, a bad value rejected with a clear error, and an unrelated key unchanged. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
