New files this task will create: none.

INTENT
`snodo config` should let an operator read, set and clear the validator fallback list the same way it already handles the recon model list, so nobody has to edit the file by hand, and the new key is documented from the moment it can be set.

Evidence: the config command knows which keys hold a list (recon.models is one) and parses a list value for them. llm.validator.fallback is a new list-typed key under the same section; without a mention in the command, setting it from the command line either fails as an unknown key or stores a plain string, which the loader then rejects. An earlier attempt found that clearing the list and reading the file back exposed malformed YAML when the list is written for the first time into a config that has no such key. That attempt passed its tests but the gate failed: scripts/enforce_docs_coverage.py rejects a config key that can be set but is mentioned on no page under docs/, and does not allow a new key into its baseline.

What it should do: register llm.validator.fallback as a list-typed key beside the existing list key, so `snodo config set` accepts the same list notation recon.models accepts, `snodo config get` prints it the same way, and `snodo config list` (or its equivalent) shows it with the others. An empty list is valid and clears the setting. The file written must stay valid YAML in each of these cases: first write into a config without the key, replacing an existing list, and clearing it, and the loader must read each result back. Invalid values go through the same validation the existing list key has; where that validation rejects a value for recon.models, the same value is rejected for this key. Document the key in docs/configuration.md with one row beside the other llm.validator keys (name, what it holds, default empty, one short sentence: models tried in order when the validator model fails operationally); a later ticket writes the full description.

CONSTRAINTS
Files that may change: snodo/cli/commands/config_cmd.py, tests/cli/test_config.py and docs/configuration.md (the one row only). Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change any other key or how existing keys are parsed. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show set, get and clearing of llm.validator.fallback through the command, including set on a config that lacks the key and a read-back through the config loader after each step, the same notation accepted as for recon.models, a value that recon.models rejects rejected for this key with a clear error, and an unrelated key unchanged. The key is mentioned in docs/configuration.md. `make gate-task` is green, including the documentation coverage check.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
