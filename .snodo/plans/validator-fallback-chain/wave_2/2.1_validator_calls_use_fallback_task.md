New files this task will create: none.

INTENT
A validator judge can be handed an ordered list of alternative models, and its model call walks that list when the model in use fails operationally, so a rate-limited or unreachable provider does not stop the judge.

Evidence: LLMValidator (packages/snodo-engine/src/snodo/validators/llm_validator.py) makes every model call through _call_completion_with_retry, which retries transient faults inside its budget and then raises, and the task halts as validator_error. The completion function a judge uses is a partial that binds a model and its api_base together (issue #237, see the comment in _call_llm), so using another model means using that model's own completion function, not passing a different model name. A helper that tries names in order and advances only on operational faults exists at packages/snodo-foundation/src/snodo/infrastructure/model_fallback.py. Nothing connects them yet, and the engine does not build alternatives yet (a later ticket does).

What it should do: LLMValidator accepts an optional ordered list of alternatives, each a model name with its own completion function; the default is empty and then behaviour is exactly as today. When the model in use fails with an operational error after its own transient retries are spent, the call is made on the next alternative, and its result is used. The model that answered stays the one reported for that call (the telemetry and usage that name the model must name the real one). A verdict from any model is final: pass, warn, blocker and an unusable verdict (ADR 059) never cause another model to be tried. When every model fails operationally, the last error is raised exactly as the single-model path raises it today, so the existing validator_error halt and its reason text are unchanged. The switch should be observable by callers through a callback or return value so a later ticket can write the job-log line; do not write the log line here.

CONSTRAINTS
Files that may change: packages/snodo-engine/src/snodo/validators/llm_validator.py and tests under tests/validators/. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change how the engine or runner build or pass completion functions, the classifier, verdict handling, severities, quorum or tool access. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: with one alternative, a rate-limit failure that survives the transient retries on the first model leads to the alternative answering; a verdict of any severity (and an unusable one) from the first model is final and the alternative is never called; with every model failing operationally the last error is raised; with no alternatives the call path is unchanged; the model reported for a call is the one that answered. `make gate-task` is green.
