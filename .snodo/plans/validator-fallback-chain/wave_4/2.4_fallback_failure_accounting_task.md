New files this task will create: none.

INTENT
When validator models fail over, the accounting stays honest: failed attempts still count in token usage and an exhausted list reports the last error.

Evidence: validators now walk llm.validator.fallback on operational failures. A failed attempt may still have consumed tokens at the provider, and the existing usage tracking records usage per call through the completion path; the existing validator_error halt reports the error that stopped the call. With several models in play it is no longer obvious which error is reported or whether usage of an attempt that failed after partial work is kept.

What it should do: check, and fix only if there is a gap, that (1) token usage of every attempt, including attempts that ended in an operational failure and any retry on the same model, is still recorded by the existing usage tracking, attributed to the model that was called; (2) when every model in the list fails operationally the task halts as validator_error with the last model's error in the reason, using the existing reason format; (3) a switch does not duplicate or drop usage records of the call that finally answered. If everything already holds, add the tests that pin it and change no production code.

CONSTRAINTS
Files that may change: the validator modules under packages/snodo-engine/src/snodo/validators/, the modules that record validator usage, and tests under tests/validators/ and tests/engine/. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change the classifier, verdict handling, severities, quorum or tool access. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: usage recorded for a failed first model and for the answering second model, each under its own model name; with every model failing operationally the halt is validator_error and the reason carries the last error; no usage record is duplicated or lost across a switch. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
