New files this task will create: none.

INTENT
The work-type classifier is one more validator-side LLM call that can stop a task on a provider fault, so it should use the same fallback list the validators use.

Evidence: the classifier resolves its own model once and makes its call through the engine governance path. A rate limit or timeout there halts the run before validation even starts. The validators already switch models on operational failures through llm.validator.fallback; the classifier does not.

What it should do: when the classifier call fails operationally, try the next model from llm.validator.fallback, using the same helper and the same one-line job-log entry per switch that the validators use. The classifier's own model, token budget and temperature settings are unchanged and its configured model is tried first. A classification result from any model is final. When every model fails operationally the existing behaviour for a classifier failure applies unchanged. With fallback empty nothing changes.

CONSTRAINTS
Files that may change: the engine modules that build and call the classifier (under packages/snodo-engine/src/snodo/engine/), and their tests under tests/engine/. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change classification prompts or outcomes. Do not add any new config key. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: a rate-limit failure on the classifier model leads to the first fallback model answering with one log line for the switch; a classification result is final; exhausted list behaves as a classifier failure does today; empty fallback leaves behaviour unchanged. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
