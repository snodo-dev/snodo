New files this task will create: none.

INTENT
The configuration page should tell an operator that the validator model can have fallbacks, what triggers a switch, and what never does.

Evidence: llm.validator.fallback is a new key. The configuration page documents the other llm keys, including recon.models, and a docs-coverage check in the gate looks for every config key.

What it should do: add a short section to docs/configuration.md describing llm.validator.fallback: an ordered list tried in order; a switch happens only after the configured model failed for an operational reason (rate limit, timeout, connection fault, provider server error) and its own retries are spent; a model that answers, whatever it says, is final; the classifier uses the same list; each switch writes one line to the job log; when every model fails the run halts as validator_error as before. Include one example setting through `snodo config set`, written as a single line a reader can copy. Plain and short.

CONSTRAINTS
Files that may change: docs/configuration.md. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Documentation only; no code or test changes. Do not add any state, status, severity or halt type.

ACCEPTANCE
The page documents the key, the trigger, the never-trigger and the exhausted-list outcome, and CHANGELOG.md carries the entry. `make gate-task` is green. (The gate does not run the strict docs build, so it is not a criterion here.)

PROCESS
