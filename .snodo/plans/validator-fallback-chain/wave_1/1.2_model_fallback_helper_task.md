New files this task will create: packages/snodo-foundation/src/snodo/infrastructure/model_fallback.py, tests/infrastructure/test_model_fallback.py.

INTENT
The engine needs one small, reusable piece that calls a model and, only when the call fails for an operational reason, calls the next model in an ordered list. It should be independent of validators so the wiring tickets that follow can use it for every validator call and for the classifier.

Evidence: recon has a failover loop that hands off on faults and silence and never on a poor answer. Provider error classification (rate limit, 5xx, timeout, connection fault) already exists and is the single source of truth for what counts as operational. Validator calls currently have no way to move to another model after their retries are spent.

What it should do: given an ordered list of model names and a way to make one call for a model, try the models in order and return the first call that returns. Switch to the next model only when the failure is operational by the existing classification; any other failure, and any returned value (whatever it says), ends the search at that model. Each model is called at most once by this piece (retries inside a call stay where they are). Duplicated names are tried once. When every model failed operationally, raise the last model's error unchanged so callers keep their existing error handling. Report each switch to an optional callback that receives the model that failed, the model about to be tried and a short reason, so callers can write one log line per switch. Report which model finally answered to the caller. An empty list or a single model behaves as a plain call.

CONSTRAINTS
Files that may change: only the two named above. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Reuse the existing provider error classification; do not write a second one. Do not read configuration in this piece and do not touch validators. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests cover: first model answers (no switch); first model fails operationally and second answers (one switch reported, the answering model reported); a non-operational error on the first model is raised without trying the second; every model failing operationally raises the last error; duplicates and a single-model list; the callback sees each switch once and in order. `make gate-task` is green.
