INTENT
The validator section of the llm configuration should accept an ordered list of fallback models, so an operator can name the models to try, in order, when the configured validator model is unavailable. This ticket only adds the setting; nothing reads it yet.

Evidence: recon already carries an ordered list of models in the same section and fails over along it. The validator takes a single model, so one rate-limited provider halts a task as validator_error even when other models are available. The llm section rejects keys it does not know (ADR 046), so a new key must be a declared, typed field before anyone can set it.

What it should do: add an optional list of model names under the validator part of the llm configuration, named fallback, empty by default. An empty list means today's behaviour exactly. Entries are non-empty strings; duplicates and an entry equal to the configured validator model are tolerated and later ignored by the reader, not rejected. The unknown-key rejection stays as it is, and the new key appears in the list of valid keys that error message prints.

CONSTRAINTS
Files that may change: packages/snodo-foundation/src/snodo/infrastructure/config.py, tests/infrastructure/test_config.py. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change any default, any other key, or how the validator model is resolved. Do not add any state, status, severity or halt type.

ACCEPTANCE
A config file with llm.validator.fallback as a list of model names loads and the values are available on the loaded config; a file without it loads with an empty list; a non-list value or a non-string entry is rejected with a ConfigLoadError naming the key; an unknown key under llm.validator is still rejected and the message lists fallback among the valid keys. `make gate-task` is green.
