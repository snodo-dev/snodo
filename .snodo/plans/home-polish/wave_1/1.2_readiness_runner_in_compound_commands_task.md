# Readiness names the real test runner in a compound test command

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
The readiness check warns when a quality validator's test runner is not on the workstation PATH. In a project whose test command starts with a subshell group, it reports nonsense: "Test runner binary '(test' for validator 'qa-gate' is not found on workstation PATH." The check takes the first whitespace-separated word of the command. Shell syntax such as `(`, `{`, `!`, env assignments (`FOO=1 pytest`), `cd dir &&`, `exec` and the `test`/`[` builtins is not a runner. The warning should name a real executable that is actually missing, or say nothing.

## THE CHAIN
- `packages/snodo-engine/src/snodo/readiness/checker.py`, the "Workstation Check: is the runner executable on PATH?" block: it takes `runner_binary = effective_cmd.strip().split()[0]` and calls `shutil.which`.
- The same finding is shown by `snodo ready` and the bare `snodo` home view.

## CONSTRAINTS
- Keep it a small, readable rule. Tokenise the command with shell-aware splitting, skip shell punctuation, builtins and leading env assignments, and look at the first word of each simple command. Only warn for a word that is a plausible executable and that `shutil.which` cannot find.
- If the command can't be parsed, say nothing. A false warning is worse than none.
- Keep the finding id, severity and wording as they are.
- No new status, severity, halt type or audit event.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run the readiness tests.

## ACCEPTANCE
- Tests show:
  - `(test -f x || exit 0) && pytest` checks pytest;
  - `FOO=1 npm test` checks npm;
  - `cd web && make test` checks make;
  - an unparseable command produces no finding;
  - a plain missing runner still produces today's warning.
