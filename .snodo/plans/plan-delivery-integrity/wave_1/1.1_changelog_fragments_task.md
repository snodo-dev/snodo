Before starting, open a GitHub issue on snodo-dev/snodo titled "Changelog entries as per-change fragments; missing entry warns at task gate, enforced at release". Put "Fixes #<n>" in the commit message.

INTENT
Today `make gate` runs a changelog check that fails when an issue-closing commit (`Fixes #n`) has no mention in `CHANGELOG.md`. That causes two problems:
1. A correct, fully tested feature is blocked by a missing changelog line. In plan `orchestrators-default-to-plans`, task 1.4 passed 5,094 tests and was blocked only by this check.
2. Every task edits the same `CHANGELOG.md`, so tasks in one wave conflict, and parallel waves are effectively impossible.

The owner's position: a missing changelog entry should not hold up a feature at task-gate time, and the fix must be sustainable.

When this task is done:
- Each change records its changelog entry as its own small fragment file, keyed by issue number, so parallel tasks never touch the same file.
- At task-gate time, a missing fragment for an issue-closing commit is a visible warning, not a failure.
- The release path assembles the fragments into the versioned `CHANGELOG.md` section and clears them. The release path is where a missing entry is enforced, because that is when the changelog must be complete.
- Existing `CHANGELOG.md` history is untouched. Entries already under `## [Unreleased]` still count.

THE CHAIN
1. A fragments directory exists with a short README saying how to add an entry.
2. The changelog check (find it from `make gate`) accepts either a fragment or an existing `CHANGELOG.md` mention for each issue-closing commit. In gate mode a missing one warns; in release mode it fails.
3. `make release` assembles fragments into the new version section before its existing CHANGELOG version check, and removes the fragments it consumed.
4. Contributor docs and the guide's spec-writing guidance say tasks add a fragment, not a `CHANGELOG.md` edit.
5. Tests cover: a fragment satisfies the check; a missing entry warns in gate mode and fails in release mode; assembly produces the expected section.

CONSTRAINTS
- Snodo's state machine is closed. Add no status, halt type, severity, audit event or field.
- Do not weaken any other gate check.
- Keep it git-only and vendor-neutral. No GitHub API calls in the check.

ACCEPTANCE
- The tests in link 5 exist and pass.
- This task's own changelog entry is a fragment.
- `make gate` passes.
