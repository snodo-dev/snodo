## Intent
Give a recon somewhere to write what its agents are doing while they work, and a way to read it back while it is still being written. This task adds only the log itself: writing, reading from a position, and turning a record into one readable line. Wiring it into the agent loop and into `snodo logs` is done by later tasks.

## Evidence
- A recon persists nothing between start and an agent's final answer: `.snodo/recons/<id>/` holds only state.json and results.json, so a watcher has nothing to show for the minutes an agent spends reading files.
- Jobs already have the pattern to follow: an append-only stdout.log that the logs command tails and drains. Recon directories are managed by `ReconManager` in packages/snodo-mcp/src/snodo/recon/__init__.py; that file is already large, so put the new code in a new module beside it instead of growing it.

## Outcome
- A new module in the recon package provides an event log bound to one recon directory: append one event, read the events that appear after a given byte offset (returning the events and the new offset), and format one event as a single human-readable line.
- Storage is one JSON object per line in `events.jsonl` inside the recon directory, appended with a single write per event so concurrent agent threads cannot interleave a line, and created lazily on the first event.
- An event carries a timestamp, the lane position (an integer), the agent label, the model, a kind, and a small detail mapping. The kinds are: an agent starting, a tool turn (tool names and a short summary of each argument, never file contents), a failover to another model, an agent finishing, and an agent failing. Unknown kinds read back from a file are tolerated and formatted generically.
- Reading tolerates a missing file, an empty file, and a final line that is only partly written (it is left for the next read, and the returned offset does not advance past it).
- Argument summaries are bounded in length so one event stays short, and nothing secret or large is written.
- A failure to write an event never raises into the caller: it is logged at debug level and the recon carries on.
- Tests cover append and read from an offset, two threads appending without corrupting lines, a partial last line, a missing file, formatting of each kind, bounded summaries, and a write failure that is swallowed.
- `make gate` passes.
