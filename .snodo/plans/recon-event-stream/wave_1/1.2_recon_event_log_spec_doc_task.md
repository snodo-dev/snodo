## Intent
Record the design of the recon event log in the recon-agents spec, so the code written by the later tasks of this plan and the people reading it share one description.

## Evidence
- docs/specs/recon-agents-cli.md describes how recon agents are chosen and run, and says nothing about progress being visible while they work. Issue 1065 describes the need.

## Outcome
- The spec gains a short section describing the event log: one `events.jsonl` per recon directory, one JSON object per line appended while agents run, the fields of an event (timestamp, lane position, agent label, model, kind, detail), the kinds (agent started, tool turn, failover, agent finished, agent failed), that argument summaries are short and never carry file contents, that the log is optional to read and a failure to write it never affects the recon, and that the recon's own status values are unchanged.
- The section says `snodo logs <recon id> --watch` renders the log live and then prints the agents' answers as it does today.
- Existing statements in the spec stay correct.
- `make gate` passes, including the docs-coverage and docs link checks.
