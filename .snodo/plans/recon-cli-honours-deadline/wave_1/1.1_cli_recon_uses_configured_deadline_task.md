## Intent
`snodo recon` gives each recon agent the deadline configured in `llm.recon.deadline_seconds`, and the command waits long enough for agents to finish or reach that deadline, so a slow local model is not cut off at 300 seconds when the operator has configured more.

## Evidence
- docs/configuration.md documents `llm.recon.deadline_seconds` (default 300) beside `llm.recon.max_tool_turns` and `llm.recon.max_tokens`.
- snodo/cli/commands/recon_cmd.py submits the recon without a deadline and then waits with a hard-coded `mgr.shutdown(timeout=300.0)`. Setting the key to 900 changes nothing from the CLI; every agent still ends at 300 seconds.
- The MCP recon handler (find it by searching for where the recon tool reads its settings) reads the recon settings from the configuration. The CLI path should end up with the same effective deadline as the MCP path for the same configuration.

## Outcome
- With `llm.recon.deadline_seconds` set to a value other than 300, the CLI passes that deadline to the agents and its wait is not shorter than the deadline plus a small margin for shutdown.
- With the key unset, behaviour is unchanged (300 seconds).
- A zero, negative or non-numeric value is handled the way the other recon numeric keys are handled today, with a clear message rather than a crash.
- The CLI and the MCP path resolve the deadline from one place, not two copies of the lookup; extend the existing settings lookup rather than adding a new mechanism.
- Tests cover: default, a larger configured value reaching the agents, the wait following it, and an invalid value.
