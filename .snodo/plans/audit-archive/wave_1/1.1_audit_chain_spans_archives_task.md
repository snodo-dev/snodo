# The audit chain can continue across archive files

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
Project audit logs have grown to 0.6–2.6 GB, and every process that opens one parses and re-verifies the whole file. That alone takes tens of seconds; recon took 23 s just to return an id. A later task in this plan will archive the current log weekly or by size, into sibling files named by ISO week such as `audit.log.2026-w41`. When it does, the next event in a fresh `audit.log` continues the chain: its previous hash is the archive's last event hash, and its sequence carries on.

This task makes the audit log understand that layout before anything creates it:
- **Opening the log** loads and verifies only the current file. If an archive exists, the current file's first event must chain from the newest archive's last event, which is checked by reading only that archive's tail. The genesis rule (sequence 0, all-zero previous hash) applies only to the very first event of the oldest file.
- **Appending** to an empty or missing current file chains from the newest archive's last event, if there is one.
- **`snodo audit verify`** walks every archive in week order and then the current file, as one chain. It reports a break with the file and line where it happens.
- **A history walk.** A way to read events across all archives plus the current file, oldest first, streamed rather than loaded all at once, for the readers that need history (a later task moves them onto it).

With no archives present, everything behaves exactly as today.

## THE CHAIN
- `packages/snodo-foundation/src/snodo/infrastructure/audit.py` holds the hash-chained log. Today it assumes one file whose first event is the genesis event, with sequence 0 and an all-zero previous hash, both when loading and when verifying. Its tail read, used to chain the next event, looks only at the current file.
- `snodo/cli/commands/audit_cmd.py` is `snodo audit verify`.
- The audit tests live under `tests/infrastructure/` and `tests/cli/`.

## CONSTRAINTS
- With no archive files, behaviour and output are unchanged, and existing tests pass unchanged.
- Archive order comes from the ISO year and week in the file name. A later rotation within the same week gets a numeric suffix, for example `audit.log.2026-w41.2`, ordered after the unsuffixed one.
- No rotation is performed here. That is a later task.
- No new audit event, status, severity or halt type.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run the audit and audit-command tests.

## ACCEPTANCE
- Tests built from synthetic archives in a temp dir show:
  - opening loads only the current file, and accepts a first event that chains from the newest archive;
  - appending to an empty current file chains from the archive tail;
  - verify walks all files and passes on a good chain;
  - verify names the file and line on a broken link at an archive boundary, and inside an archive;
  - the history walk yields every event in order;
  - with no archives, nothing changes.
