# Session and mock-usage checks still see archived audit history

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
The audit log is about to be archived weekly, or by size, into sibling files such as `audit.log.2026-w41`. The previous task in this plan added a streamed, oldest-first walk over the archives plus the current file. Two checks read the whole log file directly today and must keep seeing old events once archives exist:
- the session manager's checks of which session ids the log has ever cited, including whether a cited session was later deleted;
- the cloud live-spec check that suppresses delivery for sessions that used the mock coder.

They should use the archive-aware history walk instead of opening `audit.log` themselves, so a session cited three weeks ago is still known.

## THE CHAIN
- `packages/snodo-foundation/src/snodo/infrastructure/session.py`: the audited-session and audited-but-missing checks read every line of `.snodo/audit.log`.
- `packages/snodo-foundation/src/snodo/infrastructure/cloud_live_specs.py`: the delivery-suppression check reads the whole file into memory.
- The history walk added by the earlier task in `packages/snodo-foundation/src/snodo/infrastructure/audit.py`. This task may build on task 1.1's branch.

## CONSTRAINTS
- Results are identical when no archives exist.
- Stream the history and do not load it all into memory. These logs reach GB sizes.
- No new audit event, status, severity or halt type.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run --extra dev ruff check` on touched files, and run the session and cloud live-spec tests.

## ACCEPTANCE
- Tests show:
  - a session id cited only in an archive is still reported as audited;
  - its deletion recorded in the current file is honoured;
  - a mock-coder usage record found only in an archive still suppresses delivery;
  - results with no archives are unchanged.
