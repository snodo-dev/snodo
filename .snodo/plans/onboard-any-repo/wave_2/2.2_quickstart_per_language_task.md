Before starting, open a GitHub issue on snodo-dev/snodo titled "Docs: quickstart for Node/TypeScript, Go and Rust". Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased].

INTENT
`snodo init` now detects the language and test command for Python, Node/TypeScript, Go and Rust, and the mock coder writes a passing fixture for each. The quickstart in `docs/runbook.md` still shows only Python (`uvx --with pytest … --test-command "PYTHONPATH=. pytest"`).

When this is done, the quickstart shows the same short first run (init, a mock run, then reading the result) for each of the four stacks. Each one uses the commands that actually work now. Where the default template ends with the work unmerged, that is explained once, clearly.

THE CHAIN
1. The quickstart in the runbook gains per-language variants, as tabs or short subsections following the docs' existing style.
2. The README points to the per-language quickstart.
3. The docs build passes.

CONSTRAINTS
- Documentation only.
- Use the real command names and flags: read `snodo init --help`. Don't invent options.
- Keep guide markers intact.

ACCEPTANCE
- The quickstart covers four stacks.
- The docs build passes.
- The CHANGELOG entry is present.
- `make gate` passes.
