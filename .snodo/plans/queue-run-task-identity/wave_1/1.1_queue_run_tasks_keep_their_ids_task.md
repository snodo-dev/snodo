# queue_run gives every plan task the queue job's id

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
When the MCP `queue_run` tool runs a queue, each plan task keeps its own task id (for example `1.1_xxx`), and with it its own worktree, task branch and task state file. That is what `run_plan` already does.

## THE CHAIN
Symptom: queue job j_7784d8341725 ("Run queue(s): adoption-next") ran plan first-run-delivery-choice. Both wave tasks ran as task id `j_7784d8341725`, sharing one worktree, branch and state file, so the second task inherited the first task's diff and failed the gate on it. In `list_jobs` that job shows task_ref equal to its own id.

How it happens. Two independent reads agree on this, and the key lines were spot-checked:
- `packages/snodo-mcp/src/snodo/mcp/queue_handlers.py` submits the queue job with `queue_run: True` and no `plan_name`.
- `resolve_task_identity` in `packages/snodo-mcp/src/snodo/jobs/__init__.py` returns the job id itself for `queue_run` jobs, so the queue job's task.json stores `task_id = <queue job id>`.
- `packages/snodo-mcp/src/snodo/jobs/wrapper.py` exports `SNODO_JOB_ID=<queue job id>`. It sets `SNODO_PLAN_JOB=1` only when the job has a `plan_name`, so for a queue job it removes that marker.
- `snodo queue run` runs each plan inline in the same process. In `snodo/cli/commands/plan_run.py`, `_execute_wave_task` builds the Task with the right id and calls `_execute_task`.
- In `snodo/cli/commands/run_cmd.py`, around line 840, `_execute_task` treats the run as a single background-task job because `SNODO_PLAN_JOB` is unset. It reads the stored task_id back from the queue job's task.json and replaces the wave task's id with it, for every task.
- `run_plan` jobs avoid all of this: they have a `plan_name`, so the marker is set and no task_id is stored.
- The CLI `snodo queue run`, run by hand, is unaffected because `SNODO_JOB_ID` is not set there.
- Concurrent wave dispatch is unaffected because it submits each task with an explicit task_id.
