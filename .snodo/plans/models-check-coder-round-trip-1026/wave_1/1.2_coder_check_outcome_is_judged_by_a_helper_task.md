## Intent
`snodo models --check` (snodo/cli/commands/models_check.py) reports each configured model as OK, FAILED with a reason, or NOT CHECKABLE with a reason, as (role, model, healthy, reason). A helper in that module, `_judge_opencode_cli_run(exit_code, stdout, stderr)`, turns the raw result of one prompt run through the OpenCode CLI into that (healthy, reason) pair: True with no reason on a clean run; False with the CLI's own error-event message when stdout carries one (also on exit 0), otherwise the last stderr line, otherwise the exit code alone; the reason is one line and bounded in length. It is the only reader of the CLI's output in the check, and it is not yet called from `check_configured_models`. Earlier attempts built it with tests in tests/cli/test_models_cmd.py covering the six required cases (clean success, non-zero with an error event, non-zero with only stderr, non-zero with nothing, exit 0 with an error event, very long text cut), and two reviews judged it correct, including the architecture and decision-record checks. Do not rework it.
