# Task worktrees can run the project's linter out of the box

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
A coding agent working in a fresh task worktree should be able to lint its change before committing. The worktree's environment is built with the project's default dependency sync. Today that sync leaves out ruff, because ruff is declared only in the optional `dev` extra and not in the default dev dependency group. Running ruff in a fresh worktree fails with "Failed to spawn: ruff", so lint findings are only caught later by the full gate. In this repository's recent history, 15 gate failures were ruff findings.

A default sync should give a worktree the same linter, at the same pinned version, that the gate uses.

## THE CHAIN
- The root `pyproject.toml` declares both an optional `dev` extra (which pins ruff) and a default dev dependency group (which does not).
- The lockfile, `uv.lock`, must agree with whatever `pyproject.toml` declares.
- The gate's lint step is in `scripts/gate_remote.sh`.

## CONSTRAINTS
- Use the same ruff version the extra already pins. Leave other dependencies and their resolved versions unchanged.
- No new status, severity, halt type or audit event.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.

## ACCEPTANCE
- After a default sync in a fresh checkout, ruff runs and reports the pinned version.
- The lockfile changes are limited to adding ruff to the default group.
- There is a CHANGELOG entry under ## [Unreleased].
