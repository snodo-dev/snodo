# 3.3_machine_interface_validator_replay_json

## INTENT
`snodo models --benchmark-run --validator <id> --model <m> --json` emits a JSON record with the recorded and the new verdict and the metrics. A script that ranks models for a validator needs its shape. `docs/machine-interface.md` does not describe it.

## STARTING STATE
Waves 1 and 2 are merged, so the record exists in `snodo/cli/commands/models_validator_compare.py` (its JSON rendering) and is emitted by `models_benchmark.py`. Task 2.2 of this plan has already edited the `snodo validate` section of `docs/machine-interface.md`; add this as a new section beside the other `snodo models` JSON sections and leave the rest as it is.

## THE CHAIN
1. Open a GitHub issue first ("Machine interface: validator replay JSON") and put "Fixes #<n>" in the commit message.
2. Read `models_validator_compare.py`, `models_benchmark.py` and `tests/cli/test_models_validator_compare.py`, `tests/cli/test_models_benchmark_run_validator.py`. Every field you document must be seen in the code; do not invent fields or examples.
3. Add the section in the table style of the neighbouring ones (field, type, meaning): the schema name, both sides of the comparison, the direction, the metric pairs and how a missing value is represented, and which fields are scored.
4. `CHANGELOG.md` gets one new line under `[Unreleased]` in the same commit, in the style of the neighbouring entries, ending with "(Fixes #<n>)".
5. Run the docs checks the gate runs for `docs/`; fix what they report in your own change only.

## CONSTRAINTS
