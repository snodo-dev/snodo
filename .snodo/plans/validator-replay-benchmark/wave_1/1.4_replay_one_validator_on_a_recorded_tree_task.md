# 1.4_replay_one_validator_on_a_recorded_tree

## INTENT
The core of a validator benchmark: judge a recorded spec and a recorded tree with one validator and one chosen model, and report the verdict with its elapsed time and token usage. This task adds that as a function that takes explicit arguments, so it does not depend on the other pieces of this plan and the wiring task of wave 2 can call it. Evidence of the need: running a validator today means `snodo validate`, which judges the current checkout, not a recorded commit, and does not report time or tokens per validator.

## STARTING STATE
Nothing of this task exists yet; an earlier attempt was refused before any code was written, so the checkout is the plan integration branch as it stands.

## THE CHAIN
1. Open a GitHub issue first ("Replay one validator on a recorded commit with a chosen model") and put "Fixes #<n>" in the commit message.
2. Read `snodo/cli/commands/validate_cmd.py` and, in `packages/snodo-engine/src/snodo/validators/runner.py`, `resolve_validators`, `build_completion_fn`, `run_validators` (note its `base_ref`, `verdict_cache` and `verdict_cb` parameters). Read ADR 039 (`docs/decisions`) for the model precedence, `packages/snodo-foundation/src/snodo/infrastructure/worktree.py` for the existing worktree helpers, and how `UsageTracker` records the usage of a validator call.
3. Add a new module `snodo/cli/commands/models_validator_run.py` with a function (name your own) that takes the project root, the protocol and mode, the validator id, the phase, the spec text, the commit to judge and its base commit, and the model. It creates a temporary detached worktree at the commit to judge using the existing worktree helper where one fits (no hand-rolled git plumbing in the CLI layer beyond what the helper lacks), runs exactly that one validator through the shared runner, gives the runner no verdict cache, measures elapsed seconds, and removes the worktree even on failure. The module stays thin: it wires existing pieces together and holds no validator logic of its own.
4. Model rule, stated in the module docstring: the replay model is the provided override of ADR 039's precedence, so it deliberately takes the place of the validator's pinned `model:` for this measurement only, never for the gate. The returned record includes the pinned model, when the protocol pins one, so the report can say it was set aside instead of hiding it.
5. Token, time and cost figures: `run_validators` does not return them; usage is recorded out of band by `UsageTracker`. Collect the input and output tokens (and cost when known) with a small wrapper around the completion function that reads the usage from each response, and report them as absent when a response carries none. The replay must write nothing into `.snodo/`: it sets no `SNODO_PROJECT_ROOT`, job id or task identity for those calls, and leaves `UsageTracker` records alone.
6. A model or validator failure is returned as an error result (the result's existing `error` flag and a blocker, as the runner already represents an operational fault), not raised, so the caller can still print a report. An error result is never presented as a judgement.
7. Add tests in a new file `tests/cli/test_models_validator_run.py` with exactly these names: `test_replay_judges_the_recorded_commit_not_the_checkout`, `test_replay_runs_only_the_named_validator`, `test_replay_uses_no_verdict_cache`, `test_replay_removes_its_worktree_after_a_failure`, `test_replay_reports_elapsed_time_and_tokens`. Use a fake completion function and a small temporary git repository; no network calls.
8. `CHANGELOG.md` gets one new line under `[Unreleased]` in the same commit, in the style of the neighbouring entries, ending with "(Fixes #<n>)".
9. The project supports Python 3.12. Do not run `ruff format` over whole files. Run `python -m pytest tests/cli/test_models_validator_run.py` and `ruff check packages tests snodo`.

## CONSTRAINTS
- Files that may change: the new module, the new test file, `CHANGELOG.md`. Nothing under `packages/` changes.
- The temporary worktree lives outside the project tree and is always removed. Nothing is written into `.snodo/` by this function.
- No new states, statuses, severities, halt types or event names.

- `snodo/cli/commands/models_validator_run.py` exists, takes no verdict cache, removes its worktree in a `finally` path, and states the ADR 039 override rule in its docstring.

- The diff adds one line under `[Unreleased]` in CHANGELOG.md that mentions the issue.
