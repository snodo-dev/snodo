# 1.5_validator_replay_notice

## INTENT
Before a task benchmark runs, `snodo/cli/commands/models_benchmark_notice.py` tells the operator what is being compared (baseline coder and model, candidate coder and model, and whether the harness differs). A validator replay spends model calls too and compares a different thing, so it needs its own notice: which validator, which phase, which commit is judged, the recorded model of that validator when known, the candidate model, and the fact that the call is billed or uses a subscription. Without it an operator cannot tell what a replay is about to do.

## THE CHAIN
1. Open a GitHub issue first ("Notice before a validator replay") and put "Fixes #<n>" in the commit message.
2. Read `snodo/cli/commands/models_benchmark_notice.py` and follow its conventions (best effort, printed to stderr, also in `--json` mode, no failure when information is missing, "unknown" for what cannot be resolved).
3. Add a second function to that module, `print_validator_replay_notice`, taking the baseline record, the validator id, the phase, the commit to judge and the candidate model. It prints a few lines to stderr with the items listed in the intent. The recorded model of the validator is taken from the baseline's recorded result when it carries one, otherwise printed as unknown.
4. Add tests in a new file `tests/cli/test_models_validator_replay_notice.py` with exactly these names: `test_notice_names_validator_phase_and_commit`, `test_notice_says_recorded_model_unknown_when_absent`, `test_notice_goes_to_stderr_only`. Follow the style of the existing benchmark notice tests.
5. `CHANGELOG.md` gets one new line under `[Unreleased]` in the same commit, in the style of the neighbouring entries, ending with "(Fixes #<n>)".
6. The project supports Python 3.12. Do not run `ruff format` over whole files. Run `python -m pytest tests/cli/test_models_validator_replay_notice.py` and the existing benchmark notice tests, and `ruff check packages tests snodo`.

## CONSTRAINTS
- Files that may change: `snodo/cli/commands/models_benchmark_notice.py`, the new test file, `CHANGELOG.md`. Existing function behaviour does not change.
- The new function is called by task 2.1 of this plan (the `--validator` wiring); this task only adds and tests it, and its final message names the function and its parameters.
- No new states, statuses, severities, halt types or event names.

## ACCEPTANCE
- `models_benchmark_notice.py` has the new function and the existing `print_benchmark_notice` is unchanged.
- `tests/cli/test_models_validator_replay_notice.py` exists and contains the three named tests.
- The diff adds one line under `[Unreleased]` in CHANGELOG.md that mentions the issue.
- No file outside the list under CONSTRAINTS differs.
