INTENT
Write docs/providers/deepseek.md, a step-by-step guide for the built-in DeepSeek provider (DeepSeek's own API), ending at a passing `snodo models --check`.

PAGE SHAPE (shared by every provider guide)
1. What you need. 2. Store the key (default variable, `snodo config add`, `api_key_ref`, and that a literal or encrypted `api_key` wins over the environment variable). 3. Configure: the smallest `providers:` block, noting what the built-in catalog supplies. 4. Choose model ids: the form snodo maps to this provider, one example per role (coder, validator, classifier, recon), listing with `snodo models --provider deepseek`. 5. Verify with `snodo models --check`. 6. Troubleshooting table.

THE CHAIN (confirm each point in code)
- DeepSeek is in the built-in catalog with a default key variable; ids are recognised by the "deepseek/" prefix. Read both from the code.
- DeepSeek models served by another host (for example "ollama-cloud/deepseek-v4-pro:0813") belong to that host's block and key, not this provider; say so in one line.
