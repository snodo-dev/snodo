Title: Provider guide: Ollama (local and Ollama Cloud) and other OpenAI-compatible servers

Start by opening a GitHub issue in snodo-dev/snodo describing this change (pass the body with --body-file), or reuse an open one that already covers it. The commit message must include "Fixes #<issue number>". Do not edit CHANGELOG.md: the guides are written in parallel, and a later task records them all in one entry that cites your issue.

INTENT
Write docs/providers/ollama.md, a step-by-step guide for a local Ollama server and for Ollama Cloud, ending at a passing `snodo models --check`. The same pattern covers any OpenAI-compatible server (llama.cpp, vLLM, LM Studio, self-hosted gateways); say so in one short section.

PAGE SHAPE (shared by every provider guide)
1. What you need. 2. Store the key (default variable, `snodo config add`, `api_key_ref`, and that a literal or encrypted `api_key` wins over the environment variable). 3. Configure: minimal `providers:` block, one-line reason per key. 4. Choose model ids: form, one example per role (coder, validator, classifier, recon), listing with `snodo models --provider <name>`. 5. Verify with `snodo models --check`. 6. Troubleshooting table.

THE CHAIN (evidence; confirm each point in code)
- Ollama is not a built-in provider: the user names a block (for example `ollama` or `ollama-cloud`), and ids are written `<block name>/<model>`.
- A local server needs `base_url` `http://localhost:11434/v1` and `litellm_provider: openai`; it needs no key, and a block without `api_key_env` is exempt from the pre-run credential check.
- Ollama Cloud uses `base_url` `https://ollama.com/v1`, `litellm_provider: openai`, and a key from an environment variable the user names in `api_key_env`.
- Passing check lines look like: `OK ollama-cloud/deepseek-v4.1-flash (classifier) — LiteLLM model: openai/deepseek-v4.1-flash`. Model tags with a colon (`deepseek-v4-pro:0813`) are valid ids.
- The configuration page already shows `snodo config set providers.ollama.base_url …` and `providers.ollama.litellm_provider openai`; reuse that pattern.
