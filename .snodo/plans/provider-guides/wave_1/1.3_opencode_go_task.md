Title: Provider guide: OpenCode Go gateway

The commit message must include "Fixes #<issue number>". Do not edit CHANGELOG.md: the guides are written in parallel, and a later task records them all in one entry that cites your issue.

INTENT
Write docs/providers/opencode-go.md, a step-by-step guide for using the OpenCode Go gateway as a snodo provider, ending at a passing `snodo models --check`. Its trap is that one gateway serves model families in two API formats, so some models need a route rule.

PAGE SHAPE (shared by every provider guide)
1. What you need. 2. Store the key (default variable, `snodo config add`, `api_key_ref`, and that a literal or encrypted `api_key` wins over the environment variable). 3. Configure: minimal `providers:` block, one-line reason per key. 4. Choose model ids: form, one example per role (coder, validator, classifier, recon), listing with `snodo models --provider <name>`. 5. Verify with `snodo models --check`. 6. Troubleshooting table.

THE CHAIN (evidence; confirm each point in code)
- OpenCode Go is a custom block (commonly named `ocgo`): `base_url` `https://opencode.ai/zen/go/v1`, `litellm_provider: openai`, key in an environment variable the user names.
- Claude models (and MiniMax) on that gateway speak the Anthropic Messages format. They need `model_routes` entries sending `claude-*` (and `minimax-*`) to `litellm_provider: anthropic`; the configuration page already has this example. Before that rule existed, a Claude model through `ocgo` failed every call; after it, `snodo models --benchmark` for `claude-haiku-5-5` passed 5/5.
- Other families, such as "ocgo/qwen3.6-plus", use the default OpenAI-compatible route.
- An optional header `x-opencode-session: "{task_id}"` under `extra_headers` keeps one session per task; check how `{task_id}` is substituted.
- Two blocks with separate keys (for example `ocgo1` and `ocgo2`) spread load across accounts; mention briefly.
- A very large request has been refused by the gateway with HTTP 413; list it under troubleshooting as "request too large for the gateway".
