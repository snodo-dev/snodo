Title: Providers overview page, navigation and changelog for the provider guides

Start by opening a GitHub issue in snodo-dev/snodo describing this change (pass the body with --body-file), or reuse an open one that already covers it. The commit message must include "Fixes #<issue number>".

INTENT
The previous wave added one setup guide per provider under docs/providers/ (cloudflare, ollama, opencode-go, anthropic, openai, google, openrouter, deepseek), each with its own GitHub issue. They are not reachable yet. Give them a front door and a place in the docs navigation, and record them in the changelog.

THE CHAIN
- Write the index.md page in the docs providers folder: a short page that explains, once, the rules every guide relies on: how snodo decides which provider block a model id belongs to (built-in prefix rules, then a configured block name before the first slash, then LiteLLM's own detection); the credential order (`api_key`, including "@keys/<provider>.key", then `api_key_ref`, then `api_key_env`); what `base_url`, `litellm_provider` and `model_routes` do; and that `snodo models --check` is how you confirm a setup. End with a table linking each guide with a one-line "use this when".
- Add a "Model providers" group to the Use Snodo section of mkdocs.yml with the overview first and the eight guides after it.
- Add one CHANGELOG.md entry under [Unreleased] for the provider guides, citing this task's issue and each guide's issue (find them by their "Provider guide:" titles).

CONSTRAINTS
- Confirm every rule on the overview page in the code (core config module's provider resolution and key resolution). Leave out anything you cannot confirm.
- Do not rewrite the guides; if one contradicts the code or the overview, note it in the issue rather than editing it.
- Every `snodo …` command and flag must exist; the docs-coverage check rejects dangling ones. The docs build is strict, so every link must resolve.
- Do not edit configuration.md, choosing-models.md or runbook.md; a parallel task adds links there.
- Plain, soft second-person copy.
- Do not run the snodo CLI, make gate or make release, and do not touch .snodo/.

ACCEPTANCE
- All nine provider pages appear in the site navigation, and the strict docs build passes.
- The overview's resolution and credential rules match the code.
- The changelog entry cites every provider-guide issue.
