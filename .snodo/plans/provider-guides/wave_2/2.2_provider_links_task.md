Title: Point existing pages at the provider guides

Start by opening a GitHub issue in snodo-dev/snodo describing this change (pass the body with --body-file), or reuse an open one that already covers it. The commit message must include "Fixes #<issue number>". Do not edit CHANGELOG.md: a parallel task records the provider guides in one entry.

INTENT
Provider setup is described in fragments across the user configuration page, the choosing-models guide and the quickstart runbook. Now that docs/providers/ holds one step-by-step guide per provider (cloudflare, ollama, opencode-go, anthropic, openai, google, openrouter, deepseek) plus an overview at the index.md page in the docs providers folder, a reader on any of those pages should find the right guide in one click.

THE CHAIN
- docs/configuration.md, Providers section: keep the key reference table, and add a short pointer to the provider guides near its top. Where a long example duplicates a guide (for example the OpenCode Go route rules), keep it if it explains a config key, otherwise link the guide.
- docs/choosing-models.md: link the provider guides where it talks about which providers are configured.
- docs/runbook.md: the sentence listing the built-in providers should link the guides.

CONSTRAINTS
- Links only, plus small trims of duplicated provider walkthroughs. Do not change any statement about behaviour unless it contradicts the code; if it does, fix it and say so in the issue.
- The overview (the index.md page in the docs providers folder) is written by a parallel task and does not exist in your worktree; link the eight guide files directly and do not link the overview, so the strict build passes.
- Do not edit mkdocs.yml or anything under docs/providers/.
- Every `snodo …` command and flag must exist; the docs-coverage check rejects dangling ones. The docs build is strict.
- Do not run the snodo CLI, make gate or make release, and do not touch .snodo/.

ACCEPTANCE
- Each of the three pages links the provider guides where a reader would look for setup help.
- No content about config keys is lost, and the strict docs build passes.
