New files this task will create: none.

INTENT
An LLM validator that judges a task hands back that task's identifier exactly as it was given, so a plan no longer halts because a judge copied quotation marks around the id into its verdict, while the exact-match rule of ADR 059 stays as strict as it is today.

Symptom and evidence: a ticket whose id is 1.2_e2e_cli_call_timing halted in four consecutive queue runs before any coding, each time with "Unusable submit_verdict: task_id '1.2_e2e_cli_call_timing\"' does not exactly match '1.2_e2e_cli_call_timing'. Fail-closed." The security and adr validators, both served by the deepseek-flash model, returned the id with a trailing quotation mark, and the validator retries inside one run repeated it. The same glitch has appeared before on other tickets and on other validators, and a plain rerun sometimes clears it, sometimes not. The instruction the judges receive (the verdict subject text in the validators package, written for ADR 059) states the id wrapped in JSON quotation marks, so the quotes sit right next to the value the judge is told to return, and a model that copies the whole quoted token produces an id that never matches. The strict equality check in the same module is correct and must stay: it is what stops a verdict about another task from being accepted.

What it should do: change how the subject instruction presents the identifier so there are no quotation marks adjacent to the value, for example by naming it on a line of its own or in a form where the characters to return are unambiguous, while still telling the judge to return that exact identifier in task_id and not to substitute another. Do not loosen the equality check, do not strip or normalise what a judge returns, and do not change what counts as an unusable verdict. Add a regular test next to the existing tests for this module that pins the instruction: it contains the identifier verbatim, contains no quotation mark directly touching the identifier, and still carries the rule that a missing or different id makes the verdict unusable. Keep an existing test passing or update it only where it asserted the old quoted form.

CONSTRAINTS
Files that may change: the verdict subject module in packages/snodo-engine/src/snodo/validators/, the test file for it (find the existing one, or add a test beside the nearest validators tests), and CHANGELOG.md (one entry under [Unreleased] ending with the issue reference Fixes #<n>). Do not change docs/decisions, other validators, prompts outside this instruction, or the runner. No new state, status, severity or halt type.

ACCEPTANCE
The instruction names the identifier without adjacent quotation marks and still requires the exact identifier; the strict equality check is unchanged; a test pins both; make gate-task is green.

PROCESS
Open a GitHub issue first and put Fixes #<n> in the commit message. This is a non-interactive run: open the issue directly with gh issue create, without asking for confirmation of title or body. Commit your change before running make gate-task, because it tests HEAD and needs a clean tree, and run it in the foreground and wait for it to finish before ending your turn.
