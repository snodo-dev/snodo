INTENT
A person can sign out, and can see at a glance how snodo is connected to the cloud.

Builds on the login command and the credential resolution merged in the previous wave. The cloud commands live in snodo/cli/commands/cloud_cmd.py.

Indications: add `snodo cloud logout`, which clears the OAuth tokens from the store and, if a refresh token exists, asks the cloud to revoke it when the metadata lists a revocation endpoint (a failed or missing revocation never blocks the local sign-out; say so). Make the existing `disconnect` also clear any OAuth login so it truly disconnects. Extend `snodo cloud status` to show the authentication method in use (OAuth login, API key, or none), when the access token expires, whether a refresh token is present, and the account or organisation if known, never any token value. If both an OAuth login and an API key exist, say which one wins.

Acceptance: tests cover logout with and without a refresh token and with revocation failing, disconnect clearing both, status output for each method, and that no output contains a token. CHANGELOG.md updated.

First open a GitHub issue in snodo-dev/snodo for this ticket and put "Fixes #<n>" in your commit message; mention the issue number in the CHANGELOG.md entry. Secrets (access tokens, refresh tokens, authorization codes, PKCE verifiers) are never printed, logged, put in audit events, or sent anywhere except the cloud endpoints named here. The state machine is closed: add no new status, halt type, severity, audit event type or audit field. Do not touch snodo-cloud. Tests use temporary directories and a stubbed HTTP transport (no real network, no real browser) and never write the repository's own .snodo/ directory. `make gate` must pass.
