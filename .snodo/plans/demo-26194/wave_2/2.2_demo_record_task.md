# 2.2_demo_record

## INTENT
After a demo run, one small function turns what snodo left behind into a single JSON record that can be compared across models: outcome, wall time, tokens, cost, and where the work is. A script never has to read human text or trust the process exit code, because the exit code does not separate a validator block from other halts.

## THE CHAIN
1. Open a GitHub issue first ("Demo: per-run record from snodo run artifacts") and put "Fixes #<n>" in the commit message.
2. Evidence on what a run leaves behind (see `docs/outcomes.md` and `docs/machine-interface.md`): `.snodo/tasks/<task_id>/state.json` holds status, a terminal halt payload (halt_type, final_decision, phase, reason, validator_results) and a cost object with duration and tokens; `snodo task show <id> --json` and `snodo worktree list --json` give the same facts with a schema tag and, for a retained worktree, its path. The cost object carries no monetary price; absent measurements must stay absent, never become zero. Open a real state file from `.snodo/tasks/` in this repository (a completed one and a blocked one) and read the field names from there rather than assuming them.
3. Create a new module file named record.py in the `demo/` folder (the folder already exists; look at how existing tests import code that lives outside `packages/`, for example under `experiments/`, and follow that pattern so the new tests can import the module) with a function that takes the project root, the task id, the model string and the arm name (`governed` or `bare`) and returns a dictionary with: `arm`, `model`, `task_id`, `outcome`, `halt_type`, `wall_seconds`, `input_tokens`, `output_tokens`, `cost_usd`, `cost_source`, `worktree_path`, `validator_findings` (list of validator id, severity and the justification text, bounded in length). `outcome` is `passed` when the task completed without a halt, `blocked` when the halt type is `blocker`, `halted` when it is `escalate`, and `error` plus the halt type for the engine and environment halt types; a missing or unreadable state gives `unknown`, never `passed`.
4. `cost_usd` is a number only when a per-call price is present in the recorded usage; otherwise it is null and `cost_source` is `unavailable`. Tokens are null when not recorded.
5. Add a second function that finds the task id of a run without parsing text: list the task folders under `.snodo/tasks/` before the run and after it, and return the new one (and say so clearly when zero or several are new). Add a third that writes the record as one JSON file.
6. Add tests in a new test file named test_demo_record.py under the tests folder using small fixture state files created in a temporary folder, in the real on-disk shape. Use exactly these test function names and keep them unchanged for the whole task, including in any follow-up fix pass (a coverage check fails the task when a test name disappears or is renamed): `test_completed_task_is_passed`, `test_blocker_keeps_validator_justification`, `test_escalate_is_halted`, `test_engine_fault_is_error_with_halt_type`, `test_missing_state_is_unknown`, `test_absent_tokens_and_cost_stay_null`, `test_new_task_id_found_from_before_and_after_listings`. More tests may be added. No snodo command and no network in tests.
7. The project supports Python 3.12; do not use 3.13-only APIs. Before finishing, run `python -m pytest tests/test_demo_record.py` and do not finish until every test passes (the gate reruns the file and one failing assertion blocks the task); write each expected value from what the code really returns. Also run `ruff check` and `ruff format --check` on every file you touched and fix what they report (remove unused imports and variables). These are checks for you to run; the reviewer does not re-run them.

## CONSTRAINTS
- Read the state file directly; do not shell out to snodo in this module.
- Do not change anything under `packages/` or `experiments/`.
- Add one line under `[Unreleased]` in `CHANGELOG.md`.
- No new states, statuses, severities, halt types or event names: use only the halt types and statuses the state files already carry.

## ACCEPTANCE
- In the diff, the record function maps the halt types as described (passed, blocked, halted, error plus halt type, unknown for a missing state) and keeps absent tokens and cost null with `cost_source` set to `unavailable`.
- The record contains the validator justification for a blocker.
- The new test file contains the seven named tests above.
- Verifiable from the diff of the new module, the new test file and CHANGELOG.md.
