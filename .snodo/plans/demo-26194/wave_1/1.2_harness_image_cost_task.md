# 1.2_harness_image_cost

## INTENT
The research harness scores a known-good patch as resolved and records cost for each arm. Today a positive-control run fails with `KeyError: 'image'` and every `cost_usd` is null.

## THE CHAIN
1. Open a GitHub issue first ("Harness: fix swebench 5.x image KeyError and populate cost") and put "Fixes #<n>" in the commit message.
2. In `experiments/scoring.py` (the swebench harness invocation near the comment about swebench 5.x), find where the dataset rows are handed to the swebench harness. swebench 5.x test specs need an `image` field on the dataset row that the selection files do not carry. Make the scoring path add the field the installed swebench version requires, derived the way swebench derives it, and only when the installed version needs it. If the installed swebench is not importable, report a clear `swebench not runnable` error as today instead of raising.
3. In `experiments/arms/arm_a_opencode.py` and `experiments/arms/arm_c_snodo.py` the arm functions return cost as `None`. Replace that with a value read from what the run left behind. For arm c: the run's persisted usage records, passed to `summarize_usage` (`packages/snodo-foundation/src/snodo/infrastructure/usage_summary.py`, which takes a list of record dicts). Evidence from earlier attempts that failed review: one called its own helper with the wrong number of arguments, and one read audit events under a `payload` key although on-disk audit events carry their content under `data` (see the `AuditEvent` dataclass in `packages/snodo-foundation/src/snodo/infrastructure/audit.py`), so cost was always `None`. Read the real on-disk shape (the task state file's `usage` list under `.snodo/tasks/<id>/state.json`, and `task_usage_records` in `packages/snodo-foundation/src/snodo/infrastructure/cloud_usage.py`, which already reads it) rather than assuming it. For arm a: the token counts and cost opencode prints when it provides them. When no figure exists, keep `None` and record `cost_source: "unavailable"` in the result so a missing number is never mistaken for zero.
4. Add unit tests in a new test file named test_experiments_scoring_image.py under the tests folder that run without Docker and without swebench. Use exactly these test function names and keep them unchanged for the whole task, including in any follow-up fix pass (a coverage check fails the task when a test name disappears or is renamed): `test_dataset_row_adds_swebench_image` (image-field helper with a fake row); `test_arm_c_cost_through_run_callsite` (writes a fixture in the real on-disk shape into a temporary run directory and calls the same function the arm's `run()` calls, the real call site and not an inner helper, asserting a number with `cost_source` for a fixture with usage and `None` with `cost_source: "unavailable"` for an empty one); `test_arm_a_parses_usage_samples` (a sample carrying tokens and a cost, a sample carrying tokens but no cost, a sample with neither, each with the expected values taken from what the arm's parsing function really returns for that sample); `test_swebench_missing_returns_error` (with swebench not importable, scoring returns a `swebench not runnable` error row). More tests may be added, none of these may be dropped or renamed.
5. Before finishing, run `python -m pytest tests/test_experiments_scoring_image.py` and the existing tests under `tests/` that cover `experiments/`, and do not finish until every test passes; the gate reruns the new file and a single failing assertion blocks the task. Also run `ruff check` and `ruff format --check` on every file you touched and fix what they report (remove unused imports and unused variables). These are checks for you to run; the reviewer does not re-run them.

## CONSTRAINTS
- Do not rerun any benchmark or call a model. No network in tests.
- Do not change arm behaviour other than the returned cost fields.
- Add one line under `[Unreleased]` in `CHANGELOG.md`.
- No new states, statuses, severities, halt types or event names.

## ACCEPTANCE
- The new test file contains the four named tests above and they cover the image field, arm c cost through the real call site, arm a cost with and without token counts and cost, and the swebench-absent error row.
- In the diff, arm c's cost path reads the persisted usage in the shape the on-disk files really have and calls `summarize_usage` with a list of records.
- Cost is `None` plus `cost_source: "unavailable"` when nothing is known, and a number when usage exists.
- Verifiable from the diff of the touched files and the new test file.
