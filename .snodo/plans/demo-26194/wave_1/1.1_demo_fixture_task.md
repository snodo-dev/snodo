# 1.1_demo_fixture

## INTENT
A user who clones this repository can find, in one small folder, everything needed to reproduce the scikit-learn-26194 bug-fix demo: the issue text, the repository, the base commit, and the tests that must go from failing to passing. The folder contains no solution.

## THE CHAIN
1. Open a GitHub issue first ("Add scikit-learn-26194 demo fixture") and put "Fixes #<n>" in the commit message.
2. The source row is line 67 of `experiments/tasks/s47.selection.jsonl` (instance_id `scikit-learn__scikit-learn-26194`). The file is large (about 1.4 MB): do not read it whole; take that one line (for example with `sed -n 67p`) and parse it as JSON. It carries repo, base_commit, problem_statement, FAIL_TO_PASS and PASS_TO_PASS.
3. Create a new folder `demo/scikit-learn-26194/` containing two new files, each to be created by this task (the worktree starts clean, so the folder and both files must be created again):
   - a new file named task.md in that folder: the problem_statement exactly as stored, byte for byte. Evidence from an earlier attempt: the stored text contains carriage returns (CRLF line endings), and a text-mode read/write silently turns them into plain newlines, which made the equality test fail even though the visible text looked identical. Write the file as bytes (or with `open(path, "w", newline="")`) so the stored text round-trips exactly.
   - a new file named instance.json in that folder with keys `instance_id`, `repo` (`scikit-learn/scikit-learn`), `repo_url`, `base_commit`, `fail_to_pass` (list), `pass_to_pass` (list). It has no gold-solution keys.
4. Create a new test file named test_demo_fixture.py under the tests folder. It reads the selection row from line 67 of the selection file (iterating lines, not loading the whole file at once), reads task.md without newline translation, and asserts: task.md text equals the row's problem_statement exactly; the instance.json keys above exist; `base_commit` is a 40-char hex string; `fail_to_pass` equals the two test ids of the row; no gold-solution text from the row appears anywhere in the new demo folder. It skips with a clear message if the selection file is absent.
5. The project supports Python 3.12. Do not use `Path.read_text` or `Path.write_text` with a `newline` argument (that exists only on Python 3.13+, and a previous attempt failed the gate on exactly this). Read with `open(path, newline="", encoding="utf-8")` or `read_bytes().decode("utf-8")`, and write with bytes or `open(path, "w", newline="", encoding="utf-8")`. This applies to the "no solution text" scan of the demo folder too.
6. Before finishing, run `ruff check` and `ruff format --check` on the new test file and fix what they report, and run the new test yourself. This is a check for you to run; the reviewer does not re-run it.

## CONSTRAINTS
- Do not copy the gold solution fields of the selection row anywhere into the new demo folder.
- Use only stdlib in the test. Do not modify anything under `experiments/`.
- Add one line under `[Unreleased]` in `CHANGELOG.md` describing the demo fixture.
- No new states, statuses, severities, halt types or event names.

## ACCEPTANCE
- The new test file asserts that task.md equals the selection row's problem_statement exactly with newline translation off, that instance.json has exactly the keys listed, and that no gold-solution text is present in the demo folder.
- The new test uses no Python 3.13-only API.
- instance.json contains exactly the keys listed and no gold-solution keys.
- Verifiable from the diff of the new files and CHANGELOG.md.
