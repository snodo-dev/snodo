## The one failure, and its actual cause

Failing node: `tests/cli/test_retry_spec_safety.py`, the test
`test_cli_retry_workspace_choice_preserves_spec_and_prior_work`, only in its
`fresh` parametrization. It fails when the `continue` case runs first in the same
process, and passes on its own.

The cause is workspace sharing, not the retry logic:

- A task's worktree root is a **sibling** of the project root: a project placed in
  some directory gets its worktrees in a container directory next to it, not inside
  it.
- The test creates both parametrized cases as projects directly under the OS temp
  directory with the same task id, so both cases resolve the *same* worktree path.
- The reuse rule in the foundation worktree module returns an existing path
  without checking that it belongs to the repository being retried in. The second
  case therefore reuses the first case's leftover directory, no branch is created
  for it, and the assertion that looks up the previous attempt's branch raises an IndexError reporting that no branch exists for the
  previous attempt's identity.

Measured, from the preserved workspace, with the cases run in order:

```
uv run pytest tests/cli/test_retry_spec_safety.py -p no:randomly -k workspace_choice
```

and the same run with `-k "workspace_choice and not continue"` passes.
