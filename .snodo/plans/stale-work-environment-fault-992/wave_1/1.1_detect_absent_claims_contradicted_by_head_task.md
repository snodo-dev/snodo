# Detect "files absent" claims that the workspace HEAD contradicts (Fixes #992)

GitHub issue #992 already tracks this work. Put "Fixes #992" in the commit message.

## INTENT
A coder sometimes returns saying the task's subject files or named tests do not exist, when the workspace it was dispatched to already holds them (issue #975 showed it after a retry). The engine needs a small, conservative way to tell that apart from an honest "nothing to change". This ticket builds only the detection: given the coder's report text and the dispatched workspace, say which explicitly named paths the coder called absent that are in fact present at the workspace's HEAD.

## THE CHAIN
1. Input: the coder's final report text and the dispatched workspace (path and its checked-out HEAD).
2. The detector looks for file paths the report names explicitly as missing, absent, or nonexistent. Matching on named paths is the whole signal; a refusal-sounding phrase without a named path never fires it.
3. Each named path is checked against the workspace's HEAD, not against the project root (confusing the two is the bug being detected). Paths are resolved relative to the workspace and cannot escape it.
4. Output: the contradicted paths (absent per the coder, present per HEAD), plus the HEAD identifier, or nothing when there is no contradiction. A path the coder calls absent that is also absent at HEAD is not a contradiction.

## CONSTRAINTS
- Conservative on purpose: a false positive that halts a legitimate attempt is worse than a miss. Prefer explicit paths and clear wording over cleverness.
- A small self-contained unit with no wiring into the engine's halt path; a sibling ticket in the next wave does the wiring.
- Do not add a status, severity, halt type or audit event.
- No new third-party dependency.
- Do not touch CHANGELOG.md; the wiring ticket owns the entry.
- Tests use a real throwaway git repository with a linked worktree, so project root and workspace differ in content, and stay offline. Targeted tests only.

## ACCEPTANCE
- A report naming a file as missing that exists at the workspace HEAD, while the project root lacks it, yields that path and the HEAD.
- A report naming a file as missing that is also absent at HEAD yields nothing.
- A report with refusal-style wording but no named path yields nothing.
- A named path that tries to leave the workspace is ignored.
- Targeted tests pass and lint is clean for the whole tree.
