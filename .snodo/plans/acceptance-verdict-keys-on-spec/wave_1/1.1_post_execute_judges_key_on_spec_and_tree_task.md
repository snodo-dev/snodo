# 1.1_post_execute_judges_key_on_spec_and_tree

## INTENT
A post-execute judge such as acceptance judges the produced work against the acceptance criteria written in the task spec. Its cached verdict is keyed on the tree alone, so a spec that is rewritten on an unchanged tree gets the old verdict back, flagged "reused". Symptom and evidence: in plan retry-reuses-validator-verdicts, task 3.2, the spec's acceptance criteria were corrected, the tree stayed the same, and the acceptance warn stored before the correction came back as "(reused)" in the run and in all three recovery attempts. Fixing the spec could never clear that warn; the cache entry had to be edited by hand. The same applies to coverage_accountability, which reads the spec to learn that a test removal is intentional.

The wanted behaviour: a judge whose answer depends on the spec and on the work is keyed on both. An unchanged spec on an unchanged tree still reuses the verdict, so a retry or recovery attempt stays cheap. A changed tree or a changed spec is judged again.

## THE CHAIN
1. Open a GitHub issue first ("Post-execute judges are cached on the tree alone, so a rewritten spec replays a stale verdict") and put "Fixes #<n>" in the commit message.
2. In `packages/snodo-engine/src/snodo/validators/runner.py`, `_verdict_subject_kind` currently sends every post-execute judge to the plain tree subject. Change it so the post-execute judges that read the spec (tool-using judges, and the single-completion judges that today fall back to the tree) use the existing composite spec-plus-tree subject that pre-execute tool judges already use. A validator class that declares the plain tree on purpose and does not read the spec, such as the quality gate, keeps the plain tree subject. Update the docstring of that function so it states the new rule and why (a judgement about produced work is also a judgement against the criteria in the spec).
3. `tests/validators/test_verdict_cache.py` pins the old behaviour in `test_post_execute_tool_judge_keying_is_unchanged_by_spec`. The old behaviour is the defect, so that test is replaced ON PURPOSE by `test_post_execute_tool_judge_rejudges_when_spec_changes`, which asserts: same spec and same tree reuse the verdict, and a changed spec on the same tree is judged again. Keep every other test name in that file unchanged; adjust the other post-execute tests only where their expectation depends on the old rule, and keep their names.
4. `CHANGELOG.md` gets one new line under `[Unreleased]` in the same commit, in the style of the neighbouring entries, ending with "(Fixes #<n>)".
5. The project supports Python 3.12. Do not run `ruff format` over whole files. Run `python -m pytest tests/validators/test_verdict_cache.py` and `ruff check packages tests`, and write each expected value from what the code returns.
