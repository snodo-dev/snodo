# 1.2_align_cache_subject_comments

## INTENT
Two comments say that the runner forces every post-execute judge onto the plain tree subject and that acceptance "judges the produced work, not the spec". That is the rule the sibling task 1.1 of this plan is replacing: post-execute judges that read the spec are keyed on spec plus tree, because acceptance judges the work against the criteria written in the spec. Left as they are, the comments would describe behaviour the code no longer has. This task only brings the comments in line.

## THE CHAIN
1. Open a GitHub issue first ("Comments on post-execute cache keying describe the old tree-only rule") and put "Fixes #<n>" in the commit message.
2. In `packages/snodo-engine/src/snodo/validators/acceptance.py`, the comment above `cache_subject` under `class AcceptanceValidator`; and in `packages/snodo-engine/src/snodo/validators/llm_validator.py`, the comment block above `cache_subject = "spec"` in `LLMValidator`: reword them to say that the runner decides the subject structurally, and that a post-execute judge which reads the spec is keyed on spec plus tree (an unchanged spec and tree reuse the verdict, a changed spec or tree is judged again). The assigned `cache_subject` values themselves do not change.
3. `CHANGELOG.md` gets one new line under `[Unreleased]` in the same commit, in the style of the neighbouring entries, ending with "(Fixes #<n>)".
4. The project supports Python 3.12. Run `ruff check packages tests`. Do not run `ruff format` over whole files.

## CONSTRAINTS

- No new states, statuses, severities, halt types or event names.
