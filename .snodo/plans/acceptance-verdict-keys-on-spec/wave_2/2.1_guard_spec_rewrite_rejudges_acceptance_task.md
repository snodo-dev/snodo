# 2.1_guard_spec_rewrite_rejudges_acceptance

## INTENT
Task 1.1 of this plan keys post-execute judges that read the spec on spec plus tree. This task proves it end to end with tests, so that a future change putting the cache back on the tree alone fails loudly. Symptom being guarded against: a task spec is corrected after an acceptance warn, the tree is unchanged, and the old warn comes back as "reused" until the cache is edited by hand.

## THE CHAIN
1. Open a GitHub issue first ("Guard: rewriting the spec re-judges acceptance on an unchanged tree") and put "Fixes #<n>" in the commit message.
2. Read `tests/engine/test_verdict_cache_visibility.py` (how a run with a verdict cache is exercised and how reuse is observed) and the post-execute tests in `tests/validators/test_verdict_cache.py` (how a tool-using acceptance judge and a git double are set up).
3. Add tests to `tests/engine/test_verdict_cache_visibility.py` with exactly these names, kept unchanged for the whole task including any follow-up fix pass (a coverage check fails the task when a test name disappears or is renamed): `test_acceptance_rejudged_after_spec_rewrite_on_unchanged_tree` (attempt 1 warns; attempt 2 has a rewritten spec on the same tree; the fake judge is called again and the result is not marked reused), and `test_acceptance_reused_when_spec_and_tree_unchanged` (a second attempt with the identical spec and tree makes zero judge calls and the result is marked reused). Production code is not changed in this task; if a test cannot pass without a production change, fix the test's setup first, and only report the gap in the final message if the production behaviour is really wrong.
4. `CHANGELOG.md` gets one new line under `[Unreleased]` in the same commit, in the style of the neighbouring entries, ending with "(Fixes #<n>)".
5. The project supports Python 3.12. Run `python -m pytest tests/engine/test_verdict_cache_visibility.py` and `ruff check` on the file you touched. Do not run `ruff format` over whole files.

## CONSTRAINTS
- Only `tests/engine/test_verdict_cache_visibility.py` and `CHANGELOG.md` may change; no file under `packages/`.
- No new states, statuses, severities, halt types or event names.

## ACCEPTANCE
- The diff adds the two named tests to `tests/engine/test_verdict_cache_visibility.py` and changes no file under `packages/`.
- The diff adds one line under `[Unreleased]` in CHANGELOG.md that mentions the issue.
