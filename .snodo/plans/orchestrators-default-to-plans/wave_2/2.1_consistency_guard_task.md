Before starting, open a GitHub issue on snodo-dev/snodo titled "Guard: orchestrator-facing guidance must agree that plans are the default" and put "Fixes #<n>" in the commit message.

INTENT
Every surface an orchestrating agent reads now teaches the same canonical rule, verbatim:

"Group work into plans. A plan is one clear intention. Waves group its tasks: tasks in a wave run in parallel, and waves run in series. Queues group and schedule plans. Dispatch a single task only for a true one-off with no related work. A plan with one task in one wave adds nothing."

Those surfaces are:
- the MCP connect-time instructions, built by `_build_instructions` in `packages/snodo-mcp/src/snodo/mcp/transport.py`;
- the `guide` tool's default answer and its `waves`, `mistakes`, `planning`, `automation` and `queues` topics (from `docs/authoring-a-plan.md`, `docs/running-unattended.md` and `docs/queues.md`);
- `README.md`;
- `docs/specs/mcp-self-description.md`.

Before this change, the old "smallest structure" rule drifted across these surfaces and agents kept defaulting to single tasks. This task adds a guard so the surfaces can't drift apart again, and records the change in the CHANGELOG.

THE CHAIN
1. `tests/mcp/test_structure_guidance.py` (new): a test that builds the connect-time instructions and reads each guide topic through the guide tool's own functions. It also reads `README.md` and `docs/specs/mcp-self-description.md`. It asserts that each contains the canonical rule.
2. Same file: a test asserting that none of those surfaces contains "smallest structure", "smallest-structure", "dispatch one task directly", "do not wrap it in a one-task plan" or "use a plan only".
3. `CHANGELOG.md`, under `## [Unreleased]`: one entry saying that orchestrator guidance now defaults to plans, with a guard test. It references this issue and the four issues opened in the previous wave for the same change; find them on GitHub by their titles.

CONSTRAINTS
- Wording and tests only. No behaviour or state-machine change, because Snodo's state machine is closed.
- If a surface does not yet contain the canonical rule, report that as a failing test. Do not edit that surface's wording to make the test pass, because each surface had its own task.
- Out of scope: every other file.

ACCEPTANCE

- The CHANGELOG entry is present.
- `make gate` passes.
