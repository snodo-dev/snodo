INTENT
`docs/running-unattended.md` (the `automation` guide topic, for long unattended runs) and `docs/queues.md` (the `queues` topic) are read by orchestrators.
- Today running-unattended tells them to follow the "smallest-structure rule" for each intent.
- For "an intent that is one task" it says to dispatch it directly and "do not wrap it in a one-task plan".
- It also says to "Prefer the direct path for one task unless preserving that hierarchy is an intentional reporting requirement".
- queues.md also points to the smallest-structure rule.

Unattended orchestrators therefore turn a stream of intents into single jobs. The owner's model is that each intent becomes a plan: one clear intention, its tasks grouped into waves, and plans grouped and scheduled by queues. When this task is done, both pages teach that model with this canonical rule, verbatim:

"Group work into plans. A plan is one clear intention. Waves group its tasks: tasks in a wave run in parallel, and waves run in series. Queues group and schedule plans. Dispatch a single task only for a true one-off with no related work. A plan with one task in one wave adds nothing."

THE CHAIN
