Before starting, open a GitHub issue on snodo-dev/snodo titled "README and MCP self-description spec describe smallest-structure rule instead of plans-as-default" and put "Fixes #<n>" in the commit message.

INTENT
Two documents restate the old rule that steers orchestrators toward single tasks:
- `README.md`, in "The working loop" section, says the orchestrator "chooses the smallest structure that fits—one task, a parallel wave, a multi-wave plan, or a queue of plans".
- `docs/specs/mcp-self-description.md` says the instructions "recommend the smallest structure that fits: one direct task, a wave for parallel tasks, a plan for multiple waves, and a queue for several plans".

The owner's model is that plans are the default unit of work. When this task is done, both documents describe that model with this canonical rule, verbatim:

"Group work into plans. A plan is one clear intention. Waves group its tasks: tasks in a wave run in parallel, and waves run in series. Queues group and schedule plans. Dispatch a single task only for a true one-off with no related work. A plan with one task in one wave adds nothing."

THE CHAIN
1. `README.md` "The working loop": the orchestrator groups work into plans, using the canonical rule. The rest of the paragraph (validator loop, async jobs, live view) is unchanged.
2. `docs/specs/mcp-self-description.md`: the instructions are described as recommending the canonical rule.

CONSTRAINTS
- Wording only. Snodo's state machine is closed.
- Out of scope: everything else under `docs/`, plus code, tests and `CHANGELOG.md`.

ACCEPTANCE
- Both files contain the canonical rule verbatim and no "smallest structure" text.
- `make gate` and the docs build pass.
