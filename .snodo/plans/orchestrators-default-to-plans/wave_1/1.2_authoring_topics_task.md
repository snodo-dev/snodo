INTENT
`docs/authoring-a-plan.md` is served through the `guide` tool. It supplies the `waves`, `mistakes` and `planning` topics, which are delimited by `<!-- snodo-guide ... -->` markers. Today these topics teach a "smallest structure" rule: dispatch one task directly, and use a plan only when there is more than one wave. The planning loop even begins "When multiple waves are needed". So agents that read the guide default to single tasks. The owner's model is that plans are the default unit of work. When this task is done, these topics teach that model with this canonical rule, verbatim:

"Group work into plans. A plan is one clear intention. Waves group its tasks: tasks in a wave run in parallel, and waves run in series. Queues group and schedule plans. Dispatch a single task only for a true one-off with no related work. A plan with one task in one wave adds nothing."

The existing true content stays:
- Dependencies are between waves, not tasks.
- A wave holds several small tasks.
- `validate_plan` is not a human authorization gate.
- Plan tasks use the same validators and auto-merge policy.
- Plans add durable plan→wave→task history (ADR 054).

THE CHAIN
1. `docs/authoring-a-plan.md`, section "1. The one modelling rule" (`waves` topic): the canonical rule replaces the smallest-structure paragraph.
2. Same file, section "4. What gets the plan refused" (`mistakes` topic): "Choose the structure before authoring" refers to the canonical rule. It names "sending related work as a string of single tasks" as a mistake, next to the existing "one task per wave" mistake.
3. Same file, section "8. The planning loop, end to end" (`planning` topic): the loop starts from one intention as a plan, with no "when multiple waves are needed" condition. The direct `validate_task` → `dispatch_task` path is described only as the one-off exception.
4. The section anchor `#1-the-one-modelling-rule` and all `snodo-guide` markers (topic names, aliases, sections) keep working. Other docs link to that anchor.

CONSTRAINTS
- Keep the `snodo-guide` marker comments intact, because the guide tool parses them.

- Out of scope: every other file, including `docs/running-unattended.md`, `docs/queues.md`, `README.md`, `docs/specs/`, code, tests and `CHANGELOG.md`.

ACCEPTANCE
