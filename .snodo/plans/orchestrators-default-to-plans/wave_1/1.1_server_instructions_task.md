Before starting, open a GitHub issue on snodo-dev/snodo titled "Connect-time instructions and guide default steer orchestrators to single tasks" and put "Fixes #<n>" in the commit message.

INTENT
Orchestrating agents read the MCP server's connect-time instructions and the `guide` tool's default (no-topic) answer first. Today both steer them to single tasks: the instructions say "Choose the smallest structure that fits: dispatch one task directly; use a wave only for multiple tasks…; use a plan only for multiple waves…", and the guide default points at "the `waves` topic for the smallest-structure rule". The result is that every agent sends related work as a string of one-off jobs. The owner's model is different: plans are the default unit of work. When this task is done, both surfaces teach that model with this canonical rule, verbatim:

"Group work into plans. A plan is one clear intention. Waves group its tasks: tasks in a wave run in parallel, and waves run in series. Queues group and schedule plans. Dispatch a single task only for a true one-off with no related work. A plan with one task in one wave adds nothing."

The existing true statements about plans stay: a plan adds plan→wave→task history for cloud reporting, does not add a human authorization gate, and does not change the task validator loop or auto-merge policy.

THE CHAIN
1. `packages/snodo-mcp/src/snodo/mcp/transport.py` (`_build_instructions`): the connect-time instructions carry the canonical rule instead of the smallest-structure sentence.
2. `packages/snodo-mcp/src/snodo/mcp/guide.py` (`guide_text` default path): when plan tools are exposed, the default answer states that plans are the default and points to the plan loop (`propose_plan` → `generate_spec` → `validate_plan` → `run_plan`, `queue_run` for queued plans). It no longer mentions a "smallest-structure rule". When only `dispatch_task` is exposed, the existing direct-task text stays, since that mode cannot make plans.
3. `tests/mcp/test_server.py`: the assertions that pin the old wording ("dispatch one task directly", "smallest-structure rule", "smallest-structure rule above") assert the new wording instead.

CONSTRAINTS
- Do not change tool names, tool behaviour, or which tools a mode exposes. This change is about wording only. `_assert_names_only_exposed_tools` must still pass, so don't name a tool the mode does not expose.
- Snodo's state machine is closed. Add no status, halt type, severity, audit event or field.
- Out of scope: everything under `docs/`, `README.md` and `CHANGELOG.md`. Other tasks own those.

ACCEPTANCE
- The updated tests in `tests/mcp/test_server.py` pass. They assert that the connect-time instructions contain "Group work into plans. A plan is one clear intention." and contain neither "smallest structure" nor "dispatch one task directly".
- A test asserts that the guide default answer (with plan tools exposed) contains no "smallest-structure" text and does mention `propose_plan`.
- `make gate` passes.
