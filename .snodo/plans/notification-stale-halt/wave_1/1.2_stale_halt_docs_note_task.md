# 1.2_stale_halt_docs_note

## INTENT
The outcomes documentation tells an operator how a finished job is announced: a job that completed with exit code 0 is reported as a success, even if an earlier attempt of one of its tasks halted and was resolved by a retry.

## THE CHAIN
1. Open a GitHub issue first ("Docs: finished-job situation when an earlier attempt halted") and put "Fixes #<n>" in the commit message.
2. Symptom: a plan that finished 3/3 completed was announced as Blocked in Slack because an earlier halt stayed in the job state.
3. Read `docs/outcomes.md` and the notification parts of `docs/running-unattended.md`. Where they describe how a finished job is classified or announced, add a short passage in the same voice: a job that completed with exit code 0 is a success; an earlier halt that a retry resolved does not change that; a job that failed or ended unmerged keeps its halt as the reason. If neither page describes classification, add the passage to the page that describes outcomes.
4. Run `make docs` yourself to confirm the docs still build in strict mode and the anchor check passes. This is a check for you to run; the reviewer does not re-run it.

## CONSTRAINTS
- Documentation files only. Do not touch code or tests.
- Soft, natural wording; no new terminology and no new states, statuses, severities, halt types or event names.
- Add one line under `[Unreleased]` in `CHANGELOG.md`.

## ACCEPTANCE
- The docs state that a completed exit-0 job is a success regardless of an earlier resolved halt.
- The change is verifiable from the diff of the docs files and `CHANGELOG.md`; no git history lookups are needed.
