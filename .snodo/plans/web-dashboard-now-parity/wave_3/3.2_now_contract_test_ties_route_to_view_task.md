INTENT
The Now route and the Now view are built by different tasks and agree only through a response shape written in task specs. Nothing in the tests checks that the two sides still agree, so a renamed field would leave the page quietly empty. This task adds that check: one test file that builds a realistic project, asks the route code for its answer, and confirms the view script reads what the route sends.

Evidence: tests/web/test_routes_now.py checks the route and tests/web/test_static_now.py checks the script as text, and neither looks at the other.

What it should cover: a temporary project with a real git repository, a plan with several waves and a mix of completed, running and blocked tasks, a task run outside any plan and one uncommitted file; the route's builder gives every field of the contract (window_hours, generated_at, counters with projects_active, plans, queues, waves, tasks.count, tasks.by_status, recons, commits; projects with name, liveness, last_activity_at, plans with name, wave, waves, last_activity_at and wave_groups carrying id, total, status_counts and tasks with task_id, status, job and elapsed_seconds; outside_plan; waiting); and now.js, read as text, mentions each of those field names it is meant to consume, so a rename on either side fails this test. Counters must add up against the tree for the fixture (tasks.count equals the tasks in the tree plus those outside a plan).

CONSTRAINTS
Files that may change: the new test file and CHANGELOG.md. Do not edit the route, the view or any other test. Tests must not bind a port or start a server. The test reads files and calls the builder directly.

ACCEPTANCE
