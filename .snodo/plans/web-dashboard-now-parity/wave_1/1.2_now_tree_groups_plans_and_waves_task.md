New files this task will create: `snodo/web/now_tree.py`, `tests/web/test_now_tree.py`.

INTENT
The cloud Now page shows an In flight tree: each project with a liveness badge, under it each plan with its waves, under each wave its tasks with state and elapsed time, plus a group for tasks that run outside any plan. The local Now lists only tasks that are running this second, so a plan that finished an hour ago, its waves and its one blocked task are invisible, and a project that reported minutes ago but is between plans shows as nothing. This task supplies the data for the same tree: a read-only calculation, for one project, of everything that moved in the last 24 hours, grouped project, plan, wave, task.

What it returns for a project: a liveness word, one of working (a task is in progress or a job is running), reporting_not_progressing (something moved in the window but nothing is in flight right now), or no_recent_signal (nothing moved in the window); the time of its last activity; and every plan that moved in the window with its current wave number, total waves, last activity time, and each wave with its task total, a per-status count, and its tasks (task id, status exactly as the files report it, the running job's id when there is one, and elapsed seconds). Elapsed means how long a running task has been running, and for any other task how long ago it last changed; when the files give no timestamp it is unavailable rather than guessed. Tasks that ran outside any plan and moved in the window go in a separate group. Plans and projects are ordered by last activity, most recent first.

Evidence: snodo/web/routes_now.py builds a flat plans and tasks list limited to in-progress tasks and running jobs; the settled waves, blocked tasks and between-plans projects that the cloud page keeps visible are dropped there.

CONSTRAINTS
Pure reads: no writes, no locks, no network. No new task, plan, job or wave states: statuses pass through exactly as read, and the three liveness words are display text only. A missing or unreadable project directory yields a project with no plans and no_recent_signal rather than an exception. Reuse the existing readers in snodo.dashboard.providers where they already read this data. Keep the import-linter layering. Files that may change: the two new files and CHANGELOG.md; do not edit snodo/web/routes_now.py or any static file.

ACCEPTANCE
Tests that exist and pass, built on a temporary project with plan files and job records: a plan with every task completed an hour ago appears with its waves, per-status counts and tasks; a plan untouched for two days does not appear; a running job makes the project working and gives its task an elapsed time; a project with recent activity and nothing running is reporting_not_progressing; a project with no activity in the window is no_recent_signal; a blocked task keeps the status it reports; tasks outside any plan are in their own group; ordering is most recent activity first; an unreadable project does not raise.
