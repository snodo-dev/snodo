## Intent
`snodo recon` accepts a repeatable `--model` option and a comma-separated `--models` option, so an operator can run a recon on exactly the models they name, the way the MCP recon tool already can.

## Evidence
- In snodo/cli/commands/recon_cmd.py the command has only `--agents` / `-n` (a count); the lanes come from `resolve_recon_agents_with_notice` using the first models of the recon configuration, so there is no way to pick models from the command line.
- The MCP recon tool already accepts an explicit list of agents, where each entry is a lane and a lane may be a failover chain; the CLI should reuse that shape (one lane per model) rather than invent a new one.
- A model that fails at dispatch today surfaces as a raw provider error (for example "Missing credentials") long after the command returned.

## Outcome
- `--model <name>` can be given several times; each value is one agent running that one model (no failover chain from the command line). `--models <a,b,c>` takes a comma-separated list and is the same as repeating `--model` for each name. If both forms are used, the models run in the order given.
- The same model may be listed more than once (independent runs of one model).
- The models listed always override the recon configuration; they are exactly what runs, and the dispatch output lists them as it does for configured models.
- `--model` or `--models` together with `--agents` / `-n` is refused with a short error message that says the count comes from the number of models listed, and nothing is dispatched.
- A model that is not known, or whose provider is not configured, is refused before dispatch with a plain message naming the model; nothing is dispatched.
- Without `--model` or `--models` the command behaves exactly as before.
- Tests cover: two models by repeating `--model`, a comma-separated `--models` list, a repeated model, `--model` with `-n` refused, an unknown model refused, and the no-option path unchanged (no network, no real model calls).
- `make gate` passes, including ruff, import-linter and the file-length and docs-coverage checks.
