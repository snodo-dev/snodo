## Intent
When every task in a wave is completed (some recorded by hand), running that wave again should finish it by merging the integration work to main, not exit as though nothing needed doing.

## Evidence
- Recent plan, wave 2: after the last task was hand-merged and recorded completed, running the wave returned a job that finished in about a second with exit 0 and no merge. The integration branch, which still held the wave's other two tasks, stayed unmerged until the orchestrator merged it by hand. A later wave merged normally, so behaviour depended on how the wave was reached.
- In snodo/cli/commands/plan_run.py, `_execute_waves` skips the wave-complete callback when no tasks need running, and the full-plan delivery fallback does not necessarily apply to a single-wave run. `deliver_healthy_plan_wave` in plan_delivery.py performs the delivery.

## Outcome
- A rerun of a wave with no pending tasks delivers any unmerged integration work to main through the existing delivery path, and reports that it did, or says clearly why it did not (for example nothing to deliver, or a failed health check).
- Work already delivered is not delivered twice.
- Tests: a wave whose tasks are all completed, one of them recorded through `record_task_status`, is delivered on rerun; a wave already delivered reports that and changes nothing.
- `make gate` passes.
