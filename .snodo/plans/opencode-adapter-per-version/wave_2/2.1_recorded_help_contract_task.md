# Pin each OpenCode major's launch flags to its recorded `run --help` (Fixes #983)

## INTENT
The 2.x regression slipped through because nothing compared what snodo sends against what the installed OpenCode actually accepts; a fetched web page and an unreviewed assumption won over the real `--help`. Each supported major should have its real `opencode run --help` text recorded in the repo, and a test should fail whenever an adapter's launch argv contains a flag that major's recorded help does not list. The recorded text is the source of truth, not docs and not memory.

## THE CHAIN
1. Record the real `run --help` output for 2.x, taken from the installed 2.0.32 and given below, as a fixture under the existing coder test fixtures area.
2. Record the 1.x `run --help` as a fixture too. Use what the 1.x adapter sends today as the lower bound: the fixture must list the directory flag, the skip-permissions flag, the format flag and the model flag. Mark in a comment that the 1.x text is reconstructed from the adapter's contract until a real capture replaces it.
3. A contract test builds each major's launch argv (fake the version; spawn nothing) and asserts every flag-looking token in it appears in that major's recorded help.
4. A second assertion for 2.x states plainly that the directory flag and the skip-permissions flag are absent from the recorded help, so a future edit that adds either to the 2.x argv fails with a message pointing at the fixture.

Recorded 2.0.32 `run` options (flags only, verbatim names): `--help`, `--version`, `--print-logs`, `--log-level`, `--command`, `--continue`, `--session`, `--fork`, `--share`, `--model`/`-m`, `--agent`, `--format`, `--file`/`-f`, `--title`, `--attach`, `--standalone`, `--auto`, `--variant`, `--thinking`.

## CONSTRAINTS
- Tests and fixtures only. Do not change production code, and do not edit CHANGELOG.md.
- Do not touch the adapter test file used by the sibling task in this wave; add a new test file and new fixture files.
- Do not call the real OpenCode binary from tests.
- No new dependency.

## ACCEPTANCE
- A new contract test file passes against the adapters as they are on main after wave 1.
- Temporarily adding a directory flag to the 2.x argv would make the new test fail with a message naming the fixture (verified by reasoning in the test, not by editing production code).
- Targeted coder tests pass.
