## INTENT
When a coder runs a snodo command inside its task worktree, the command should work normally for the coder without persisting audit events into `.snodo/`. A coder's own self-check is not governed work.

## THE CHAIN

- The committed implementation: under `SNODO_CODER_SUBPROCESS=1`, `get_audit_log()` redirects audit paths under `.snodo/` to a process-local temporary log, so reads during the command still work. It has `ready` tests for both the marked and unmarked cases. `validate`, `task list` and `plan list` make no other `.snodo/` writes.
