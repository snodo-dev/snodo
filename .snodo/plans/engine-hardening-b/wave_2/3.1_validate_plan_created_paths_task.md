## Intent
`validate_plan` should flag a path a task spec cites only when nothing in the plan creates it.

## Evidence
- While authoring a plan, validation returned "Missing referenced path" for files that the plan's own earlier tasks create (a new module and a new command module). The workaround was to write specs that name modules in words instead of paths, which makes specs vaguer for the coder.
- `verify_plan` in packages/snodo-foundation/src/snodo/compiler/verifier.py already exempts paths found in the created-by-task and earlier-created sets; `planned_spec_paths` and `_spec_referenced_paths` in packages/snodo-foundation/src/snodo/infrastructure/worktree.py decide which paths a spec creates and which it cites. Investigate which spec shapes fail to register as creating a path (for example creation described on a different line from the path, or in a bullet) before changing anything.

## Outcome
- A cited path is accepted when an earlier task in the same plan is declared to create it, whichever of the usual spec shapes states that; when the creating task comes later in the plan, the report says so clearly instead of calling the path missing.
- A genuinely missing input path is still reported.
- Tests cover a second task citing a file the first task creates (in more than one phrasing), a creator that comes later, and a genuinely missing path.
- `make gate` passes.
