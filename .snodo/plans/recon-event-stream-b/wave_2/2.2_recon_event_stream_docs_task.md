## Intent
Tell operators that a recon can be watched live, so they use it, and make the spec's event wording match the code.

## Evidence
- docs/command-reference.md and docs/decompose-and-recon.md describe following a recon with `snodo logs <recon id> --watch` as printing each agent's answer when it arrives; they do not say the command also shows each agent's progress while it works.
- docs/specs/recon-agents-cli.md has a section on the recon event log, but it names the kinds in prose ("agent started", "tool turn", "agent finished", "agent failed"); the code's record kinds are start, tool_turn, failover, finish and failure (see the event log module in the recon package).

## Outcome
- The command reference says that watching a recon shows each agent's progress lines (reads and failovers) as they happen, then the answers, and that Ctrl-C detaches without stopping the recon.
- The decompose-and-recon guide mentions the live progress next to the existing note on following a recon, and names the spec for the `events.jsonl` format by its repository path shown as code (docs/specs is not served on the published site, so it is not a markdown link).
- The spec section names the kinds exactly as the code does.
- Existing statements stay correct.
- `make gate` passes, including the docs-coverage and docs link checks.
