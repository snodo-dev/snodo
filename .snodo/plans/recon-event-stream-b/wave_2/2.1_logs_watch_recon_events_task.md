## Intent
Show a recon working. When an operator runs `snodo logs <recon id> --watch`, they should see each agent's progress as it happens, followed by the answers, rather than silence until an agent finishes.

## Evidence
- `snodo logs` for a recon id with `--watch` follows the recon to completion and prints each agent's result once as it lands; that loop lives in snodo/cli/commands/logs_cmd.py. Recons write progress events to `events.jsonl` in their directory, and the event log module in the recon package (event_log.py) can read events from a byte offset and format one as a line.
- Jobs are followed by tailing their stdout.log and draining it at the end (`_stream_job_stdout`); the same tail-then-drain approach applies here. logs_cmd.py is already long; if the file-length check complains, put the new rendering in a new module beside it rather than raising a baseline.

## Outcome
- While watching a recon, new events are read from the last offset on each poll and printed as one line each, in file order, before any result that lands at the same poll; when the recon ends the remaining events are drained once more so none are lost.
- Each agent's answer is still printed exactly once as it lands, as before; a recon with no events file (an older recon, or one that wrote none) is watched exactly as it is today.
- Without `--watch`, output is unchanged and the events are not printed.
- Ctrl-C still detaches quietly.
- Event lines carry the lane position and agent label so two agents on the same model can be told apart.
- Tests cover: events interleaved with results over several polls, drain at completion, an old recon with no events file, a partial last line left for the next poll, and unchanged output without `--watch`. Polling stays injectable so tests do not sleep.
- `make gate` passes.
