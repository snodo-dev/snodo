## Intent
Readers should be able to learn what the engine now does when a host CLI coder works outside its workspace, and, just as important, what it still does not do. The behaviour described is already merged (wave 1 of this plan and the earlier plan coder-escape-guard-946), so the documentation can state it in the present tense.

## Evidence
- The escape check runs on every coder exit; an explicit `sandboxed: true` on a host CLI coder halts as `environment_error` with guidance (ADR 051 carries a dated clarification saying so). The executor also compares the content of the operator's checkout against a baseline taken before dispatch and blocks acceptance on any change, listing the changed paths; engine runtime state under `.snodo/` is excluded while plan definition files and protocol.yml are watched; the guard does not apply to in-place work or in-process coders.
- Existing documents on this: docs/decisions/058-protected-path-advisory-guidance-and-merge-base-detection.md (advisory versus blocking), docs/decisions/051-coder-containment-is-declared-not-deployed.md (what a contained coder is and the `environment_error` outcome), and the docs page that covers coder configuration and the `sandboxed` setting. Find the page that mentions `sandboxed` or workspace confinement before choosing where to write.
- Limits to state plainly: this detects after the fact and blocks acceptance, it does not prevent the write and does not undo damage; it cannot see writes to arbitrary host paths outside the repository; a concurrent edit by the operator looks the same as a coder edit; true prevention is the contained adapter of ADR 051.

## Outcome
- One short section in the coder configuration documentation (the page that covers `sandboxed`) says what the setting does for each coder family, that an explicit `sandboxed: true` on a host CLI coder is refused with the halt and the way out, and the limits above.
- A short dated clarification note appended to the end of ADR 058 points to this behaviour and restates that prevention remains out of scope; existing decision text is untouched.
- The docs strict check passes (links and anchors resolve). Run it yourself and report the result.
- No new states, statuses, severities or halt types.
