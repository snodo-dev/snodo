Before starting, open a GitHub issue on snodo-dev/snodo titled "Give every job notification type its own icon". Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased].

INTENT
The owner reads job notifications (the "SnodoDev Notifications" Slack app) on his phone. Today only some types carry an icon:
- a completed job starts with ✅;
- a failed job starts with ⚠️;
- the stall alert ("job j_… — plan … — no log activity for 900s — Inspect: snodo logs j_…") has no icon at all.

Scrolling a busy channel, the stall alerts look like everything else. He asked for an hourglass (⏳) on the no-log-activity alert, and in general a distinct icon for every notification type, so the type is visible at a glance.

The notification text is built in snodo's job notifications module (the one that emits "no log activity").

When this is done:
- every notification type the module can emit starts with its own icon, from one mapping that covers every type;
- the stall alert uses ⏳;
- a failure is visually distinct from a warning-like event, so pick the icons with that in mind;
- the rest of each message (repo, host, job id, plan, "Inspect:" hint) is unchanged.

THE CHAIN
1. Find every notification type the module emits and give each one a single icon in one place.
2. Messages, for Slack and any other sink the module formats for, start with that icon.
3. Tests:
   - each notification type renders with its icon;
   - the stall alert starts with ⏳;
   - a test fails if a notification type is added without an icon, so the mapping cannot drift.
4. If the docs describe notification messages (for example `docs/running-unattended.md` or `docs/configuration.md`), list the icons there.

CONSTRAINTS
- Presentation only. Snodo's state machine is closed: add no status, notification type, severity, halt type or audit event.
- Do not change when notifications fire, or their thresholds.
- No file may exceed its file-length limit or baseline.

ACCEPTANCE
- The tests in link 3 exist and pass.
- The CHANGELOG entry is present.
- `make gate` passes, including lint.
