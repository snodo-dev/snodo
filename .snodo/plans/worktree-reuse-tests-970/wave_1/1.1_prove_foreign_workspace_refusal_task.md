# Prove a foreign or non-git workspace is refused, not reused

## Intent

The workspace-reuse step now refuses an existing directory that the repository does not record as its own worktree (delivered for #970), but nothing exercises that behaviour. This ticket adds the missing proof for the refusal side.

## Tracking

Open a GitHub issue first, or reuse https://github.com/snodo-dev/snodo/issues/970, and put "Fixes #970" in the commit message. This change adds tests only; no CHANGELOG entry is needed unless the repository's changelog gate demands one.

## Symptom and evidence

- Issue #970: two projects that share a parent directory and a task id used to run in each other's leftover workspace; in the reported run the reused path was not even a git repository.
- The reuse step in the foundation worktree module now raises the existing isolation error for an unregistered path, with a message naming the path, what was found, the asking project and the worktree removal command. No test covers it.

## Contract

- Add a new test module beside the existing foundation worktree tests, with its own name, so it does not collide with other work.
- Case one: two real git repositories created by the test under one parent directory. Project A has left a workspace for a task id at the path project B would also map to (or, if project scoping makes the paths differ, a directory placed at B's path by the test). B requests the same task id. B is not run inside A's directory; assert on the message content (path, what was found, the removal hint), not only the exception type, and assert A's directory is untouched.
- Case two: the existing path is a plain directory that is not a git repository (the shape in the issue). The task is not run there and the message says it is not a git repository.
- Case three: the existing path is a git repository that is not registered to the asking project. The message names the branch or repository found.

## Acceptance

- The new tests pass, use real repositories in temporary directories, and need no network.
- Existing foundation worktree and retry-workspace ownership tests still pass; repository lint passes on the new file; no baseline is edited.

## Constraints

- Tests only. Do not change production code; if a case cannot pass because production behaviour differs from the contract above, say so in the task result rather than editing it.
- Do not touch .snodo/. Do not weaken, skip or deselect existing tests.
- Do not leave notes about validation anywhere in the tree.
