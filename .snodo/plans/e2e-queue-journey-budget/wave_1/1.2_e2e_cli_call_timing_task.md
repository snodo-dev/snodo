New files this task will create: tests/scripts/test_e2e_cli_call_timing.py.

INTENT
When an end-to-end test that drives the snodo CLI runs long or times out, the failure says which CLI invocation was slow and how long each one took, so the cause can be read from a single gate log, and a regular test proves the summary appears.

Symptom and evidence: the same e2e queue journey has failed the release gate three times with a bare pytest-timeout whose traceback ends inside subprocess.communicate in tests/e2e/conftest.py (the _run helper of the snodo_cli fixture). Nothing in the output says which of the roughly fifteen CLI calls in the test was running or how long the earlier ones took, and every attempt to find out costs a full fifteen minute release gate. An earlier attempt at this ticket already produced a working change in tests/e2e/conftest.py (a per-call record and a failure-report section) and was blocked only because the per-task gate cannot execute an e2e-only change: e2e tests are deselected by default and run only in gate-ci, and the gate rightly will not record a pass for work that did not run (ADR 031). So this ticket pairs the change with a regular test.

What it should do: make the snodo_cli helper in tests/e2e/conftest.py record the arguments and elapsed time of each invocation, and make that record appear in the test output when the test fails, including when it fails by timeout while a call is still running, naming the call that was in flight and how long it had been running. Keep the helper's return value and behaviour for passing tests unchanged, and keep the output short, one line per call. Add a regular test, not marked e2e, in the new file that proves it, for example by running a tiny failing test through pytest's own test-running plugin against the same conftest logic and checking the summary lines; the test must run under gate-task and must not start a real snodo process if a stand-in works. Use whichever mechanism fits the suite best.

CONSTRAINTS
Files that may change: tests/e2e/conftest.py, the new tests/scripts/test_e2e_cli_call_timing.py, and CHANGELOG.md (one entry under [Unreleased] ending with the issue reference Fixes #<n>). Do not change product code, the individual e2e tests, scripts, validators or pyproject.toml. No new state, status, severity or halt type.

ACCEPTANCE
A failing or timed-out e2e test that uses snodo_cli shows a per-call timing summary naming the invocation in flight, passing e2e tests are unaffected, and the new regular test pins this and is executed by make gate-task, which is green.

PROCESS
Open a GitHub issue first and put Fixes #<n> in the commit message. This is a non-interactive run: open the issue directly with gh issue create, without asking for confirmation of title or body. Commit your change before running make gate-task, because it tests HEAD and needs a clean tree, and run it in the foreground and wait for it to finish before ending your turn.
