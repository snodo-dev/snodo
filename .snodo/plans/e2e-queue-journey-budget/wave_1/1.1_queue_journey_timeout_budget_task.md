New files this task will create: none.

INTENT
The end-to-end queue journey tests get a time budget that matches what they do, so they stop failing the release gate on a 60 second limit meant for ordinary unit tests.

Symptom and evidence: the release gate (make release PART=minor, gate-ci, which runs with -m "" and --timeout=60 --timeout-method=signal so the e2e tests are included) failed three times in a row on tests/e2e/test_queue_run.py::test_blocked_queue_can_be_corrected_while_another_queue_finishes. The latest failure is a plain pytest-timeout at the line that runs the second queue run (resumed = snodo_cli(["queue", "run", "default", "--mock"])), inside subprocess communicate, so the CLI process was still running at 60 seconds. The run before it failed in the teardown of the same test, meaning its body had used almost the whole 60 seconds before teardown began, and everything else in the suite passed (6932 tests). The test drives about fifteen separate snodo CLI processes (init, queue create, three plan validates, three queue moves, two queue runs), each a cold Python start, on a gate host that is running about twenty test workers at once. A change earlier in this wave made the per-test .snodo guard cheaper and the total gate time did not move (about 908 seconds before and after), so that guard was not the dominant cost.

What it should do: give the tests in tests/e2e/test_queue_run.py a timeout that fits a multi-process journey, using the timeout marker the suite already registers so it overrides the gate's command-line limit for these tests only. Pick a value with clear headroom over what the journey takes on a loaded host and say in a short comment why the figure was chosen. Do not weaken any assertion and do not change the limit for the rest of the suite.

CONSTRAINTS
Files that may change: tests/e2e/test_queue_run.py and CHANGELOG.md (one entry under [Unreleased] ending with the issue reference Fixes #<n>). Do not change scripts/gate_remote.sh, pyproject.toml or product code. No new state, status, severity or halt type.

ACCEPTANCE
The marker takes effect: the journey tests run under their own limit while other tests still run under the gate's 60 seconds. make gate-task is green.

PROCESS
Open a GitHub issue first and put Fixes #<n> in the commit message. This is a non-interactive run: open the issue directly with gh issue create, without asking for confirmation of title or body, then continue.
