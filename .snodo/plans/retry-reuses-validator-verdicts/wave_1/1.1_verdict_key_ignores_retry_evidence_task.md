# 1.1_verdict_key_ignores_retry_evidence

## INTENT
When a task is retried (`snodo run --retry`) or recovered inside a run, the spec-only pre-execute validators (security, architecture, meta-spec) are judged from scratch every time, 15 to 50 minutes each, even though the task spec has not changed and they passed on the previous attempt. Evidence: `_spec_subject` in `packages/snodo-engine/src/snodo/validators/runner.py` appends `retry_evidence_block(context)` to the spec before hashing it into the verdict-cache subject. That block carries the attempt number and the previous failure's prose, so it differs on every attempt and the cache can never hit on a retry. The block is instructional text for the judge (it says the Task section is authoritative and adds no criterion of its own) and it is the same for every validator on an attempt, so it does not change what the validator is being asked about. The judge must keep receiving the block; only the cache key should stop depending on it. A reused verdict should be limited to a previous pass, because a previous warn or blocker is exactly what the retry evidence is there to re-examine.
