# 1.2_authorized_prior_result_lookup

## INTENT
After `snodo authorize`, a retried task still dispatches the authorized validator again (15 to 50 minutes) only so that the policy evaluator can overrule the new warn with the signed decision. The decision is consulted in `packages/snodo-engine/src/snodo/engine/policy.py` (around lines 193 to 211, `find_adjudicated(..., task_matcher=same_task_lineage)`) only after dispatch. A signed decision binds the task (or its lineage), the validator id, the adjudicated severity and `decision == proceed`; it does not bind the spec the warn was about, so it cannot by itself justify skipping a judge call when the spec has changed. This task adds the small pure lookup that the next wave will use: given a task, say which pre-execute validators have an authorized prior warn whose spec is unchanged, and hand back their prior results. It does not wire anything in yet.

## THE CHAIN

3. Add one new module `packages/snodo-engine/src/snodo/engine/authorized_prior_results.py` exposing a pure function `authorized_prior_results(...)` with no I/O: its inputs are the task id, the current root spec, the validator ids about to be dispatched, the verified decision records with their issuer, and the previous attempt's results together with the spec those results were produced for (take these in the shape the persisted records already have, do not invent a new record type). It returns a mapping from validator id to the prior validator result for exactly those validators that (a) had a prior result with severity warn, (b) have a valid matching proceed decision found through `find_adjudicated` with `same_task_lineage`, and (c) were judged against a spec equal to the current root spec. Anything else is left out so it gets dispatched normally; in particular a prior blocker or error, a missing prior result, a missing or invalid decision, or a changed spec are never returned.
