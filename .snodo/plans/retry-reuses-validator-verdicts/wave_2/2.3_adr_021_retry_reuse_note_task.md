# 2.3_adr_021_retry_reuse_note

## INTENT
The architecture validator reads the decision records. ADR 021 (`docs/decisions/021-recovery-builds-from-original-task.md`, section "Constraints preserved") says re-running pre-execute validators on each cycle is unchanged, because a recovery spec is new content. Since the first wave of this plan, a pre-execute validator whose earlier verdict was a pass on the same spec and tree is answered from the verdict cache on a retry or recovery instead of being judged again, and the retry evidence text no longer takes part in the cache key (an earlier choice recorded in `CHANGELOG.md` under 0.27.0, "key verdict reuse on the complete subject the judge sees, including retry or recovery evidence (Fixes #968)", is reversed on purpose). The record should say so in its own words, so the next reviewer does not read the change as a silent reversal of ADR 021.

## THE CHAIN
1. Open a GitHub issue first ("Record in ADR 021 that a retry may reuse prior passing pre-execute verdicts") and put "Fixes #<n>" in the commit message.
2. Read `docs/decisions/021-recovery-builds-from-original-task.md` (in particular "Constraints preserved"), `docs/decisions/README.md` for how amendments to an accepted record are written in this project (follow the existing pattern; if records are never edited in place, add an amendment section at the end of ADR 021 that points to this change), and the changelog entry for #968.
3. Add a short amendment to ADR 021, a few sentences: pre-execute validation still runs on every cycle; a validator whose prior verdict was a pass on an unchanged spec and tree subject is satisfied from the verdict cache, because since #931 the judge reads the root spec and the retry evidence block is explanatory text, not a criterion; the retry evidence is deliberately not part of the cache key any more, which changes the choice made in #968; a prior warn or blocker for a spec-only validator is still judged again; an authorized warn on an unchanged spec need not be dispatched again (the signed decision still decides). Mention the issue number of this change and of the first wave tasks only if they are known from the repository history; do not invent numbers.
4. `CHANGELOG.md` gets one new line under `[Unreleased]` in the same commit, in the style of the neighbouring entries, ending with "(Fixes #<n>)". The commit is incomplete without it; the changelog check in the gate reports a commit that closes an issue the changelog does not mention.
5. Run the docs checks that apply to a changed decision record (the docs ratchet and link checks run by `make gate-task`; look at what the gate runs) and do not finish until they pass.
