# 2.2_retry_reuses_passes_end_to_end

## INTENT
The cache-key change of the first wave is only worth anything if a real retry now skips the judges that already passed. This task proves that end to end with tests, so a future change that puts per-attempt text back into the cache key fails loudly. Symptom being guarded against: on `snodo run --retry` (attempt 2), security and meta-spec were judged again for 15 to 50 minutes each although they passed on attempt 1 and the spec and tree were unchanged.

2. Read `tests/engine/test_verdict_cache_visibility.py` (how a run with a verdict cache is exercised and how reuse is observed) and `tests/engine/test_retry_judge_input.py` (around lines 89 to 111, the fake completion that records the retry evidence block the judge receives), and `tests/validators/test_verdict_cache.py` for the replaced tests of the previous wave.
