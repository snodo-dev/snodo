## Intent
An operator who wants to benchmark one model should be able to name it the way they name it everywhere else, as provider, a slash, then model, with `snodo models --benchmark <provider>/<model>`, instead of combining `--provider`, `--id` and `--benchmark`.

## Evidence
- The models command is in the models_cmd module in the snodo/cli/commands/ directory. `--benchmark` is a plain boolean option there; the benchmark itself runs in `models_benchmark_command`, which reads `args.provider`, then `_select_benchmark_model(provider_name, args)` resolves exactly one model from `--provider` plus the discrete filters (`--id`, `--id-contains`, cost and context filters) and prints a message for no match or several.
- A model id can itself contain a slash (a provider can route names made of a vendor, a slash and a model), so only the first segment names the provider and the rest is the model id.
- Existing tests for the benchmark are in tests/cli/test_models_benchmark.py (and tests/cli/test_models_cmd.py for the command surface); they show how a provider and its models are faked.
- The `--json` error shape for this command is `emit_error("models-benchmark", ...)`, used where `--benchmark` has no provider.
- A first attempt passed every test but was stopped by the file-length ratchet: the models_cmd module sits just under the 1000 lines-of-code limit and that attempt left it 8 lines over, and a file that crosses the limit and is not in the baseline fails the gate. The check is the script enforce_file_length.py in the scripts directory; it counts code lines only, not blanks, comments or docstrings, and running it takes a second.

## Outcome
- `snodo models --benchmark <provider>/<model>` benchmarks that one model with the same result and output as `snodo models --provider <provider> --id <model> --benchmark`. `--benchmark` with no value keeps its current meaning, and the long form is unchanged, including its error messages. `--benchmark-runs` and `--json` work with the short form.
- An unknown provider, an unknown model, or a malformed value (empty, no slash, an empty provider or model part) prints a clear message and exits non-zero; under `--json` it emits the existing machine-readable error shape instead.
- If `--provider` or `--id` is also given together with a provider-and-model value, the command says which to use rather than guessing.
- The help text for `--benchmark` shows the short form.
- The models_cmd module ends the task with no more code lines than it started with, and the file-length script reports no failure. Put the splitting, validation and conflict checks of the short form in a new small module beside the existing models_benchmark modules, and keep the additions in models_cmd to a thin call into it. Move a little existing benchmark code out if that is what it takes to stay under the limit. Never add the module to the baseline file.
- Tests cover the short form (success), the long form still working, a model id that itself contains a slash, an unknown provider, an unknown model, a malformed value, the `--json` error, and the conflicting-flags message. Tests for the new module go in a new test file next to the existing models tests.
- `make gate` passes, including ruff (no unused imports), the file-length check and the docs-coverage check.
