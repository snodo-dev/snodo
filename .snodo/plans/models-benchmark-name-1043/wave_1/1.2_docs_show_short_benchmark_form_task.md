## Intent
Operators reading the docs should learn that one model can be benchmarked by name with `snodo models --benchmark <provider>/<model>`, next to the longer form they already know.

## Evidence
- The behaviour is added by a sibling task of this plan (a `--benchmark` value of the form `<provider>/<model>`; the longer `--provider <p> --id <m> --benchmark` form keeps working; an unknown or malformed name gives a clear message and a non-zero exit, or the usual machine-readable error under `--json`).
- docs/command-reference.md lists the options of `snodo models` in a table row and has prose about benchmark results and baselines; docs/machine-interface.md describes `snodo models --benchmark --json` (schema `snodo.models-benchmark.v1`). Search docs/ for `--benchmark` to find any other place that shows how to benchmark one model, such as a choosing-models page.
- Checks: scripts/enforce_docs_anchors.py, the docs-coverage check and `mkdocs build --strict` (the repo's docs target) must pass.

## Outcome
- The pages that show how to benchmark one model show the short form first and mention the long form as equivalent; the option table notes that `--benchmark` takes an optional `<provider>/<model>` value.
- The machine-interface entry says the same output is produced by either form.
- The docs strict check passes. Run it yourself and report the result.
- No Python or test file is changed.
