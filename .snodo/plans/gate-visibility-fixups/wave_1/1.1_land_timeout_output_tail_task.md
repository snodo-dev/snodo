INTENT
The branch above makes the quality validator (packages/snodo-engine/src/snodo/validators/quality.py) keep the partial stdout and stderr of a test command that times out, so a timeout's output_tail shows where the time went. The gate on 2026-10-08 ~23:00Z blocked it: 7 failed, 5277 passed. Failures included:
- tests/validators/test_quality.py::TestQualityValidatorEvaluate::test_stderr_used_when_no_stdout
- tests/engine/test_post_validate_recovery.py::TestEvidenceReachesFixTask::test_quality_validator_emits_output_tail
The change altered existing output-capture behaviour that other code and tests rely on: stderr fallback when stdout is empty, and output_tail evidence for fix tasks.

When this is done, the timeout path keeps partial output and every existing behaviour of the non-timeout path is unchanged:
- stderr is still used when there's no stdout;
- output_tail still reaches fix tasks in the same form.
Fix the implementation, not the tests, unless a test was asserting something the intent deliberately changes. If so, say which test and why in the commit message.
