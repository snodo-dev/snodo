# 2.1 — a suite-wide guard refuses environment preparation against the checkout

GitHub issue #1036 already exists for this work. Do not open another; put "Fixes #1036" in the commit message. Do not edit the CHANGELOG (test-only change).

## Context (same for every task in this plan)

During the release gate (`make gate-ci`, a full pytest-xdist run in a freshly pushed checkout) a plain `uv sync` is spawned by a pytest worker with the checkout root as its working directory; it removes the docs extras (mkdocs, markdown extensions) from the venv the run is still using, so 25 docs tests fail ("No module named mkdocs"). The only code that runs `uv sync` is `prepare_environment` in `packages/snodo-foundation/src/snodo/infrastructure/environment.py`, reached from the governance node's first iteration (`packages/snodo-engine/src/snodo/engine/nodes/governance.py` around line 299, whose target is the worktree path, then the project root, then the current directory) and from worktree set-up. Since commit ea786a92 it reinstalls when `uv.lock` is newer than `.venv`, the normal state of a gate checkout right after a force push; earlier an existing `.venv` always skipped.

Tests that build the engine graph without a project root of their own reach the current-directory fallback, which is the checkout. Wave 1 of this plan gives each such test file a temporary project root; wave 2 adds a suite-wide guard that makes any future test doing this fail loudly. No task changes `environment.py`, `worktree.py` or `governance.py`.

## INTENT

Running the test suite must never modify the environment of the repository it runs in. Any test that reaches `prepare_environment` with the real checkout (or a path inside it) as target should fail loudly and name itself, so a future test cannot silently strip the gate's docs extras again.

## Evidence

Wave 1 gave every currently offending test file a temporary project root. A first attempt at this guard (by an earlier run) used the function-scoped `monkeypatch` fixture and thereby broke tests/cli/test_worktree_cmd.py::TestWorktreeCommands::test_list_and_prune_cover_registered_plan_worktrees_only at teardown: that test patches `Path.rglob` with its own `monkeypatch`, the existing checkout-fingerprint fixtures in tests/conftest.py call `rglob` in their teardown, and a guard that requests `monkeypatch` makes that fixture be created before them and undone after them, so the test's patch is still active when they run.

## Outcome

- tests/conftest.py has an autouse guard that refuses, naming the test, any `prepare_environment` call whose resolved target is the repository root or inside it (the root derived from the conftest location, not from the current directory), unless the call brings its own stubbed runner (`run_command_fn` or `shell_mcp`) or an `explicit_command` that is not run for real. Calls whose target is outside the repository pass through to the real function unchanged. No test is exempted by name.
- The guard leaves the set-up and teardown order of every other fixture as it was; test_worktree_cmd passes.
- A new test file next to it shows both behaviours: a call that targets the repository raises and spawns nothing; a call that targets a temporary directory with a stub runner passes through.

## Acceptance

- The new guard test, tests/cli/test_worktree_cmd.py, tests/infrastructure/test_environment.py and tests/infrastructure/test_worktree.py pass together; the linter is clean. The engine's own run of the whole suite after you finish is the check that no test is left that targets the checkout.

## Constraints

- tests/conftest.py and one new test file only.
- Run the named test files in the foreground (two or three groups); do not run the whole suite.
