# 1.5 — the head-not-moved governance tests use a temporary project root

GitHub issue #1036 already exists for this work. Do not open another; put "Fixes #1036" in the commit message. Do not edit the CHANGELOG (test-only change).

## Context (same for every task in this plan)

During the release gate (`make gate-ci`, a full pytest-xdist run in a freshly pushed checkout) a plain `uv sync` is spawned by a pytest worker with the checkout root as its working directory; it removes the docs extras (mkdocs, markdown extensions) from the venv the run is still using, so 25 docs tests fail ("No module named mkdocs"). The only code that runs `uv sync` is `prepare_environment` in `packages/snodo-foundation/src/snodo/infrastructure/environment.py`, reached from the governance node's first iteration (`packages/snodo-engine/src/snodo/engine/nodes/governance.py` around line 299, whose target is the worktree path, then the project root, then the current directory) and from worktree set-up. Since commit ea786a92 it reinstalls when `uv.lock` is newer than `.venv`, the normal state of a gate checkout right after a force push; earlier an existing `.venv` always skipped.

Tests that build the engine graph without a project root of their own reach the current-directory fallback, which is the checkout. Wave 1 of this plan gives each such test file a temporary project root; wave 2 adds a suite-wide guard that makes any future test doing this fail loudly. No task changes `environment.py`, `worktree.py` or `governance.py`.

## INTENT

The tests below must not let the engine's first governance iteration fall back to the current directory (the checkout). Each should run against a temporary project root of its own, with what it asserts unchanged.

## Evidence

`tests/engine/test_head_not_moved.py`: the tests that run the governance node or the compiled graph (read the file to find the builders that carry no project root of their own). Each builds the engine graph without a project root, so `prepare_environment` would target the checkout.

## Outcome

- Every test named above runs against a temporary project root instead of the checkout; assertions and behaviour under test are unchanged.

## Acceptance

- `tests/engine/test_head_not_moved.py` passes in full; the linter is clean.

## Constraints

- `tests/engine/test_head_not_moved.py` only (plus a shared helper in that same file if it has one).
