# snodo cloud's model gateway is not a provider snodo knows

This work is tracked by GitHub issue #869, which is already open; reference it as "Fixes #869" and add a CHANGELOG entry under ## [Unreleased] if one for #869 isn't there yet.

## INTENT
"snodo-cloud" is a built-in model provider. A model named "snodo-cloud/<id>" routes to the snodo cloud gateway's OpenAI-compatible API, at https://models.snodo.dev/v1 by default, configurable as `cloud.models_url`. It authenticates with the user's snodo cloud login: the OAuth access token, refreshed when needed, or else the configured `cloud.api_key`. With no cloud login, it behaves like any other unconfigured provider. The full test suite stays green with the new provider in the default catalog.

## THE CHAIN
- An earlier attempt (task 1.1_builtin_snodo_cloud_provider in this plan) built a working implementation on its own task branch; its focused tests passed. The coder may build on it.
- That attempt failed the full suite only because a model-discovery test pins the default provider catalog at exactly six entries. Tests that check the catalog should name the providers they expect, so adding a provider doesn't break them.
- Model names under snodo-cloud include ids that start with "gpt-" and "@cf/", which other providers' prefixes would otherwise claim (see `PROVIDER_MODEL_PREFIXES` in `packages/snodo-core/src/snodo/config.py`).
- snodo-foundation, which holds the cloud credential resolver, depends on snodo-core, so the core package must not import foundation at module level.

## CONSTRAINTS
- Never log or print the credential.
- An explicit `providers: snodo-cloud:` block in config.yml still overrides the defaults.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages go through files under /tmp.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` on touched files. Run the config, provider-routing, cloud-credential and model-discovery tests.

## ACCEPTANCE
- Tests show:
  - snodo-cloud model names resolve to the snodo-cloud provider and the gateway URL;
  - the key comes from the cloud login, or is None without one;
  - `cloud.models_url` overrides the default;
  - plain OpenAI model names still route to openai.
- The model-discovery tests pass and expect snodo-cloud among the default providers.
- There is one CHANGELOG entry for #869.
