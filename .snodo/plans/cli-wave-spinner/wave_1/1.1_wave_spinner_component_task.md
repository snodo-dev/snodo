Before starting, open a GitHub issue on snodo-dev/snodo titled "CLI: snodo wave loading indicator". Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased].

INTENT
Some snodo commands sit silent for several seconds before printing anything. For example, `snodo ready --json` checks the repo, the workstation and the MCP installs before it emits JSON. The operator can't tell whether it is working or hung. We want a snodo-branded loading indicator, the "wave": a 5-cell swell that rolls through a bracket, followed by a short label and the elapsed time:

  [▁▂▃▅▇] checking readiness… 2.4s

Frame generation (the agreed design): take the cycle g = "▁▂▃▄▅▆▇█▇▆▅▄▃▂". Frame i is "[" + g[(i+0)%len] + g[(i+2)%len] + g[(i+4)%len] + g[(i+6)%len] + g[(i+8)%len] + "]", drawn about every 110ms in the accent color. The label and elapsed time are dimmed.

This task builds the reusable component only. Wiring it into commands is a later task.

When this is done, there is one small, well-tested component that any CLI command can wrap around slow work. It should be a context manager or similar; choose the shape that fits the codebase. Its behaviour:
- It draws on stderr only, never stdout. `--json` output stays byte-for-byte unchanged and pipeable.
- It only shows when stderr is an interactive terminal, and only after a short delay (about 300ms), so fast commands never flicker.
- It is disabled when CI is detected (the CI env var), when NO_COLOR is set, when TERM=dumb, inside the MCP server or background jobs, and by an explicit opt-out env var such as SNODO_NO_SPINNER=1. Reuse an existing pattern if the codebase already has one.
- It falls back to ASCII frames ("[-\|/]"-style) when the terminal encoding is not UTF-8.
- It clears its own line completely before the command prints real output and on exit. That includes exceptions and Ctrl-C, and the cursor must never stay hidden.
- It has no effect on exit codes, and no measurable overhead when disabled.

rich is already a dependency, so use it if it fits. A custom rich spinner or Live/Status are both acceptable.

THE CHAIN
1. Look for an existing terminal/console helper in snodo/cli/ and extend it rather than adding a parallel mechanism.
2. Implement the wave frames, the delay, the gating conditions, clearing and the ASCII fallback.
3. Tests:
   - frame generation matches the formula above;
   - with a non-TTY stderr, nothing is written to either stream;
   - CI, NO_COLOR, TERM=dumb and the opt-out each disable it;
   - work shorter than the delay never draws;
   - stdout content is untouched while it runs;
   - the line is cleared after normal exit and after an exception.
