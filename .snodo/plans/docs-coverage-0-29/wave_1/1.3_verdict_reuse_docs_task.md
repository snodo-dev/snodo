INTENT
A user can learn from the docs when a validator verdict is reused instead of judged again, and what happens when a judge returns no verdict.

Evidence: 0.29 changes these behaviours (see CHANGELOG.md [Unreleased]: #1158, #1135, #1127, #1129, #1131, #1161 and #1164, and ADR 021 as amended), but the user-facing docs do not explain them; the explanation exists only in the changelog and in decision records. Users see the effects: a retry that does not call security and meta-spec validators again, an acceptance verdict that is judged fresh after the spec was corrected, and a judge that fails closed with provider diagnostics.

What it should say, in the page that already explains outcomes and recovery (docs/outcomes.md; use the section that fits best, or add a short one): a cached validator verdict is reused when the task spec and the repository tree it judged are both unchanged, whatever its severity, and a retry's evidence is not part of that key; a judge that reads the spec is judged again when the spec changes even if the tree is unchanged, and is reused when both stay unchanged; a judge that returns no verdict gets one extra attempt on a verdict-only turn, and if it still returns none the task fails closed and the diagnostics (provider finish reason, completion token count, whether text came back) are reported. Read the code behind those changelog entries and ADR 021 to state it correctly, and link ADR 021. Keep the existing text unchanged.

CONSTRAINTS
Files that may change: docs/outcomes.md and CHANGELOG.md (one entry under [Unreleased] ending "(Fixes #<n>)"). Do not change code or decision records. Keep links plain relative links to pages that exist. Do not demand a strict docs build as acceptance; the gate runs the docs tests.

ACCEPTANCE
docs/outcomes.md explains verdict reuse (spec and tree key), the spec-change rejudge and the verdict-only retry with its fail-closed diagnostics, and links ADR 021; existing text is unchanged. `make gate-task` is green.
