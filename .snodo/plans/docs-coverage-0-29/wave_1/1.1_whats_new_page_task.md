New files this task will create: docs/whats-new.md.

INTENT
A reader who upgrades to 0.29 can find, on one page, what is new and where each feature is documented.

Evidence: the release adds many features across the CLI and the web dashboard (see CHANGELOG.md, section [Unreleased]), and each has its own page or section, but nothing ties them together; a user has to read the changelog to learn that, for example, `snodo logs <job_id>` now ends with a usage table or that `snodo intake --generate-adr` exists.

What it should do: a page titled "What's new", with a section for 0.29, grouped by what a user does: the web dashboard (Now, Plans, Delivery, Gates and the Protocol editor); models and validators (validator fallback models, single-validator replay and benchmarking, verdict reuse); usage and logs (usage tables, `snodo logs --json`); intake (`snodo intake --generate-adr`); notifications and job outcomes; and the scikit-learn demo. Each group has two to five short plain sentences naming the command or view and linking to the page or section that documents it. Read CHANGELOG.md and the existing pages under docs/ to get names, flags and links right; link only to pages and anchors that exist. Add the page to the navigation in mkdocs.yml next to the other user pages.

CONSTRAINTS
Files that may change: docs/whats-new.md, mkdocs.yml and CHANGELOG.md (one entry under [Unreleased] ending "(Fixes #<n>)"). Do not change code or other docs pages. Describe only behaviour the existing docs and changelog support. Do not demand a strict docs build as acceptance; the gate runs the docs tests.

ACCEPTANCE
The page exists with the groups above, each linking to an existing documentation page, and appears in the mkdocs navigation. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
