# Carry the surrounding MCP surfaces onto mcp 2.x

GitHub issue #922 already exists for this work. Do not open another; put "Fixes #922" in the commit message. Do not edit the CHANGELOG; the last task in this plan owns the entry.

## Why this task exists

Task 1.1 got the producer server to build and start on mcp 2.x. The surfaces
that hang off the client context were deliberately left for this task, because
2.x changed them along with the server class:

- **progress reporting** — already carried over by task 1.1, because its round-trip
  test is part of the gate; do not redo it, and do not weaken that test,
- **resources** — the guide documents, job status and the live job view are
  served as resources,
- **traffic logging** — a debug hook wraps request handling,
- **bearer-token auth** — the optional remote path builds the server with auth
  settings and a token verifier.

Issue #922.

## What "done" means

Each surface above behaves on 2.x the way it does today, on the new server class
and the new context/auth types. Where 2.x names something differently, use the
2.x name rather than keeping a compatibility shim, so there is one way to do it.

## Acceptance criteria

1. Progress notifications still reach the client for a request (covered by the
   round-trip test task 1.1 left passing); confirm it still passes.
2. The resources the server advertised before are still advertised, and a test
   fetches at least one of them by URI and gets the same content shape.
3. The traffic-logging hook still wraps request handling when enabled.
4. The auth path still constructs a server that rejects a request without a
   valid token and accepts one with it; the foundation-side token verifier keeps
   working.
5. The existing MCP tests pass, including the progress, auth and job-watch ones.

## Constraints

- Do not change what the tools return; this task is about transport-level
  surfaces.
- Keep each file under the project's file-length gate — split rather than grow.
- No new halt types or severities; no engine or CLI changes.
- Leave no compatibility shim for the v1 module path once 2.x is the only
  supported line.
- Either the gate passes and you submit, or it does not and you fix it. Do not
  leave notes about validation anywhere in the tree.

## Running tests

Run the targeted MCP tests and the linter, and do not run the whole suite yourself: the engine runs it right after you finish, and a multi-minute silent command has been dropping the coder connection. Confine the diff to what this task asks for and drop every hunk the outcome does not require.
