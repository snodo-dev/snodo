INTENT
The Landed per day chart on the Delivery page should label its days so a person can read them.

Evidence: with the 30 day window the chart prints all 30 labels in the full form 2026-10-28 under 30 narrow bars. Neighbouring labels overlap into one smear (for example "2026-10-282026-10-26..."), so no date can be read. A first attempt at this ticket measured the chart width at run time (ResizeObserver and a width-based capacity); it was judged fragile because the chart is built while detached from the page (its width reads 0, so the first paint shows only two labels), the fallback without ResizeObserver never restored the 7 day labels, and re-rendering every 10 seconds piled up observers and listeners. Later fix rounds also renamed and replaced the existing test case, which a coverage check reports as a disappeared test and which blocked the ticket.

What it should do: the labels are chosen from the data alone, with no measuring of the page and no observers. Labels use a short form (month and day, such as 10-28). The number of labels drawn is a plain function of how many days the chart holds: every day when there are 7 or fewer, otherwise a regular step so that about eight labels are drawn, always including the first day and the last day, and dropping the sampled label just before the last one when it would sit closer than half a step to it. The function works for any window length (the page will gain a 90 day window later in this plan). The bars and the count above each bar stay as they are. Each bar still carries its full date and count as its title and as its aria-label. Labels are single lines that do not wrap.
