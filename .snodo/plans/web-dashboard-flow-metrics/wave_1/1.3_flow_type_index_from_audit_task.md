New files this task will create: snodo/web/flow_types.py, tests/web/test_flow_types.py.

INTENT
The dashboard should be able to say whether a landed task was a feature, defect, debt or risk item, quickly, without re-reading hundreds of megabytes of audit history on every request.

Evidence: a task's work type is recorded only as audit events with event_type task_classified, whose data holds task_ref, flow_type (feature, defect, debt or risk), wave_id and task_summary. In this repository there are 1399 such events for 895 distinct tasks (a task can be classified more than once; the latest event is the one that counts). They live in .snodo/audit.log and its rotated siblings (audit.log.2026-w35 and so on); the rotated files total about 600 MB, one of them 578 MB, and they never change after rotation. Task state files and wave.json do not carry the type.

What it should do: a small module offers one function that, for a project path, returns a mapping from task_ref to flow type, built from every audit file of that project (the current audit.log and the rotated ones). A line is parsed only if it can contain the event (a cheap byte-level pre-filter before json parsing), malformed lines are skipped, and when a task has several events the latest by timestamp (or file order if equal) wins; only the four known types are accepted. Rotated files are indexed once: results are cached per file keyed by path, size and modification time, in memory and in a small best-effort cache file in the user's cache directory (never inside the project, never failing the caller if it cannot be read or written). The live audit.log is re-read on each call (it is small) or incrementally. A second call with nothing changed does no scanning of rotated files. The function is blocking and is meant to be called from worker threads.

CONSTRAINTS
Files that may change: snodo/web/flow_types.py (new) and tests/web/test_flow_types.py (new). Do not edit CHANGELOG.md or docs: a final docs ticket in this plan adds the entries. Read-only with respect to the project: nothing is written under the project folder. No new dependencies. Do not add any state, status, severity or halt type (the four types are values read from existing audit events, not new vocabulary in snodo itself).

ACCEPTANCE
Tests that exist and pass, using temporary projects with small audit files: events from the current and a rotated file are merged; the latest event for a task wins; unknown types and malformed lines are ignored; a missing audit folder gives an empty mapping; the second call does not re-open a rotated file whose size and modification time are unchanged (assert through a counter or a patched opener); changing a rotated file's size invalidates its cache entry; the on-disk cache location is outside the project and a read-only cache directory does not make the function fail. `make gate-task` is green.
