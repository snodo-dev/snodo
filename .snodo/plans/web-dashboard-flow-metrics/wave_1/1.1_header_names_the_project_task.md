New files this task will create: snodo/web/routes_identity.py, tests/web/test_routes_identity.py.

INTENT
A person who runs several local dashboards at once should see in the top bar which project each one belongs to, without reading the port number.

Evidence: the right-hand side of the top bar shows only the host and port (127.0.0.1:44331) and the update time (snodo/web/static/index.html writes location.host into the element with id host). Two dashboards started from different repositories look identical.

What it should do: next to and before the host, the top bar shows the project the dashboard was started in as "name: remote", for example "snodo: github.com/snodo-dev/snodo". The project identity follows ADR 012 (docs/decisions/012-project-identity-from-git-remote.md): it is resolved from the repository's git origin remote, so a project that has a remote always has the remote as its id (host/org/repo form, such as github.com/snodo-dev/snodo), and only a project with no remote has a local:<uuid> id. The cached copy in .snodo/project.json is never authoritative and this feature does not read it. Resolution lives in packages/snodo-core/src/snodo/project.py (resolve_project_id, get_project_id, scope_for_project_id); use that existing code. Rules for the text: when the id is a remote, the name is the last path segment of the id (snodo) and the remote part is the id, shown once and never repeated. When the id is local, the name is the project folder name and the remote part is the word local. The text is short enough to sit in the bar without wrapping on a normal window; a very long remote is cut with an ellipsis and the full text is available as a hover title. A small read-only route, GET /api/identity, returns {name, remote, project_id} for the project the server was started in, so the page can fill the element at load. The route must not write anything under .snodo (resolve_project_id does not cache; get_project_id may, so prefer the first or check that the call leaves the folder untouched).

CONSTRAINTS
Files that may change: snodo/web/routes_identity.py (new), snodo/web/app.py (route registration only), snodo/web/static/index.html (the host element, its small style rules and the load script), tests/web/test_routes_identity.py (new), tests/web/test_static_shell.py, tests/web/test_static_shell_style.py, tests/web/test_app.py (only where a new assertion belongs) and CHANGELOG.md. The route is GET only, read-only, and runs its git work off the event loop (starlette.concurrency.run_in_threadpool, like the other routes). Any resolution error falls back to the folder name and the word local, never an error response. Page code keeps the existing rules: DOM built with createElement and textContent only, no innerHTML, no external URLs or fonts, no hex colours outside the token block in index.html (use tokens and color-mix). Do not add any state, status, severity or halt type.
