INTENT
The Delivery route should report how much landed work was a feature, defect, debt or risk item, week by week and as a whole, and how long each type takes, so the page can show flow velocity, flow time and flow distribution.

Evidence: snodo/web/flow.py counts landed tasks per day and a single median flow time, and snodo/web/routes_delivery.py sums them across projects. Nothing splits the work by type, and the route only accepts 7 or 30 day windows. The type per task is available from snodo/web/flow_types.py (a function that maps task_ref to feature, defect, debt or risk, built from the audit history and cached).

What it should do: flow_metrics (per project) and the Delivery totals gain these keys, which later tickets in this plan rely on: by_type, an object with feature, defect, debt and risk, each holding landed (count), share (landed divided by the number of classified landed tasks, or null when none), median_flow_seconds and p85_flow_seconds (the 85th percentile of start-to-landed seconds; null when no task of that type has both times); unclassified, the count of landed tasks with no recorded type (these are not part of share); by_week, a list ordered oldest first with one entry per Monday-starting week that overlaps the window, each holding week_start (ISO date of that Monday), a count for each of the four types, and unclassified. Totals across projects are pooled from the underlying durations and counts, never an average of medians. The route also accepts a 90 day window (7, 30 and 90) and still answers 400 for any other value. All existing keys and their meaning stay exactly as they are. A project with no landed work, or with no audit history, yields zero counts and nulls without errors.
