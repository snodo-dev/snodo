New files this task will create: snodo/web/recon_runs.py, tests/web/test_recon_runs.py.

INTENT
The local dashboard can read a project recon runs and tell which are running, which completed recently and which are stale, so the Now page can show them truthfully.

Evidence: every recon writes .snodo/recons/<recon id>/state.json with a status (running, complete or failed), created_at, completed_at (empty while running), the pid of the process that runs it, and its agent lanes. In this repository 124 recon records exist, and 5 of them say running, but four of those are 800 to 1100 hours old: the process was killed and the record was never updated. A reader that trusts the status word would report five running recons when one is. The recon module (packages/snodo-mcp/src/snodo/recon/__init__.py) holds the record layout and a default deadline constant for a recon run. The local dashboard modules in snodo/web/ read project files read-only and tolerate missing or unreadable files, for example snodo/web/now_counters.py.

What it should do: a small read-only module offering one function that returns, for a project path and a current time, a list of recon runs with the recon id, the effective state (running, completed, failed or stale), the created and completed timestamps, and nothing that needs the network. A record whose status is running is running only when its recorded process is still alive on this machine (signal zero on the pid; a permission error counts as alive), or, when it has no usable pid, when it started within the recon deadline; otherwise it is stale. Unreadable, malformed or missing records are skipped without raising. Never modify any file. Keep the function small and typed so the Now counters and the Now tree can both call it.

CONSTRAINTS
Files that may change: snodo/web/recon_runs.py, tests/web/test_recon_runs.py and CHANGELOG.md (one entry under [Unreleased] ending with the issue reference Fixes #<n>). Do not change other modules in this ticket. No new state, status, severity or halt type in the engine or the protocol; the effective states above exist only as read-only labels inside the dashboard reader.

ACCEPTANCE
Tests cover a live running record (use the current process pid), a stale running record (a pid that is not alive), a running record without a pid inside and outside the deadline, complete and failed records, and a malformed record. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put Fixes #<n> in the commit message.
