New files this task will create: none.

INTENT
The Recons card on the local Now page shows real numbers instead of unavailable.

Evidence: snodo/web/now_counters.py sets recons to an unavailable marker for every project, and its module description claims that no recon-run records are persisted or read by the local dashboard, which is no longer true: each recon writes a record under .snodo/recons, and snodo/web/recon_runs.py (added by an earlier ticket in this plan) reads them and labels each run running, completed, failed or stale. The aggregate in snodo/web/routes_now.py already sums a recons entry shaped as count, running and completed, and the page tile in snodo/web/static/now.js already renders Running and Completed from it, so only the per-project counter is missing.

What it should do: for each project, report recons for the same 24 hour window the other counters use: running is the number of live runs, completed is the number whose completion falls inside the window, and count is the number of runs that started in the window or are running now. Stale runs are not running, and they count only if they started inside the window. A project whose records cannot be read keeps the unavailable marker. Update the module description so it no longer says recons are unavailable, and replace the existing test that expects the unavailable marker with tests for the new behaviour.

CONSTRAINTS
Files that may change: snodo/web/now_counters.py, snodo/web/routes_now.py (only if the aggregate needs a change), tests/web/test_now_counters.py, tests/web/test_routes_now.py, tests/web/test_now_contract.py and CHANGELOG.md (one entry under [Unreleased] ending with the issue reference Fixes #<n>). Do not change snodo/web/recon_runs.py or the activity tree. No new state, status, severity or halt type.

ACCEPTANCE
Tests show a project with one live running recon, one completed inside the window, one completed outside it and one stale record reporting the right running, completed and count values, and the aggregate summing two projects. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put Fixes #<n> in the commit message.
