New files this task will create: none.

INTENT
A project that is running a recon looks alive on the local Now page.

Evidence: snodo/web/now_tree.py derives each project liveness (working, reporting but not progressing, or no recent signal) and its last activity time only from plans, tasks and jobs. A project that is only running a recon therefore shows no recent signal even while recon agents are making tool calls, which is what a user sees when a recon is launched on a project with no plan running. snodo/web/recon_runs.py (added by an earlier ticket in this plan) lists a project recon runs with an effective state of running, completed, failed or stale.

What it should do: a live running recon counts as a working signal for its project, and a recon that started or completed inside the 24 hour window counts toward the project last activity time. Stale runs count only through their start time and never make a project working. Plans, waves and tasks in the tree stay exactly as they are; recons do not appear as plan rows. A project whose recon records cannot be read behaves as it does today.

CONSTRAINTS
Files that may change: snodo/web/now_tree.py, tests/web/test_now_tree.py and CHANGELOG.md (one entry under [Unreleased] ending with the issue reference Fixes #<n>). Do not change snodo/web/recon_runs.py, the counters or the page scripts. No new state, status, severity or halt type; the liveness words already exist.

ACCEPTANCE
Tests show a project with only a live running recon reporting working with a last activity time, a project with only a stale recon not reporting working, and unchanged output for a project without recon records. `make gate-task` is green.

Open a GitHub issue for this task first and put Fixes #<n> in the commit message.
