## Intent
Survey and its judge chain treat models of a provider that signs in with a ChatGPT subscription (setting `auth: chatgpt-oauth`, no API key by design) as configured agents, so an operator can use such a model as a survey judge.

## Evidence
- `_agent_is_configured` in snodo/cli/commands/survey_cmd.py returns whether `get_key_for_model(model)` is truthy, and the judge builder in snodo/survey/judge.py (`build_survey_judge`) adds a candidate to the chain only when the same lookup is truthy, unless survey runs in force mode. For an OAuth provider the lookup returns nothing by design (it refreshes the token as a side effect and the model call authenticates through LiteLLM), so its models are dropped from the candidates and the chain.
- The meaning documented on `_agent_is_configured` is a model whose provider the operator set up in snodo's own config; ambient environment keys do not count.
- The config manager has `provider_uses_oauth(provider)`; the provider of a model is resolved by the config manager from the model name.

## Outcome
- A model whose provider uses OAuth counts as a configured agent in survey's auto mode and is included in the judge chain; models of key-based providers are decided exactly as before, and force mode is unchanged.
- Providers without the `auth` setting, and provider objects without an `auth` attribute, behave exactly as before.
- Tests cover an OAuth-provider model (included), a key-provider model with a key (included), one without a key (excluded) and force mode, using fakes and no network.
- `make gate` passes, including ruff, import-linter and the file-length and docs-coverage checks.
