## Intent
The dashboard settings panel shows a provider that signs in with a ChatGPT subscription (setting `auth: chatgpt-oauth`, no API key by design) as signed in or not signed in, instead of a provider with no key.

## Evidence
- In snodo/dashboard/panels/settings.py the provider rows compute "Key Set" from whether the config manager returns a key for the provider (around line 163); an OAuth provider has none by design, so it always reads as not set.
- The config manager has `provider_uses_oauth(provider)`, and the token module's `chatgpt_sign_in_state()` reports sign-in from the token file only with no network call (small mapping when signed in, None otherwise).

## Outcome
- For a provider that uses OAuth the row shows its sign-in state in place of the key status (signed in, or not signed in), with no network call; rows of key providers are unchanged.
- Providers without the `auth` setting, and provider objects without an `auth` attribute, behave exactly as before.
- Tests cover an OAuth row signed in, one not signed in (fake sign-in state) and a key provider row unchanged.
- `make gate` passes, including ruff, import-linter and the file-length and docs-coverage checks.
