## Intent
Record the decision to make the operator's intent a first-class record that plans trace back to, so the reasoning is durable and later tasks can cite it.

## Evidence
- Decision records live in docs/decisions/ in the Nygard form used by the neighbouring records (read two of them, for example 059-verdict-names-its-task.md and 058-protected-path-advisory-guidance-and-merge-base-detection.md, and copy their headings and tone). The latest number is 059, so this one is 060; docs/decisions/README.md has one table row per record that must gain a row.
- ADR 038 (orchestrator role and audit contract) is the precedent for recording orchestration-time artifacts in the audit trail. ADR 055 and ADR 054 describe plan events and what the cloud sees.
- The decisions to record, as agreed with the operator: (1) intent is captured as its own record before planning; a plan may carry an optional `intent_ref` naming one intent; (2) a record is written once and is never edited in place; a correction is a new intent that supersedes the old one (fix forward); (3) one optional GitHub issue reference lives on the record; (4) there is no intent lifecycle status: whether an intent has been acted on is read from the plans that point to it; (5) one new local-only audit event, `intent_recorded`, which is not part of the cloud contract; (6) `intent_ref` does not ride on the plan_proposed / plan_run events, so the cloud wire and interface version are unchanged; (7) this adds no state, status, severity or halt type (state this plainly). Alternatives rejected: a mutable intent with a status field (adds a state), carrying intent_ref on the plan history events (changes the cloud contract).
