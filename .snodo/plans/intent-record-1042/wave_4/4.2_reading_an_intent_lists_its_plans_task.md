## Intent
The trace should work in both directions: reading an intent should show the plans that implement it. Whether an intent has been acted on is read from those plans; there is no status field on the intent.

## Evidence
- The store is the `intent_store` module in packages/snodo-foundation/src/snodo/infrastructure/ (task 1.1); the MCP tools `get_intent` / `list_intents` are in the `intent_handlers` module beside plan_handlers.py (task 2.2); `snodo intent show` / `list` are in the `intent_cmd` module beside plan_cmd.py (task 2.3).
- Plans live under `.snodo/plans/<name>/plan.yml`, with an optional `intent_ref` key (tasks 2.1 and 3.2); per-task status is in each plan's status.json. Plan directories may be absent or contain malformed files; the existing plan listing code (`list_plans` in the planner module of the mcp package) shows how unreadable plans are skipped. Do not edit the planner module in this task.
- Tests: the intent store, intent tool and intent CLI test modules created by tasks 1.1, 2.2 and 2.3.

## Outcome
- A helper in the intent store finds the plans whose `intent_ref` names a given intent and returns, per plan, its name and a derived summary of task status counts using the existing status values (no new values). Unreadable or malformed plans are skipped, not fatal.
- `get_intent` and `snodo intent show` (text and `--json`) include that plans list; `list_intents` and `snodo intent list` do not, to stay cheap.
- Tests cover an intent with no plans, with one plan, with several, and with a malformed plan directory alongside.
- `make gate` passes.
