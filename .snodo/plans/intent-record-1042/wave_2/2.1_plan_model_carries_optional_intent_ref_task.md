## Intent
A plan should be able to say which recorded intent it implements. This task teaches the plan model to carry an optional `intent_ref` and to round-trip it through plan.yml. It does not check that the intent exists (a later task does) and does not expose it anywhere yet.

## Evidence
- The plan model is `Plan` in packages/snodo-foundation/src/snodo/compiler/models.py with `to_dict()` (the exact plan.yml shape: name, intent, waves) and `from_dict()` (which reads `intent`). Intent ids have the form `int_<6-hex>` (created in task 1.1 in packages/snodo-foundation/src/snodo/infrastructure/intent_store.py; the id format check can be a small local pattern here so the model does not depend on the store).
- Existing plans have no `intent_ref`; they must load and serialise exactly as before.
- tests/compiler/test_models.py covers Plan.from_dict / to_dict.

## Outcome
- `Plan` has an optional `intent_ref` (string or none). `to_dict()` writes the key only when it is set, so existing plan.yml files are unchanged byte for byte when saved. `from_dict()` reads it when present.
- A value that is not a string of the intent id form is reported through the model's existing parse-error mechanism (`parse_errors`) rather than raising or being silently dropped, following how other malformed fields are handled there.
- Tests in tests/compiler/test_models.py cover: absent stays absent through a round trip, a valid value round-trips, a malformed value is reported, and an old-style plan dict is unaffected.
- `make gate` passes.
