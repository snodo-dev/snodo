## Intent
A plan that names an intent should fail validation when that intent does not exist, so a typo or a deleted record cannot leave a plan pointing at nothing. Plans without an `intent_ref` are unaffected.

## Evidence
- Plan validation is `verify_plan(plan, plan_dir, workspace_root)` and `verify_plan_dir(...)` in packages/snodo-foundation/src/snodo/compiler/verifier.py; it already reports errors such as `Missing intent`. It is the single gate used by the CLI (`snodo plan validate`, plan run) and MCP (`validate_plan`, run_plan gate), so one check here covers all of them.
- `Plan.intent_ref` is added by task 2.1 in packages/snodo-foundation/src/snodo/compiler/models.py; the intent store (task 1.1) is packages/snodo-foundation/src/snodo/infrastructure/intent_store.py and resolves records under `<workspace_root>/.snodo/intents/`.
- tests/compiler/test_verifier.py and tests/mcp/test_plan_verification.py cover the verifier.

## Outcome
- When `plan.intent_ref` is set and no such intent exists under the workspace's `.snodo/intents/`, `verify_plan` reports one clear error naming the id; when it exists, nothing is reported. When `intent_ref` is absent, behaviour is exactly as before. The check reads the store only; it never creates anything.
- Tests in tests/compiler/test_verifier.py cover: absent ref passes, existing intent passes, missing intent fails with the id in the message, and a plan with a malformed ref surfaces the model's parse error without crashing.
- `make gate` passes.
