## Intent
An operator reading plans at the terminal should see which intent a plan implements, when it names one.

## Evidence
- snodo/cli/commands/plan_cmd.py: `_plan_list` builds one summary row per plan from the dicts that the planner's list_plans returns (name, intent, wave_count, task_count, status_counts; no intent_ref yet, and the planner is outside this task). `_plan_status` prints the `Intent:` line from the plan's plan.yml data. `intent_ref` is an optional key in plan.yml (written by earlier tasks 2.1 and 3.2); the Plan model validates it. For `plan list`, read `intent_ref` from each plan's plan.yml inside plan_cmd (reuse how `plan status` loads the plan) rather than changing the planner.
- `snodo plan status --json` is only defined together with `--run-summary` today (plain `--json` prints the human view). Leave that behaviour and the run-summary payload exactly as they are; do not invent a new plan-status payload.
- `snodo plan list --json` goes through `emit_json` / `schema_name("plan")` in snodo/cli/json_output.py. Optional, presence-dependent keys under an unchanged schema version are an established pattern (ADR 022; for example `analysis.drift`).
- Tests: tests/cli/test_plan_cli.py shows how plan commands are tested. docs/machine-interface.md describes the `--json` shapes and a check keeps documented keys honest; add the one conditional `intent_ref` key to the `plan list` entry there.
- Run `ruff check` on the files you touch before finishing: unused imports fail the gate.

## Outcome
- `snodo plan status <name>` prints an `Intent ref:` line right after the `Intent:` line only when the plan has an `intent_ref`. `snodo plan list` shows it only when present (a short extra suffix or column in the house style); `snodo plan list --json` includes `intent_ref` in a plan's entry only when set. Plans without an `intent_ref` produce byte-identical output to today, in text and in `--json`.
- Tests cover plans with and without the key for `plan list` (text and `--json`) and for the `plan status` text view.
- docs/machine-interface.md mentions the optional `intent_ref` key for the `plan list` payload.
- Changes are confined to plan_cmd.py, its tests, and that one docs entry.
- `make gate` passes, including ruff and the docs checks.
