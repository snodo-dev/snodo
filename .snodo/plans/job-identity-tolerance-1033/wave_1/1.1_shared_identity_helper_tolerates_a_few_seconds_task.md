# 1.1 — the shared process-identity helper tolerates a few seconds of start-time wobble and has its own tests

GitHub issue #1033 already exists for this work. Do not open another; put "Fixes #1033" in the commit message. Do not edit the CHANGELOG (task 1.2 owns the entry).

## Context (same for every task in this plan)

A running job is reported `failed` (exit -1, "PID N now belongs to a different process") although it is alive. On macOS the process start time that psutil reports for the same live PID differs by exactly 1.0 s between the reading taken right after the spawn and a later reading (the recorded value was already 1.0 s later than the wall-clock time taken before the spawn, which a process cannot do), so any exact or sub-second comparison of the two eventually fires. Seen on every long plan run on the Mac mini; it once caused a duplicate concurrent run. Evidence (job j_1295444d2dd0): created_at=1793023122.6035, process_started_at=1793023123.6048, flipped to failed at 1793023974.9 while stdout.log kept being written.

Three places decide process identity from that start time: `packages/snodo-mcp/src/snodo/jobs/__init__.py` (the reconcile around lines 250 to 265, exact `actual_start != recorded_start`, the one that flips jobs), and the shared helper `process_identity_matches` in `packages/snodo-foundation/src/snodo/infrastructure/process_identity.py` (10 ms tolerance) used by `snodo/dashboard/liveness.py` and `packages/snodo-foundation/src/snodo/infrastructure/cloud_liveness.py`. The aim of the check is to catch a reused PID, whose start time is far from the recorded one (seconds to days), so a tolerance of a few seconds loses nothing. The helper's own comparison has no direct test; the dashboard and cloud tests replace it with a stub.

Rules for the whole plan: no new state, status value, severity or halt type; foreign-host, missing-start-time, no-longer-running and legacy-record (no identity) behaviours stay exactly as they are; only the comparison of two start times changes.

## INTENT

`process_identity_matches` should say "same process" when the two start times are within a few seconds of each other, and "different process" when they are further apart, with the tolerance named and documented in one place so the jobs reconcile (next wave) can use the same value.

## Outcome

- The tolerance is a named, documented module-level value in process_identity.py of 5 seconds, exposed so another module can import it, with a one-line reason (the start time of the same live process wobbles by about a second on macOS, a reused PID is far further away).
- The helper compares against it. Everything else the helper does (None when no start time, False for a foreign host, None when psutil cannot answer) is unchanged.
- New direct tests (a new test file under tests/infrastructure, patching only psutil's create_time): a 1.0 s difference in either direction matches; a difference just under the tolerance matches; just over it does not; a difference of hours does not; the unchanged None/False cases.

## Acceptance

- The new tests pass together with tests/dashboard/test_liveness.py and tests/infrastructure/test_cloud_liveness.py; the linter is clean.

## Constraints

- process_identity.py and the new test file only.
