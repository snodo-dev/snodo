# 2.1 — the job reconcile compares start times with the shared tolerance

GitHub issue #1033 already exists for this work. Do not open another; put "Fixes #1033" in the commit message. Do not edit the CHANGELOG (task 1.2 owns the entry).

## Context (same for every task in this plan)

A running job is reported `failed` (exit -1, "PID N now belongs to a different process") although it is alive. On macOS the process start time that psutil reports for the same live PID differs by exactly 1.0 s between the reading taken right after the spawn and a later reading (the recorded value was already 1.0 s later than the wall-clock time taken before the spawn, which a process cannot do), so any exact or sub-second comparison of the two eventually fires. Seen on every long plan run on the Mac mini; it once caused a duplicate concurrent run. Evidence (job j_1295444d2dd0): created_at=1793023122.6035, process_started_at=1793023123.6048, flipped to failed at 1793023974.9 while stdout.log kept being written.

Three places decide process identity from that start time: `packages/snodo-mcp/src/snodo/jobs/__init__.py` (the reconcile around lines 250 to 265, exact `actual_start != recorded_start`, the one that flips jobs), and the shared helper `process_identity_matches` in `packages/snodo-foundation/src/snodo/infrastructure/process_identity.py` (task 1.1 of this plan is merged: it now has a named tolerance of a few seconds and its own tests) used by `snodo/dashboard/liveness.py` and `packages/snodo-foundation/src/snodo/infrastructure/cloud_liveness.py`. The aim of the check is to catch a reused PID, whose start time is far from the recorded one (seconds to days), so a tolerance of a few seconds loses nothing.

Rules for the whole plan: no new state, status value, severity or halt type; foreign-host, missing-start-time, no-longer-running and legacy-record (no identity) behaviours stay exactly as they are; only the comparison of two start times changes.

## INTENT

The reconcile in `packages/snodo-mcp/src/snodo/jobs/__init__.py` that marks a job failed with "now belongs to a different process" should compare the actual and recorded start times with the same tolerance the shared helper uses (import the named value from process_identity.py; do not copy the number), so a live job whose start time reads one second differently stays running and a genuinely reused PID is still failed.
