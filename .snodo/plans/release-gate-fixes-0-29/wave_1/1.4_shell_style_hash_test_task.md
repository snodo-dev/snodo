INTENT
The shell style test forbids color literals in the component styles, not the id selectors the Protocol view legitimately uses.

Evidence: the full gate fails tests/web/test_static_shell.py::test_static_shell_skeleton_has_reduced_motion_and_token_styles on its assertion that the hash character does not appear anywhere in the component part of the style block in snodo/web/static/index.html. The check exists to keep hex colors out so every color comes from the theme tokens, together with its neighbouring check for rgba. A later change scoped a reset for headings and lists to the Protocol view using id selectors that start with the hash character, so the blunt check now trips on selectors, not on colors. The page styling is correct and uses tokens.

What it should do: the test keeps its intent and checks for hex color literals (a hash followed by three to eight hexadecimal digits that is not part of a longer word, as the delivery stylesheet test in tests/web/test_static_delivery_style.py does), so id selectors pass and a real hex color would still fail. Do not change the page styles.
