INTENT
When a recon model ends a turn on finish_reason length with no visible text, the agent recovers where it honestly can and reports the true cause, instead of failing the lane with a message that blames disengagement or auth.

Symptom and evidence: three recon agents given a question that invites exact counting each produced about 16000 output tokens in one turn, ended with finish_reason length and no visible text, and the lane failed with the message Final answer unavailable; run ended with truncated:length. Reading packages/snodo-mcp/src/snodo/recon/__init__.py (call_agent, _forced_answer, _retry_forced_answer) shows these gaps:
- An empty reply on a non-final turn with no tool calls is taken as the final answer, so the agent breaks out of the loop and _retry_forced_answer never runs.
- On the forced answer path, a cut-off submit_answer payload fails json.loads and its partial answer text is discarded entirely.
- Earlier model-authored narration is only used as a fallback when the retry came back with tool calls, so a retry that returns nothing loses it.
- The trace ending truncated:length is overwritten with empty_final:length, so the real cause is lost.
- The warning possible model disengagement or auth issue is logged for every empty final answer, including length cut-offs. A real authentication failure returns earlier and never reaches it.

What it should do:
- A length finish with empty text on a non-final turn goes into the forced answer path, with the retry that already exists, rather than ending the run as an answer.
- A truncated submit_answer payload yields its leading answer text when that text is recoverable; an unrecoverable payload still counts as no answer.
- Earlier genuine narration (with tool output echoes already removed) is used as the fallback whenever the forced retry yields nothing usable, not only when the retry contained tool calls. It is returned with the existing truncation note and error so the lane still moves on to the next model, and it is kept as the partial answer if every model fails.
- The true ending reason (for example truncated:length) stays visible in the trace and in the returned error; it is not overwritten.
- The empty-result warning names the observed ending reason and the output token count, and no longer says auth when the cause is a length cut-off.
- Reasoning-only output is deliberately NOT treated as an answer and is not read as one. If a turn produced only reasoning, the outcome is still a failed lane with an accurate reason.

ACCEPTANCE

Existing recon tests still pass. make gate-task is green.
