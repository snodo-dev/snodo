INTENT
The Protocol page can preview and save an edit to the project's .snodo/protocol.yml. This is the first thing the local dashboard writes, so it is narrow, guarded against other web pages in the user's browser, and recorded in a decision record.

Evidence: the dashboard's request guard today refuses every method except GET and HEAD, and docs/web-dashboard.md says the dashboard is read-only and writes nothing to projects. The mockup (docs/design/protocol-editor.html) has a Review diff step that shows a diff of .snodo/protocol.yml and a Write file step, with the note that committing and pushing stay with the user. An earlier ticket in this plan added the read route and the text-level editor for validators; the read payload carries an etag of the file content.

What it should do: add two POST routes. The preview route takes the project, the etag and the edit list, applies the edits with the text editor, validates the result with the same protocol validation the read route uses, and returns the unified diff of the file, the list of changes, the validity and the rule results, without writing anything. The save route takes the same input plus a page token, repeats the preview, and writes the new text atomically only when it is valid, the etag still matches the file on disk and the guard checks pass; it returns the refreshed read payload. A stale etag answers 409 with a message that the file changed on disk; an invalid result answers 422 with the failing rules; nothing is written in either case. The guard stays strict: only these two routes accept POST, still only on a loopback Host, the Origin header when present must match the Host, a JSON content type is required, and the save route needs a per-process random token that the read route hands to the page (compared in constant time). The route writes only the protocol file of a project the dashboard knows, never another path, never commits, pushes or runs git, and never echoes secrets. The read route payload gains the token field. Write the decision record in the style of the existing records: status Accepted, the context (first write path, browser-based attacks on loopback servers), the decision (the guard rules above, atomic write, no git), and the consequences. Change the sentence in docs/web-dashboard.md that says the dashboard writes nothing so it is accurate: it writes the protocol file only, from the Protocol view, on an explicit save.
