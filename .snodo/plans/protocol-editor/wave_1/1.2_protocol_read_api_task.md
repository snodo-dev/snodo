New files this task will create: snodo/web/protocol.py, snodo/web/routes_protocol.py, tests/web/test_protocol_api.py.

INTENT
The dashboard needs a read-only endpoint that describes a project's .snodo/protocol.yml in the shape the Protocol page shows, so the page never parses YAML itself.

Evidence: the other dashboard views each have a route module that reads local project files for one project and returns JSON, and the project list route tells the page which projects exist. The mockup (docs/design/protocol-editor.html) shows what the page needs: protocol identity and version, the initial mode, a count of modes, the validators with their type, phase, severity cap, tools and criteria, which validators the producer mode runs and in what order, the execution settings, the disagreement policy, the delivery setting, and a list of the rules that are checked when saving, each with an ok or failing state.

What it should do: add GET /api/protocol for one project (selected the same way the other per-project routes select it). The JSON carries: the project, the path of the protocol file, an etag that changes whenever the file's content changes, protocol (id, name, version, initial_mode, disagreement_policy), modes (id, name, tools, concurrency and the ids of the validators it runs, in order), validators (id, type, phase as pre_execute or post_execute, scope, severity_cap or null, tools list, check_tool_access, criteria list), execution (max_retries, branch_ttl_days, max_recovery_depth, max_total_fix_attempts, branch_prefix, delivery, auto_merge, and the queue values parallel_runs and non_blocking), and rules: one entry per cross-field rule that the protocol schema command already publishes, each with id, description, ok and a short detail when it fails. A validator that no mode runs is still listed, with an empty list of modes it belongs to. Reuse the loading and validation code the rest of snodo uses for protocol files and the published rule list; do not duplicate the rules. A project without a protocol file, or a file that does not parse or validate, answers with a clear error object and a non-secret message, never a stack trace, and an unknown project answers 404. The route is read-only like the others and sends no file contents beyond what is listed above.

CONSTRAINTS
Files that may change: snodo/web/protocol.py (new), snodo/web/routes_protocol.py (new), snodo/web/app.py (register the route only), tests/web/test_protocol_api.py (new). Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change the request guard, other routes or any static file. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests that exist and pass: a fixture project with two modes and a validator no mode uses returns every field listed above with the right values and order; the etag changes when the file changes and stays the same when it does not; a missing file, an unparseable file and an invalid file each return the error object; an unknown project returns 404; the rule entries match the published rule list in id and number; the new route accepts GET and HEAD and still refuses other methods. `make gate-task` is green.
