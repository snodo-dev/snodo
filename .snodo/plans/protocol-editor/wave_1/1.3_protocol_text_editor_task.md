New files this task will create: snodo/web/protocol_edit.py, tests/web/test_protocol_edit.py.

INTENT
The Protocol page edits validators and saves them into .snodo/protocol.yml without destroying the file's comments and layout. A plain YAML dump would erase the explanatory comments and reorder keys, so the edit is applied to the text of the file, touching only what changed.

Evidence: the project's own .snodo/protocol.yml carries header comments, a comment above the architecture validator's scope setting, comment lines between criteria, quoted strings, and blank lines between validators. The project depends on PyYAML only, which drops comments on dump. The mockup (docs/design/protocol-editor.html) lets a person change, per validator: type, phase, severity cap, tools, the criteria list (edit text, add, remove) and whether the producer mode runs the validator.

What it should do: a pure function that takes the current file text and a list of edits and returns the new file text, plus a small description of what changed (validator, field, before, after) that the diff view can show. Edits are per validator id: set the type; set the phase (pre_execute or post_execute); set or clear the severity cap; replace the tools list (an empty list removes the key); replace the criteria list; add or remove the validator id in the validators list of a named mode. Rules for the output: every line outside the edited validator blocks and the edited mode list is byte-identical to the input; inside an edited criteria list, criteria that did not change keep their exact original lines, including any comment lines attached to them; new or changed scalars are written as double-quoted strings with correct escaping, in the style the file already uses; keys the validator did not have are inserted in the same place the other validators have them; Windows line endings and a missing final newline are preserved. After applying the edits the function re-parses the result and refuses (with a clear error naming the validator and the field) if it no longer parses, if a requested change is not visible in the parsed result, or if the validator or mode id is unknown. Applying an empty edit list returns the input unchanged.

ACCEPTANCE
Tests that exist and pass, using a fixture shaped like the real protocol file (header comments, a comment above a validator setting, comment lines between criteria, quoted strings with colons and quotes in them, a validator not in any mode): each edit kind alone; several edits at once; a diff of input against output shows changes only inside the edited validator and the mode list; untouched validators and comments are byte-identical; a criterion containing quotes, a colon, a backslash or a non-ASCII character round-trips exactly; unknown ids raise the error; the empty edit list returns the same text; Windows line endings survive. As an extra check the test runs the function on the repository's real .snodo/protocol.yml with a harmless criteria edit and confirms the rest of the file is byte-identical. `make gate-task` is green.
