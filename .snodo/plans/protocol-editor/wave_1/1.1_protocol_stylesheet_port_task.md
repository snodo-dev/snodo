New files this task will create: snodo/web/static/protocol.css, tests/web/test_static_protocol_style.py.

INTENT
The Protocol page must look like Ylli's mockup, so its stylesheet is a faithful port of the mockup's style block, and a test keeps it that way. Earlier dashboard pages drifted far from their designs because styles were rewritten by eye; this ticket removes that risk for the Protocol page.

Evidence: docs/design/protocol-editor.html holds the design in the repository, with its CSS in one style block. The dashboard already shares the same design tokens (colour, line, radius and font variables) in the token block of snodo/web/static/index.html, with the one exception that the mockup also uses an "automated" colour family (--automated, --automated-dim, --automated-border) and the --serif and --body font variables, which a later ticket adds to that token block. Other dashboard views already use generic class names such as .card, .pill, .row, .tile and .eyebrow, so unscoped copies of the mockup rules would restyle them.

What it should do: create protocol.css containing every rule of the mockup's style block, with these exceptions only: the :root token blocks (they live in index.html), the universal reset, the body rule, and the top bar rules (.top, .logo, .env, .tabs, .meta), because the dashboard shell provides those. Every other rule keeps its selector, its declarations, its order and its media query, with each selector prefixed by one scoping class, #protocol-view, so nothing leaks into other views (selectors on bare elements such as label, input, select, textarea and pre are scoped the same way). Rules written for body-level things the page still needs, such as the fixed save bar and the diff overlay, are kept and scoped too. Declarations are copied as they are, including the use of the font variables, so no font name is written in this file. Do not link protocol.css from anywhere yet; the shell ticket does that.

Add a test that reads the mockup's style block and protocol.css and checks that every non-excluded mockup rule appears in protocol.css under the scoping prefix with the same declarations (ignoring whitespace and declaration order), including rules inside the media query, and that protocol.css contains no rule the mockup does not have. The test names the excluded selectors in one list so a reader sees exactly what was left out and why. It also checks there are no hex colours and no external URLs in protocol.css.

CONSTRAINTS
Files that may change: snodo/web/static/protocol.css (new), tests/web/test_static_protocol_style.py (new). Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not edit the mockup, index.html or any other view's files. Do not add any state, status, severity or halt type.

ACCEPTANCE
Tests that exist and pass: the parity test described above on the real mockup file; a deliberate mismatch fixture (a modified declaration) makes the parity check fail; no hex colours or external URLs in protocol.css; every selector in protocol.css starts with #protocol-view or is inside a media query with the same prefix. `make gate-task` is green.
