INTENT
The Validators card lists every declared validator as a row that matches the mockup, with the group header and the summary of what each validator is. Editing inside the rows comes in a later ticket.

Evidence: in the mockup (docs/design/protocol-editor.html) the Validators section has a section head (eyebrow "Validators", the sub line "Ordered as the producer mode runs them. Open a row to edit its criteria. Nothing is written until you save." and a "+ Add validator" button) and a card with a group header: the mode name as an h3, an "initial" pill when it is the initial mode, and a dim summary "<n> active · <m> declared but unused". Below it each validator is a row with: a caret, the validator id in the mono style with the "edited" marker when its working copy differs from the original, a sub line "<type> · <n> criteria" (singular "criterion" for one, plus " · reads files" when the validator has tools), a phase pill (run style for pre_execute, abs style for post_execute), a set of short bars (one per criterion up to eight; grey when the validator is not run by the mode), and a status pill "active" or "unused". Rows are ordered as the initial mode runs them, followed by the declared but unused validators. Clicking a row toggles it open. An open row shows its edit area, which this ticket creates as an empty container with the mockup's edit class so the next ticket can fill it. The shell ticket gave protocol.js shared state with subscribe and the open-row setting, and an empty renderer in protocol-validators.js.

What it should do: implement the section with the mockup's classes and copy (sec, sec-h, eyebrow, sub, btn, card, grp, pill variants, dim, row with open and mod, car, nm, sb, ph, bars with the x variant, edit with show) and the mockup's element order. The "+ Add validator" button is shown as in the mockup but disabled with a title that says adding validators is not available yet; its handler is not part of this plan. When the data has several modes, the group header and rows are repeated per mode in the protocol's order, and validators run by no mode are listed once at the end under their own group header with the "declared but unused" wording.
