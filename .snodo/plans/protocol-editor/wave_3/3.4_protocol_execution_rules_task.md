INTENT
The Execution card and the Rules card match the mockup and show real values and the real rule results.

Evidence: in the mockup (docs/design/protocol-editor.html) the Execution section has a section head (eyebrow "Execution", sub "Branch isolation, retries and delivery. Delivery and auto_merge cannot both be set.") and a card with a key-value grid of six cells, each a small label and a large mono value: max_retries, branch_ttl_days, max_recovery_depth, max_total_fix_attempts, branch_prefix and queue.parallel_runs. The Rules section has a section head (eyebrow "Rules checked on save", sub "Save stays disabled while any of these fail.") and a card with a list in which each rule shows an "ok" pill, the rule id in mono, and its description in dim type. The read API (GET /api/protocol and the preview route) returns the execution values and a list of rules, each with id, description and ok; today the server reports ok as true for every rule and sends no detail field, so a failing rule or a detail text can only come from data that a later server change or the preview supplies, and this ticket must handle both shapes without needing them. The mockup's own script (its line that sets the schema state pill) shows the style used for a problem: the pill class abs. The shell ticket gave protocol.js shared state with subscribe and an empty renderer in protocol-execution.js.

What it should do: implement both sections with the mockup's classes and copy (sec, sec-h, eyebrow, sub, card, kv, rules, pill pass, code, dim) and element order. A value the protocol leaves unset shows as the default the engine uses where that is documented, and as a dash otherwise. A rule whose ok is false shows a pill with the classes pill abs and the word "fail" instead of the pass pill, and, when the rule has a detail text, that text after the description in dim type; a rule without a detail field simply shows no detail. The ok and fail state follows the data the shared state holds: the server's rules on load, and the preview's rule results after a preview from the save bar. Expose a way for the save bar to ask whether any rule is failing, through the shared state. The tests feed rule data with ok false and a detail text directly to the renderer, since the server does not produce it yet.
