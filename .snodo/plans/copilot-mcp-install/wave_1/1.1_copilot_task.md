Title: GitHub Copilot as an MCP install target

Start by opening a GitHub issue in snodo-dev/snodo describing this change (pass the body with --body-file), or reuse an open one that already covers it. The commit message must include "Fixes #<issue number>". Add an entry to CHANGELOG.md under [Unreleased].

INTENT
`snodo serve --mcp-install` registers snodo's MCP servers with Claude Desktop, Codex, Claude Code, Cursor and Gemini CLI. GitHub Copilot is missing, and it is the most promising desktop harness for people running open models (it supports bring-your-own models). Users of Copilot should get snodo's servers registered the same way, and the matching uninstall, listing and orphan-scan paths should cover Copilot too.

THE CHAIN
Copilot reads MCP servers from two user-level places, each with its own shape:
- VS Code (Copilot Chat): the user-profile mcp.json inside the "Code" then "User" folder of the per-OS application config location (Application Support on macOS, the XDG config folder on Linux, APPDATA on Windows). Servers live under the top-level key "servers", and a stdio server entry carries "type": "stdio" plus command, args and env.
- Copilot CLI: ~/.copilot/mcp-config.json (COPILOT_HOME overrides the folder). Servers live under "mcpServers", and a local server entry carries "type": "local" plus command, args, env and "tools": ["*"].
The installer already models one target per client with its own servers key and format, and already shapes entries per client (Codex gets timeouts). Extend that pattern rather than adding a parallel mechanism. Presence detection follows the existing rule: a client counts as installed when its config folder exists, and it is reported as skipped otherwise.

A related hazard: when a JSON client config cannot be parsed, the installer currently treats it as empty and writes a fresh file, which would erase the user's own servers. VS Code's mcp.json allows comments and trailing commas, so this would bite Copilot users first. A file that cannot be parsed must be left untouched and reported, for every JSON target. Reading VS Code's comment-tolerant JSON is welcome if it stays simple; either way, no data loss.

CONSTRAINTS
- No new top-level CLI command and no new flags; this rides on the existing install, uninstall and list behaviour.
- Use the two client names "GitHub Copilot (VS Code)" and "GitHub Copilot CLI" in output.
- Entries written for other clients stay exactly as they are today.
- Tests must not touch the real home folder; isolate HOME and the per-client environment overrides.
- Run only the installer tests and any tests you add. Do not run the snodo CLI, make gate or make release, and do not touch .snodo/.

ACCEPTANCE
- With a VS Code user folder present, install writes a snodo entry under "servers" with "type": "stdio"; uninstall removes it and leaves other servers alone.
- With a Copilot CLI folder present, install writes a snodo entry under "mcpServers" with "type": "local" and "tools": ["*"]; uninstall removes it and leaves other servers alone.
- Without either folder, install reports Copilot as skipped, as it does for Cursor.
- A client config that cannot be parsed is left unchanged and the output says so; other clients still install.
- The docs list Copilot among the supported clients.
