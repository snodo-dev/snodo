# 1.2_demo_commands

## INTENT
The demo runs the same task through `snodo run` for each arm. One small helper builds that command as an argument list (never a shell string), so any model string, a pinned snodo version and a multi-line task text all pass through unchanged. A user can pin the snodo version with `uvx`; otherwise the installed `snodo` is used.

## THE CHAIN
1. Open a GitHub issue first ("Demo: snodo run command builder") and put "Fixes #<n>" in the commit message.
2. Evidence: `docs/command-reference.md` lists `snodo run` with `[description]`, `--protocol`, `--model`/`-m`, `--coder` and `--retain-worktree`; `docs/coders.md` explains the coders, including the LiteLLM one that is the default. Read both and use the real flag names. Look at `demo/protocols.py` and `tests/test_demo_protocols.py` for how modules in `demo/` are imported by tests and follow that pattern.
3. Create `demo/commands.py` with: a function returning the command prefix as a list (`["snodo"]` by default, `["uvx", "snodo@<version>"]` when a version is given); a function that returns the full `snodo run` argument list for a task text, a protocol file path, a model string and an optional coder name (omitted from the command when not given), always including `--retain-worktree`; a function that reads the task file `demo/scikit-learn-26194/task.md` as bytes and decodes it as UTF-8 without any newline translation, so the task text equals the fixture exactly.
4. Create `tests/test_demo_commands.py`. Use exactly these test function names and keep them unchanged for the whole task, including in any follow-up fix pass (a coverage check fails the task when a test name disappears or is renamed): `test_prefix_defaults_to_installed_snodo`, `test_prefix_pins_version_with_uvx`, `test_run_command_carries_protocol_model_and_retain_worktree`, `test_task_text_is_one_argument_unchanged` (multi-line text with quotes and a CRLF pair), `test_coder_flag_only_when_given`, `test_task_text_read_without_newline_translation`. More tests may be added.
5. The project supports Python 3.12; do not use 3.13-only APIs. Before finishing, run `python -m pytest tests/test_demo_commands.py` and do not finish until every test passes (the gate reruns the file and one failing assertion blocks the task); write each expected value from what the code really returns. Also run `ruff check` and `ruff format --check` on every file you touched and fix what they report (remove unused imports and variables). These are checks for you to run; the reviewer does not re-run them.
