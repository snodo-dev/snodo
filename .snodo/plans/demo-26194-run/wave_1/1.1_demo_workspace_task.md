# 1.1_demo_workspace

## INTENT
A demo run needs a clean checkout of the scikit-learn repository at the exact commit the task was recorded against, with snodo initialised in it. One small helper module prepares that checkout so the runner never has to. The fixture already exists in `demo/scikit-learn-26194/instance.json` (keys instance_id, repo, repo_url, base_commit, fail_to_pass, pass_to_pass); it is correct, do not change it.

## THE CHAIN
1. Open a GitHub issue first ("Demo: workspace helper") and put "Fixes #<n>" in the commit message.
2. Evidence: `docs/command-reference.md` lists `snodo init` with `--template` and `--yes`; the shipped template is named `bugfix-surgeon`. Look at `demo/protocols.py` and `tests/test_demo_protocols.py` for how modules in `demo/` are imported by tests and follow that pattern.
3. Create `demo/workspace.py` with: a function that loads an instance file and returns its dictionary, raising a clear error naming the missing key when a required key (instance_id, repo_url, base_commit) is absent; a function that clones the instance's `repo_url` into a target folder and checks out `base_commit` detached, refusing a target folder that already exists and is not empty; a function that runs `snodo init --template bugfix-surgeon --yes` inside the clone. The command prefix (a list such as `["snodo"]`) is passed in by the caller, and every external command goes through one small injectable runner function so tests never touch the network or need snodo installed.
4. Create `tests/test_demo_workspace.py`. Use exactly these test function names and keep them unchanged for the whole task, including in any follow-up fix pass (a coverage check fails the task when a test name disappears or is renamed): `test_load_instance_reads_required_keys`, `test_load_instance_names_the_missing_key`, `test_clone_checks_out_base_commit` (uses a small local git repository with two commits created in a temporary folder as the source, no network), `test_non_empty_target_is_refused`, `test_init_command_uses_bugfix_surgeon_template` (a recording runner, asserts the argument list). More tests may be added.
5. `CHANGELOG.md` gets one new line under `[Unreleased]` in the same commit, in the style of the neighbouring entries, ending with the issue reference, for example "(Fixes #<n>)". The commit is incomplete without it; the changelog check in the gate reports a commit that closes an issue the changelog does not mention.
6. The project supports Python 3.12; do not use 3.13-only APIs. Before finishing, run `python -m pytest tests/test_demo_workspace.py` and do not finish until every test passes (the gate reruns the file and one failing assertion blocks the task); write each expected value from what the code really returns. Also run `ruff check` and `ruff format --check` on every file you touched and fix what they report (remove unused imports and variables). These are checks for you to run; the reviewer does not re-run them.

## CONSTRAINTS
- Do not change `demo/scikit-learn-26194/`, `demo/protocols.py`, `demo/record.py` or anything under `packages/`.
- No new states, statuses, severities, halt types or event names.

## ACCEPTANCE
- The new module loads an instance, clones and checks out a base commit, and runs `snodo init` with the `bugfix-surgeon` template through an injectable runner, visible in the diff.
- The new test file contains the five named tests above.
- The diff adds one line under `[Unreleased]` in CHANGELOG.md that mentions the issue.
- Verifiable from the diff of the new module, the new test file and CHANGELOG.md.
