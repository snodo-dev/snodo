## Intent
Document that `snodo logs <id> --watch` also follows a running recon, so the docs match the behaviour introduced for issue 1064.

## Evidence
- docs/command-reference.md describes `snodo logs` and its `--watch` option for jobs only; docs/decompose-and-recon.md describes how to retrieve recon results without saying results can be followed live.

## Outcome
- The command reference states that `--watch` works for a recon id as well as a job id: it stays attached until the recon is complete or failed, printing each agent's answer once as it arrives, and Ctrl-C detaches without stopping the recon.
- The decompose-and-recon guide mentions following a recon with the logs command and `--watch`, next to where it already describes reading recon results.
- Existing statements about jobs stay correct.
- `make gate` passes, including the docs-coverage and docs link checks.
