INTENT
The mock judges that stand in for an LLM validator hand back the task identifier the prompt names, under the wording the verdict-subject instruction has today, so mocked validator runs pass again; the instruction text and the code that reads it come from one place and a regular test keeps them from drifting apart.

Symptom and evidence: the release gate (make release PART=minor, gate-ci) ended with 61 failed and 6878 passed. The failures are in tests/validators (about 40, mostly test_llm_validator.py plus the verdict cache, change-context and mock-hermetic tests), tests/cli/test_main.py (six runs that assert exit code 0 and got 1), tests/mcp/test_pr.py (two), tests/engine/test_verdict_cache_visibility.py, and the e2e journeys that run the mock coder (mode switch, solo, team, ungated first task, project announced, queue run). Their captured logs all carry the same warning: "Unusable submit_verdict: task_id '' does not exactly match 'task_281185101cfb'. Fail-closed." Every validator verdict then becomes a blocker. The cause is the change merged under issue 1341: the instruction in packages/snodo-engine/src/snodo/validators/verdict_subject.py no longer wraps the identifier in JSON quotation marks on the same line; it now names it on the line after "The task identifier under judgement is:". Readers of the old wording look for a marker string ending in "is " followed by a JSON value and no longer find it, so the identifier comes back empty. Known readers: the mock completion in packages/snodo-engine/src/snodo/coders/mock.py, the scripted completion in tests/validators/conftest.py, and one in tests/validators/test_verdict_cache.py; search packages and tests for the marker text to find any others. Real judges are unaffected; the strict equality check in the same module is correct and must not change.

A previous attempt at this ticket did most of the work and then failed its own gate-task with 44 failed and 500 passed, all in tests/validators (test_acceptance.py and others: assert 'blocker' == 'warn' or 'pass'), plus an "LLM tool-loop operational error on turn 2" on the security validator. The cause is visible in the tree: tests/validators/conftest.py lost its json import while the autouse fixture that binds the subject for legacy scripted judges still calls json.loads and json.dumps. Inside the patched completion that raises NameError, which the tool loop reports as an operational error. The work already in that checkout is a good base; finish it rather than starting over, and look for any other name an edit removed but code still uses.

What it should do: make every reader recover the identifier from the instruction as it is worded now, with the identifier's punctuation and escaping preserved exactly, and prefer one shared reader next to the instruction (the same module) over private copies, if the package layering allows it. Add a regular test, not marked e2e, that builds the instruction for several identifiers (including one with quotes, a backslash and unusual punctuation) and proves each reader returns exactly that identifier, so a later change of wording fails here and not at release time. Do not loosen the equality check, do not normalise what a judge returns, and do not change the instruction wording again.
