## Intent
Every tool result that enters a model conversation must be bounded, in the LLM validator loop and in the recon agent loop as well as the coder loop. The coder loop already bounds results through the shared helper in packages/snodo-engine/src/snodo/coders/tool_result_text.py (MAX_TOOL_RESULT_CHARS, model_tool_result_text). Two other loops handed results to the model unbounded: the validator loop, packages/snodo-engine/src/snodo/validators/llm_validator.py, and the recon agent loop, `call_agent` in packages/snodo-mcp/src/snodo/recon/__init__.py. Recon has its own loop and its own read tools (read_files, read_file, read_file_lines, list_files, search_string, search_symbol); it does not run through the validator loop.

## Evidence
- Recon rec_04abc0 on 2026-10-28: the agent running openai/gpt-6.1-sol failed with "Invalid 'input[56].output[0].text': string too long. Expected a string with maximum length 10485760, but got a string with length 93549595". Its tools were exactly the recon read tools; none of them runs tests.
- The production change is already in place from earlier attempts and was judged correct: the validator loop appends `model_tool_result_text(str(result))`, and the recon loop bounds its tool message and the findings it keeps, both through the one shared helper. The recon tests pass. Do not rework production code.
- What is left is one validator-loop test. The latest quality gate (make gate) ran 5957 tests and 2 failed: both cases ([oversized] and [small]) of tests/validators/test_llm_validator.py::TestSummarizeDirectoryTool::test_tool_loop_bounds_results_before_model_message. The earlier AttributeError (`_make_post_context`) is already fixed. The current error, identical for both cases, is:
  pydantic_core._pydantic_core.ValidationError: 1 validation error for Validator ... tools: Value error, Validator tool 'result_bound_probe' is not a read-only tool. Allowed tools: ['git_log', 'git_show', 'list_files', 'read_diff_between_refs', 'read_file', 'read_file_lines', 'summarize_directory']
  The test builds `Validator(..., tools=['result_bound_probe'])`, a tool name the Validator model rejects at construction. The model only accepts the read-only tool names listed in that error. Fix the test: construct the Validator with an allowed tool name (for example `list_files` or `summarize_directory`), and make the fake or patched tool result for that name return the oversized or small string. Look at the sibling tests in TestSummarizeDirectoryTool and mirror how they build a Validator and feed a tool result through the loop. Do not widen the Validator's allowed-tool list and do not add a new tool name.
- Ids must stay short: if the test is parametrized, give explicit short ids such as "oversized" and "small", and build the large string inside the test or pass sizes rather than the string itself.
