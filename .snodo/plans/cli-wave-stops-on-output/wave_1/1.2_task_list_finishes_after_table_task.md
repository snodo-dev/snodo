Before starting, open a GitHub issue on snodo-dev/snodo titled "CLI: snodo task list keeps running long after printing its table". Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased]. If CHANGELOG.md conflicts with a sibling task's entry, keep both entries.

INTENT
In the snodo-public repo, which has a few hundred task records, `snodo task list` printed its full table and then the process was still running about 20 seconds later. The wave indicator, which had a separate bug, was still counting. A list command should be done when its table is on screen. Either the slow work happens after printing, or it runs before printing and takes ~20s; both are poor for an operator.

When this is done, `snodo task list` on a repo with hundreds of tasks returns promptly. It should take roughly the time it needs to read task records and render, not tens of seconds. Any expensive per-task work, such as git calls per branch, worktree inspection, stale-task reconciliation or cleanup, is either not done on a plain list, batched, or deferred to the commands that need it. The output content must stay the same.

THE CHAIN
1. Profile `snodo task list` on this repo, for example with python -X importtime and cProfile. Find what takes the time and whether it happens before or after printing.
2. Remove, batch or defer the slow work, without changing what the table shows.
3. Tests:
   - a test that fails if task list starts calling git per task again (count calls with a fake), or an equivalent guard on the expensive path you found;
   - an output snapshot test showing the table content is unchanged.
4. Note the before/after timing in the commit message.

CONSTRAINTS
- Do not touch snodo/cli/spinner.py or snodo/cli/slow_commands.py; a sibling task owns them.
- Add no status, severity, halt type, audit event or result field.
- No file may exceed its file-length limit or baseline.

ACCEPTANCE
- The tests in link 3 exist and pass.
- The before/after timing is in the commit message.
- The CHANGELOG entry is present.
- `make gate` passes, including lint and the file-length check.
