So something shut the shared executor, or the recon process's interpreter, while those agents were still running. Possible causes include one agent's failure tearing down a shared pool, a wall-clock limit, and process exit. Find which one it is from the recon runner code before changing anything.

When this is done, each agent runs to its own end: an answer, its own error, or its own budget. Another agent's failure does not stop it. If the recon must stop early, every agent still records what it has, including a truncated answer and its trace, as the budget path already does.
