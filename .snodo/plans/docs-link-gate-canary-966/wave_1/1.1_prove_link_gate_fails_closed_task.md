# Make the documentation link gate prove it works

GitHub issue #966 already exists for this work. Do not open another; put "Fixes #966" in the commit message. You write the CHANGELOG entry.

## Why this task exists

Issue #966 is the fix-forward review of the delivery that added link validation to
`mkdocs.yml` and corrected the published example links.

The gate is real: the site builds with `strict: true`, and unresolved, absolute and
unrecognised local links are set to warn, which a strict build turns into a failure.
But nothing in the test suite proves it still fails closed. The project's rule for
new verification gates is that a gate ships with a canary that would catch the gate
being switched off or mis-set. What exists today is a four-step manual recipe in
CONTRIBUTING.md.

That recipe is also broken as written. Step 2 creates a temporary page under `docs/`
that is not in the site nav, and the Material theme warns about a page missing from
the nav. Under `strict: true` that warning fails the build on its own, so step 3
succeeds for the wrong reason: the build fails, but it reports a nav problem rather
than the missing link the recipe is testing. An operator following the recipe
concludes the gate works when the observation never happened.

## What "done" means

The fail-closed behaviour is asserted by an automated test that runs as part of the
standard gate, and the manual recipe is corrected so it demonstrates what it claims
to demonstrate.

## Acceptance criteria

1. A test proves that a local link the site cannot resolve makes a strict docs build
   fail, and that the failure names the missing target rather than something
   unrelated. It must fail if any of the three validation levels is dropped below
   warning, or if strict mode is removed.
2. The test does not build the whole published site: it exercises the same
   validation settings against a minimal fixture so it costs seconds, not minutes,
   and it is collected in the default test run rather than behind a manual marker.
3. The manual recipe in CONTRIBUTING.md is corrected so the temporary canary page
   cannot produce a nav warning, and its step 3 states the single failure the
   operator should see.
4. The published docs still build cleanly, and the full gate passes.

## Constraints

- Do not change the link targets that the original delivery fixed, and do not
  restructure the docs nav.
- The validation levels stay at warning or higher; the point of the test is that a
  lower level breaks the gate, so do not solve it by raising them to errors.
- The test must not depend on network access or on a docs theme being downloaded at
  run time.
- Add one bullet under the `## [Unreleased]` section of CHANGELOG.md describing the
  new gate coverage. Touch only that section — other in-flight branches edit the same
  block, so do not reflow or reorder anything else in the file.
- Either the gate passes and you submit, or it does not and you fix it. Do not leave
  notes about validation anywhere in the tree.

## Running tests

Run the targeted tests for the code you touch and the linter, and do not run the whole suite yourself: the engine runs it right after you finish, and a multi-minute silent command has been dropping the coder connection. Confine the diff to what this task asks for and drop every hunk the outcome does not require.
