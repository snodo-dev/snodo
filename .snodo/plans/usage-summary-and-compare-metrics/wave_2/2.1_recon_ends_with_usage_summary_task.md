## Intent
`snodo recon` ends with the usage summary the previous wave's helper produces: one line per agent and a total, so an operator comparing agents or models sees input tokens, output tokens, elapsed time and output tokens per second, with the rate marked reported or calculated.

## Evidence
- A recon already records per-agent usage (`input_tokens`, `output_tokens`, `duration_ms`, cost) in its results (packages/snodo-mcp/src/snodo/recon/__init__.py, `.snodo/recons/<id>/results.json`), and `snodo recon` prints only "Recon complete:" and each agent's answer or error (snodo/cli/commands/recon_cmd.py).
- `snodo logs <recon id> --watch` also prints a recon's answers as they arrive (snodo/cli/commands/logs_cmd.py).
- The helper module from task 1.1 of this plan accepts recon-agent records and renders the lines.

## Outcome
- After the answers, `snodo recon` prints the usage summary: a row per agent (named by its model) and a total, in the helper's format. An agent that failed before any usage was recorded shows its tokens as n/a.
- `snodo logs <recon id> --watch` prints the same summary once the recon has completed.
- The total elapsed time is the recon's own wall time from its start to its completion, not the sum of the agents.
- Both commands use the helper; neither duplicates its arithmetic or formatting. The existing output above the summary is unchanged.
- Tests cover a recon with two agents, one agent that failed, and a recon with no usage recorded.
