INTENT
`snodo dashboard` becomes the one entry point for both dashboards: the existing terminal dashboard (--cli) and the new local web dashboard (--web). Running it with neither flag keeps doing exactly what it does today, so nothing that uses it changes.

State of the repository before this task: snodo/cli/commands/dashboard_cmd.py registers the command `dashboard` with no options and runs the terminal dashboard through dashboard_command(args), which also backs the snop_entry shortcut. snodo/web/projects.py provides resolve_projects(roots, cwd) returning the projects to show; snodo/web/roots.py provides load_roots() and save_roots(roots); snodo/web/app.py provides serve(projects, port) which starts the loopback web server and blocks until it is stopped.

THE CHAIN
1. snodo/cli/commands/dashboard_cmd.py: the dashboard command gets an option pair --web/--cli (default --cli), an option --port (an integer, default none) and a repeatable option --root (a folder).
2. With --cli (the default) the command behaves exactly as before: the same checks, messages and exit codes. Giving --port or --root with --cli ends with a clear error and a non-zero exit code, since they mean nothing there.
3. With --web the command takes the roots from --root when given and saves them with save_roots; otherwise it uses load_roots(). It finds the projects with resolve_projects(roots, current folder), ends with a clear error and a non-zero exit code when there are none (the message tells the person to pass --root or run it inside a snodo project), and otherwise calls serve(projects, port).
4. The web import happens only when --web is used, so the terminal dashboard and the other commands start no slower and need nothing extra.
5. tests/cli/test_dashboard_web_flag.py uses the Typer test runner with the web server function replaced by a recorder.
6. The repository's layering contract (`.importlinter`, contract "Snodo architectural layers (app)") forbids snodo.cli from importing snodo.dashboard, and the web modules snodo/web/flow.py, snodo/web/gates.py, snodo/web/routes_now.py and snodo/web/routes_plans.py import snodo.dashboard.providers, which the command now reaches through snodo.web.app. In `.importlinter`, under that contract's ignore_imports, next to the existing `snodo.cli.commands.dashboard_cmd -> snodo.dashboard.app` line, add one line for each of those four modules in the same form (`snodo.web.flow -> snodo.dashboard.providers`, and so on) and nothing else. Run `lint-imports` and make sure the contract is kept.

CONSTRAINTS
The terminal dashboard code (snodo/dashboard/) is not changed, and neither are snop_entry and dashboard_command's behaviour. Do not start a real server in tests. The only other file that may change is `.importlinter`, for the lines in step 6. Out of scope: snodo/cli/commands/serve_cmd.py.

ACCEPTANCE
