New files this task will create: `snodo/web/static/gates.js`, `tests/web/test_static_gates.py`.

INTENT
The Gates view shows what the gates sent back and whether it landed afterwards. Add snodo/web/static/gates.js, the script the page shell loads for #/gates.

State of the repository before this task: the page shell snodo/web/static/index.html loads this script and calls window.snodoViews.gates(container) on show and every 10 seconds. GET /api/gates?days=21 (or 7 or 30) returns {"window_days", "sent_back", "landed_after_retry", "by_validator": [{"validator", "count"}], "by_project": [{"name", "sent_back", "landed_after_retry"}], "records": [{"project", "task", "plan", "validator" or null, "outcome" ("landed_after_retry" or "not_landed"), "when"}]}.

THE CHAIN
1. snodo/web/static/gates.js registers window.snodoViews.gates, fetches /api/gates with the chosen window (7d, 21d or 30d, 21d by default) and renders the container.
2. It opens with one plain sentence, for example "The gates sent back 188 tasks in the last 21 days. 130 landed after being rewritten.", then three small panels: "What the validators caught" (horizontal bars by validator, a null validator shown as "unknown"), "Per project" (bars of landed after retry out of sent back) and the counts.
3. Below, "The record": a table with one row per record showing Task, Project, What stopped it (the validator or "unknown"), Outcome ("Landed after a retry" or "Not landed yet") and When as a relative time such as "11h".
4. tests/web/test_static_gates.py checks the file as text.

CONSTRAINTS
Build the page with DOM calls and textContent only; never innerHTML or insertAdjacentHTML. No libraries, no external URLs. An empty record list shows one short line instead of an empty table. A failed fetch shows one line and keeps the last good content. Out of scope: index.html, every other script and every Python module.

ACCEPTANCE
Tests that exist and pass: the file registers window.snodoViews.gates; it fetches "/api/gates"; it offers the 7, 21 and 30 day windows; it does not contain innerHTML or insertAdjacentHTML; it contains the strings "The record" and "unknown"; it handles a failed fetch.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message. Add one CHANGELOG.md entry under [Unreleased] ending "(Fixes #<n>)". Before finishing, run `ruff check` on the files you wrote and fix every finding, such as unused imports.
