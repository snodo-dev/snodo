New files this task will create: `snodo/web/static/index.html`, `tests/web/test_static_shell.py`.

INTENT
The local web dashboard is one static page that switches between four views: Now, Delivery, Gates and Plans. Add the shell, snodo/web/static/index.html, with the look and navigation. The view contents are added by other work as separate scripts, so the shell only provides the frame and a small contract for them.

State of the repository before this task: snodo/web/app.py serves this file at "/" and the static folder beside it under "/static/". The four view scripts, named after the views and served from /static/, are written by other work.

THE CHAIN
1. snodo/web/static/index.html is a single self-contained page (inline CSS and one inline script; no external hosts, fonts or libraries) with a top bar showing the name "snodo" and "local", a navigation with four buttons Now, Delivery, Gates and Plans, and a theme button.
2. The look: calm and plain. Colour tokens are CSS variables defined on :root with a dark set under prefers-color-scheme and under a data-theme attribute that the theme button toggles: a near-white or near-black background, a slightly lifted surface, a thin border, muted text, a teal accent, and soft amber, red and green for tags. Numbers use a monospace face. The page works at phone width with a 16px side gutter.
3. Navigation uses the URL hash (#/now, #/delivery, #/gates, #/plans) and defaults to #/now. Switching shows one section with id view-now, view-delivery, view-gates or view-plans and loads the matching script from /static/<name>.js the first time.
4. The contract: a view script registers a function with window.snodoViews = window.snodoViews || {}; window.snodoViews.<name> = function (container) {...} that fetches its own data and fills the container. The shell calls it when the view is shown and again every 10 seconds while that view is visible and the tab is visible, and shows a small "updated" time in the top bar after each call. A script that fails to load or throws shows a one-line message in the view and never breaks the other views.
5. tests/web/test_static_shell.py checks the file as text.

CONSTRAINTS
Never put data from the API into the page with innerHTML; the shell does not render data at all. Do not write the view scripts. Out of scope: every Python module and snodo/dashboard/.

ACCEPTANCE
Tests that exist and pass: index.html contains the four view section ids, the four navigation entries and the hash defaults; it references no external URL (no http:// or https:// except inside comments or the localhost examples, if any); it defines both the light and dark colour sets; it contains the snodoViews contract and the 10-second refresh; it does not use innerHTML.
