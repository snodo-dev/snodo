New files this task will create: `snodo/web/app.py`, `tests/web/test_app.py`.

INTENT
Assemble the pieces of the local web dashboard into one small web app that can be started on the loopback address. Add snodo/web/app.py. It must be safe to leave running on a developer machine: read-only, reachable only from the same machine.

State of the repository before this task: snodo/web/projects.py defines Project (name and path). The modules snodo/web/routes_now.py, routes_plans.py, routes_delivery.py and routes_gates.py each provide an async handler(request) that reads request.app.state.projects. The static folder under snodo/web may or may not exist yet; its index page is added by other work in the same wave and is served at the root path when present.

THE CHAIN
1. snodo/web/app.py provides create_app(projects) returning a Starlette application with app.state.projects set, and routes: GET /api/projects (a list of {name, path}), GET /api/now, GET /api/plans, GET /api/delivery and GET /api/gates (the four handlers), GET / (the index.html in the static folder when present, otherwise a short plain page saying the dashboard files are missing) and GET /static/... from the static folder that sits beside the module, found through the package location so it also works when installed.
2. Only GET and HEAD are accepted; any other method gets status 405.
3. A request whose Host header is not loopback (127.0.0.1, localhost or [::1], with or without a port) gets status 400, which protects against DNS-rebinding.
4. snodo/web/app.py provides serve(projects, port) that starts uvicorn bound to 127.0.0.1 only. With port None it picks the first free port starting at 55441 and trying up to 20 consecutive ports, and fails with a clear message when none is free; with an explicit port that is taken it fails with a clear message instead of picking another. It prints the URL it serves on.
5. tests/web/test_app.py covers the behaviour below using Starlette's test client; the port choice is tested with a function that takes a "is this port free" check so no real server is needed.

CONSTRAINTS
No write endpoints, no cookies, no authentication and no CORS headers: the loopback binding and the Host check are the whole protection. Do not import snodo/cli/commands/serve_cmd.py or change it; the port range matches serve's default on purpose but is its own code. Out of scope: snodo/dashboard/.

ACCEPTANCE
Tests that exist and pass: each of the five API paths returns 200 JSON for a project list; "/" returns the placeholder when the index page is absent and the file when present; POST to an API path gives 405; Host "evil.example" gives 400 while "localhost:55441" and "127.0.0.1" are accepted; port choice returns the first free port and raises a clear error when all 20 are taken; an explicit taken port raises.
