New files this task will create: `snodo/web/routes_delivery.py`, `tests/web/test_routes_delivery.py`.

INTENT
The web dashboard's Delivery view answers "how is work landing across my projects". Add snodo/web/routes_delivery.py: a pure builder plus a Starlette handler.

State of the repository before this task: snodo/web/projects.py defines Project (attributes name and path). snodo/web/flow.py provides flow_metrics(project_path, window_days, now) returning landed, landed_by_day (list of {date, landed}), median_flow_seconds (or None), first_try_rate (or None) and flow_load. snodo/web/delivery.py provides plans_delivery(project_path) returning a dict from plan name to "in_main", "not_in_main" or "no_branch".

THE CHAIN
1. snodo/web/routes_delivery.py provides build_delivery(projects, window_days, now) returning {"window_days", "projects", "by_day", "totals"}.
2. projects has one entry per project: {"name", "landed", "plans_in_main", "median_flow_seconds", "first_try_rate", "flow_load"}, taken from flow_metrics, with plans_in_main the number of the project's plans whose delivery is "in_main".
3. by_day sums landed per date over all projects, one entry per day of the window. totals holds landed, flow_load, the number of plans not in main, and median_flow_seconds and first_try_rate computed over all projects only when every project that has landed tasks reports a value, and None otherwise.
4. routes_delivery.py provides async handler(request) that reads an optional days query parameter (7 or 30, default 7; any other value gives status 400) and returns JSONResponse(build_delivery(...)).
5. tests/web/test_routes_delivery.py covers the builder with stubbed flow data and the handler with a Starlette test client.

CONSTRAINTS
Read-only and GET only. A figure that is None stays None; it is never turned into zero. No new states. Out of scope: snodo/dashboard/ and every file outside snodo/web/, tests/web/ and CHANGELOG.md (the one required entry).

ACCEPTANCE
Tests that exist and pass: per-project values pass through; by_day sums two projects; totals are None when one project cannot report a median; days=30 changes window_days; days=5 returns 400; the handler returns JSON with status 200.
