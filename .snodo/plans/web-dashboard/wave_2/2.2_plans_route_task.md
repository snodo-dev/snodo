New files this task will create: `snodo/web/routes_plans.py`, `tests/web/test_routes_plans.py`.

INTENT
The web dashboard's Plans view lists every plan across the projects, newest first, with progress and whether it reached main. Add snodo/web/routes_plans.py: a pure builder plus a Starlette handler.

State of the repository before this task: snodo/web/projects.py defines Project (attributes name and path). snodo/web/delivery.py provides plans_delivery(project_path) returning a dict from plan name to "in_main", "not_in_main" or "no_branch". snodo/dashboard/providers.py has the read-only DashboardDataProvider(project_root) whose get_plans() returns, per plan, name, intent and a tasks dict from task id to status. These are used as they are.

THE CHAIN
1. snodo/web/routes_plans.py provides build_plans(projects) returning a list of {"project", "name", "intent", "tasks_total", "tasks_completed", "running", "delivery", "updated_at"}.
2. running is true when any task of the plan is in_progress. delivery is the string from plans_delivery for that plan. updated_at is the ISO modification time of the plan's status.json, or null when the file is missing.
3. The list is sorted by updated_at descending, plans without a time last, with project name and plan name as tie-breakers.
4. routes_plans.py provides async handler(request) returning JSONResponse(build_plans(request.app.state.projects)).
5. tests/web/test_routes_plans.py covers the builder with temporary projects and the handler with a Starlette test client. For the delivery assertions use a real temporary git repository created with `git init -b main` (the default branch is main, never master). A plan's status.json records its branch as `{"tasks": {...}, "integration": {"branch": "<branch name>"}}`; delivery reads it from there. For the merged plan create that branch and merge it into main; for the unmerged plan create that branch with one commit that main lacks. Assert exactly "in_main" and "not_in_main" respectively.

CONSTRAINTS
Read-only and GET only. A plan whose files cannot be read still appears with what is known and never fails the response. No new states. Out of scope: snodo/dashboard/ and every file outside snodo/web/, tests/web/ and CHANGELOG.md (the one required entry).

ACCEPTANCE
Tests that exist and pass: counts of tasks_total and tasks_completed are correct; a plan with an in_progress task has running true; delivery reflects git for a merged and an unmerged plan; ordering is newest first across two projects; a plan folder without status.json appears with updated_at null and sorts last; the handler returns JSON with status 200.
