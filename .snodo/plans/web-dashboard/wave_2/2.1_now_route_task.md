New files this task will create: `snodo/web/routes_now.py`, `tests/web/test_routes_now.py`.

INTENT
The web dashboard's Now view needs one JSON answer to "what is running across my projects, and what is waiting for me". Add snodo/web/routes_now.py: a pure builder plus a Starlette handler. Nothing here changes how snodo runs; it only reads.

State of the repository before this task: snodo/web/projects.py defines Project (attributes name and path). snodo/web/delivery.py provides plans_delivery(project_path) returning a dict from plan name to "in_main", "not_in_main" or "no_branch". snodo/dashboard/providers.py has the read-only DashboardDataProvider(project_root) with get_plans(), get_tasks(""), and get_jobs("") (each job has job_id, task_ref, status, started_at). These are used as they are.

THE CHAIN
1. snodo/web/routes_now.py provides build_now(projects, now) returning {"projects": [...], "waiting": [...]}.
2. Each entry of projects is {"name", "state", "plans"}. state is "working" when any of the project's tasks is in_progress or any job is running, and "idle" otherwise. plans lists only plans that have an in_progress task or a running job; each is {"name", "wave", "waves", "tasks"} where wave is the first wave with an unfinished task, waves is the number of waves, and tasks lists {"task_id", "status", "job"} with job being {"job_id", "status", "elapsed_seconds"} for the task's running job or null.
3. waiting is a list with {"kind": "not_in_main", "project", "plan"} for every plan whose tasks are all completed and whose plans_delivery is "not_in_main", and {"kind": "uncommitted", "project", "files": [...]} for a project whose repository has modified tracked files (untracked files are not counted), listing up to 10 file names.
4. routes_now.py provides async handler(request) that returns JSONResponse(build_now(request.app.state.projects, now)).
5. tests/web/test_routes_now.py covers the builder with temporary projects and the handler with a Starlette test client.

CONSTRAINTS
Read-only and GET only. A project whose .snodo/ cannot be read is reported with state "idle" and no plans, and never fails the response. No new states: the status strings are the ones snodo already records. Out of scope: snodo/dashboard/ and every file outside snodo/web/, tests/web/ and CHANGELOG.md (the one required entry).

ACCEPTANCE
Tests that exist and pass: a project with an in_progress task is "working" and lists that plan with its running job; a project with nothing running is "idle" with no plans; a finished plan whose branch is not in main appears under waiting as not_in_main; modified tracked files appear as uncommitted and untracked ones do not; an unreadable project does not break the response; the handler returns JSON with status 200.
