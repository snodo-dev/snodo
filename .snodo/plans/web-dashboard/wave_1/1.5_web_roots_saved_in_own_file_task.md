New files this task will create: `snodo/web/roots.py`, `tests/web/test_roots.py`.

INTENT
The web dashboard remembers which root folders to scan for projects, so a person types them once. Add snodo/web/roots.py that loads and saves that list. The list lives in its own small file, web.yml, next to the user's snodo config in the user's snodo folder (~/.snodo/). It must not live inside config.yml: that file is hand-edited and carries comments that a program rewriting it would erase.

THE CHAIN
1. snodo/web/__init__.py and tests/web/__init__.py exist as empty files. If they are missing in your tree, create them with no content at all (sibling work creates the same empty files and they merge cleanly).
2. snodo/web/roots.py provides load_roots() returning a list of absolute folder paths read from the "roots" key of web.yml in the user's snodo folder, or an empty list when the file is missing, empty or unreadable.
3. snodo/web/roots.py provides save_roots(roots) that writes the list, expanding ~ and resolving to absolute paths, removing duplicates and keeping order, creating the folder and file when needed and replacing the file in one step so a crash never leaves half a file.
4. The user's snodo folder is found the same way the rest of snodo finds it (look at how snodo.infrastructure.config locates ~/.snodo and honour any override it already honours), so tests can point it at a temporary folder.
5. tests/web/test_roots.py covers the behaviour below.

CONSTRAINTS
Never read or write config.yml from this module. Saving twice with the same roots changes nothing. Out of scope: snodo/dashboard/ and every existing command module.

ACCEPTANCE
Tests that exist and pass: load_roots returns an empty list when web.yml is missing; save then load round-trips; ~ is expanded and duplicates removed; a corrupt web.yml loads as an empty list without raising; config.yml in the same folder is byte-identical after a save; the file is replaced atomically (no temporary file left behind).

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message. Add one CHANGELOG.md entry under [Unreleased] ending "(Fixes #<n>)".
