New files this task will create: `snodo/web/delivery.py`, `tests/web/test_delivery.py`.

INTENT
A plan whose tasks all completed is not necessarily in the main branch yet: its integration branch may still be waiting to be merged. Add snodo/web/delivery.py that answers "did this plan reach main?" from git, so a dashboard can show it. This is a display answer computed from git every time; it is not stored anywhere and adds no state to snodo.

THE CHAIN
1. snodo/web/__init__.py and tests/web/__init__.py exist as empty files. If they are missing in your tree, create them with no content at all (sibling work creates the same empty files and they merge cleanly).
2. snodo/web/delivery.py provides plan_delivery(project_path, plan_name) returning exactly one of the strings "in_main", "not_in_main" or "no_branch".
3. The plan's integration branch name is read from the integration.branch field in .snodo/plans/<plan>/status.json. "no_branch" is returned when that field is absent, or when the branch exists neither as a local branch nor as origin/<branch>.
4. "in_main" is returned when the branch tip is an ancestor of the commit the project's repository currently has checked out; otherwise "not_in_main". The local branch is used when it exists, and origin/<branch> otherwise.
5. snodo/web/delivery.py provides plans_delivery(project_path) returning a dict from plan name to that string for every plan folder under .snodo/plans/, opening the repository once.
6. tests/web/test_delivery.py exercises these with temporary git repositories.

CONSTRAINTS
Pure reads: never fetch, push, merge or write, because the dashboard must be safe to leave running and the repository may have no network. Use the same repository helper the rest of snodo uses (snodo.tools.git open_repo) and close it. A missing or unreadable status.json, or a project that is not a git repository, gives "no_branch" for that plan and never raises. Out of scope: snodo/cli/commands/plan_delivery.py, which delivers branches and is unrelated.

ACCEPTANCE
Tests that exist and pass: a branch merged into the checked-out branch is "in_main"; a branch with extra commits is "not_in_main"; a plan whose status.json has no integration.branch is "no_branch"; a branch that exists only as origin/<branch> is judged from that ref; a plan with no status.json is "no_branch"; plans_delivery returns an entry for each plan folder; nothing in the repository changes (HEAD and refs identical before and after).
