New files this task will create: `snodo/web/gates.py`, `tests/web/test_gates.py`.

INTENT
Gates are the validators that send a task back to be rewritten. A dashboard should show, per project, which tasks a gate sent back, which validator did it, and whether the task later landed. Add snodo/web/gates.py that reads this from what snodo already records. A value the records cannot support is None; nothing is estimated.

What exists: a task a gate stops is retried, and follow-up tasks named like <task>_fix_1 appear in the project's task records; .snodo/plans/<plan>/status.json holds task statuses; the job records under .snodo/jobs/ and the task and audit records hold the attempts and the validator that stopped each one. Where the validator that stopped an attempt is recorded is for you to discover; describe in the module docstring where each value comes from. The read-only readers in snodo/dashboard/providers.py can be reused as they are.

THE CHAIN
1. snodo/web/__init__.py and tests/web/__init__.py exist as empty files. If they are missing in your tree, create them with no content at all (sibling work creates the same empty files and they merge cleanly).
2. snodo/web/gates.py provides gate_records(project_path, window_days, now) returning a list with one record per task a gate sent back at least once inside the window. A record has task, plan, validator (the validator id that stopped it, or None), outcome and when (ISO timestamp of the last send-back).
3. outcome is the display label "landed_after_retry" when the task's status is completed, and "not_landed" otherwise. These labels are computed for display and are not snodo states.
4. snodo/web/gates.py provides summarize_gates(records) returning sent_back (number of records), landed_after_retry (number with that outcome) and by_validator (list of {validator, count} sorted by count descending, with None counted under "unknown").
5. tests/web/test_gates.py builds small temporary .snodo/ folders and checks the records and the summary.

CONSTRAINTS
Read-only. Do not modify snodo/dashboard/ or any recording code, and add no state, status value or field to snodo's records. A task that never needed a retry has no record. A missing .snodo/ returns an empty list.

ACCEPTANCE
Tests that exist and pass: a task retried once and then completed gives one record with outcome landed_after_retry; a retried task still blocked gives not_landed; a task never sent back gives no record; records outside the window are dropped; summarize_gates counts by validator and puts a missing validator under "unknown"; an empty project returns no records and a summary of zeros.
