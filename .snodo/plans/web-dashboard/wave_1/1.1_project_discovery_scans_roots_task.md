New files this task will create: `snodo/web/projects.py`, `tests/web/test_projects.py`.

INTENT
A local web dashboard needs to know which snodo projects exist on the machine. Add a small module, snodo/web/projects.py, that finds them. Nothing exists for this today: the terminal dashboard (snodo/dashboard/) shows one project at a time and must not be touched.

THE CHAIN
1. snodo/web/__init__.py and tests/web/__init__.py exist as empty files. If they are missing in your tree, create them with no content at all (sibling work creates the same empty files and they merge cleanly).
2. snodo/web/projects.py defines a Project record with a name and a path, where name is the folder name and path is the resolved absolute path.
3. snodo/web/projects.py provides discover_projects(roots, max_depth=3) that returns the Projects found under the given root folders: a folder counts when it contains a .snodo/ directory. Results are sorted by name and de-duplicated by resolved path. A found project is not searched further for nested projects. Hidden folders, node_modules, .venv, build and dist are skipped. A root that does not exist or cannot be read is skipped without failing the call.
4. snodo/web/projects.py provides resolve_projects(roots, cwd) that returns discover_projects(roots) when roots is non-empty, and otherwise only the project that contains cwd (found with the existing resolve_project_root in snodo.infrastructure.paths), or an empty list when cwd is not inside a snodo project.
5. tests/web/test_projects.py covers the behaviour below using temporary directories.

CONSTRAINTS
Read-only: the module only lists directories and never writes. Do not change anything under snodo/dashboard/ or snodo/cli/commands/serve_cmd.py. The depth limit exists so that pointing a root at a large folder stays fast.

ACCEPTANCE
Tests that exist and pass: a root with two snodo projects returns both sorted by name; a folder without .snodo/ is not returned; a project nested inside another project is not returned; a hidden folder and a node_modules folder are skipped; a missing root returns an empty list without raising; the same project reached through two roots appears once; resolve_projects with no roots returns the project containing cwd, and an empty list outside any project.
