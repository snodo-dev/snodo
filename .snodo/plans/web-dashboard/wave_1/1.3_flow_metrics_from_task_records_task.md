New files this task will create: `snodo/web/flow.py`, `tests/web/test_flow.py`.

INTENT
A dashboard should say how work is landing in a project: how many tasks landed, how long a typical one took, how many landed on the first try, and how many are started but not landed. Add snodo/web/flow.py that computes these from what snodo already records in a project's .snodo/ folder. A figure the records cannot support must come back as None, never a guess: the dashboard shows only what applies.

What exists: .snodo/plans/<plan>/status.json holds each task's status (pending, in_progress, completed, blocked and so on); .snodo/jobs/<job>/state.json holds a job's status and created_at, started_at and completed_at; task.json beside it names the task. snodo/dashboard/providers.py has read-only readers (DashboardDataProvider get_tasks, get_jobs, get_plans) that can be reused as they are. Where attempt counts and task completion times are recorded is for you to discover in the existing task records and audit data; describe in the module docstring where each number comes from.

THE CHAIN
1. snodo/web/__init__.py and tests/web/__init__.py exist as empty files. If they are missing in your tree, create them with no content at all (sibling work creates the same empty files and they merge cleanly).
2. snodo/web/flow.py provides flow_metrics(project_path, window_days, now) returning a dict with: landed (count of tasks that completed inside the window), landed_by_day (list of {date, landed} for each day of the window, zero days included), median_flow_seconds (median seconds from a task's start to landing, or None), first_try_rate (share of landed tasks that landed with no gate sending them back, between 0 and 1, or None) and flow_load (tasks started and not yet landed).
3. A task counts as landed when its status is completed; that is the only definition of landing used.
4. tests/web/test_flow.py builds small temporary .snodo/ folders and checks each figure.

CONSTRAINTS
Read-only. Do not modify snodo/dashboard/ or any recording code, and add no state, status value or field to snodo's records. Tasks with no recorded timing are left out of the median instead of being counted as zero. An empty or missing .snodo/ gives landed 0 and None for the figures that need data.

ACCEPTANCE
Tests that exist and pass: completed tasks inside the window are counted and ones outside it are not; landed_by_day has one entry per day including zero days; the median is taken only over tasks that have timing; first_try_rate is None when no landed task has attempt information; flow_load counts in_progress tasks; a project with no .snodo/ returns landed 0 and Nones without raising.
