Before starting, open a GitHub issue on snodo-dev/snodo titled "Missing CHANGELOG entry blocks a feature at task gate; warn at gate, enforce at release". Put "Fixes #<n>" in the commit message, and add a CHANGELOG.md entry under ## [Unreleased].

INTENT
Today `make gate` runs a changelog check that fails when an issue-closing commit (`Fixes #n`) is not mentioned in `CHANGELOG.md`. A correct, fully tested feature is then blocked by a missing changelog line. Evidence: in plan `orchestrators-default-to-plans`, task 1.4 passed 5,094 tests and was blocked only by "FAIL: commit ecd5c1ef64a9 closes issue #725 but CHANGELOG.md does not mention #725".

The owner's position: a missing changelog entry should not hold up a feature at task-gate time, and the fix must be sustainable.

When this is done:
- In the task gate, a missing entry is a clearly visible warning that names the commit and issue. The gate still passes.
- The release path (`make release`) fails on any issue-closing commit since the last tag that has no CHANGELOG entry. A release is where the changelog must be complete.

CHANGELOG.md stays one file, merged with merge=union, per ADR 037 in docs/decisions. Do not introduce fragment files.

THE CHAIN
1. The changelog check has a gate mode that warns and a release mode that fails. Find it from `make gate` and `make release`.
2. `make gate` uses gate mode; `make release` uses release mode.
3. Tests cover both: the same missing-entry input warns in gate mode and fails in release mode, and a present entry passes both.
4. Contributor docs describe the behaviour: the gate warns, release enforces.

CONSTRAINTS
- Do not weaken any other gate check.
- ADR 037 stands.
- Snodo's state machine is closed. Add no status, halt type, severity, audit event or field.

ACCEPTANCE
- The tests in link 3 exist and pass.
- The CHANGELOG entry is present.
- `make gate` passes.
