Before starting, work the existing GitHub issue #787 on snodo-dev/snodo ("Gate: say when it is waiting for a slot, and fail fast on a hung test"). Put "Fixes #787" in the commit message and add a CHANGELOG.md entry under ## [Unreleased]. Do not open a new issue.

INTENT
make gate hands the suite to a shared gate host. Before running it takes one of a small number of flock slots, and that wait is silent and unbounded: an operator watching make gate cannot tell whether the suite is running or queued behind someone else's run. When one test hangs, the run then burns its whole window printing nothing and never names the hung test.

OUTCOME
A remote gate run narrates its phases - waiting for a slot (including how long it has waited), acquiring one, syncing dependencies, starting the suite - and a hung individual test fails with a traceback instead of consuming the entire window.

CONSTRAINTS
- scripts/gate_remote.sh and the Makefile gate target are the current implementation; slot acquisition is a flock -n retry loop with no output and no bound.
- Narration must be visible to the operator running make gate and must not corrupt the machine-parsed output the gate already produces.
- The per-test bound must fit inside the validator's own silence/timeout window so a hung test is reported before the whole run is abandoned.
- A prior attempt exists on the local branch matching *1.2_gate_script_reports_waits*. It now conflicts with main in scripts/gate_remote.sh and tests/scripts/test_gate_remote.py, so implement against current main instead of merging it.
- tests/scripts/test_gate_remote.py exists and must keep passing; cover the new narration and the per-test bound there. Tests must never trigger a real remote gate run.
- Do not run make gate in your session.

ACCEPTANCE
- Waiting for a slot prints progress, including elapsed waiting, and eventually gives up with a clear error rather than hanging forever.
- Starting dependency sync and starting the suite each print a line.
- A hung test is cut short with a traceback naming it, while the rest of the run still reports normally.
