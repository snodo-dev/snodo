Before starting, work the existing GitHub issue #786 on snodo-dev/snodo ("Quality gate timeout records no output"). Put "Fixes #786" in the commit message and add a CHANGELOG.md entry under ## [Unreleased]. Do not open a new issue.

INTENT
When the quality validator runs a test command and that command hits the validator's timeout, the run record says only "Timeout after 600.0s". The operator cannot tell where the time went, so a gate timeout looks the same whether the suite was progressing or one test hung. The partial output the validator had already collected must survive into the record.

OUTCOME
A timed-out verification records the tail of whatever the command printed before the timeout, followed by the timeout note, and still classifies a timeout as an operational error rather than a test failure. Nothing the command had already spawned is left running after the timeout.

CONSTRAINTS
- packages/snodo-engine/src/snodo/validators/quality.py holds the timeout path; today its timeout branch records only the timeout note.
- Keep the existing error taxonomy intact: command-not-found, not-executable, timeout and exit-code failures must keep their current blocker/operational-error classification, and the sanitized-environment behaviour for validator subprocesses must not regress. tests/validators/test_quality.py already pins these; every one of those tests must still pass.
- A prior attempt exists on the local branch matching *1.1_timeout_keeps_gate_output* (inspect it with git branch --list and git show). It merges cleanly onto current main but breaks six tests in tests/validators/test_quality.py. Use it as prior art for the output-capture shape, or ignore it, but do not simply merge it.
- Do not run make gate in your session: it is a remote SSH gate and the post-execute gate already runs the full suite. Run the affected test files only.

ACCEPTANCE
- A timeout while a command is printing produces a record whose output contains the captured partial output as well as the timeout note.
- The whole process tree of a timed-out command is terminated.
- Focused new coverage for both behaviours, and the entire pre-existing tests/validators/test_quality.py suite passing.
