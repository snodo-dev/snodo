# 1.1 — the tunnel path wrapper is installed by one named function, so a test can run the real code

GitHub issue #1027 already exists for this work. Do not open another; put "Fixes #1027" in the commit message. Do not edit the CHANGELOG.

## INTENT

For a service-token tunnel, `_run_server` in `snodo/cli/commands/serve_cmd.py` replaces the MCP server's `streamable_http_app` and `sse_app` factories with wrappers that put the tunnel path router (`TunnelMCPPaths`, `snodo/cli/commands/serve_tunnel_asgi.py`) in front of the real app, forwarding every argument it is given. That wiring is written inline inside `_run_server`, so a test cannot exercise it without running the whole serve flow, and the next task needs to.

Move that wiring, unchanged in behaviour, into a small named function next to `TunnelMCPPaths` and call it from `_run_server`. Same arguments forwarded, same two factories wrapped, same Access verifier, OAuth flag and access path handed to the router. Nothing else in `_run_server` changes.

## Acceptance

- `_run_server` calls the new function; the inline wiring is gone; behaviour is identical.
- The existing serve and tunnel tests stay green without edits to their assertions; the linter is clean.
- `serve_cmd.py` gets shorter or stays the same length; no length baseline is raised.

## Constraints

- No new halt types, severities or statuses. No new dependency. No test is added by this task.

Do not run the whole suite yourself: the engine runs it right after you finish, and a multi-minute silent command has been dropping the coder connection.
