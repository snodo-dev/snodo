Title: Reshape messages when a strict OpenAI-compatible server rejects them

Start by opening a GitHub issue in snodo-dev/snodo describing this change (pass the body with --body-file), or reuse an open one that already covers it. The commit message must include "Fixes #<issue number>". Do not edit CHANGELOG.md: this wave's tasks run in parallel, and a later task records them in one entry that cites your issue.

INTENT
Strict OpenAI-compatible servers accept the first turn of a tool loop and reject the second, because snodo's follow-up messages use shapes they don't allow. Snodo should notice that rejection and resend the same conversation in the plain shape, so multi-turn tool use works on those servers.

THE CHAIN
- With Cloudflare Workers AI "@cf/openai/gpt-oss-120b" as the validator, the security and adr validators completed turn 1 (a tool call) and failed on turn 2 with: "CloudflareException - AiError: Bad input: Error: oneOf at '/' not met, 0 matches: required properties at '/' are 'prompt', Type mismatch of '/messages/0/content', 'array' not in 'string', required properties at '/messages/1' are 'role,content' … code 5006". So the server wants message content as a string, and wants a content field on the assistant message that carries the tool calls.
- The single-turn `snodo models --check` passed for the same model, which is why this was not caught.

CONSTRAINTS
- Add a small helper next to the shared provider-rejection helper in the foundation infrastructure package, as its own module. It recognises this class of rejection (message content or required-field shape) and returns the same conversation reshaped: text-only content parts joined into one string, and an empty string where an assistant tool-call message has no content. Content that is not text (images, for example) is left untouched.
- Apply it only after such a rejection, at most once per caller run, and remember per model for the life of the process, matching how parameter adaptation is remembered.
- Do not wire call sites here; a later wave does that.
- Unit tests cover the error text above, a conversation with array content and a content-less tool-call message, a conversation with an image part left as is, and the per-model memory.
- Run `uv run --extra dev ruff check` on changed files and only the tests you add. Tests must not touch the real home folder. Do not run the snodo CLI, make gate or make release, and do not touch .snodo/.

ACCEPTANCE
- Given the error above, the helper reshapes a typical second-turn validator conversation so every content field is a string.
- A rejection unrelated to message shape is not treated as one.
