Title: models --check exercises a two-turn tool exchange

INTENT
`snodo models --check` is how a user confirms a model will work before spending a run, and it claims to exercise the request shape each role really uses. Validators and recon agents run tool loops: they call a tool, get its result back, and continue. The check only sends one turn, so models that fail on the second turn pass the check and then halt every task.

THE CHAIN
- "cloudflare/@cf/openai/gpt-oss-120b" passed `snodo models --check` as validator, then every task in a plan halted with validator_error because the security and adr validators failed on their second turn (code 5006, message shape rejected).
- The check's canary call lives in the CLI commands package (models_check.py) and builds one request per role.

CONSTRAINTS
- For roles that use tools across turns (validator, recon, and the LiteLLM coder), send a second turn after the first: the assistant's tool call followed by a short tool result, in the same message shape the real loop sends. Report the role as failed if either turn fails, naming which turn.
- If the first turn returns no tool call, the second turn is skipped and the result says so instead of failing.
- Keep the classifier check single-turn.
- Keep it cheap: tiny prompts, small token limits.
- The check is a real billed call already; do not add any other calls.
- Every `snodo …` command and flag mentioned in docs must exist; update the docs line that describes what the check does.
- Run `uv run --extra dev ruff check` on changed files and only the model-check tests plus any you add. Tests must not touch the real home folder. Do not run the snodo CLI, make gate or make release, and do not touch .snodo/.

ACCEPTANCE
- A fake provider that accepts turn 1 and rejects turn 2 makes the validator line FAILED with "turn 2" in the reason.
- A fake provider that accepts both turns reports OK.
