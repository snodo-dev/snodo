Title: Apply a provider-requested parameter value, such as reasoning_effort "none"

Start by opening a GitHub issue in snodo-dev/snodo describing this change (pass the body with --body-file), or reuse an open one that already covers it. The commit message must include "Fixes #<issue number>". Do not edit CHANGELOG.md: this wave's tasks run in parallel, and a later task records them in one entry that cites your issue.

INTENT
Some models refuse a request unless a parameter is set to a specific value, and say so in the error. Snodo already adapts when a provider rejects a parameter by removing it once; it should also adapt when a provider asks for a value, so models like the gpt-6 family work through any OpenAI-compatible gateway without user configuration.

THE CHAIN
- Every validator, recon agent and classifier call to gpt-6-sol, gpt-6-luna and gpt-5.6-terra (through a Cloudflare AI Gateway) fails with: "BadRequestError: OpenAIException - Function tools with reasoning_effort are not supported for gpt-6-sol in /v1/chat/completions. To use function tools, use /v1/responses or set reasoning_effort to 'none'." Snodo never sends reasoning_effort, and the model's own default is not "none", so every tool-using call fails.
- The shared helper for provider-rejected parameters lives in the foundation infrastructure package (llm_parameter_errors.py). It recognises rejection wording and removes a named parameter at most once per caller run. The validator loop, the coder parameter fallback, the classifier path and the model check already use it.

CONSTRAINTS
- Extend that shared helper so a rejection that names a parameter and the value to set it to leads to one retry with that value, at most once per parameter per caller run, like removal.
- Error text comes from outside snodo, so only parameters on a small explicit allowlist can be set this way; reasoning_effort is the first entry. Anything else is left to the existing behaviour.
- Remember a successful adaptation per model for the life of the process, so later calls to the same model send the value up front instead of failing first. Keep that memory in the shared module.
- Keep existing callers' behaviour and signatures working; callers wired later in this plan will pick the new behaviour up.
- Unit tests cover: the exact error text above; a phrasing with double quotes; a non-allowlisted parameter being ignored; at-most-once; and the per-model memory.
- Run `uv run --extra dev ruff check` on changed files and only the tests for this module plus any you add. Tests must not touch the real home folder. Do not run the snodo CLI, make gate or make release, and do not touch .snodo/.

ACCEPTANCE
- Given the error above, the helper produces a retry request with reasoning_effort "none", and the next request for the same model includes it from the start.
- A non-allowlisted parameter named in an error is never set.
- Existing tests for parameter removal still pass.
