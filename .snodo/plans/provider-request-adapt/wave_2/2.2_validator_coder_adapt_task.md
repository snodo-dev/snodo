Title: Validator loop, LiteLLM coder and classifier use the full provider adaptation

Start by opening a GitHub issue in snodo-dev/snodo describing this change (pass the body with --body-file), or reuse an open one that already covers it. The commit message must include "Fixes #<issue number>". Do not edit CHANGELOG.md: a parallel task records the whole change in one entry.

INTENT
The validator tool loop, the LiteLLM coder and the classifier already retry once without a rejected parameter. They should also get the two adaptations added in the previous wave: setting an allowlisted provider-requested value (reasoning_effort "none") and reshaping messages after a shape rejection, both remembered per model. A model that needs either should work in every role.

THE CHAIN
- With "cloudflare/@cf/openai/gpt-oss-120b" as validator, every task in plan provider-guides halted with validator_error: the security and adr validators failed on turn 2 with code 5006 (array content not allowed, content missing on the tool-call message).
- With gpt-6-sol as validator, every validator call failed with "set reasoning_effort to 'none'".
- The validator loop lives in the engine package's validators (llm_validator.py and its provider-error helpers), the coder fallback in the engine package's coders (parameter_fallback.py), and the classifier in the foundation infrastructure package. All three call the shared removal helper today.

CONSTRAINTS
- Wire all three through the shared adaptation, applying it before any failover or fail-closed decision, and only on provider rejections (never on transient errors).
- Do not change validator verdict semantics, severities or the closed set of halt outcomes.
- Respect file-length limits; put shared logic in the shared modules.
- Tests use fake completions: one that demands reasoning_effort "none", one that rejects array content on turn 2; the validator returns a real verdict, the coder continues, the classifier returns its result.
- Run `uv run --extra dev ruff check` on changed files and only the validator, coder-fallback and classifier tests plus any you add. Tests must not touch the real home folder. Do not run the snodo CLI, make gate or make release, and do not touch .snodo/.

ACCEPTANCE
- A validator against a fake provider that rejects array content on turn 2 produces a verdict, not validator_error.
- A validator, the coder and the classifier against a fake provider that demands reasoning_effort "none" all succeed.
