Title: Recon agents adapt to provider requests

Start by opening a GitHub issue in snodo-dev/snodo describing this change (pass the body with --body-file), or reuse an open one that already covers it. The commit message must include "Fixes #<issue number>". Add one CHANGELOG.md entry under [Unreleased] for the whole provider-adaptation change, citing this issue and the issues opened by the earlier tasks in plan provider-request-adapt (search open and closed issues for the parameter-value, message-shape and two-turn check work).

INTENT
Recon is the one tool-using LLM path that does not go through the shared provider-adaptation helpers, so a recon agent on a model that needs reasoning_effort "none" or plain message shapes fails outright while the same model works elsewhere.

THE CHAIN
- `snodo recon --agents 3` with gpt-6-sol, gpt-6-luna and gpt-5.6-terra failed on every agent with "Function tools with reasoning_effort are not supported … set reasoning_effort to 'none'".
- The previous wave added, in the foundation infrastructure package, a helper that applies an allowlisted provider-requested parameter value with per-model memory, and a helper that reshapes messages after a shape rejection. Recon builds and sends its own completion requests in the recon package and uses neither.

CONSTRAINTS
- Route recon's completion calls through the shared adaptation, so they get parameter removal, parameter values and message reshaping the same way the validator loop does.
- The recon module is over the file-length ratchet; this change must not make it longer. Put any new logic in the shared modules or a small new recon helper module.
- Keep recon's existing failover between configured models working; adaptation happens before failing over.
- Tests use fake completions: one that demands reasoning_effort "none" and one that rejects array content on turn 2; both end with a recon answer.
- Run `uv run --extra dev ruff check` on changed files and only the recon tests plus any you add. Tests must not touch the real home folder. Do not run the snodo CLI, make gate or make release, and do not touch .snodo/.

ACCEPTANCE
- A recon agent against a fake provider that demands reasoning_effort "none" returns an answer.
- A recon agent against a fake provider that rejects array content on turn 2 returns an answer.
- The recon module is not longer than before.
