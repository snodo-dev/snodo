# Document how to use the TypeSafe `decide` tool in a protocol

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
A snodo user can learn from one docs page what the TypeSafe plugin gives a validator and how to turn it on. The page covers installing the package, setting the API key, and opting a validator into `decide` in protocol config. It includes a worked acceptance-check example, where the validator asks one yes/no question per ACCEPTANCE bullet over the diff and cites the probabilities in its verdict, plus cost and limits.

## THE CHAIN
- A sibling task builds the plugin package: a `decide` tool registered under `snodo.validator_tools`, with options `model`, `api_key_env` (default `TYPESAFE_API_KEY`), `base_url`, `timeout_seconds` and `max_input_chars`.
- Validators opt into plugin tools through the per-validator `tools` field (#837). The validator-tools section of `docs/extending.md` (#839) describes the mechanism.
- Jev is a decision model: it returns typed answers with probabilities and writes no text. The LLM validator stays in charge of the verdict and its justification.
- Pricing is $0.042 per million input tokens, and output is free. The context length is not published, which is why the input cap exists.
