INTENT
Listing the serve registry only reads it. The file is rewritten only when pruning actually removed something, so a relay that checks the registry several times a second does not rewrite the file and take its lock for write on every check, and concurrent serve processes recording themselves are not slowed by it.

GitHub issue #1002 already exists for this work. Do not open another; put "Fixes #1002" in the commit message. No CHANGELOG entry (the plan's entry already covers it).

EVIDENCE
Reading the registry module on the branch: listing takes the exclusive lock, filters out entries whose process is gone, and always writes the filtered list back, even when nothing was removed. The machine relay now calls the listing about four times per second while idle, so the file is rewritten and the lock taken that often for no change.

CONTRACT
- When every entry is live, listing returns them without writing the file, and the file's modification is untouched.
- When at least one entry is dead or belongs to a reused process id, listing returns the live ones and prunes the file as it does today.
- Recording and removing behave exactly as before, including replacement of the same project and mode and leaving a newer replacement alone on removal.
- A missing or corrupt file still lists as empty.

CONSTRAINTS
- Existing registry tests keep passing without edits to their expectations; new tests use only public functions and an isolated temporary home.
- Do not touch the relay, serve, the CLI or any other module. No new dependency. No new status, severity, halt type or audit event.
- Targeted tests only (the registry tests and the serve tests that record into it). Do not run the snodo CLI, make gate or make release. Do not touch .snodo/.

ACCEPTANCE
- A test that lists repeatedly with only live entries and shows the file was not rewritten (for example its modification time and contents are unchanged); a test that a dead entry is dropped from the result and from the file.
- Existing tests pass and lint is clean. Run the targeted tests and report their output.
