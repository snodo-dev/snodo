INTENT
Every request the cloud sends reaches the local serve exactly once, with its full body, and every outcome (reply, local failure, cancel, timeout) ends cleanly with the relay's bookkeeping released. This ticket is about the request side of the machine relay only; connect, lease, hello and reconnect were handled in the previous wave and must not change. Read the relay as it now stands on the branch before editing.

GitHub issue #1004 already exists for this work. Do not open another; put "Fixes #1004" in the commit message. No CHANGELOG entry (the plan's entry already covers it).

EVIDENCE
Reading the delivered relay:
- A request is dispatched when its req frame arrives if no content-length header says otherwise, and dispatched again when the body's last chunk arrives. The contract below says a body always arrives as chunk frames after the req (an empty body as one empty last chunk), so every body-less request such as a GET would be sent to the local serve twice, and a POST without a content-length header would be dispatched before its body arrived.
- Only some local failures become err frames (connect failure and timeouts); a read error, a protocol error or any other failure inside a request escapes its task silently and the cloud never hears back.
- A request cancelled by the cloud, or whose task ends in any other way, can leave its id in the relay's cancelled set, request table or task table for the life of the connection.
- Only a streamed reply and two unrelated behaviors are covered by tests.

CONTRACT (agreed with snodo-cloud, v1.1; the cloud has been asked to confirm the framing below and the relay is built on it)
- A req frame is followed by the body as chunk frames with seq starting at 0 and the last one marked last; an empty body is one empty last chunk. A request is dispatched once, when its last chunk has arrived, using the existing frame codec and reassembler. Chunks for an id that has no pending req, out-of-order chunks and an oversize body are rejected with an err frame for that id and do not disturb other requests.
- Forward to http://127.0.0.1:<port><path> of the endpoint whose registry hostname matches, with the given method, headers and body. Stream the reply as res then ordered chunk frames of at most 192 KiB, the last marked last, forwarding bytes as they arrive (a text/event-stream reply must not wait for its end).
- Any failure to reach or read the local serve (refused, timed out, reset, protocol error, unknown hostname) becomes one err frame with a short code and message that contain no headers, body or credentials. After a failure that happens mid-reply the stream simply ends with an err frame.
- While a local request is in flight a keep frame for its id goes out every 30 seconds. On cancel the local request is aborted and nothing more is sent for that id.
- At most 8 requests are in flight; a ninth waits for a free slot rather than failing.
- When a request ends for any reason, all of its state is released.

CONSTRAINTS
- Time, sleeping, the socket, the registry and the local HTTP client stay injectable so tests run without waiting or network.
- Never log or store request bodies, authorization headers or leases; log lines carry ids, statuses and counts only.
- Do not change connect, lease, hello, reconnect or backoff behavior, serve, the CLI, tunnel provisioning or the MCP transport.
- No new status, severity, halt type or audit event. No new third-party dependency. Respect the layer rules and run the import-layer check.
- Targeted tests only, plus the whole tests/infrastructure directory once. Do not run the snodo CLI, make gate or make release. Do not touch .snodo/.

ACCEPTANCE
- New tests in their own file (not the existing relay test files) with a fake cloud socket and a fake local server cover: a GET with an empty last chunk dispatched exactly once; a POST whose body arrives in several chunks dispatched once, after the last; a reply over 192 KiB and a text/event-stream reply with several events arriving as ordered chunks in order; err for an unknown hostname, a refused port, a timeout and a read error; chunks for an unknown id and out-of-order chunks rejected without affecting other requests; keep frames every 30 seconds during a slow request; cancel aborting the local request and releasing its state; the ninth concurrent request waiting for a slot; no state left behind after any ending.
- No credential, header or body appears in any captured log line in those tests.
- Existing tests pass and lint is clean. Run the targeted tests and report their output.
