INTENT
The machine relay connects, authenticates and reconnects correctly when it is wired to the real lease code, and its connection behavior is proven by tests with a fake cloud socket. This ticket is about the connection side only (lease, connect, hello, reconnect); how individual requests are forwarded is handled by a later ticket and must not change here.

GitHub issue #1004 already exists for this work. Do not open another; put "Fixes #1004" in the commit message. No CHANGELOG entry (the plan's entry already covers it).

EVIDENCE
Reading the delivered relay against its default wiring:
- The default lease fetch is the synchronous mint helper from the cloud lease module, but the relay awaits it, so the first connect would fail with a type error. The helper also performs a blocking HTTP call, which must not run on the event loop.
- The helper returns nothing when no credential is configured or the mint fails; the relay then reads the token from that missing lease and crashes with an attribute error instead of reporting that the cloud login is missing.
- Changes to the serve registry are only noticed when a frame happens to arrive, so a serve started or stopped on an idle connection is announced late or never.
- Only three behaviors are tested today (a streamed reply, machine id persistence, the socket URL).

CONTRACT (agreed with snodo-cloud, 2026-10-22)
- The lease is fetched without blocking the event loop, fresh on every connect and reconnect. When no lease can be obtained the relay reports a plain message (sign in with the cloud login; no token or credential in it) and retries with the reconnect backoff instead of crashing.
- On a 401 at connect the relay fetches one fresh lease and retries once. 403 (machine id differs from the lease) and 426 (not an upgrade) are reported plainly and are not retried in a loop. A server close with the "replaced by a newer runner connection" code (4001) means another relay for this machine took over: the relay stops reconnecting and says so.
- hello is sent first on every connection, with the endpoints currently in the serve registry (hostname and auth ["oauth"] for entries that have a hostname and a port). The registry is re-read on a short interval while the connection is idle, and hello is sent again whenever the endpoint list changed, whether or not any frame arrived.
- An open socket is never closed by the client because its lease expired.
- Reconnect uses jittered exponential backoff from 1 second to 60 seconds; the delay resets after a connection that stayed up for a long time (at least 60 seconds), and keeps growing after short-lived ones.
- Protocol pings are the only keepalive for the socket itself.

CONSTRAINTS
- Time, sleeping, the socket, the registry and the lease fetch stay injectable so tests run without real waiting or network.
- Never log or store leases, authorization headers or request bodies; log lines carry statuses and counts only.
- Do not change how requests are forwarded, chunked, cancelled or limited; do not touch serve, the CLI, tunnel provisioning or the MCP transport.
- No new status, severity, halt type or audit event. No new third-party dependency. Respect the layer rules and run the import-layer check.
- Targeted tests only, plus the tests that cover the lease exchange and the whole tests/infrastructure directory once. Do not run the snodo CLI, make gate or make release. Do not touch .snodo/.

ACCEPTANCE
- New tests in their own file (not the existing relay test file) with a fake cloud socket cover: hello content and its resend when the registry changes while idle; a fresh lease on every reconnect; no lease obtained gives a plain message and a retry; 401 then one retry with a fresh lease; 403 and 426 not retried in a loop; 4001 stopping the reconnects; backoff growth, the cap and the reset after a long-lived connection; the socket not closed when the lease expires.
- No credential, header or lease appears in any captured log line in those tests.
- Existing tests pass and lint is clean. Run the targeted tests and report their output.
