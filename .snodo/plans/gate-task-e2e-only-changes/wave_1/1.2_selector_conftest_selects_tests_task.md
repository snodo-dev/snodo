New files this task will create: none.

INTENT
When a conftest.py below tests changes, the affected-test selector picks the tests that conftest governs, instead of handing the conftest file itself to pytest as if it were a test.

Symptom and evidence: a ticket that changed only tests/e2e/conftest.py was gated with "Gate: reduced test set: tests/e2e/conftest.py; this gate does not decide." and pytest collected nothing from it. scripts/select_affected_tests.py only lists tests/conftest.py in its shared-files set, which sends a change to it to the full suite, so a nested conftest.py is treated like any other changed test path and is passed to pytest verbatim. A nested conftest governs every test in its directory tree, so the right selection is those tests.

What it should do: make the selector treat a changed conftest.py anywhere under tests as selecting the tests in that conftest's directory and below, keeping the existing behaviour for tests/conftest.py (full suite) and for every other kind of change. Extend the existing selector tests to cover a nested conftest, a top-level conftest, and a changed test file as before.

CONSTRAINTS
Files that may change: scripts/select_affected_tests.py, its existing test file under tests, and CHANGELOG.md (one entry under [Unreleased] ending with the issue reference Fixes #<n>). Do not change scripts/gate_remote.sh. No new state, status, severity or halt type.

ACCEPTANCE
Changing tests/e2e/conftest.py selects the tests under tests/e2e, changing tests/conftest.py still selects the full suite, and other selections are unchanged. make gate-task is green.

PROCESS
Open a GitHub issue first and put Fixes #<n> in the commit message. This is a non-interactive run: open the issue directly with gh issue create, without asking for confirmation of title or body. Commit your change before running make gate-task, because it tests HEAD and needs a clean tree, and run it in the foreground and wait for it to finish before ending your turn.
