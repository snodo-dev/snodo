New files this task will create: none.

INTENT
make gate-task completes its remaining checks, and exits zero, when its reduced test selection collects no tests, so a ticket that only changes end-to-end tests can pass the per-task gate. The full gate and the release gate keep failing when nothing is collected.

Symptom and evidence: two tickets in plan e2e-queue-journey-budget changed only files under tests/e2e (one test file, one conftest) and were blocked by the quality validator with "Gate: reduced test set: tests/e2e/conftest.py; this gate does not decide. ... no tests ran in 3.42s ... make: *** [gate-task] Error 5". pyproject.toml sets addopts to -m 'not e2e', so when the affected-test selection names only e2e tests pytest deselects everything and exits 5, and scripts/gate_remote.sh returns that as a failure. The gate-task output itself says the reduced set does not decide, and the e2e tests run in gate-ci (marker filter cleared), which is the gate that decides at release. A coder that tried to finish such a ticket ended its turn with the gate failing, and the next ticket of this kind will do the same.

What it should do: in the gate-task path of scripts/gate_remote.sh, treat pytest's exit code 5 (no tests collected) for a reduced selection as nothing to run, say so in the existing "Gate:" progress lines, and carry on to ruff, the import contracts and the ratchets and changelog checks that follow. Any other pytest failure must still fail the gate, and the gate and gate-ci targets must keep treating exit 5 as a failure. If the repository has tests for gate_remote.sh, extend them to pin both behaviours; if it has none, say so in the commit and pin it in whatever way the existing scripts tests make clean.

CONSTRAINTS
Files that may change: scripts/gate_remote.sh, an existing or new test of it under tests/scripts, and CHANGELOG.md (one entry under [Unreleased] ending with the issue reference Fixes #<n>). Do not change the selector or pyproject.toml. No new state, status, severity or halt type.

ACCEPTANCE
A gate-task run whose selection collects no tests finishes the rest of the gate and exits zero; a failing selected test still exits non-zero; gate and gate-ci still fail on exit 5. make gate-task is green.

PROCESS
Open a GitHub issue first and put Fixes #<n> in the commit message. This is a non-interactive run: open the issue directly with gh issue create, without asking for confirmation of title or body. Commit your change before running make gate-task, because it tests HEAD and needs a clean tree, and run it in the foreground and wait for it to finish before ending your turn.
