New files this task will create: none.

INTENT
A ticket that changes only end-to-end tests passes the per-task gate by taking the gate's existing "no tests selected" path, instead of handing pytest tests that its default marker filter then deselects.

Symptom and evidence: two tickets in plan e2e-queue-journey-budget changed only files under tests/e2e (one test file, one conftest) and were blocked by the quality validator with "Gate: reduced test set: tests/e2e/conftest.py; this gate does not decide. ... no tests ran in 3.42s ... make: *** [gate-task] Error 5". pyproject.toml sets addopts to -m 'not e2e', so when the affected-test selection names only e2e tests pytest deselects everything and exits 5, which scripts/gate_remote.sh returns as a failure. The e2e tests run in gate-ci at release, with the marker filter cleared, which is the gate that decides; gate-task itself says its reduced set does not decide. An earlier attempt at this ticket made gate_remote.sh tolerate exit 5 and was blocked by the adr validator on ADR 031, which says a gate must never record a pass for work that did not run, so gate_remote.sh and the quality validator must stay as they are. The gate already has an honest path for a selection that names nothing: "Gate: reduced test set: no tests selected; skipping pytest", used today for changes that touch no tests, and that is the path an e2e-only change should take.

What it should do: make scripts/select_affected_tests.py leave out of the reduced selection any test that the repository's default marker filter deselects, which today means the tests under tests/e2e, so that a change which only touches them selects nothing and the gate takes that existing path. Keep every other selection as it is, including the change just made to select the tests under a changed nested conftest, and keep tests/conftest.py selecting the full suite. Where the selector can read the default filter from pyproject.toml rather than hard-code the directory, prefer that; if it cannot do so cleanly, a clearly named constant with a comment pointing at addopts is fine. Extend the existing selector tests to cover an e2e-only change selecting nothing, a mixed change keeping its non-e2e tests, and the earlier cases unchanged.

CONSTRAINTS
Files that may change: scripts/select_affected_tests.py, its existing test file under tests, and CHANGELOG.md (one entry under [Unreleased] ending with the issue reference Fixes #<n>). Do not change scripts/gate_remote.sh, the quality validator or pyproject.toml. No new state, status, severity or halt type.

ACCEPTANCE
Changing only files under tests/e2e selects no tests, a change that mixes e2e and other tests selects the other tests, and all earlier selector behaviour is unchanged. make gate-task is green.

PROCESS
Open a GitHub issue first and put Fixes #<n> in the commit message. This is a non-interactive run: open the issue directly with gh issue create, without asking for confirmation of title or body.
