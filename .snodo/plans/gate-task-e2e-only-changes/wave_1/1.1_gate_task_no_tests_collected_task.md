New files this task will create: none.

INTENT
Contributors and ticket authors can read, in the test-tiering documentation, that end-to-end tests are verified only by the release gate, and that a change to e2e tests or their conftest has to ship with an ordinary non-e2e test that the per-task gate really runs.

Symptom and evidence: two tickets in plan e2e-queue-journey-budget changed only files under tests/e2e and were blocked by the quality validator with "Gate: reduced test set: tests/e2e/conftest.py; this gate does not decide. ... no tests ran ... make: *** [gate-task] Error 5". pyproject.toml sets addopts to -m 'not e2e', so an e2e-only change leaves pytest nothing to run in gate-task, and the e2e tests themselves run only in gate-ci at release. Two attempts to make gate-task pass such a change, one tolerating exit 5 in scripts/gate_remote.sh and one making the selector select nothing, were both blocked by the adr validator on ADR 031, which says a gate must never record a pass for work that did not run. That decision is right, so the way forward is not to loosen the gate: a ticket that changes e2e tests should also carry a regular test that is selected and executed by gate-task, for example one that pins the property the e2e change relies on, and the docs should say so. Nothing in the docs says this today, so each author finds out by blocking a ticket.

What it should do: add a short, plain explanation to the existing test-tiering documentation (docs/specs/w6-01_test-tiering.md is the likely place; check CONTRIBUTING.md and any testing page in docs for where contributors actually look and put it there, linking rather than duplicating) covering which tests run in which gate, why an e2e-only change cannot be verified by gate-task and why the gate will not paper over that, and what to do instead. Keep it a few sentences, in the voice of the surrounding text.

CONSTRAINTS
Files that may change: documentation files under docs, CONTRIBUTING.md if that is where it fits, and CHANGELOG.md (one entry under [Unreleased] ending with the issue reference Fixes #<n>). Do not change scripts, validators, pyproject.toml or any test. The docs build and the docs checks in the gate must stay green. No new state, status, severity or halt type.

ACCEPTANCE
The documentation states which gate runs the e2e tests and tells authors to pair an e2e-only change with a non-e2e test that gate-task executes. make gate-task is green.

PROCESS
Open a GitHub issue first and put Fixes #<n> in the commit message. This is a non-interactive run: open the issue directly with gh issue create, without asking for confirmation of title or body. Commit your change before running make gate-task, because it tests HEAD and needs a clean tree, and run it in the foreground and wait for it to finish before ending your turn.
