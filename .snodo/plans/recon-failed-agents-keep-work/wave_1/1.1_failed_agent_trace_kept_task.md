INTENT
Recon rec_0ab738 (2026-10-08 00:57Z, 3 agents) ran after the recon-reliability fixes landed:
- qwen succeeded, with a trace (26 turns, tools_called listed);
- gemini failed after a retried 429;
- deepseek failed with "Final answer unavailable; run ended with empty_final:tool_calls" after 80s and 1.88M input tokens.

Both failed agents came back with `"trace": {}`. The recon-reliability plan (1.1, agent failure isolation) required that an agent ending early still records its trace and any partial answer. That holds for the cut-short case its tests covered, but not for an agent that fails through the model-failover chain ("all models failed; tried …"). The orchestrator can't see what deepseek read in 1.88M tokens of work, or why it never answered.

When this is done, every agent's result carries its trace (turns used, tools called, how it ended), whether it succeeded or failed. When a failed agent had produced findings or a partial answer before failing, those are kept too, using the result fields that already exist.

1. Find where the trace is attached to a result. Make the failure path, including the "all models failed" path in the failover chain, attach the trace the agent built up.
2. Keep any partial or truncated answer the agent produced, the way the budget path already does.
3. Tests:
   - an agent that fails after several tool turns returns a non-empty trace;
   - an agent whose provider fails on the first call returns a trace showing zero turns and how it ended;
   - a successful agent's trace is unchanged.
