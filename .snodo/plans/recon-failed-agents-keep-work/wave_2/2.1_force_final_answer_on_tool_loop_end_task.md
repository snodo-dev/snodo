INTENT
In recon rec_0ab738 the deepseek agent (ollama-cloud/deepseek-v4-pro:0813) worked for 80 seconds, used 1.88M input tokens, and then failed with "Final answer unavailable; run ended with empty_final:tool_calls". It was still calling tools when its run ended, and it never produced an answer. Earlier recon work added a forced `submit_answer` step, retried once, that keeps truncated answers. This ending shows a path where that forcing did not happen, or did not succeed: the last model message was tool calls rather than an answer.

When this is done, an agent that reaches its turn or token budget while still calling tools gets the forced final-answer step. It is asked to answer from what it has gathered, with tools disabled. If it still returns tool calls, its last substantive text or gathered findings come back as a truncated answer. "empty_final:tool_calls" ending as a failure with nothing returned should only happen when the agent truly gathered nothing.

THE CHAIN
1. Trace how a run ends with `empty_final:tool_calls`, and why the forced `submit_answer` path did not rescue it.
2. Make budget exhaustion during tool use go through the forced final answer, with tools disabled for that call, and keep a truncated answer if the model still won't answer.
3. Tests, with a fake provider that keeps returning tool calls:
   - at the budget it gets the forced final-answer call;
   - a provider that answers on the forced call yields a successful result;
   - a provider that still returns tool calls yields a truncated answer built from what was gathered, not an empty failure.
