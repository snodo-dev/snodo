INTENT
One test module proves the rule "no merge without snodo's own gates on that exact commit" for every merge path, so a regression in any of them fails the gate. Paths: task branch into plan integration, plan integration into queue integration, plan delivery in local_merge, push_branch and change_request, and a single task outside a plan.

Indications: add tests only (for example a new module under tests/cli/), using temporary repositories and the real merge code, not mocks of the merge path. For each path, a branch with no verification is refused with unverified_merge_blocked and a branch with a passing verification at its head is merged. Do not change production code; if a path does not behave as described, mark that test as an expected failure with the reason and say so in the commit message.

Acceptance: the new module runs in make gate; CHANGELOG.md updated.

First open a GitHub issue in snodo-dev/snodo for this ticket and put "Fixes #<n>" in your commit message; mention the issue number in the CHANGELOG.md entry. The state machine is closed: add no new status, halt type, severity, audit event type or audit field (reuse verification_executed and unverified_merge_blocked as they are). Tests use temporary git repositories and never touch the real worktree root, the repository's own .snodo/ directory or the real user home. `make gate` must pass with everything committed.
