# An expired OAuth login permanently refuses the session

First open a GitHub issue for this work. Write the body to a file under /tmp and pass it with `gh issue create --body-file`, never as an inline string. The commit message must say "Fixes #<that issue number>". Add a CHANGELOG entry under ## [Unreleased].

## INTENT
A lease mint that fails because the login has expired or the refresh failed is a credential problem, and the session is still welcome. It must not record a session refusal, which stops liveness and audit sync for that session until someone runs a forced sync. Sync backs off as it does when the server is unreachable. Once a working credential exists again, after a successful refresh or a new `snodo cloud login`, sync and liveness resume on their own.

## THE CHAIN
- Recon rec_267c88: in `packages/snodo-foundation/src/snodo/infrastructure/cloud_lease.py` (around lines 205–240), a 401 with `oauth=True` triggers one forced refresh through `safe_cloud_sync_credential`. If that refresh fails, the code sets "OAuth authorization expired; run `snodo cloud login` again" and falls through to the 4xx branch, which calls `state.record_refusal(session_id, ..., status_code=401)`.
- A refused session stops liveness (`cloud_liveness.py`, the `is_refused` checks around lines 381 and 610) and audit sync until `snodo cloud sync --all --force`.
- This is how one failed refresh silenced a running machine for 8 hours.

## CONSTRAINTS
- Treat a 401 after a failed refresh the way the existing unreachable or backoff handling treats a transient failure. Reuse that path; don't add new state.
- Keep the clear message. `_last_admission_error` and the stderr line still say to run `snodo cloud login`.
- Other 4xx refusals (a server that really refuses the session, e.g. 403 or 413) keep today's behaviour.
- Existing refusals recorded with status 401 should stop blocking: handle that in `cloud_lease.py` or the sync-state module (`CloudSyncState`), for example by not counting a 401 refusal as refused. Do not edit `cloud_liveness.py`; a sibling task changes it in this wave.
- No new status, severity, halt type or audit event.
- Never pass text containing backticks or `$(` through an inline shell string. Commit messages and issue bodies go through files under /tmp.
- Do not run the `snodo` CLI against this repo, `make release` or `make gate` in the worktree, and do not create, change or delete anything under `.snodo/` in the repo.
- Run `uv run ruff check` and `uv run python scripts/enforce_file_length.py` on touched files. Run only the cloud lease, cloud sync state and liveness tests.

  - a later mint with a working credential succeeds without a forced sync;
  - an existing 401 refusal no longer blocks liveness or sync;
