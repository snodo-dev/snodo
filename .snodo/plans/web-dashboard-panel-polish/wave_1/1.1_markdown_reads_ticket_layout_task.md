New files this task will create: none.

INTENT
The small Markdown renderer should read snodo ticket specs the way a person does, so the task panel shows a structured document instead of a wall of text.

Evidence: a task's spec file lays out its sections as bare lines (INTENT, CONSTRAINTS, ACCEPTANCE, PROCESS) followed on the next line by their text, with no hash marks and often no blank line between. snodo/web/static/markdown.js joins consecutive lines into one paragraph, so the panel shows "INTENT A view that has not drawn yet..." as one block, and it treats underscores inside words as emphasis, so a path such as tests/web/test_static_shell.py appears as "teststaticshell.py" with the underscores gone and the text slanted.

What it should do: a line that stands alone and is made only of capital letters and spaces (three to thirty characters, such as INTENT or WHAT IT SHOULD DO) renders as a section heading, even with no blank line before or after it. A single line break inside a paragraph stays a visible line break instead of being merged away. Emphasis with underscores applies only when the underscores sit at the edge of a word, never inside an identifier, file name or path; asterisk emphasis keeps working; the content of inline code is never touched by emphasis. A short lead-in at the start of a paragraph (a few words ending in a colon, such as "Evidence:" or "What it should do:") is wrapped in its own element with a class so it can be styled as a label. Ordered lists, block quotes and horizontal rules render as well, in addition to what is supported now (headings, bullet lists, fenced code, inline code, bold, italic, links). Anything still unsupported appears as plain text.

CONSTRAINTS
Files that may change: snodo/web/static/markdown.js, tests/web/test_static_markdown.py and CHANGELOG.md. The output stays DOM nodes built with createElement and textContent only: no innerHTML, no libraries, no external URLs. Links keep their rules (only http, https or relative targets, rel noopener noreferrer). window.snodoMarkdown.render keeps its name and return type (a DocumentFragment). Do not touch any other static file, stylesheet or Python module. Existing tests stay; add new ones.

ACCEPTANCE
Tests that exist and pass: a bare capital-letters line becomes a heading with and without surrounding blank lines; consecutive lines keep their breaks; a path or identifier containing underscores renders with the underscores intact and no emphasis element; asterisk emphasis still works; inline code content is untouched; a lead-in label is wrapped in an element with a class; ordered lists, block quotes and rules render; unsafe link targets are still refused; no innerHTML appears in the file; the existing markdown tests still pass. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message. Add one CHANGELOG.md entry under [Unreleased] ending "(Fixes #<n>)". Before finishing, run `ruff check` on any Python files you wrote and fix every finding, such as unused imports.
