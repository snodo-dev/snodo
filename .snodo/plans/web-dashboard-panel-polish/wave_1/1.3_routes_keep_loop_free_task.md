INTENT
A slow dashboard answer should not hold up every other request. The routes' blocking git and file work should run off the server's event loop so the spec, the static files and the other views stay responsive.

Evidence: each route handler in snodo/web/routes_now.py, routes_plans.py, routes_gates.py, routes_delivery.py and routes_spec.py is declared async but calls its blocking collection code directly (for example the Now handler calls build_now inline). While a Now answer is being computed, which takes seconds for a project with many plans, the server cannot answer the spec request or serve a stylesheet, so the page looks stuck and the spec panel shows loading for as long as the Now answer takes.

What it should do: every handler runs its blocking collection in a worker thread (Starlette's threadpool helper) and awaits it, returning exactly the same payloads, status codes and headers as today. Reading project state stays read-only. Nothing about the request guard, host checks or app wiring changes.
