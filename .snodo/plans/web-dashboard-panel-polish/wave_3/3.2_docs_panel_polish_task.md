INTENT
docs/web-dashboard.md should describe how the Now task panel now behaves, so the next person knows what to expect and why the routes use worker threads.

Evidence: docs/web-dashboard.md describes the panel as always present beside the tree, says nothing about the full-width start, the spec progress bar and how it learns, the Markdown conventions the spec renderer understands, or that route handlers do their blocking work off the event loop.

What the docs should say, in the style of the surrounding text: the tree uses the full width until a task is selected, then narrows for the panel, and Close or Escape returns the width; the spec loads behind a progress bar whose expected duration starts at ten seconds and follows the average of the last ten loads kept in the browser's local storage; the spec renderer reads bare capital-letter lines as section headings, keeps line breaks, leaves underscores inside identifiers alone and shows unsupported syntax as plain text; and that every route runs its blocking work in a worker thread so one slow answer does not hold up the others.
