New files this task will create: none.

INTENT
When a task renames a test function inside the same file, the coverage_accountability validator no longer reports that test as disappeared.

Evidence: in packages/snodo-engine/src/snodo/validators/coverage_accountability.py, coverage_findings compares the set of test function names before and after for each changed Python file and warns "Test case `x` disappeared" for every name that is gone. File renames are already followed (git diff -M), but a function renamed within a file shows up as one removed name and one added name, so the warning fires although the test body is unchanged. In plan runs this warning has turned acceptance into a blocker and started recovery rounds for work that was fine.

What it should do: a removed test case counts as retained when the file after the change has a test function with an identical body (compare the parsed function bodies, so formatting and comments do not matter) under a different name. Only the name changed, so there is no finding for it. A test whose body was removed, or edited and renamed at once, still reports as before. The existing handling of requested removals in the task spec and of deleted files stays as it is.

CONSTRAINTS
Files that may change: packages/snodo-engine/src/snodo/validators/coverage_accountability.py and tests/validators/test_coverage_accountability.py. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change how findings are worded or their severity, and do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show: a test renamed within its file with an identical body has no finding; a test removed outright still has a finding; a test renamed and edited at once still has a finding; the existing tests in that file still pass. `make gate-task` is green.

Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
