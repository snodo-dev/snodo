New files this task will create: none.

INTENT
The tests that check snodo's home-directory protection no longer depend on whatever is in the real ~/.snodo, so activity on the gate host cannot make the gate fail.

Evidence: a protection test (look in tests/coders/test_local_home_protection.py and tests/mcp/test_snodo_protection.py for it) reads the whole real ~/.snodo of the user running the gate. Any snodo activity on the gate host during a run, such as another job writing there, can change what the test sees and break the gate for an unrelated ticket.

What it should do: find which protection test touches the real home directory and make it use a temporary HOME and SNODO_HOME for the test (monkeypatch), building the files it needs inside that temporary directory. It must still check the same protection behaviour. If every protection test already isolates HOME, say so in the commit message and change nothing except adding a test that fails if any of them reads outside its temporary directory.

CONSTRAINTS
Files that may change: the protection tests named above and a shared fixture in tests/conftest.py or the tests/coders or tests/mcp conftest if one is needed. Also edit CHANGELOG.md: add one entry under [Unreleased] ending "(Fixes #<n>)". Do not change production code and do not add any state, status, severity or halt type.

ACCEPTANCE
Tests show the protection checks pass with an empty real HOME and with a populated one, with the same assertions as before. `make gate-task` is green.

PROCESS
Open a GitHub issue for this task first and put "Fixes #<n>" in the commit message.
