## Intent
A validator's adjudicated verdict for one task must never be applied to a different task.

## Evidence
- Audit events `decision_record_task_mismatch` fired in every wave of a recent plan: a stored record for a task from another plan was found while other tasks were being dispatched, and one task was escalated by a warn whose text described a different task's design.
- `DecisionRecordIssuer.find_adjudicated` in packages/snodo-foundation/src/snodo/infrastructure/decisions.py has a first pass that checks the expected task reference and a second carry-forward pass that verifies records without it, so a record for another task matching on validator and severity can be returned. `PolicyEvaluator.evaluate` in packages/snodo-engine/src/snodo/engine/policy.py consumes it when it reclassifies a warn.
- Carrying a verdict across a retry of the same task must keep working; only a different task must be refused.

## Outcome
- A record is used only when it belongs to the same task, and the spec it was given for has not changed; otherwise it is ignored and the validators run fresh.
- Tests: a stored record for another task with the same validator and severity has no effect on the current task's policy decision; a record for the same task still applies on a retry.
- Existing decisions and policy tests pass, with any that relied on cross-task carry-forward updated to say so.
- `make gate` passes.
