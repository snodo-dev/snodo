## Intent
The `read_diff_between_refs` tool that validators use should show the diff between the refs it is asked about, whatever form the refs arrive in.

## Evidence
- Acceptance runs fail the tool because the range reaches git as `X..HEAD..HEAD`; the validator then falls back to other tools and reports a partial read.
- `GitMCP.diff_between_refs` in packages/snodo-tools/src/snodo/tools/git.py builds `ref1..ref2` unconditionally. It is called from the validator tool support and the coder history tools with a bare ref, an already formed range such as `X..HEAD`, or two refs.
- Fix it where the range is built, in the git tool, and leave the validator tool support module alone so another task can edit it at the same time.

## Outcome
- The range is built once for a bare ref (compared against HEAD), an already formed range, and two refs; an input that cannot be read as any of these returns a short clear error.
- Tests cover each of those forms and the doubled case from the issue, against a real temporary repository.
- Existing history tool tests pass unchanged.
- `make gate` passes.
